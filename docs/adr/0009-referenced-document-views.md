# 引用文档视图分离读取、呈现与写回

## 状态

已接受架构方向，2026-09-29。用户确认先只读、后 Live，提前设计通用架构。一期（#218–#225）已于 2026-09-30 实施完毕；#225 收口核对未发现实施偏离本决策的点（只读无写端口、容器与模式解耦、文件类型扩展空间与挂载适配分层均按决策落地）。

## 背景

悬停预览和文档嵌入均展示另一个文档或其范围，未来需要可编辑视图。若底层只返回脱离文档身份的 HTML，后续无法可靠接入编辑；若读取强依赖完整编辑会话，又会使只读阶段背负不必要的实现成本。

## 决定

- 文档访问负责目标身份、带版本内容、范围定位、源位置映射、更新订阅与释放，不依赖写回能力。
- Reading 与 Live 是呈现模式，只读与可写是能力约束；悬停与嵌入是展示容器，容器不固定为某种模式。
- 首期实现 Reading 引用视图并禁用写入能力，不是只读 Live 视图；后续 Live 通过独立编辑端口写回目标文档，并与其他目标视图同步。
- 视图的滚动、选区和生命周期独立于文档内容；共享文档数据不等于共享同一个 DOM 或 EditorView。
- 通用接口保留文件类型扩展空间，Markdown 与附件可使用不同渲染器。已确认路线为一期 Reading 只读、1.5 期递归及表格与其他混排、二期 Live 编辑、三期 PDF 预览与嵌入；PDF 引擎与其他附件范围另行决定。
- 一期只在独占正文行挂载，但引用识别、文档访问和内部视图不依赖顶层块假设；为 1.5 期表格单元格与混排容器保留挂载适配层。

## 影响与取舍

可分期交付，同时避免只读 HTML 成为未来编辑的架构边界。首期仍需实现文档身份、版本与范围契约，并验证无写入端口的视图能正常刷新和释放。

此决定不要求首期实现 Live 写回或完整多视图编辑系统。后续必须具体设计版本冲突、局部范围重定位、撤销／保存归属及焦点与快捷键隔离，不能宣称接口预留已经解决这些问题。

详细建议、证据与访谈问题集中在 [共识草案](../specs/hover-preview-embed.md)。


## #242 已实施的实例与容器边界（2026-09-30）

共享只读内容由 `RefContentInstance` 与 `RefContentMount` 承担：实例属于来源中的具体引用位置，保存滚动和属性状态；每次挂载独立拥有内容 DOM、来源图片、属性按钮监听器与延迟恢复帧。浮层和卡片保留展示壳、布局与请求／版本仲裁，资源释放通过实例／挂载清理入口配对。根面板身份、直接来源身份、来源区间与目标规范身份／语义范围分别建模。

同一目标的不同引用位置允许共用读取结果，各自的 UI 与释放独立；同一位置在父 Live／Reading 之间的恢复语义保持一期约定。内容层只接已读取数据和只读消息依赖，不读取磁盘、不创建可写 EditorView。宿主来源记录按已校验的 occurrence 订阅固定，最后退订后才恢复缓存淘汰，面板销毁后迟到结果不再登记。

本票保持一层独占行，卡片原全量挂载与浮层原虚拟视图策略。内部滚动宿主驱动挂载由 #243 完成；递归、来源逐层校验、全局订阅容量与预算由 #244 及后续切片完成。父实例／展开路径／预算注入接口不代表这些能力已经实施。


独立审查后，来源固定进一步明确为「成功送达 → 待订阅租约 → occurrence 持有 → 释放」。租约是每次送达的生命周期凭据，不属于读取缓存或解析数据：相同缓存结果送达两个位置仍发两个租约。请求 opt-in、watch 精确转交与独立 release 是兼容协议扩展；原子转交校验来源目标及会话，旧目标退订不撤销新目标待订阅租约。浮层与卡片分派先确定消费者，再统一释放未消费回包，面板销毁整体收回。预算与递归仍由 #244 负责。

## #244 卡片递归的来源与预算决定（2026-10-01）

独占行卡片的子引用继续使用同一只读 Reading 内容实例和卡片壳。父卡片的真实内容块挂载时创建子卡；父块回收或父目标换版本时释放子视图、来源订阅和异步响应资格。根 A 为深度 0，卡片 B/C/D 默认展开至深度 3；深度设置 1–6 存于插件自有设置页。混排、列表／引用、表格与悬停浮层中的递归分别留给后续切片。

根面板会话身份与直接来源严格分开。子请求只带父 occurrence 和已送达的来源身份，宿主从该面板的 watch 租约记录取得父版本、范围与路径，再从当前 `TextDocument` 验证整行嵌入原文及语法上下文。通过后按直接父目录解析目标；父释放、未保存版本前移或目标原文不匹配都拒绝。循环在当前祖先路径中以规范 fsPath 加语义范围判断，根 A 也在路径内；同目标兄弟仍可独立出现。

实例预算按 occurrence 逐个保留，数据预算按实际保留副本保守收费：宿主 LF 正文与 webview 全文解析／生成 HTML 分别有每树 2 MiB、每面板 8 MiB 限额，另各有界缓存单独计量；同内容可能命中解析缓存，但不得仅凭 fsPath/version 假定物理共享。每树 24、每面板 64 个实例，宿主端每面板最多 8 个在途读取。provider 内跨面板共享的 128 个 watch 目标槽满额时拒绝新目标并回可见错误，不撤销旧在场目标。上述是工程上界和逻辑计费单位，不等同进程堆字节；测量与暂态边界记录在引用性能报告。

## 1.5 期收口：递归、混排与表格格内的架构落位（#249，2026-10-01）

1.5 期七张切片（#242–#248）合入 PR #250 后由 #249 收口核对，实施与本决策一致，未出现需要修订决策的偏离：

- **递归与容器无关**：同一 EmbedCardManager 与 RefContentInstance 在正文卡片（独占行/混排/列表/引用/表格格内）与悬停浮层内复用——「容器不固定模式、呈现与读取分离」的决策在全部 1.5 期容器形态上成立；悬停浮窗保持一次一个，未出现多层浮窗。
- **禁写边界保持**：递归内部（含表格格内与浮层内递归）全程只读 Reading，无 EditorView 写入端口；父文档 Live 只决定展示模式，不使目标可写。目标 Live 写回仍属二期 #227。
- **表格格内的三坐标边界**：源码坐标（写回/索引/rename 落点）、表格转义坐标（`|` 解码）与渲染文字坐标经 `tableCellEmbed` 的显式映射分离——「源位置映射」职责在 1.5 期扩展到转义表格，识别（呈现/准入/索引）三层同源。
- **预算与订阅闭环**：occurrence 级实例计费、树/面板字节上限、来源租约与 watch 槽位的工程上界在 #244 落定后被 #245–#248 的容器扩展原样继承；#249 收口实测（宽分支/重复引用/快速开关/滚动）未见超限或静默失效（见引用性能报告）。

收口实测发现两项虚拟化已知缺陷（表格格内 Reading 卡内层滚动位置丢失、长文档底部 spacer 记录偏大），均属 #7/#243 视口机制边界、不构成本决策的架构偏离，修复另行专项。组合矩阵、验证器完成度对账与人工验收状态见规格 #249 节。

## 三期产品方向与待验证路线（#228，2026-10-04）

本轮已确认 PDF、图片附件、可读文本与外链预览的产品范围，沿用本 ADR 的来源、访问、呈现与写回分离原则。用户于 2026-10-04 确认正式方案与 12 票拆分并授权发布，#333–#344 已建立；PDF 与文本技术路线仍须前置验证。见[三期正式规格](../specs/hover-preview-embed.md)。

- PDF 和普通文本为只读内容，不因为父 Live 而取得写端口；PDF 使用独立渲染器，基础阅读范围已确定，具体引擎仍需下界、worker、资源与包体验证。
- 图片双链嵌入委托普通 Markdown 图片的呈现与交互，不强迫图片使用文档引用卡片壳，既有弹窗排除不扩大。
- 普通文本以原生文字外观为对照，语法／语义／主题复用仍需实测；未经用户接受不把有高亮的原生目标直接降为纯文本，不在本 ADR 提前选定未验证引擎。
- 外链总开关默认关闭，默认卡片、可选原网页；原网页不可用时卡片退回并说明原因。宿主元信息抓取与客户端原网页网络是两条不同通道，均不获得文档写能力或扩展控制权限。
- 原生 Explorer 独立小浮窗移四期 [#330](https://github.com/ONEGAYI/vsidian/issues/330)；右侧 WebviewPanel 不再作为该目标的已接受替代方案，载体另行验证，不阻塞三期。
