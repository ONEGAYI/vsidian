# 引用内部编辑归属目标文档会话与宿主历史

## 状态

已接受归属与产品行为，2026-10-01。来源为二期 #227 设计访谈 Q5，用户选择「采用目标文档保存与历史」。具体目标撤销路由和兼容性尚待验证，本记录不宣称实现可用。

2026-10-02 用户确认 Q1–Q19 总共识，转入正式规格与本地票草案。目标历史等宿主路线由 P2-01 真宿主验证，未通过前依赖实施票保持阻塞。

## 背景

A 面板中展示 B 的引用内容时，容器属于 A，编辑文本却属于 B。若沿用 A 的保存和撤销命令，会把操作交给错误文档；若为每个引用单独维护持久撤销栈，又会与 B 在其他视图中的历史分叉。

[ADR-0009](0009-referenced-document-views.md) 已确定宿主文档权威、读取与写回分离、UI 状态逐实例独立。现有 `DocumentSession` 按文档管理编辑队列、版本映射和冲突恢复，provider 按目标 URI 持有会话；引用实例尚未接入目标编辑端口。

## 决定

- A 引用 B 时，引用内部编辑归属 B 的权威 `TextDocument` 与文档会话；父容器身份不决定写入文档。
- 焦点位于 B 引用内部时，Ctrl+S 只保存 B，Ctrl+Z／重做作用于 B 的宿主文档历史，包括 B 在其他视图中的修改。焦点回到 A 后恢复 A 的操作。
- 引用头部显示 B 的未保存状态，并提供保存 B 的入口。
- 悬停浮窗 head 显示目标 B 的文档名称标题；B 未保存时在名称旁显示 `·` 圆点，保存成功并清除未保存状态后消失。圆点对应 B，不能借用父文档 A 的 dirty 状态。
- 显式关闭的确认框选择「丢弃修改并关闭」时，恢复整个 B 到已保存内容，包含 B 在其他视图中的未保存修改。确认框必须明确显示目标文件与影响；对话框期间 B 再被修改时重新确认，不能沿用过期确认丢弃新修改。
- 目标内容与历史以文档为单位共享；引用位置的模式、选区、滚动和挂载资源以实例为单位持有。
- Live 浮窗仅在目标 B 有未保存修改时保活，B 干净时沿用 Reading 的普通关闭行为；实例状态的会话记忆不要求干净编辑器常驻。输入法／在途提交保护与冲突暂停选择仍分别生效，不把未提交输入冒称为 B dirty。
- 目标撤销的技术路由必须验证后采用。当前活动编辑器是 A 时，禁止用未经目标校验的全局撤销命令替代 B 的撤销。

## 影响与取舍

多个引用和原生／自定义 B 视图围绕同一权威文本与历史同步，避免出现仅在某个卡片可撤销的隐藏编辑。

该选择意味着，在 B 引用内按撤销可能撤销 B 另一个视图最近产生的修改；这属于已确认的文档级历史语义。容器关闭、模式切换和离屏回收仍需定义未确认输入的保留与恢复，不能简单等同于文档释放。

## 父标签关闭后的目标交接（已确认）

用户于 2026-10-01 核对公开 API 后接受：普通关闭 A 文件标签后，将其引用编辑涉及且仍有未保存修改的 B 打开为独立普通文本编辑标签。该标签显示现有 B `TextDocument`，使用 `preview: false`；不自动保存、丢弃或另建 B 文本副本。后续编辑、保存和丢弃由 B 标签继续承接。

此决定只涵盖已成功写入 B 的修改。未成功写入 B 的输入按后续已确认的当次冲突选择处理：对比并解决、放弃当前版本、取消。当前源码的通知与复制取回仍属待替换的基线，不能当作持久保护。用户随后要求二期从简，独立持久恢复草稿、多快照管理与跨会话历史恢复延后到未来「历史版本」功能，想法已追加总体三期 [#18](https://github.com/ONEGAYI/vsidian/issues/18)。正常退出、窗口重载与 SSH 断连也不能直接套用普通标签关闭的重开逻辑。

二期继续保留日常撤销／重做与运行期版本校验；它们分别用于当前编辑的回退和安全同步，不据此建设用户可浏览的持久历史库。写入冲突暂停后保留临时输入；「对比并解决」打开 VSCode 原生对比页，左侧提供临时副本，右侧为 B 当前冲突版本。扩展负责临时资源和打开入口、目标文档同步，对比页交互交给宿主；不另建自有解决界面。hover 长说明及三项选项的准确文案见功能规格 Q15／Q17。「放弃当前版本」作用于本次未成功提交的输入版本，不能借用普通关闭时对整个 B 的回滚操作。

公开接口已经核实：A 的 `WebviewPanel.onDidDispose` 通知后，可用 `window.showTextDocument` 显示仍打开的 B 文档。关闭时的在途回流、多个 dirty 目标和已有 B 标签的交接须由真宿主验证；API 存在不等于完整流程已经通过验收。[1.86.2 API 声明](https://github.com/microsoft/vscode/blob/1.86.2/src/vscode-dts/vscode.d.ts)、[showTextDocument 文档](https://code.visualstudio.com/api/references/vscode-api#window.showTextDocument)

## 待验证的技术边界：目标撤销路由

现有 `src/host/textEditorProvider.ts` 的 `openEntry` 撤销／重做实现先确认活动 tab 属于该文档的 custom editor，再调用宿主全局命令。父 A 面板内编辑 B 不能直接复用该活动 tab 条件。

目标 URI 撤销路线、命令焦点隔离、与 B 其他视图交错操作、最低支持 VSCode 与 Remote SSH 的行为需有源码依据和真实宿主验证。在技术证据齐备前，此项应作为实施前置验证，不将内部未公开服务视为可直接调用的扩展 API。

二期交互与验收见 [功能规格](../specs/hover-preview-embed.md) 的「二期正式规格」节；逐轮访谈保留来源记录。
