# 组件主题统一入口与互斥选择

## 状态

2026-10-15 用户在 #530–#535 设计访谈中确认 #533 的主题入口与选择规则，已接受设计方向，尚未实施。同日进一步接受宿主登记与页面执行的分工、替代组件先可安装可用再移除内核 Codex 的交付顺序，并在 Q11/Q12 确认安装只新增主题候选及跟随 VSCode 实际生效主题。产品选择规则已收口，接口声明与协调实现仍待细化。

同日 T07（#546）落实宿主主题目录、唯一选择与页面明暗订阅，公开 API 仍为 1.0.0 候选；具体消费入口与验证见[主题规格实施落档](../specs/addon-themes.md)。bridge#3 的替代组件交付和 #535 的内核退役仍按既定顺序接续。

## 背景

现有 Codex 主题位于「外观 → 预设主题」页签，由内核 Mermaid 设置控制。#533 为迁到附加组件的 Codex 主题及其他组件主题提供统一登记通道，#535 承接内核 Codex 实现的退役。

主题入口若另存一份选择，再与渲染提供者选择分别写入，可能出现界面选中主题与实际渲染不一致。用户明确要求所有组件主题统合到原位置，选择唯一且互斥。

## 决定

- 保留现有外观页第四个页签的位置，将名称由「预设主题」改为「主题」。Codex 与其他组件提供的主题在此统一列出与选择。
- 主题选择唯一且互斥，不另设可与它冲突的渲染器主题选择入口。界面选中项与实际生效主题由同一份选择驱动。
- 安装主题组件只新增主题候选，保留当前主题，由用户在「主题」页选择。主题提供者不因新安装而自动接管；这是对 ADR-0012 一般渲染组件自动接管规则的明确例外，普通非主题渲染组件沿用原规则。
- 组件停用或故障降级时保留主题首选；组件恢复可用后沿用原首选。实际渲染的接管与故障边界继续遵循 ADR-0012。
- 主题跟随 VSCode 当前实际生效的明暗主题；VSCode 启用跟随系统时随系统自动变化，手动固定主题时遵循该固定值。已打开内容须收到变化并更新，无需重开；状态取得与通知接口的形状尚未冻结。
- 主题元数据在扩展宿主登记，Vsidian 统一管理目录；各文件页面负责实际渲染。目录不依赖先打开某个文档页面。
- 先让替代组件可安装、可用，再从 Vsidian 内核移除 Codex；#533 完成不单独构成 #535 移除实现的交付条件。

## 影响与取舍

主题的发现、选择与回显由平台统一管理，组件不能各建与此并行的主题选择状态。实现时需要协调主题选择与既有 renderer-selection 的自动接管、显式首选和降级，避免两套可写状态相互覆盖。

本决定不将所有代码块渲染扩展等同于主题，也不删除 ADR-0012 中一般渲染提供者的候选机制。两者的具体接线、主题身份、持久化与迁移方案须在 #533 技术设计中落实。

主题与普通渲染提供者具有不同的安装默认行为。实现必须识别主题关联的提供者，不能让一般渲染自动接管路径绕过主题单选；组件同时提供的其他非主题渲染能力仍按自身规则接入。关联载荷、注册同步与持久化方案属于后续技术设计，不在本记录中虚构签名。
