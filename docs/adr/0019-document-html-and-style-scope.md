# 原生 HTML 保持源文权威，文档内样式限定本篇渲染正文

## 状态

产品约束已接受，2026-10-16。用户在设计访谈中选择：支持文档内 `<style>`，块级与行内 HTML 一起支持；样式覆盖本篇 HTML 与 Markdown 正文，排除工具栏、源码编辑层及嵌入的其他文档。后续轮次明确选择全量 HTML 支持目标、纯 `<style>` 块在 Live 源码常显，以及 CSS 按实际 DOM 匹配、尊重原意。用户已确认拆票，规格总票 [#565](https://github.com/ONEGAYI/vsidian/issues/565)，子票 #566–#574；功能未实施。规格见 [html-rendering.md](../specs/html-rendering.md)，技术实现仍需先完成 T01 探针。

## 背景

用户希望在双模式渲染原生 HTML，截图样例为带合并单元格的 HTML 表格。Live 还需保留直接编辑源文的能力：点击渲染区或按钮进入源码并全选，键盘进入及大选区相交时显形，离开恢复渲染。

当前架构以宿主 `TextDocument` 为权威、CM6 为 Live 编辑器、markdown-it 为 Reading 渲染器（[ADR-0003](0003-source-text-dual-view-editor.md)）。两种视图均保持全文模型与视口 DOM 分离（[ADR-0005](0005-viewport-rendering.md)）。Reading 目前禁用原生 HTML，DOM 净化还会移除 `<style>`；不能将已有防御层直接视为接受任意 HTML 输入的完整净化策略。

## 决定

1. **HTML 仍属于 Markdown 源文**。渲染是视图行为，不把 HTML 改写为 Markdown，也不以浏览器修复后的 DOM 序列化结果回写文件。代码围栏和行内代码中的 HTML 保持字面语义；既有 HTML 注释行为单独维护。
2. **Live 按片段显形源码**。点击渲染内容或编辑按钮时选择该片段完整源码；键盘落点及非空选区相交只驱动显示切换，保留原落点与原选区；完全离开后恢复渲染。显形不产生文档修改或独立撤销历史。
3. **文档内 `<style>` 归属本篇文档**。规则可作用于本篇原生 HTML 与 Markdown 渲染正文；不得将其作用范围扩大为整个 Webview，不影响工具栏、源码编辑层或嵌入的其他文档。每份被引用文档的样式按其自身内容归属处理，不能依靠父容器 DOM 嵌套自然串联作用域。
4. **样式存续依附全文源文**。按源码顺序收集与更新，不依附 `<style>` 区块 DOM 的挂载、视口位置或当前显形状态。删除或修改源文规则时同步更新；释放文档视图时释放其样式装载资源，不留下影响其他文档的规则。
5. **HTML 内容经过受控渲染**。脚本与事件属性不获得执行能力；资源、导航和宿主操作沿现有权限边界接线。不能因支持 CSS 而放开脚本权限或允许原生 HTML 伪装成内部操作控件。
6. **标签范围以全量支持为目标**。用户未选择“首批常用标签”的范围裁剪，iframe、音视频、表单以及 SVG／MathML 均纳入设计与拆票。逐类处理矩阵须说明可见结果、属性、资源和交互方式，不能将这些类别无说明地整类删去。“全量”是功能范围目标，不表示本次已验证全部元素或获得脚本执行权限；确有平台限制时列出证据并返回设计讨论。
7. **纯样式块不伪装成可视内容**。纯 `<style>` 块在 Live 保持源码可见、可直接编辑，不增加占位后点击显形的交互；Reading 隐藏源码，样式继续参与全文规则装载。
8. **CSS 按实际 DOM 保持原生匹配语义**。不把 `h1`、`p`、`table` 等标签选择器转换为 CM6 内部类来追求双模式等效，也不为匹配任意标签选择器而重建 Live Markdown DOM。相同原生 HTML 使用同一内容规则；Markdown 部分因实际 DOM 不同而产生的样式差异属于用户接受的口径，须在文档与样例中说明。样式作用域隔离仍须兑现决定 3，不因尊重匹配原意就允许整页污染。

## 影响与取舍

- 原生 HTML 可保留 Markdown 无法表达的表格结构和排版能力；需要共享解析边界、净化策略与源码区间，避免双模式各自解释同一输入。
- `<style>` 作为全文数据必须参与文档更新及视图生命周期，不能随虚拟化区块卸载；正文 DOM 仍按现有视口机制回收。
- 本篇正文与引用内容共处同一 Webview，单纯给 CSS 选择器追加外层类名未必能兑现隔离；继承、选择器、CSS 变量及嵌套引用须有独立绘制证据。隔离机制不在本 ADR 中预先选定。
- Live 的 Markdown 主要使用 CM6 的 `div/span`，Reading 使用语义 HTML。用户接受实际 DOM 带来的差异，避免引入维护成本高、难以忠实覆盖所有 CSS 的选择器语义转换；原有公开样式入口继续按自身契约维护。
- 公开样式入口遵守 [ADR-0004](0004-stable-styling-contract.md) 与项目 style-contract 技能。不能以支持原生 HTML 为由更换既有 DOM 契约、削弱历史测试或重写历史基线。

## 工程验证前置

- 在最低支持宿主上验证样式作用域方案，证明不会影响源码层、工具栏和被引用文档，也不通过改写标签含义来制造双模式等效。
- 按全量目标形成 HTML 标签、属性、资源与原生交互处理矩阵。Live 普通点击进入源码的既定规则优先于原生控件激活；Reading 承载其受支持的原生交互。

以上是开票后的技术验证工作，不是对全量目标的预先削减。未取证的能力如实标记待验证；若与已确认需求无法兼得，提交证据并回到设计讨论，不静默改为仅支持常用标签。
