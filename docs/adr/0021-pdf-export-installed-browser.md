# PDF 导出调用已安装浏览器，保留现有阅读样式

## 状态

产品方向已接受，2026-10-21。用户在三轮 PDF 导出访谈中确认：首期同时包含当前文档、选区、批量和合并；调用已安装浏览器自动生成，外观跟随当前阅读样式；Remote SSH 从远端读取内容，在本机生成并保存。产品范围与十票拆分均已确认，[总览 #618](https://github.com/ONEGAYI/vsidian/issues/618)与子票 #619–#628 已发布，详见 [PDF 导出规格](../specs/pdf-export.md)。本文不锁定浏览器控制库或跨宿主传输接口，也不表示可行性已经通过或功能已经实现。

## 背景

Vsidian 的编辑与阅读视图使用全文文本模型和视口 DOM 分离的架构（[ADR-0003](0003-source-text-dual-view-editor.md)、[ADR-0005](0005-viewport-rendering.md)）。当前可见 DOM 不包含所有正文，不能把复制预览区域视为全文导出。

本次核查的 Better Export PDF 2.0.3 会另建完整打印正文，再使用 Electron 打印接口或 Obsidian 内部打印消息输出 PDF。其完整正文装配思路可以参考；Obsidian 提供的打印通道不属于 Vsidian 所面向的 VSCode 公开 Webview 接口。

浏览器引擎的分发方式会影响扩展包体、用户安装前提和后续升级维护，需要在选用具体控制库之前记录产品取舍。

## 决定

1. **使用已安装浏览器自动生成**。用户在扩展内选择保存位置后，调用已安装的 Chrome／Edge 生成 PDF，不要求用户进入外部浏览器手动打印。
2. **不随扩展附带或自动下载浏览器引擎**。浏览器缺失时提示配置。具体发现方式、支持版本与控制库由后续可行性探针验证，不以开发机已装浏览器冒充普通安装环境已经可用。
3. **首期范围包含四类导出**。当前文档全文包含未保存修改；选区、批量、多文档合并也属于首期。具体文件收集、排序与选区规则另按访谈确认，不将其静默移出首期。
4. **默认跟随阅读样式**。PDF 默认采用当前阅读模式的主题与正文样式，并适配纸张分页；不在本轮预设独立浅色打印主题。
5. **Remote SSH 在本机生成并保存**。文档与资源由远端工作区侧读取，用户本机浏览器负责生成 PDF，结果保存到本机。不得将远端安装浏览器或在远端输出 PDF 作为已确认需求的替代；跨宿主执行与资源传输先做最小探针。
6. **准备阶段固定输入**。一次导出准备期间读取并固定各文档和阅读样式；已打开文档及 Markdown 嵌入目标优先使用未保存内容，生成过程中不混入后续编辑。该约定不声称对整个文件系统提供同一时刻的事务快照。

## 影响与取舍

- 可以避免随 VSIX 分发浏览器二进制，但用户环境中必须有受支持且允许调用的浏览器；其实际支持范围须有探针证据。
- 生成 HTML、等待渲染与资源、调用浏览器和保存 PDF 都需要生产链路。已有 PDF.js 阅读能力不承担该链路，开发依赖中的 Playwright／pdf-lib 也不能直接视为可分发的导出后端。
- 需要验证 VSCode 1.82.3 与宿主 Node 18 下界，不得为了采用当前开发用浏览器工具而自动提高项目兼容下界。
- 阅读视图的虚拟化约束保持；完整导出正文的装配与释放方案须单独验证，不能以导出为由使日常编辑常驻全文 DOM。
- 当前扩展声明为工作区侧运行；不能假定 Remote SSH 的扩展宿主能直接调用本机浏览器或本机文件系统。需要验证本机执行端与远端读取端的接线；未通过时报告阻塞，不自行收窄远程范围或更改整个扩展的运行侧。
- 完整导出正文与 PDF 预览会产生额外任务和资源。手动刷新预览、取消、关闭和批量结果必须有独立生命周期，不复用仍在变化的编辑视图 DOM 充当固定输入。
