# 表格边沿光标与独立格内输入

## 状态

2026-10-23，用户确认原型交互，并授权在独立工作树接入边沿交互与独立格内输入两部分。生产实现待用户验收。

## 背景

源码网格依靠透明填充空格承载原生光标，删除与输入法会触及这些源码字符。文档首尾的表格也没有可达的普通行，无法仅靠移动光标插入前后空行。

## 决定

- 网格继续使用现有源码 mark 与 CSS grid。每个 Live 实例创建一个活动格 textarea，原生文字输入与源码渲染分开；空格子输入值可以为真正的空字符串。
- `src/shared/tableCellInput.ts` 提供可编辑文本与源码的双向投影，复用 `tableCells` 的代码区间、换行判定。输入后序列化活动格，再取最小源码差分提交外层 CM6；不重写整表。
- 格区输入清空所选格并把完整新内容放入左上格；结构键与剪贴板继续复用原有表格执行体。鼠标拖选期间由 CM6 持有焦点，松手后再切换输入载体。
- 表外落点以 CM6 StateField 保存临时状态，以对应边沿高亮和中央光标表示。导航不写源码；插行、删除相邻空行仍是普通文档事务。
- 所有内容修改沿既有 LiveEditorInstance → 宿主文档管线提交；组合输入复用宿主缓冲，撤销不建第二份历史。
- 紧邻普通行键入不自动补空行。此项为用户明确排除的范围。

## 取舍与兼容

保留 `.vsidian-table-grid-row`／`.vsidian-table-grid-cell` 及既有表格样式变量，不整体替换为 DOM 表格编辑器。对照基线为 `c1ae8410fe97dac5e2843ab2d5d8bb9463402878`（1.4.0 所在开发基线）；本次没有弃用或移除公开样式入口。

这条路线分离输入载体，同时继续复用既有可见网格与复杂格内渲染。代价是需要维护文本坐标投影与焦点交接；浏览器回归覆盖空格、转义管道、格区替换、上下导航和组合输入。真实输入法候选窗、物理鼠标手感与大表滚动仍需按人工验证清单验收。
