# Callout 源文、视图状态与样式入口

## 状态

已接受产品与架构约束，2026-10-28。规格总票 [#651](https://github.com/ONEGAYI/vsidian/issues/651) 已创建；具体 Live 容器装配路线待 [T01 / #652](https://github.com/ONEGAYI/vsidian/issues/652) 验证，完整要求见 [callout 规格](../specs/callout.md)；尚未实施。

## 背景

callout 需要在引用块源文上增加类型、标题、折叠和可定制外观。用户确认 Live 编辑正文时保留外框，Reading、悬停、嵌入和 PDF 同时支持，并要求 Obsidian 原名 CSS 入口和类型菜单的实际颜色预览。

现有 Live 按 CM6 行装饰显示引用，Reading 经 markdown-it token 渲染。CM6 的可编辑行结构与跨行 `.callout-content` 不是天然同一结构。若先承诺静态外框，再另写一套编辑器或仅保留空的别名节点，会破坏源位置、输入或 CSS 的实际语义。

## 决定

1. **源文仍为唯一内容**：callout 是源文引用容器的一种解释，不保存第二份富文本模型；创建与转换只经原子宿主文本编辑。折叠和呈现不写文档。
2. **共享语义，分别适配**：类型注册、区间事实、标题声明及转换规划在共享纯逻辑层维护；Live 与 Reading 通过既有解析器的容器结构消费，不做两套全文正则识别。具体接口由技术验证确定。
3. **视图状态按实例归属**：一个实例内 Live／Reading 共享手动开合，主正文与各引用位置独立，重开采用源文默认值。折叠不进入宿主撤销历史；PDF 固定输入始终展开正文。
4. **样式入口是实际契约**：承诺的 `.callout`、标题／内容子元素、类型 data 属性及变量须真实命中并产生样式。原类型标识与默认外观类别分离，未知类型能被用户 CSS 定制。普通引用的既有入口保留。
5. **菜单外观与正文同源**：类型行使用实际类型呈现及 CSS 的有效颜色，不再维护菜单专用色表；逐项分隔只用于 callout 类型列表。正文布局规则不直接接管菜单按钮的点击与排版。
6. **先验证困难接缝**：T01 用生产控制器路径验证可编辑容器、嵌套、IME、源位置、视口性能和样式父子关系。没有通过结论不得放行依赖实现，也不得把整块源码回退当作需求达成。

本决定不选择嵌套 EditorView、跨行行容器或某种 widget 装配方式；这些候选必须由探针数据收敛。现有 TextDocument 权威、引用编辑归属和公开样式维护期限继续有效。

## 影响与取舍

- 用户得到编辑时稳定外框与可复用片段的明确入口，但实现必须同时满足可编辑结构和 CSS 命中，技术验证不能省略。
- 共享元数据减少类型、别名和菜单的分叉；两种解析器仍需相同夹具对拍，不能宣称共用类型表便消除了语法差异。
- 按实例记忆避免同一文档的不同引用互相收起；用户重开后不会恢复临时开合选择，这是已确认边界。
- 原类型标识保留使自定义类型可用，也要求别名的语法归类与 CSS 类型变量映射分别验证。
- 菜单实际配色需要在对应主题／正文样式上下文中求值；承诺经过测试的颜色入口，不把它延伸为任意复杂 CSS 内容选择器的布局克隆。
