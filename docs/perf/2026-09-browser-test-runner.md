# 浏览器测试调度实测

## 结论与范围

默认双并发将本机完整浏览器回归从 62.70 秒降到 32.52 秒，缩短约 48%，原有 16 个脚本全部通过。主要收益来自脚本并行；构建复用节省了重复工作，但不是当前耗时的主要来源。四并发没有进一步收益，默认保留双并发。

本轮只调整测试基础设施，不改产品代码、不删除测试断言、不缩短交互等待，也不引入自动重试。浏览器实例、页面和上下文仍各自隔离。

## 运行方式

```sh
npm run test:browser
npm run test:browser -- --workers=1
npm run test:browser -- --workers=4
npm run test:browser -- --suite=tableCaret,graphicPopup
npm run test:browser -- --workers=2 --no-reuse
```

- 默认并发上限为 2，可指定 1～16；定向执行使用原脚本的文件名，不含 `.mjs`。
- 每轮创建 `out/test/browser-runs/run-*/`。`report.json` 在脚本开始、结束时更新；完成后另写 `report.md`。逐脚本 `.log` 保存标准输出、标准错误、退出码与超时标记；`.phases.jsonl` 保存构建和浏览器启动阶段计时。
- `artifacts/` 保存本轮构建产物与截图；不同轮次隔离，原有单脚本 `node test/browser/<name>.mjs` 仍可使用。
- 某个脚本失败后继续收集其他脚本结果，任一失败整体退出码为 1。单脚本超时为 120 秒；超时和主动取消都清理已启动的进程树。取消返回 130，尚未启动的脚本记录为 `skipped`。
- CI 在成功或失败后均上传 JSON、Markdown、阶段计时与完整日志；不上传构建产物。浏览器测试是否作为 GitHub 必需检查不属于本次变更。

## 复用与隔离

运行器通过 IPC（父子进程消息）统一调度普通 esbuild 构建。配置按字段排序后作为键，同一构建在本轮最多执行一次；共享路径的配置不一致会报错，不允许覆盖正在使用的产物。每次运行创建新缓存和新产物目录，不跨运行复用，修改源码后的下一轮会重新构建。

复用覆盖设置页、快速操作/图形夹具、大纲拖拽、语言数据岛及 Mermaid 产物。含插件函数的表格 fixture 无法直接通过 IPC 传输，保留在子进程内构建；它有独立资产目录，也纳入计时。

本轮 24 次构建请求中，10 次命中复用、14 次实际构建。浏览器启动仍为独立实例，不共享测试状态。禁用复用时，各脚本使用独立产物目录，避免重复写入互相影响。

## 测量方法与结果

2026-09-27，在 Windows x64 独立工作树中，以提交 `1b8742f0cc2485803992166da3c6dfa0ad155a12` 为基线，使用相同锁定依赖与 Playwright Chromium。首次 `npm ci` 不计入测试耗时，各组逐次执行，完整输出和退出码均落盘。原始日志保存在该工作树的 `out/test/browser-benchmark/`，结构化数据见 [browser-test-runner.json](data/browser-test-runner.json)。

| 配置 | 运行器套件总耗时 | 结果 |
| --- | ---: | --- |
| 串行，开启复用 | 63.10 秒 | 16/16 通过 |
| 双并发，开启复用，首轮 | 33.23 秒 | 16/16 通过 |
| 四并发，开启复用 | 33.64 秒 | 16/16 通过 |
| 双并发，禁用复用 | 33.64 秒 | 16/16 通过 |
| 双并发，最终配置复跑 | 32.74 秒 | 16/16 通过 |
| 双并发，同口径外层计时轮次 | 32.26 秒 | 16/16 通过 |

表中运行器耗时包含脚本启动、构建、浏览器启动、测试交互与清理，不含外层 npm 启动。原始入口采用外层 Stopwatch 测得 62.70 秒；同口径的最终入口为 32.52 秒，缩短 48.14%。这轮内部计时为 32.26 秒，不能直接把内部计时与原命令总耗时混用。

串行报告中实际构建约 1.00 秒，18 次浏览器启动累计约 1.65 秒。最长脚本 `tableCaret` 包含表格、公式、Mermaid 和代码卡片回归，在并行组中约 33 秒；双并发已能将其余脚本基本放进这段时间，增加到四并发没有明显收益。

这是单台机器、少量轮次的观察，不代表 CI/Linux 或长期偶发失败率。后续若继续提速，优先测量 `tableCaret` 内部各场景，再评估是否拆成独立套件；不应直接减少断言或压缩去抖等待。

## 验证

新增运行器契约覆盖并发上限、失败汇总、运行中报告、完整日志、IPC 构建复用、超时与取消。构建契约覆盖并发去重、配置冲突、跨轮源码变化、关闭复用及失败传播；这些测试已接入 `npm run test:unit`。

本轮本地验证结果：

- `npm run compile` 通过，包含构建与 TypeScript 类型检查。
- `npm run test:unit`：107 个 Vitest 文件、2056 条用例通过；Node 测试启动器另有 42 条通过，其中 6 条为本轮新增契约。
- 原始基线与最终双并发的 131 条测试结果日志逐条对照一致，无缺项。
- 文件树严格检查与 Git diff 空白检查通过；规范轴和需求轴只读审查均无阻止交付的问题。

本轮未推送，未触发修改后的 Linux CI；未改产品实现，也未重跑真实 VSCode 宿主集成测试。取消契约使用 Node 测试进程，未单独注入真实 Chromium 多级进程树故障；正常浏览器退出路径已随完整回归执行。
