# 悬停预览与嵌入一期性能实测（工单 #225）

状态：2026-09-30 实测。**本文为工程门槛实测数据，非官方承诺**；对应规格见 [悬停预览与文档嵌入](../specs/hover-preview-embed.md) 的验证策略节（「报告须证明回收有效与编辑不发生明显阻塞」），架构约束见 [ADR-0009](../adr/0009-referenced-document-views.md)。不设虚构阈值：本文只陈述实测数字与结构性证据（有界缓存、挂载回收、增量重建），不宣称满足任何外部性能标准。

## 被测对象

一期引用视图的两条性能敏感路径（#223 遗留项与 #225 票面要求）：

- **长文档多嵌入的装饰重建成本**：父文档 Live 中 200 枚独占行 `![[…]]` 嵌入的嵌入表（`liveEmbedSpansField`）与装饰集（`liveEmbedDecorations`）——表按变更区间增量重建、装饰集每次事务全量重建但经装饰实例缓存（LRU 64）保 `RangeSet.eq` 命中。
- **全量编辑阻塞**：多嵌入在场时的逐字符编辑延迟（含嵌入表增量、装饰重建与视口内卡片 DOM 同步），以及读取/缓存/订阅链路（#224 已有定向数据 [hover-refresh.json](data/hover-refresh.json)，本文补全链路真宿主侧）。

## 测量方法

两层口径，原始数据分别落 [data/hover-embed-perf.json](data/hover-embed-perf.json)（状态层）与 [data/hover-embed-perf-host.json](data/hover-embed-perf-host.json)（真宿主）：

- **状态层**（vitest + jsdom，真实 CM6 状态机直驱——`EditorState` + `liveEmbed` 扩展全装配，含 `liveDecorationsField`/`mermaidFencesField` 依赖场；无 EditorView 布局与绘制，装饰重建成本的上界口径）：10k 行文档每 50 行一枚嵌入（200 枚），量初始构建、单字插入+删除（120 轮）、光标进出嵌入区间的选区翻转（400 次事务）、装饰实例缓存复用与上限。纯文同体量文档作增量编辑基线对照，嵌入开销按差值归属。测量脚本为临时文件（跑完已删），断言口径随数据记录在 JSON 内。
- **真宿主**（沿 `test/perf/runPerf.mjs` 模式：临时 fixture 工作区 + 1.86.2 便携宿主 `--disable-extensions` + `_test.*` 钩子）：1 万段落（约 2 万行）+ 200 嵌入（20 个真实目标文档）对同体量纯文基线，量打开耗时、`liveEmbedReveal` 探针（嵌入表覆盖数）、`perfProbe` 50 轮输入延迟、Reading 按需挂载（`requestViewState` 的 readingTotalBlocks/MountedBlocks）、订阅登记（`_test.hoverWatchStats`）与面板关闭后回落、读取缓存（`_test.hoverReadCacheStats`）。

## 数据（2026-09-30）

### 状态层：装饰重建与增量编辑（jsdom 上界口径）

| 指标 | 数值 | 对照 |
| --- | --- | --- |
| 初始构建 10k 行纯文 | 73 ms | — |
| 初始构建 10k 行 + 200 嵌入 | 71 ms | 与纯文同量级（表扫描+装饰首建不构成显著差） |
| 初始构建 100k 行 + 2000 嵌入 | 515 ms | 一次装载成本，10 倍体量约 7 倍耗时（无超线性拐点） |
| 增量编辑基线（纯文 10k，单字插入+删除 ×120） | avg 28.7 ms / p95 34.1 ms | liveDecorations 等依赖场既有成本 |
| 增量编辑（同体量 + 200 嵌入，普通段） | avg 29.6 ms / p95 37.6 ms | **较基线 +0.9 ms**——嵌入表增量窗口 + 装饰全量重建的净开销 |
| 增量编辑（嵌入源码内、显形态） | avg 36.5 ms / p95 39.1 ms | 较同文档普通段 +6.9 ms（该嵌入 span 重建 + 双装饰切换） |
| 选区翻转（光标进出嵌入区间 ×400 事务） | avg 0.151 ms / p95 0.264 ms | 纯选区事务的装饰重建远低于一帧（16.7 ms） |
| 装饰实例缓存（≤上限时隐→显→隐） | 同键同实例（`sameInstance: true`） | `RangeSet.eq` 可命中的结构性前提 |
| 缓存上限 | 65 枚顺序翻转后状态正确 | LRU 淘汰超限旧键（上限 64 由单测钉住） |

jsdom 无真实布局与 JIT 热身，绝对值偏高；**差值与选区翻转两项是稳定结论**：多嵌入在场的编辑增量开销为毫秒级零头，光标进出（显隐切换）亚毫秒。

### 真宿主：全链路编辑阻塞与挂载有界性

| 指标 | 1 万段落 + 200 嵌入 | 纯文基线（同体量） |
| --- | --- | --- |
| 打开至会话就绪 | 358 ms | 188 ms |
| `liveEmbedReveal` 嵌入表覆盖 | 200 枚（初始全隐） | — |
| 内容 DOM 数（装载稳定后） | 80 | 89 |
| 输入延迟（50 轮，含 2×rAF 稳定等待） | avg 16.8 ms / max 33.3 ms | avg 12.2 ms / max 14.8 ms |

- **编辑不阻塞**：嵌入档较基线 avg +4.6 ms、max +18.5 ms（输入延迟口径含两帧 rAF 稳定等待 ~33 ms 地板，嵌入增量在其中占比小；max 33 ms ≈ 最坏两帧，不构成可感知卡顿）。`longTasks` 在本宿主返回 null（PerformanceObserver longtask 条目不可用），该项无数据、不以无长任务作结论。
- **DOM 有界**：200 嵌入在场时内容 DOM 与基线同量级（80 vs 89）——卡片 widget 只为视口内嵌入建 DOM；嵌入表（状态）覆盖全部 200 枚但不含内容 DOM。
- **Reading 按需挂载**：同文档阅读模式总块 10000、挂载 50、内容 DOM 108——挂载量随视口不随文档体量。
- **订阅与缓存回收**：视口内嵌入装载后订阅 1 目标 1 实例、读取缓存 1 条（178 字节，上限 24 条 / 2 MiB）；**面板关闭后订阅回落 0/0**——释放无残留（与 #224 单测「配对 unwatch」互证）。读取合并与双上限淘汰的定向数据见 [hover-refresh.json](data/hover-refresh.json)（100 请求 1 次读取 + 50 命中、2 MiB 边界、80 实例 dispose 归零）。
- 观测口径说明：`perfProbe` 的滚动为 25%/75% 跳转往返，仅落点附近嵌入进入视口——真宿主未制造「连续滚过数十枚嵌入」的中间态；订阅目标数上限（128）与嵌入 entry 上限（64）的淘汰行为由 #224 单测钉住（`hoverRefresh.test.ts`、`embedCard.test.ts`），本实测证其在真宿主不失效（低量正确 + 关闭归零）。

## 结论

- **回收有效**：三层证据闭环——装饰实例 LRU（状态层同实例复用 + 超限淘汰）、挂载随视口（Reading 50/10000；Live DOM 与基线同量级）、订阅关闭归零（真宿主 0/0）。
- **编辑无明显阻塞**：状态层净开销 +0.9 ms/键、显形态编辑 +7 ms/键（jsdom 上界）；真宿主全链路 avg +4.6 ms、max +18.5 ms（含既有基线与 rAF 等待地板）。
- **边界声明**：100k 行 + 2000 嵌入的初始构建 515 ms 为一次装载成本（打开档 358 ms 真宿主实测为 200 嵌入规模）；悬停浮层重复开关与快速切目标的读取/缓存成本已在 [hover-refresh.json](data/hover-refresh.json) 覆盖，本文不重复。
