# 原生 HTML 批次性能收口测量（#574 / T09）

## 测量对象与目的

T02–T08 落地原生 HTML 渲染（块级/行内 widget、净化、文档内 `<style>` 装载、资源归属解析、媒体/iframe/SVG/MathML）后的针对性性能档位，验证：

1. **视口有界性保持**——HTML widget 与文档样式产物不破坏「全文模型与视口 DOM 分离」（ADR-0005）；不以常驻全文 DOM 兑现 CSS。
2. **输入延迟不劣化**——HTML 密集文档与样式源文编辑的逐字符输入延迟与纯文本基线同量级。
3. **离屏资源回收**——图片密集 HTML 文档的块挂载/卸载窗口有界，DOM 内图片槽位保持视口规模。

## 基线与候选

基线取既有报告 `docs/perf/data/perf-report.json`（2026-10-03，同 1.86.2 宿主）：

| 指标 | 纯文本基线（1k/10k/100k） | HTML 候选（htmlMany/htmlLong） | 结论 |
|---|---|---|---|
| Live 视口 DOM（.cm-content 全元素） | 59 → 59（10 万行不变） | 228 → 228 / 228 → 228（3.3 倍体量不变） | **有界保持**：HTML widget 使单屏 DOM 高于纯文本（每屏 ~7 个表格/块级 widget 的原生 DOM），但与文档体量解耦 |
| Reading 挂载块 | 50/50，max 80 | 47/46，max 76 / 47/46，max 76 | **窗口保持**：挂载窗口与纯文本基线同规模，不随总块数（1202→4002）增长 |
| 输入延迟 avg | 33.3–37.0 ms | 33.8 ms / 42.2 ms | htmlMany 同量级；htmlLong 均值高于基线**均值范围**（33.3–37.0ms，本轮 max 50.0ms 在基线 max 50ms 以内）——**未闭环的性能回归信号**，见下方「测量修订记录」 |
| 长任务（longtask） | — | 全档实测 **0 条**（观测窗口内；探针构造签名修复后的真实读数） | 键入路径无 ≥50ms 长任务样本 |

单项结论：

- **单大表格（htmlGiantTable）**：整表是**一个块级 widget/一个 Reading 块**（总块数 3），Live DOM 1675 恒定、Reading 挂载 2 恒定——DOM 恒定不随滚动增长；输入延迟 avg 57.6 ms（max 66.7）高于纯文本基线（相邻行编辑带装饰更新），量级可接受。**边界如实记录**：Reading 侧未对巨型 HTML 块做块内分片（与 #7 时代「整块挂载」同语义，代码围栏的 FENCE_CHUNK_LINES 分片不覆盖 HTML 块）——400 行全表在进入视口时一次性构建；这是单块边界的既定语义而非本批回归，更大的单表需要块内分片时应另立票据。
- **样式更新（htmlStyle）**：探针键入落在 400 规则 `<style>` 块源文内，逐字符 avg **27.5 ms**（max 33.4）——「样式源文编辑 → 全文收集/改写/产物更新 → 绘制」的完整往返低于纯文本基线均值（规则改写为词法级，未随规则数劣化）。
- **离屏资源回收（htmlImageDense）**：602 块文档，Reading 挂载窗口 10→11（max 79）；DOM 内图片槽位（`data-vsidian-img-state` 计数）装载后 **4 个**、滚动回收后仍 **4 个**（loading 0 / error 0）——槽位保持视口规模而非文档规模（300 块的图片 DOM 不同时常驻），块卸载连带槽位回收。
- **模式切换**：→reading 124–467 ms（htmlLong 最长，含 4002 块的块模型构建）、→live 123–126 ms，与既有档位同量级。

## 测量修订记录（2026-10-17 三轮复审）

- **长任务读数修订**：首轮报告曾写「全档 0 条（Chromium 观测窗口内）」，但归档 JSON 五档 `longTasks` 实为 `null`——探针把 `'longtask'` 误传作 `PerformanceObserver` 构造首参（标准签名首参为回调），构造抛 TypeError 被外层 catch 吞掉，观测从未生效。该表述属于**把不可用记成零**的证据缺陷（评审指出）。本轮修复构造签名（回调首参 + `observe({entryTypes:['longtask']})`，契约测试钉住）并重测：五档观测窗口内真实 **0 条**。本行现在是测量值而非缺省值。
- **htmlLong 输入延迟（未闭环信号）**：首轮归档 39.3 ms；二轮工作树交替实验观察到 ~49 ms 均值——该均值差曾被表述为「+1 帧（帧数量化）」，但均值变化本身推不出每键必然多一帧，该表述作废（四轮复审指出）；本轮（含行内容器整段扫描与上下文排除的三轮修复）为 **42.2 ms**（max 50.0）。该档差**不宣布闭环也不宣布解决**：现有探针口径（dispatch + 双 rAF、每档 10 样本、非物理键击到绘制的全程）不足以区分脚本/样式/paint/GC 的贡献，也不足以排除环境漂移（首轮与本轮为不同进程、不同预热）。无既定硬阈值，不单凭该差值阻塞、不新设 10ms 拒绝线；闭环需按「同宿主、同输入位置/视口/预热，旧新各 ≥3 交替轮 ×50 键、保留同步 dispatch/首末 rAF 样本与 p50/p95/慢帧比例、短 trace 归因」的方法学重测。
- 其余指标（DOM 有界性、Reading 窗口、图片槽位回收、模式切换量级）与首轮一致，未受三轮修复影响。

## 结论

HTML 批次未破坏视口有界性与虚拟化边界：Live DOM 与 Reading 挂载窗口均与文档体量解耦，输入延迟与纯文本基线同量级（htmlLong 的档差按「未闭环信号」如实跟踪，不据此宣布性能项验收完毕），样式更新与资源回收成本在位，键入路径无长任务样本。单大表格的块内分片是已记录的边界项，不阻塞收口。**本报告不设新性能阈值**——验收口径沿用 mvp.md「MVP 性能契约」的既有模型（体量增长 10 倍 DOM ≤ 2 倍；本批 3.3 倍体量 DOM 零增长）。
