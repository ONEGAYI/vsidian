# #244 引用卡片递归驻留与滚动测量

测量于 2026-10-01，生产 `WebviewSyncController` 置于 headless Chromium，900×640 视口，`test/browser/recursiveEmbed.mjs` 从真实 Reading 卡片与内部滚动壳采样。原始报告：[ref-expansion-244.json](data/ref-expansion-244.json)，浏览器运行报告 `out/test/browser-runs/run-iJOHHc/`。数据是**逻辑预算计费与块生命周期**，不等同 V8 堆快照，也不把相同字符串值推定为共享物理存储。

## 工程上界与计量

主文档 A 为第 0 层；默认可到 B/C/D 三层，设置允许 1–6。每树最多 24、每面板最多 64 个实际展开 occurrence；宿主端每面板最多 8 个引用读取。宿主 LF 正文按 UTF-16 code unit×2 加 128 字节记录，每树／面板分别限 2／8 MiB。webview 全文解析后按正文与所有生成块 HTML 的 UTF-16 长度×2、每块 128 字节元数据计费，同样限 2／8 MiB。相同目标的不同 occurrence 独立收费；同 occurrence 的两次挂载按挂载数保守重复收费。此口径可能高于实际共享块对象图，是为避免小目标命中缓存和大目标跳过缓存时低估活跃借用者。虚拟视图每挂载的索引、高度与位置数组仍是独立的；其块数由实例限额及单块边界约束，未作为精确堆字节声明。

宿主读取缓存另限 24 项／2 MiB；webview 解析缓存另限四项／2 MiB、单项 512 KiB，大目标跳过缓存。缓存根与活跃借用者分开观察：缓存淘汰不能当成已挂载视图释放；离屏根 `EmbedEntry.loaded` 仍持全文并继续占预算，离屏子树退订且释放。provider 内跨面板 watch 注册表是 128 个**规范目标槽**，同目标多实例共用一槽；满额拒绝新目标，旧目标持续可刷新。

## Chromium 实测

样本 A→B→C→D→E：B、C 各 401 个 UTF-16 字符并含约 22 段长文，D 为 11 字符短文，E 为第四层占位。B/C 具有各自 480px 滚动区；真实滚轮先滚 C，到底后接续 B；D 保持自然高度。逐层引用边条和正文命中经绘制层断言；引用链没有 `edit.request`。

| 阶段 | 在预算内实例 | 活跃计费字节 | 已挂载块 | 解析缓存字节 |
| --- | ---: | ---: | ---: | ---: |
| B/C/D 在场，E 占位 | 3 | 15,616 | 50 | 10,554 |
| 深度热改为 1，撤 C/D | 1 | 10,124 | 24 | 10,554 |
| 关闭面板 | 0 | 0 | 0 | 10,554 |

关闭后解析缓存仍持 10,554 逻辑字节，这是其独立上限内的共享计算缓存；不把它误写成面板活跃借用。样本累计 3 次解析、1 次缓存命中，全部 50 个块挂载在关闭后逐个释放。另以 614,400 字符单段目标试探边界：旧单项缓存跳过两次（隐藏 Live 与 Reading 双挂载各一次），生成 HTML 后超过树预算，在创建目标正文 DOM 前显示预算占位；活跃实例／字节／watch 均为 0。该单块样本验证的是超限终态，不证明低于限额的任意巨大单块都只创建少量节点；#243 已记录单块列表边界。

这些工程值由三层常见小样本、600 Ki 字符边界和现有缓存上限共同校准，目标是使单棵递归树不能仅靠文本与生成 HTML 占满面板。测量未覆盖进程实际堆峰值、远程文件系统延迟、所有 Markdown 生成比率或物理鼠标滚轮；这些分别需要堆快照、Remote SSH 与用户人工验收。三层真实宿主的 B/C 跨目录解析、未保存刷新和关闭订阅回落见 [人工验证记录](../specs/manual-verification.md)。
