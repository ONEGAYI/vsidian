# #373 多列表格高度优化实测：候选/评估预算、纯计算与浏览器三路径

测量于 2026-10-05，生产 `WebviewSyncController` 置于 headless Chromium（Playwright 默认视口 1280×720，基座 `test/browser/tableHeightPerfFixture.ts`——生产控制器装配 + `optimizeTableHeight` 页内直调探针）。原始数据：[table-height-opt-perf.json](data/table-height-opt-perf.json)。复现入口：`node test/browser/tableHeightPerf.mjs`（独立脚本，不在 `test:browser` 套件清单内）。

## 口径

- **纯计算**：页内 `performance.now()` 直调 `optimizeTableHeight`。冷 = 每轮新建折行指标缓存的首跑；热 = 复用全局缓存的第 2..20 轮取中位/均值。行/列内容与冻结样例同构（六字短标签列 + 交替长列 + 周期性全短行）。
- **显示重排**：真实控制器进表 → 净编辑一字 → 光标离开 → 等待搜索计数 +1 → 两帧 rAF 后读几何，3 次取中位。含一次 CDP evaluate 往返与 waitForFunction 轮询，是**上界读数**；几何只覆盖视口内已挂载行（CM6 视口裁剪），且挂载扫描可能已把 before 侧优化——整表高度下降的几何证据在 `tableCaret`/`blockquoteTablePaint` 套件的断言（31 行三列与 10 行引用三列冻结样例实测下降）。
- **原生输入**：表内格点击聚焦后连续键入 20 个英文字符，页面内记录 keydown→input 事件间隔取中位（含浏览器派发与 CM6 处理，不含 Playwright 出站开销）。

## 实测摘要

| 场景（列×行） | 出口 | 候选 | 格评估 | 纯计算冷/热中位 | 离开→落定中位 | 键入 keydown→input 中位 |
| --- | --- | --- | --- | --- | --- | --- |
| 3×101 | optimized | 10 | 3030 | 0.8 / 0.6 ms | 41 ms | 0.4 ms |
| 3×1001 | **degraded** | 0 | 0 | 0.1 / 0.0 ms | 37 ms（无发布） | 0.5 ms |
| 6×101 | optimized | 10 | 6060 | 1.5 / 0.9 ms | 33 ms | 0.5 ms |
| 6×1001 | **degraded** | 0 | 0 | 0.0 / 0.0 ms | 39 ms（无发布） | 0.6 ms |
| 5×125（恰好预算） | optimized | 10 | 6250 | 1.6 / 1.0 ms | 42 ms | 0.6 ms |

DOM 有界（CM6 视口裁剪）：已挂载格数在 3 列 ×100/1000 行同为 69、6 列同为 138——不随全表行数线性增长；千行表网格行常驻 23（视口量级）。

## 解读

- **预算三类的确定结果**：恰好预算（5 列 ×125 行 ×32 候选 = 20000 评估上限）照常搜索且 1.6 ms 内完成；超预算千行表在预检阶段确定降级（0 候选 0 评估，不跑搜索），离开路径与输入路径耗时与百行表同量级——大表「有界路径」成立。
- **候选数收敛在 10**：种子（基线 + 等分 + 逐列内容锚点 = n+2）+ 第一层阈值转移（本样例各列最高格只有 1–2 个可行阈值目标）已找到改进，第二层无严格改进即终止——预算 32 是上界不是常态开销。
- **缓存**：首次运行后折行指标缓存条目 = 行数×列数级别（每格一条，6250 评估对应约 625 条 profile），上限 4096 条命中清空重建（T02 既有策略，不变）。
- **输入路径不感知表规模**：keydown→input 中位 0.4–0.6 ms、最大约 1.3 ms，百行与千行同量级——完整搜索只在离开/挂载扫描时进入 0ms 冲量，不进键入路径（调度层契约由单测钉住）。

## 预算常量与依据

| 常量 | 值 | 依据 |
| --- | --- | --- |
| `TABLE_OPT_MAX_CANDIDATES_MULTI` | 32 | 种子 n+2 + 每层 ≤3n（n≥6 时 2n）阈值候选；3 列约 3 层、6 列约 2 层局部调整；6 列 ×100 行 ×32 = 19200 ≤ 评估上限，百行六列表可搜索 |
| `TABLE_OPT_MAX_CELL_EVALS`（共用 T02） | 20000 | 延续 #372 集中定义；多列按同式预检（行×列×候选上限），千行表确定性降级属共同规格的大表有界路径 |
| `TABLE_OPT_MAX_COLUMNS` | 12 | 单候选评估成本随列数线性增长而收益递减；超限走轻量计划（签名登记防重试） |

理论次数不换算为毫秒承诺：上表毫秒数为本次环境（Windows / headless Chromium，单一会话）读数，作相对量级证据。

## 未覆盖与边界

- 未测进程内存峰值与 Remote 宿主延迟；真实中文 IME、物理滚轮手感与观感属人工待验（manual-verification 批次节区分）。
- 离开→落定中位 33–43 ms 是含 CDP 往返的上界：其中纯计算 ≤1.7 ms，其余为发布事务重绘（31 行三列表的发布在套件断言中完成整表重发射）与测量通道开销，不构成用户可感知延迟的承诺值。
- 千行表降级后列宽保持 T01 可读轻量计划；本文不含降级表的手动观感核对（自动化断言「模板逐字节等于轻量计划」在单测钉住）。
