# 双链联想容量与费用基准（#382 T07）

> 测量日期：2026-10-06。本文是工单 #382（T07 容量、跨环境回归与交付收口）
> 的解读文档：全文件清单与候选查询管线在 1千／1万／10万文件混合语料上的
> 实测结果、容量边界结论与待验清单。原始数据单一事实源为
> [wikilink-catalog-bench.json](data/wikilink-catalog-bench.json)（含全部轮次、
> 轮数与运行方法自述）；本文数字均引自该文件，复跑入口见「复现」节。

## 测量对象与结论

**测量对象**：双链联想的候选供给管线——全文件清单（`src/host/vaultIndexService.ts`
的 `scanCatalog`/`loadCatalogFile`/`catalogFileEvent`，#377 T02）与候选查询
（`queryWikilinkFileCandidates` → `src/shared/wikilinkQuery.ts` 的评分排序）。
基准脚本经 esbuild 即时编译生产服务本体直驱（单一事实源，不复制逻辑），
扫描/存储端口为真实 `node:fs`（写盘为临时写 + rename 原子提交，与生产壳同语义）。

**结论先行**：

1. **1千与1万文件工作区费用良好**：查询中位 ≤26ms、首建 ≤7s、冷恢复 ≤50ms、
   事件可见 ~870ms（800ms 去抖主导），事件循环停顿 ≤43ms。
2. **10万文件是当前实现的感知边界**：单次同步查询 42–516ms，逐字输入单步
   中位 148ms（六步序列 81→248ms 递增），事件循环停顿与查询同量级（评分
   为同步 CPU 计算，执行期间不让出）。60fps 帧预算 16ms 在 10 万档被超出
   约 5–15 倍——**逐键可感延迟**，规格预留的「分批让出/缓存/限流调整」
   （见[主规格](../specs/wikilink-completion.md)技术设计节）在该规模上
   有必要，属后续票的调优空间；本票如实报数，不宣称已调优。
3. **恢复与事件费用与库规模近似脱钩**：冷启动恢复走 catalog.json 缓存
   （三档判据均为「未重写缓存」），10 万档 446ms；单文件事件到清单可见
   三档均 ~870ms（去抖占 800ms）。
4. **长任务有界可取消成立**：覆盖重算中途取消，被取消轮即时收敛
   （三档 69ms/257ms/2.6s，含探针等待），重入轮完整重建、终态清单完整
   （文件数与 complete 标志均正确）。
5. **缓存不含附件全文**：语料附件正文埋唯一哨兵串，三档 catalog.json
   扫描均未检出；清单 10 万条目仅 5.0 MB（每条约 51 字节）。

补充说明：

- **查询轮数**：每查询 25 轮裸计墙钟取中位 + 3 轮饿死探针采样；首建/冷恢复/
  事件/取消各 1/3/1/1 轮（事件与取消为行为测量，取单次观测）。
- **取消时序**：探针等待（首建中途回调点）按档位 60ms/200ms/2s 设定，
  「被取消轮收敛」含探针等待本身；重入轮为完整全量重扫（覆盖重算语义
  如此——排除变更触发全根重扫，非增量）。
- **端口计数为全程累计**（首建 + 查询 + 事件 + 取消重算），10 万档全程
  stat 约 110 万次、md 正文读取 82.3 MB（三轮 fullScan 各读一遍）。
- **md 索引与清单并行**：首建墙钟含两者（`Promise.all`），单独拆分未测——
  md 索引（快照分片构建）占大头（引用索引侧容量结论见
  [2026-09 存储基准](2026-09-vault-index-storage.md)，此处不重复）。

## 空查询域与仅登记类型（区分口径）

语料 55% Markdown + 20% 常用资源（png/pdf/mp3/mp4/txt）+ 25% 仅登记类型
（pyc/bin/无扩展名）。实测空查询三档 total 分别为 750/7 500/75 000——
恰为 md + 常用资源之和（仅登记类型不进空查询）；有查询时仅登记类型可被
名称命中（「pyc 等其他类型可被有查询命中」的规模验证）。常用资源在枚举时
取真实 stat（mtime/size），仅登记类型零 IO（元数据 0 沉底）。

## 方法与诚实边界

- **纯 Node 直跑**：非 VSCode 扩展宿主进程内；宿主内绝对数字会不同
  （进程内并发、GC、宿主 Node 版本），方向性结论（同步评分的停顿形态、
  线性增长趋势、恢复走缓存）预期保持。
- **冷启动恢复**：新起子进程（JS 堆/编译缓存冷）；OS 文件缓存无法用户态
  清空，为热缓存近似。initialize 墙钟为激活感知——启动核验（#198 契约：
  快照恢复后清单比对，含全文件列举与 stat）后台执行不阻塞，其费用在
  端口计数中体现（`listAllFiles` 调用属核验，非重建；重建信号为缓存
  重写，三档均为 0）。
- **文件事件**：经 watchRoot 端口回调直驱（服务内去抖→三态判定→清单
  更新→提交去抖全链路真实），OS watcher 传播延迟不在测量内；可见性以
  maintenanceInfo 轮询判定（100ms 间隔，零查询污染）。
- **事件循环双路证据**：monitorEventLoopDelay 直方图 + 20ms 饿死探针；
  同步查询阻塞下直方图样本缺失，停顿数字以饿死探针为准。
- **查询词**：语料文件名中英混合（构造查询有真实命中）；长查询为 24
  字符连续串（命中 0——评分全库跑完才淘汰，是费用上界形态）。
- **Remote SSH 未测**：见主规格「失败、容量与交付口径」与本文末待验清单。

## 待验与边界调整建议

- **10 万档逐键延迟**：同步评分单步 ~148ms 中位。规格允许的调整空间：
  评分分批让出（切片 + 保留高亮代次）、查询会话内短缓存、输入去抖。触发
  条件与优先级由后续票按本数据决定；本票不动实现。
- **Remote SSH**：候选来源（`listAllFiles`/stat 经远端文件系统）与断连
  恢复（inaccessible 三态路径在远端的真实表现）未实测，见
  [人工验证清单](../specs/manual-verification.md)双链批次节的可复现步骤。
- **扩展宿主内数字**：本基准的宿主内对账归集成测试既有用例（清单就绪、
  部分就绪、事件更新语义已覆盖；绝对耗时未在宿主内单独测量）。
