## 实测发现（影响生产协议）

**F1（最重要）——关闭脏文本标签会静默丢弃未保存修改**。1.82.3 实测：`vscode.window.tabGroups.close` 关闭一个有未保存修改的文本标签（临时激活路由的收口步骤），宿主直接回滚该文档到盘面（版本 +1、文本回落），无提示。既有单步 `historyViaTempActivation` 与本探针的批量路由同构暴露在此风险下——只要目标文档 B 在历史操作后仍处于 dirty 态（撤回未到保存点、或重做恢复了修饰），收口即丢修改。探针的处置：**目标模型脏态时不关闭临时标签**（激活态已恢复来源 A，标签留给用户）。生产协议要求 T03 把该边界固化：临时激活路由的收口在目标 dirty 时必须跳过关闭（或采用不丢弃的收口方式），否则引用 B 的组撤回/重做会静默丢用户可见内容。

**F2——计划必须在执行时点计算，报告必须按请求隔离**。并发连按下，「请求时点预判 + 共享执行报告」会产生错误步数（后一个请求读到了前序请求的执行结果）。探针最终形态：历史请求经**每目标串行链**发出，计划在会话队列执行时点计算，报告由「应用指针位移 + lost」派生。这从实现上验证了设计文档「按目标文档串行执行历史请求，识别本次连续步骤；每次推进都核对预期回流，不能仅循环执行 N 次全局命令」的必要性。

**F3——外部回流补完需要执行前前置检查**。外部单步撤销落在组中部时，协调器补完剩余步骤前必须核对「下一个将被原生命令作用的条目 === 补完目标条目」；外部写入若已插入（对象错位），明确拒绝并 lost，绝不执行（否则会撤错条目）。前置检查方向按补完类型取位：undo 补完看已应用栈顶，redo 补完看可重做区底。

**F4——自驱步骤的回流吸收需要版本对位**。协调器自己执行的每个原生步骤，其回流事件（reason Undo/Redo）必须被识别为「预期内」而不当作外部对账（否则指针双移动）。可靠做法：在单步命令发出**前**登记「预期版本 + 预期文本」，回流按版本唯一性吸收。

**F5——拒绝语义必须区分「历史为空」与「映射不可验证」**。重启/重载后协调器无快照时，宿主 undo 栈通常仍在；分组协调拒绝的原因是映射不可验证（`mapping-lost`），不是空历史。协议与 UI 都不得把两者混同——实测：重建（保守 lost）后拒绝分组撤销，同一文档原生单步撤销仍成功。

**F6（探针边界）——CDP 合成 Ctrl+Z 与真实 IME 不同构**。合成按键会取消进行中的 IME 组合（真实 OS IME 期间该键以 keyCode 229 到达，不映射任何绑定）。组合期安全由 webview 既有 #148 竞态守卫承担；本验证以「组合期 229 键无动作 + 定稿落盘后撤销事件紧随其后（版本 +1）」等价覆盖。

## 生产协议建议

放行路线（V01 已证可行，T03 可按此接入）：

1. 撤销继续归宿主文本栈，不建并行 CM6 history；「一次原子操作」= 一笔 `WorkspaceEdit`（多范围一笔一撤）。
2. 同组未提交的原子 + 非原子修饰合成一笔提交（一条宿主历史项）；已提交后的追加非原子各自成项、同组连续撤回。
3. 非原子归属规则（保守）：目标当前已应用栈顶为附加组件条目才可归属，否则提交拒绝 `HistoryBoundaryUnavailable`——覆盖空日志、仅外来写入、组顶被外来写入打断三种形态。
4. 历史请求按目标串行，执行时点计算计划；每步执行后核对「版本恰 +1 且文本为记录边界」，失配即中止剩余步骤并 lost。
5. 外部 Undo/Redo 回流对账 + 补完（含 F3 前置检查、F4 版本吸收）。
6. 引用 B 的整组历史走「一次临时激活执行全组、结束后恢复来源 A」，叠加 F1 的脏态收口禁丢边界；父子目标隔离天然成立（激活路由只作用于目标文档）。
7. 丢失映射（重启无快照/失配/过期快照）→ 一切分组协调明确拒绝，不降级为另一种撤销语义、不撤销其他文档。

T03（#352）的接入点要求（放行边界，非可选）：

- 来源与原子组元数据进 `edit.request`/版本确认管线（探针用 ack 版本对位 + 固定文本状态，生产不能依赖文本全等——这是 T03 票面既有内容，本验证确认其必要且充分）。
- F1/F2/F3/F4/F5 五项发现固化为接入点行为。
- 串行链与队列：会话队列 + 协调器链的双层串行在验证中稳定，但 T03 应收敛为单一路由点，避免两处排序逻辑漂移。

## 未验项（下游实施须知）

- **组执行中途外部写入的确定性重放**：两步之间插入外部写没有稳定时序窗口（实现上有每步核对 + 补完前置检查两道保护，均经其它路径验证，但「步骤间精确竞态」未获得可重放脚本）。生产建议保留两道保护并按失配处理。
- **扩展宿主真重启**：`reloadWindow` 会终止测试进程，以 reset/rebuild 模拟（语义等价：协调器状态丢失、宿主栈保留）。持久化快照的存储与版本协商属 T03+。
- **安装态 VSIX 双包与 Remote SSH**：V02/#349 范围。
- **webview 端 Ctrl+Z 在悬浮/嵌入 B 内部 Live 的端到端组撤回**：集成侧已验证 B 会话 + refOrigin 的宿主路由（与 refEdit 端口同一机制），嵌入实例内部按键→宿主路由的端到端串联依赖 T03 公开 API 形态，留待 T03 验收。
- CRLF 文档的边界对账（探针 fixture 为 LF；T03 元数据管线不依赖文本对账后此边界自然消除）。

## 结论

**T03（#352 编辑来源与宿主历史接入点）可放行**，边界为上文「接入点要求」七条路线 + 五项发现；票面四条验收标准对应的矩阵 20/20 通过（集成 16 + CDP 4，纯逻辑契约 15 项另计），未验项如上明示，不因本票关闭而弱化。探针协调器是**验证工件而非生产实现**：其文本全等对账、虚拟面板提交通道在 T03 元数据管线落地后应被替换，而非直接转正。
