# 附加组件声明式粘贴转换规格（#530）

## 1. 状态与目标

2026-10-15 用户完成设计访谈并批准本批拆票。#530 为规格与进度父票；T01 基础规则与 T02 正则/条件/嵌套转换的完整链路均已实现，待用户整体验收。票号、依赖和组合验证记录见[批次索引](batch-2026-10-addon-api-extensions.md)。当前 API 仍为未发行候选。

目标是让组件还原特定来源的 HTML 语义，同时保留平台的剪贴板读取、富文本询问、内置转换与宿主分步撤销。例如 Codex 的 `data-prompt-link-*` span 可由组件规则产出 Markdown 链接，来源识别不进入内核。

## 2. 已定边界

- 规则在扩展宿主运行功能阶段登记，Vsidian 按组件身份与代次管理；编辑器页面接收有效规则快照，在 HTML 转换遍历中消费。
- 规则是可序列化数据，支持标签/属性匹配、正则、条件和嵌套转换；不开放命令式 DOM 遍历、脚本表达式或动态求值回调。
- 不改变内置字面正文转义，不增加通用 Markdown 源码识别。显式纯文本粘贴、代码上下文、表格与图片优先级沿用[富文本粘贴规格](rich-text-paste.md)。
- 普通规则拒绝或单次转换失败不触发全组件故障；组件本身在注册回调之外发生的可归因运行异常仍按 ADR-0012 处理。

## 3. 用户故事

1. **P-U01**：作为组件作者，我希望在宿主登记转换规则，以便全部已打开和新打开的文件使用同一组有效规则。
2. **P-U02**：作为粘贴用户，我希望来源特化 span 恢复为可点击链接，以便保留原本的链接含义。
3. **P-U03**：作为粘贴用户，我希望链接旁的粗体、代码与代码块继续按原格式转换，以便一处规则不破坏其他内容。
4. **P-U04**：作为粘贴用户，我希望不匹配、缺少必需属性或输出非法的规则回到内置转换，以便仍可粘贴正常内容。
5. **P-U05**：作为用户，我希望关闭组件后立即恢复内置转换，以便停用不会留下隐藏的转换规则。
6. **P-U06**：作为用户，我希望纯文本粘贴绕过这些规则，富文本转换继续支持分步撤销，以便控制文字与格式。
7. **P-U07**：作为组件作者，我希望用正则读取匹配信息并组合条件，以便适配来源的不同元素形态。
8. **P-U08**：作为组件作者，我希望对子元素继续执行规则或内置转换，以便保留嵌套内容的语义。
9. **P-U09**：作为用户，我希望多个组件同时命中时结果稳定，以便重启或页面装载顺序不改变粘贴结果。
10. **P-U10**：作为用户，我希望危险或无效链接仍受平台 URL 策略限制，以便来源 HTML 不能绕过现有链接限制。
11. **P-U11**：作为组件作者，我希望错误声明得到可辨认拒绝，以便修正规则而不让整个组件被暂停。

## 4. 注册与执行契约

### 4.1 注册声明

新增宿主侧粘贴规则注册面，位于按组件功能开关启停的生命周期内。每组登记包含组件内稳定规则 ID、可选整数优先级、匹配条件与产出表达式；来源组件与代次由平台注入，作者不能冒充其他组件。返回普通注册结果与释放句柄。

匹配条件与产出表达式的数据形状由共享类型模块定义，宿主校验和页面解释消费同一声明，不在两端各写一套规则语言。批内 ID 重复、非法正则、未知操作或超预算声明整批拒绝，不部分安装。

实施时新增能力进入稳定 API 候选目录；既有 API 仍为候选 1.0.0，不伪造发行日期。具体 TypeScript 声明在实现事实源导出，本文不复制完整函数签名。

### 4.2 匹配、条件与产出

| 层 | 语义 |
| --- | --- |
| 基础匹配 | 标签名、属性存在、属性值相等；缺失与空字符串区分 |
| 来源取值 | 元素文本、指定属性、子内容转换结果；必需取值缺失则本规则失败 |
| 正则 | 数据声明 pattern 与 flags，注册时编译校验；支持匹配和捕获组取值，不执行字符串代码 |
| 条件 | all / any / not 组合基础谓词或正则谓词；空组合与非法节点拒绝，不做隐式真值转换 |
| 产出 | Markdown 结构模板与具备类型的插槽：字面正文按内置规则转义，URL 槽经过现有 safeUrl 策略，子转换结果按已转换片段拼接，避免二次转义 |
| 嵌套 | 仅沿当前元素的子节点下降；可要求子规则转换或内置转换，不允许向父节点回跳、再次转换自身或按规则 ID 构造递归调用 |

组件给定的静态 Markdown 结构属于作者声明；平台不把任意 HTML 来源字符串隐式当作可信 Markdown，也不把此接口描述为对 VSCode 扩展代码的安全沙箱。继承标记、表格上下文和代码上下文继续由现有转换器处理，规则不能借嵌套重复应用同一层格式。

### 4.3 顺序与失败

有效规则按优先级降序、组件稳定 ID 升序、规则稳定 ID 升序排列，缺省优先级为 0。顺序不取决于异步页面脚本装载先后。对同一元素依次尝试，首条成功产出后停止；空产出只有显式声明丢弃才算成功。

不匹配、取值失败、URL 拒绝、产出失败和规则求值异常进入下一规则；全部未成功才回内置转换。内置 SCRIPT/STYLE 等忽略规则与既有不支持上下文仍先行生效，组件规则不能复活已忽略节点。整次 HTML 超出既有转换预算时沿用富文本粘贴失败处理，不把半成品插入文档。

转换成功须参与 `hasFormatting` 判定，但最终结果与 plain 相同时仍走既有一次撤销路径；不同结果保留现有纯文本阶段与格式阶段，不由组件另建历史。

### 4.4 预算与生命周期

沿用 `htmlToMarkdown` 的 2,000,000 字符及 100,000 节点预算。规则声明每组件至多 256 条，表达式嵌套深度至多 16；每次粘贴累计规则/表达式求值步数不超过 100,000。常量须集中定义并测试边界，不能在宿主与页面各自取值。

这些预算不等于同步 JavaScript RegExp 的可中断超时。T02 必须用长输入验证所选正则实现，不得用事后计时伪称已经中断单次匹配；引入依赖或约束正则支持面须在实现说明中给出依据，保留本规格要求的正则、条件和嵌套能力。

停用、故障、单组释放和代次结束均撤回相应规则，广播有效快照；已结束页面不接受迟到快照。一次粘贴使用开始时捕获的有效快照，转换中不拼接两个注册代次。

## 5. 实现入口与验证

复用入口：`src/webview/htmlToMarkdown.ts`、`clipboardPaste.ts`、`richPastePlan.ts`、`syncController.ts` 现有粘贴链；宿主接入沿 `src/host/addons/` 的身份、代次和运行开关。规则定义与协议放共享层，不让共享层依赖 DOM 或 vscode。

- 先写契约测试：命中/不命中、空属性、非法 URL、规则冲突、失败回退、条件/捕获组/嵌套、预算边界与代次回收。
- 浏览器使用真实 HTML/plain 双载荷，覆盖 Codex 形态加 strong/code/pre、纯文本旁路及既有分步撤销；消费样例只模拟来源，不把 Codex 专属规则写入生产内核。
- 真宿主验证宿主登记、页面广播、组件停用与富文本撤销/重做。优先扩展 `htmlToMarkdown`、`richPaste*` 和组件运行夹具现有测试接缝。
- 每张实施票同步 addonApiCatalog、生成参考、编译期消费者、覆盖映射与必要的兼容基线重锚定；重锚定须同 PR 独立说明，不提前改发行台账。
- 涉及用户文字时经 i18n；本面不新增用户操作或默认快捷键，沿用富文本粘贴入口。

## 6. 不包含

不开放剪贴板任意读取、组件自建粘贴管线、动态脚本、DOM 回调、通用源码粘贴猜测或规则管理 UI。消费方 Codex 规则归 bridge#2；本票不改正文链接行号语法。

## 7. 拆分与完成条件

T01 覆盖 P-U01–P-U06、P-U09–P-U11 的基础声明链路；T02 在相同入口扩展 P-U07/P-U08，并复验全部基础故事。T01 不接受尚未实现的高级表达式，不把它们静默降成普通文字。

两张实施票完成、对应测试与 API 门禁通过、参考样例可消费后，父票进入整体验收。规格定稿本身不关闭父票，也不代表 bridge#2 已完成。
