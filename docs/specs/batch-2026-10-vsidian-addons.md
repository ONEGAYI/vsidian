# plan: Vsidian 附加组件首版——验证、SDK、组件管理与 API 治理

状态：2026-10-08，**全部子票实施完毕，T18 收口完成自动化矩阵**——compile / 全量单测 / 浏览器全量（--no-reuse）/ 开发态集成全量 / 安装态五阶段 / Remote SSH 两阶段 / 两契约门禁（含双 baseline 锚定）全绿，证据见各票回填与 T18 票面。**整体验收未结**：人工清单 A59–A66（含真机 IME/物理输入/观感/真实重启/真实远程）待用户执行；未关闭原研究票 #18 与本总览。总览记录完整批次；不作为可认领代码票。

Blocked by: 无硬性依赖；本总览按下列子票和验证门槛跟踪。

## 目标与授权范围

用户已确认附加组件产品规则，并授权现在创建验证票与全部实施票，通过依赖安排执行。此批次先建立 Vsidian 自己的接入机制和公开 API，再用输入、渲染和界面三类样例验证。Easy Typing 是输入需求样本，不限制框架范围，也不承诺未经修改运行 Obsidian 插件。

原研究入口为 #18，仅作为来源关联；本次不关闭或改写该票及其其他三期想法。

## 已确认规则

1. 正式称 Vsidian 附加组件（Add-on），安装平台仍是 VSCode 扩展；发现与安装经 VSCode，具体设置在 Vsidian 自有页面。
2. 私有元数据只声明身份/兼容/必要展示，能力与时机由代码注册；首版与 Vsidian 同扩展宿主，核心组件也独立分发、共用 API，官方归属由 Vsidian 管理。
3. Vsidian 先返回可用 API，之后发现/检查/协调唤醒/注册；兼容启用的新装组件默认启用，用户关闭在重启与普通升级后保留。
4. 宿主与页面在一个组件 VSIX 中提供各自入口，SDK 只桥 JSON 数据；稳定与实验分层，CM6 原始接口在实验入口并共享运行时。
5. 首批六组：视图编辑、内容渲染、操作界面、设置、生命周期通信、诊断；统一视图覆盖主文档、悬停及嵌入，写入归合法 Live 目标 B，不误改父 A。
6. 用户默认/工作区覆盖支持设置与开关，值支持普通值、数组和对象。手动关闭后自己的设置页可配置；故障暂停撤下自定义代码，由平台提供基础配置/原因/重试。
7. 侧栏分选项、核心组件、第三方组件，后两组各分已启用/已停用；分组按用户开关，故障暂停另标状态。
8. 菜单只新增自己的，设置只自定义自己的；不得接管整体、覆写内置或其他组件，同名注册也不能间接覆盖。
9. 同操作适用行为默认依次触发，用户可调序和部分关闭；行为冲突管理入口在组件管理页，名称必填，说明和例子推荐，不把同操作一概视为互斥。
10. 每次文本修饰默认原子、跟踪且独立撤回；作者可声明非原子，与同一目标文档的上次原子操作一起撤回，仍记录来源与变更，文本撤销栈继续归 VSCode。
11. 所有代码块语言均可替代内置渲染。新安装的兼容启用组件自动接管其支持语言，安装后无需额外选择；用户有需要时可调整，普通重启/升级保留首选。
12. 正常停用和整组件已故障降级停用可交回内置；仍运行的渲染 bug 不自动接管。故障保留启用偏好和首选，手动恢复成功按原选择显示，不自动重试。
13. 可归因异常暂停组件在 Vsidian 的全部注册贡献，沿用普通 VSCode 扩展信任模型；不承诺终止任意扩展代码或判断错误渲染。
14. 调试复用 VSCode 工具，来源日志和错误由平台归集；新增可绑定操作统一管理，写操作只在 Live 正文接管宿主绑定，不接管源码/设置输入，不开放 Tab 绑定通道。
15. API 独立编号，主仓库声明/语义/版本文档为事实源，AGENTS 和检查与 CSS 契约同等维护；文档不要求进入 VSIX。稳定移除须从弃用实际发布日起同时满两次后续 API 次版本和 30 天。

## 证据基线与执行门槛

已在 VSCode 1.82.3 隔离最小宿主两次运行退出 0，共 9 条观察验证 API 返回后的接入、本地页面 SDK 注入、共享 EditorState 和原生/自定义编辑器的顺序历史分组。尚无生产并发/IME/引用 B/重载、真实 CM6 扩展、资源拒绝对照、Remote 或双 VSIX 的完整证据。

因此 V01/V02 是验证前置；受影响实施票现在也创建，但需验证明确通过后才放行。验证票关闭不等于方案通过。T01 的发现/轻量注册可独立推进。其余字段、错误结果、默认序、存储和 SDK 载体为技术提议，按票面验收冻结，不能擅改以上产品规则。

首次实施 T01 将本地 ADR、规格、技术方案和本索引随代码 PR 落档；各票正文独立包含范围与验收，避免依赖未推送文档链接。
