# Obsidian Callout 语法、编辑与样式

状态：**规格定稿、已开票，尚未实施**（2026-10-28）。用户已确认 1 总票 + 8 子票粒度；总票 [#651](https://github.com/ONEGAYI/vsidian/issues/651) 完整收录规格与 ADR，子票为 #652–#659。本轮只推进规格与开票。历史想法入口为 [#429](https://github.com/ONEGAYI/vsidian/issues/429)，本规格不处理该票中的历史版本功能，也不关闭想法集合票。

## 1. 问题与目标

目前 Live 将 `> [!note]` 当作普通引用，阅读侧没有 callout 专用渲染，样式清单的 `limit-callout` 明确标为不支持。设置页的说明框与正文 callout 语法是不同概念。

本批支持 Obsidian callout 的基础语法、保持外框的 Live 编辑、按实例记忆的折叠、源文转换操作，以及可用 CSS 定制的默认明暗样式。Live、阅读、悬停、文档嵌入和 PDF 导出消费同一套语义；各场景继续遵守既有编辑、资源和安全边界。

## 2. 用户故事

1. 作为笔记作者，我希望已有 callout 原文在 Live 与阅读中呈现类型颜色和图标，以便直接使用 Obsidian 文档。
2. 作为作者，我希望在保留外框时编辑正文，并在标题标记处编辑源码，以便不因输入丢失容器结构感。
3. 作为作者，我希望使用自定义标题、行内格式和链接，以便表达比类型名称更具体的信息。
4. 作为作者，我希望只写标题也能形成 callout，以便制作简短提醒。
5. 作为作者，我希望在列表、引用和 callout 内组合正文已有内容，以便保留复杂笔记结构。
6. 作为读者，我希望通过箭头开合带 `+/-` 的 callout，并在模式往返后保持状态，以便连续阅读。
7. 作为检索者，我希望查找或跳转能展开隐藏的目标，以便定位真实命中。
8. 作为键盘用户，我希望绑定插入、改类型和切换折叠操作，以便不用鼠标完成操作。
9. 作为作者，我希望把选区或当前段落转换成 callout，并一步撤销，以便安全修改原文。
10. 作为作者，我希望选择“无 Callout”后保留标题、正文和普通引用层级，以便只移除提示块语义。
11. 作为菜单用户，我希望各类型行显示实际颜色，并有逐项分隔线，以便区分相邻同色类型。
12. 作为 CSS 片段用户，我希望通过 Obsidian 原名入口修改颜色、边框、标题和图标，以便复用已登记的样式写法。
13. 作为引用内容用户，我希望悬停及嵌入内支持相同呈现和操作，以便在正确的目标文档中阅读和编辑。
14. 作为导出用户，我希望 PDF 中完整展开 callout 内容并保留样式，以便输出不遗漏隐藏正文。
15. 作为作者，我希望输入到一半的标记或不成型语法保留可编辑原文，以便修改时不丢字或误解释普通文字。

## 3. 语法与源位置

### 3.1 识别规则

- 在 Markdown 解析器确认的引用块首段首行识别 `[!类型]`，而非全文正则替换。类型名大小写不敏感。
- `+` 或 `-` 紧跟闭合方括号时声明可折叠及初始状态；无符号不可折叠。首行后续文字为显式标题，后续引用内容为正文。只有标题也成型。
- 以实际容器结构支持多层 callout、普通引用内 callout、callout 内普通引用与列表内 callout。普通引用的后续段落不能因为含字面 `[!note]` 被改成新的同层 callout。
- 围栏、缩进代码、行内代码、转义文字、frontmatter 和既有原生 HTML 源文范围不新增识别。未闭合、空类型等未成型标记按普通引用／原文呈现，不补写修复。
- 引用 lazy continuation、空引用行及列表前缀的边界由双解析器同例对拍确定；T01 固定边界样例，后续不得各写一套宽松规则。表格前缀残缺的既有降级契约保持。
- 原文是唯一内容。识别、显示与折叠均不重排或重写 Markdown；位置使用全文 LF UTF-16 坐标，继续由宿主处理 CRLF。

### 3.2 类型与标题

内置类型为 `note / abstract / info / todo / tip / success / question / warning / failure / danger / bug / example / quote`。别名覆盖 `summary / tldr / hint / important / check / done / help / faq / caution / attention / fail / missing / error / cite`。

类型注册表同时供解析、默认呈现、菜单和测试使用。**原类型标识与默认呈现类别分开保存**：未知类型用 note 的默认外观，仍以其规范化小写标识暴露 `data-callout`，让自定义 CSS 命中。手写别名不自动改写源文；菜单写入所选规范类型。

无显式标题时显示类型名首字母大写，如 `Note`、`Faq`、`Custom-question`。默认标题不写回源文。菜单及操作文案经 i18n；类型显示名称也经字典映射或源文派生，不新增用户界面硬编码。

显式标题支持现有行内文字格式与链接，复用既有解析和净化；链接点击遵守各模式既有规则。标题不另引入块级容器、图片或文档嵌入入口。类型切换保留显式标题、折叠符号与正文；取消自定义类型输入不修改文档。

## 4. 呈现与编辑

### 4.1 Live

外框、色底与类型身份在编辑正文时保留。正文继续消费现有实时预览管线，包括表格、列表、任务、代码、公式、图片和嵌入；不会为了 callout 再序列化内容或另建权威编辑文档。

光标进入标题标记区域时显露 `[!类型]` 及折叠符号供编辑，离开后恢复标题呈现。标题文字点击编辑，折叠箭头单独负责开合；正文选区跨越容器、拖选、复制和输入法组合遵守现有行为。

callout 自身替代该引用层的紫色边条与引用背景；内部普通引用仍显示自身引用样式，外层普通引用也不被取消。嵌套边框和底色不得重复叠成普通引用竖条。

**技术验证门**：CM6 的按行 DOM 不天然提供跨行 `.callout > .callout-content` 可编辑容器。T01 必须证明候选路线能同时保留源坐标、中文输入、嵌套结构、既有正文控件、视口性能和公开选择器；未通过时报告具体缺口并回到技术方案，不以静态截图或整块源码降级冒充通过。不先承诺嵌套编辑器或 DOM 重挂载路线。

### 4.2 阅读与引用

阅读渲染复用 `createMarkdownRenderer`、`splitReadingBlocks` 和现有挂载生命周期。标题、正文和嵌套结构保留源位置映射，查找只高亮真实可见命中文字。

悬停与嵌入中的 Reading／Live 复用相同能力。编辑、保存和撤销属于目标文档；资源以目标文档解析。引用头部、工具栏与外层容器不被误标为 callout 内容。

引用实例卸载时释放事件、观察器及图标资源；离屏不为菜单预览常驻重型编辑器。重挂载恢复本次实例会话内的折叠选择，不读取别的实例状态。

## 5. 折叠与定位

| 源码形态 | 默认状态 | 箭头及切换操作 |
| --- | --- | --- |
| 无符号 | 展开 | 不显示箭头，切换操作不改文本 |
| `+` | 展开 | 可手动收起 |
| `-` | 收起 | 可手动展开 |

- 手动开合为视图态：零源文写入、零 dirty、零宿主撤销项。同一实例的 Live／阅读共享状态；主正文与每个引用位置独立。重开实例恢复源码默认值。
- 外层收起不抹掉内层状态。状态按源位置随编辑与外部增量映射；标记删除或全文重新初始化时丢弃失效状态。恢复被删除的 callout 按源码默认状态初始化，不建立内容身份迁移服务。
- 用户修改源码的 `+/-` 声明时，该项重新采用新声明的默认状态；切类型或编辑正文不重置现存开合状态。
- 收起操作隐藏正文，标题保留；隐藏范围内的光标／选区端点在同一事务移到该标题末尾，不能留在不可见区域。只涉及外层可见性时保留内层选择状态。
- 查找、链接、块／标题锚点、大纲等主动定位进入隐藏区时，展开包含目标的全部 callout 再定位；展开后保持当前视图状态，不在导航完成后自动收回。标题折叠与 callout 折叠各管自己的区间，定位链依次消费两者的展开能力。
- 操作“切换当前 callout 折叠”面向焦点实例的最内层目标，Live 与阅读均可绑定，默认未绑定；无符号或无正文可隐藏时不操作。标题-only 不产生空折叠占位。
- 不直接复用标题折叠的区间定义，也不把 DOM class 当成折叠状态源。Reading 与 Live 消费同一状态与纯派生结果。

## 6. 源文操作

### 6.1 插入与类型切换

在已有 callout 内，菜单类型项和改类型操作作用于命中位置所属的最内层 callout；不再包一层。键盘操作以焦点实例主光标确定目标；右键以命中位置确定目标，不先破坏选区。

普通正文内：空行创建 callout 骨架；无选区的非空段落转换当前段落；有选区时扩展到完整行，逐行补相应容器前缀，空行同样留在所建容器内。列表和代码源文保持内部结构；结构敏感区继续沿统一菜单安全矩阵置灰，不把 callout 插入开放到代码体、表格格内或 frontmatter。

默认插入 note，完成后选中类型名；菜单选择具体类型时写入并选中所选类型名。已存在目标的类型修改保留标题、折叠符号、正文和引用层级。显式自定义类型输入采用现有输入框架，空白或不能构成单个类型标识的输入给出本地化提示，不写入半个声明。

每次创建、转换、切类型或移除为一次原子宿主编辑，可一步撤销恢复原文；保留文档换行格式。只移动选区或取消输入不产生撤销项。多个选区沿既有结构格式操作的主选区口径处理，不引入批量目标协议。

### 6.2 无 Callout

仅移除目标层的 `[!类型]` 及紧邻折叠符号，保留引用层级和内层内容。显式标题成为首段；无显式标题时删掉空标题行。若只有声明、没有正文，保留可编辑的空引用行，不连带删除外层结构。

普通正文选择此项不修改文件。“无 Callout”与当前类型一样作为类型列表中的可识别条目呈现，使用普通引用的颜色提示。

### 6.3 操作注册

| 操作 | 生效模式 | 默认绑定 | 文档写入 |
| --- | --- | --- | --- |
| 插入／转换 callout | Live | 无 | 有 |
| 修改当前 callout 类型 | Live | 无 | 有 |
| 切换当前 callout 折叠 | Live、阅读 | 无 | 无 |

操作统一进 `src/shared/keybindings.ts`，焦点路由覆盖引用内部实例；写操作不覆盖阅读或原生源码编辑器。菜单类型叶项消费同一转换规划器，键位提示由注册表派生。

## 7. 菜单与类型颜色预览

统一菜单采用“插入 → Callout → 类型”三级结构。类型页按“无 Callout、内置规范类型、自定义类型输入”组织，别名通过源文或自定义输入使用，不把所有别名重复排成菜单。Live 标题右键增加“Callout 类型”子菜单，复用同一类型列表与执行通道；阅读模式继续使用原生右键菜单。

当前类型有勾选标识，未知自定义类型能显示当前标识并进入修改输入；“无 Callout”在普通正文为当前状态且执行不改文档。取消菜单、输入框或点击父项不修改文件。

**逐行颜色与分隔线**（用户追加）：

- 每个实际类型行使用该类型在当前文档、主题及 CSS 片段下的有效色底、标题／图标颜色；不能另建固定色表。无 Callout 使用普通引用呈现，输入自定义类型的动作行保持菜单语义，不伪装成某种固定类型。
- 在相邻可见类型条目之间各显示一条分隔线，同色类型也有清晰边界；隐藏或置灰不产生重复线，首尾不附孤立分隔线。悬停、勾选、键盘焦点与置灰仍可区分，分隔线不进入键盘焦点序列。
- 预览从与正文相同的类型呈现路径和 CSS 解析结果取得；适配正文作用域时保留所需祖先选择器和文档样式身份，再将已计算的外观用于菜单。仅在菜单按钮上加 `.callout` 不能证明 `.markdown-preview-view .callout` 等片段生效，也不能让片段正文布局破坏菜单点击区域。
- 打开菜单及主题／片段变化时更新有效颜色；不常驻一份全类型重型编辑器。任意内容位置或复杂 `:has()` 选择器不承诺能在独立预览行完全复刻，必须在样式参考中写明经过测试的适用入口，不把计算色取样扩大成任意 CSS 布局兼容。
- 沿用菜单内核的递归结构、左右翻转和键盘导航。修订旧“内置最深两级”说明，仅为本类型路径增加第三级；验证左右屏幕边缘、窄窗口、低高度下的滚动可达性和分隔线呈现。

菜单新形态在实现票同步登记 ui-patterns。菜单项 `when/enable`、图标两表、i18n、提示和快捷键登记沿 [context-menu.md](context-menu.md)；不为本批另造菜单内核。

## 8. 公开样式契约

### 8.1 结构与变量

两模式的成型态提供 `.callout`、`.callout-title`、`.callout-icon`、`.callout-title-inner`、`.callout-content`、`.callout-fold` 和规范化 `data-callout`。正文必须真实位于 `.callout-content` 所表达的内容结构中，不能以空节点保留选择器。Live 侧为行级形态（T01 路线 A）：`.callout-content` 以正文行级类承载（正文行即该类元素），`.callout > .callout-content` 等严格父子容器选择器仅在阅读侧承诺；样式参考按 T01 报告 §6.1 矩阵写明各入口适用面。折叠呈现可提供与 Obsidian 对应的 `is-collapsible/is-collapsed` 状态类，具体兼容条目经 T01 固定。

首批变量按官方清单登记：

- 颜色／图标：`--callout-color`、`--callout-icon`。
- 容器：`--callout-border-width`、`--callout-border-opacity`、`--callout-padding`、`--callout-radius`、`--callout-blend-mode`。
- 标题：`--callout-title-color`、`--callout-title-padding`、`--callout-title-size`、`--callout-title-weight`。
- 正文：`--callout-content-padding`、`--callout-content-background`。
- 类型颜色：`--callout-bug/default/error/example/fail/important/info/question/success/summary/tip/todo/warning/quote` 中各个实际变量名。

`--callout-color` 同时接受已有片段常见的 RGB 三元组和标准 CSS 颜色。CSS 图标接受随包锁定 Lucide 版本支持的 ID，以及净化后的 SVG 字符串；不运行脚本、事件或新增外链资源通道。未知图标或非法外部值保留默认图标并给出可查的诊断，不静默报告定制成功。

### 8.2 兼容维护

- 固定基线 `425ec96ba` 及实施时的已发布样式版本／SHA。保留普通引用、表格、嵌入和系统菜单的既有契约；新增 callout 不自动扩大 HTML、资源许可或片段域。
- `limit-callout` 从“不支持”转为已支持能力说明时保留历史稳定 id，不删除条目规避基线。新增能力在 `styleContract.ts` 和英文覆盖登记，别名／探针同源，重生成样式指南；不在此文手写第二份运行期清单。
- 默认明暗色与图标由 T01 固定实际 Obsidian 默认主题的版本和证据。官方帮助将 `important` 列为 tip 别名，CSS 文档另给 `--callout-important`；规范类型归属与原标识样式选择必须分开核对，不凭相同颜色合并类型。
- CSS 片段保存、主题切换、模式往返及视口重新挂载均验证实际绘制结果。变量读取存在或 DOM 在场不能替代颜色、图标、边框和文字可见性断言。

## 9. 引用与 PDF 导出

引用内容复用 `RefContentMount` 和 `liveInstance` 的模式、焦点、资源归属与释放通道，不自建第二份引用文本。类型转换与撤销只修改引用目标，父文档的源码和折叠状态不被改变。

PDF 通过现有 `pdfExportAssembly` Reading 管线呈现；只消费准备阶段固定输入，所有 callout 正文（含嵌套 `-`）展开输出，不读取当前面板的临时折叠状态，不改源文。样式和资源归属按当前篇／目标文档隔离，继续沿用媒体与 iframe 降级规则。

计划将两端共享的 callout 元数据、类型和转换规划放在 `src/shared/` 的窄模块中，具体拆分与类型签名由 T01 证据确定。Live／Reading 适配器不复制类型表或路径规则。新增内部模型不自动变为附加组件公开 API；现有 `experimental.syntax` 的 quote 口径保持，文档须把“因未实现而无识别”的历史理由更新为当前边界。

### 10.2 验证矩阵

- **语义与原文**：同一夹具分别驱动 Live 树与 markdown-it，覆盖全部类型／别名、大小写、未知类型、自定义／空标题、折叠符号、嵌套、容器、lazy 行、未成型和代码内伪标记；创建／切类型／无 Callout 的精确源文与一步宿主撤销回读。
- **真实输入**：现有生产控制器浏览器缝验证标题标记显隐、跨行拖选、中文组合输入、表格／代码／图片／嵌入交互、三级菜单键盘与边缘翻转；不以只调用规划器取代输入链验证。
- **绘制**：明暗主题和 CSS 覆盖下的真实底色、边框、图标、标题／正文可见性，普通引用边条组合，菜单同色相邻项分隔、hover／focus／disabled；至少一条集成断言落 `view.state.paint` 或同等可见绘制证据。
- **状态与实例**：同实例模式往返、引用各自开合、外部增量、撤销／重做、视口回收重挂、主动定位逐层展开、销毁后回收。
- **导出**：固定 payload 的嵌套折叠正文全部在导出 DOM 与实际 PDF 中可见；引用来源资源与文档样式隔离。
- **规模**：复用现有 1千／1万／10万行档位，观察可编辑 callout 容器的 DOM 数、输入成本和滚动回收。T01 记录当前基线与候选数据，不虚构已通过性能预算。

可执行行为仍先补能暴露目标问题的契约测试再实现；输入／光标变更必跑相关浏览器套件。长命令首次落盘退出码，优先使用运行器现有报告。迭代只跑受影响检查，有效全量记录不因推送、复审或合并阶段变化重复执行。

物理鼠标、真实 IME、嵌套边框和菜单颜色观感登记人工验证清单；代理测试通过不等于用户验收。
