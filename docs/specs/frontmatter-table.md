# 规格：YAML frontmatter 表格化呈现与就地编辑

状态：已实施（工单 [#140](https://github.com/ONEGAYI/vsidian/issues/140)）；**2026-09-27 用户验收反馈改版为「只读表格 + Popover 编辑」**（见下节）。本文是 frontmatter 表格化的单一事实源，工单验收以此为准。

## 范围

- **覆盖**：文档头 YAML frontmatter 在 Live 与阅读两侧的表格卡片呈现；Live 就地增删改键值对；手动输入构造头区的自动成型。
- **术语**：frontmatter 指首行 `---` 至闭合 `---` / `...` 行的头区；边界判定单一事实源 `markdownDoc.frontmatterRange`（8192 有界扫描，未闭合 / 超长降级普通 Markdown）。
- **一期值类型**：标量（字符串 / 数字 / 布尔 / 日期）+ 字符串数组。
- **排除**：嵌套对象、对象数组等复杂类型的表格编辑（整卡降级源码）；头区 lint / 校验、模板补全；Obsidian 属性面板完整功能对标。

## 已确认决策（2026-09-27 澄清答复）

1. **两侧表格化**：Live 表格卡片 + 阅读同款表格（对称原则）。
2. **成型**：头区合法即**常驻表格卡片**；源码形态仅作降级出现。
3. **值类型**：标量 + 字符串数组进表格交互；复杂类型整卡降级源码（可编辑，转简单后自动成型）。
4. **写回**：走既有文本管线（CM6 → 消息 → WorkspaceEdit；LF 坐标 NewlineCoordinator），不新增旁路。

## 验收反馈改版（2026-09-27，只读表格 + Popover）

首版「格内直接编辑」方案经用户验收判定观感与交互不满意（参考现状截图标注：格线密、行内 ×/＋ 按钮、闭合行「添加属性」整行按钮带来的空行/空白），改为：

1. **成型头区只读**：Live 视图呈现为只读键值两列表格（格不可点击编辑，无行内结构按钮、无整行添加按钮）；阅读侧同布局只读（标题栏同构、无按钮）。
2. **标题栏 + 修改按钮**：卡片顶部为标题栏（列表图标 + Properties 标题 + 右上角圆角描边铅笔按钮），对齐参考图 A；按钮点击开关属性编辑浮层。
3. **Popover 编辑**（形态对齐参考图 B）：贴修改按钮定位的小浮层（挂 body、fixed 定位），结构化编辑行——键值对逐行（键输入框 + 值输入框 + 删除按钮）、字符串数组项逐行（项输入框 + 删项 + 加项）、底部「添加属性」主按钮。
4. **写回语义不变**：文本输入即时写回（键/值/项分别经 `planSetFmKey` / `planSetFmValue` / `planSetFmArrayItem` 单笔事务），按钮操作（删行/删项/加项/添加属性）单笔写回——一笔操作 = 一笔 edit.request = 撤销一步；浮层派发的事务不带 CM6 选区。
5. **成型态不暴露源码**（用户决策）：光标或选区进入成型头区即被引导至闭合 `---` 行之后的正文起点——transactionFilter 硬拦纯选区事务 + updateListener 微任务兜底（覆盖初始光标、undo 恢复选区）；外部同步事务（`externalSync` 注解）与 undo/redo 事务豁免 filter，头区重析不受影响。降级形态（复杂类型/非法）不引导，源码可编辑；降级瞬间打开中的浮层自动关闭。
6. **键名边界**：空键名与重复键名（归一后）不写回，输入框红边标记——写回将使头区非法整卡降级。flow 数组为值整框原文编辑（含括号，与一期「整格文本编辑」同口径）。
7. **焦点管理**：打开时焦点入首个键输入框；Esc 与点击浮层外关闭（`prevFocus` 模式，非全屏）；关闭后焦点按 prevFocus 口径返还（打开前焦点在编辑器则返编辑器，body 时返按钮）；切换到阅读视图或面板销毁时浮层关闭。禁止 `window.alert`（宿主 webview sandbox 无 allow-modals）。
8. **样式对齐**：参考图 A/B 的布局、配色、组件形态——完整边框圆角卡片、行间淡分隔、键列常规字重灰、无格线；浮层白底圆角 10px + 投影、输入框浅底描边、主按钮主题主色。样式契约与界面域探针同步（`live-fm-header-live` 静态探针；Popover 容器为交互态，按行为路径验证）。

格内编辑时代的机制全部退役：Tab/Enter 格导航键位、行尾 ×/＋ 按钮、闭合行「添加属性」整行按钮、空值占位格、「光标触及围栏行显源码」语义（被引导语义替代）；对应样式契约条目（live-fm-controls、live-fm-add-entry）移除，`vsidian-fm-remove` / `vsidian-fm-add-item` / `vsidian-fm-add-entry` / `vsidian-fm-empty-value` 类名不再发射。

## 卡片折叠（2026-10，与代码块同交互）

用户验收反馈两项缺陷之一的修复：frontmatter 卡片补齐与代码块卡片**同款折叠交互**——整卡头部热区 + 右上折叠按钮。

1. **交互入口**（与代码卡 #82/#190 同口径）：标题栏整体为折叠热区（点击标题图标/标题文字即切换，排除按钮本身）；按钮区最右新增折叠 chevron（修改按钮右侧，两态常驻、收起态转向 -90°）。折叠/展开全程零写回。
2. **收起形态**：live 侧键值/项/杂项行连同闭合围栏行整块隐藏（replace 覆盖首行换行后至闭合行行尾含换行），首行改携 `vsidian-fm-card-folded` 修饰兼任卡片底边（补底边框与四角圆角）；阅读侧表格容器挂 `vsidian-fm-folded`，行区整体 `display:none`（表壳边框圆角保留）。
3. **让位与联动**：收起态不发射「修改」按钮（编辑入口随表格让位——与代码卡收起态不发射复制钮同口径）；折叠时打开中的 Popover 自动关闭（编辑对象已隐藏）。
4. **状态承载**：live 为 CM6 视图态 field（`fmFoldField`，frontmatter 单块恒在文档首，布尔承载）；阅读为控制器布尔（`readingFmFolded`，挂载装饰按态重建）。均为**视图态**：不写源文件、不跨会话持久化（重开文档全展开）；两视图各持折叠态不互通（与代码卡 live `codeCardFoldField` / 阅读 `readingCodeFold` 分持同口径）。
5. **快捷键评估**（操作注册约定要求的记录）：折叠为纯指针交互，与代码卡折叠一致**不提供快捷键入口、无默认绑定**——折叠对象是视觉卡片而非文本操作，键位无落点；如未来需要可按快捷键注册表模式接入（mode live/reading 双模式）。
6. **样式契约**：新增公开条目 `live-fm-fold`（含 -collapsed / 首行级 -card-folded / 表格级 -folded 修饰）；`live-fm-header` / `live-fm-card-line` 条目随更新；探针走 `paint.fm` 绘制层（行数/收起计数），行为路径经浏览器与集成验证。

## 交互契约

1. **成型与降级**：合法（可解析且全部键值为一期类型）→ 表格卡片；未闭合 / 超 8192 / 解析失败 / 含复杂类型 → 源码字面呈现（现状机制），编辑不受限；合法性与形态随编辑实时切换。
2. **就地编辑（Live，改版后为 Popover 编辑）**：成型表格只读；编辑入口收敛到标题栏「修改」按钮的浮层——标量为文本输入、字符串数组呈现项列表（增删项、项内编辑）、提供新增/删除键值对入口（详见「验收反馈改版」节）。
3. **阅读侧**：同款表格（含标题栏，修改按钮不发射），只读（阅读模式除任务勾选外只读的既有边界不变）；折叠 chevron 与热区经挂载装饰在场（2026-10）。
4. **序列化最小重写**：未改动的键值行保持原文形态（顺序、引号、缩进、行内注释尽量原样），仅重写被编辑行；数组项增删在该行内重写。若实施证明成本过高，可降级为整段规范化重写，但须在工单回报显式说明取舍。
5. **与既有机制的关系**：头区内不参与列表延续 / 公式 / 双链 / 围栏渲染 / 大纲（现状降级机制保持）；行号、查找、任务勾选、外部变更同步、撤销栈均走现状管线，不回归。
6. **围栏行的源码显形（已随 Popover 改版退役）**：首版「光标触及首行 / 闭合行时撤下装饰、源码显形」语义被「成型态不暴露源码 + 光标引导」替代——光标进入头区任何位置（含围栏行）都被引导至闭合行后，编辑经浮层完成；源码形态仅降级出现（可编辑）。
7. **卡片折叠（2026-10）**：标题栏热区 + 右上折叠 chevron 收起/展开键值行区，零写回、视图态不持久化、双视图各持（详见「卡片折叠」节）。

## 用户故事

1. 作为编辑者，我在文档头手打 `---` 与几行键值后，头区自动变成表格卡片，不需要记语法细节。
2. 作为编辑者，我在表格里直接加一行、改一个值、删一个 tag，源文件跟着变。
3. 作为读者，我希望阅读视图里头信息也是整齐的表格而不是源码块。
4. 作为编辑者，我的头区写了复杂嵌套时，它退回源码形态让我继续编辑，内容不丢。

## 实施决策

- **依赖**：引入 `yaml@2.9.1`（精确版本锁定 + lockfile）；解析失败不让错误冒泡打断编辑。
- **Live 卡片**：参照表格网格 / 代码块卡片的装饰管线——头区行经 CM6 装饰替换为表格卡片 DOM，编辑事件映射为文本变更；重渲染防抖与表格网格同策略。
- **阅读侧**：`splitReadingBlocks` 的 frontmatter 块由转义 `<pre>` 换为表格 HTML（经安全渲染层，值全转义）。
- **i18n**：表头、增删入口、空态等全部文案入两语言包。
- **协议**：如需新消息以 protocol.ts 为单一事实源（优先复用既有文本编辑消息通道）；parity 由既有机制把关。

## 验证与完成条件

- **TDD**：解析 → 编辑计划 → 序列化纯函数先行（最小重写、非法降级、头区外 `---` 不误判、数组编辑等用例）。
