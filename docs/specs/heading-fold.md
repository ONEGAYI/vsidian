# 正文标题折叠——Live 编辑器折叠本体与跨模式语义规格

> 状态：**规格定稿（2026-10-09，#409 to-spec 阶段起草）**，待 to-tickets 切片开票。
> 材料锚点：[#409 票面](https://github.com/ONEGAYI/vsidian/issues/409)（用户决策：按「产品功能 → API 开放 → 插件调用」推进，本票是第一环）、[#403 research](../research/addon-fold-capability-probe.md)（语义边界）、[keybindings.md](keybindings.md)（统一快捷键登记形态）。
> 本规格起草自工作树 `feat/heading-fold`（基于 main 5ffd8f0d），全部代码事实均经该基线勘察核实。

## 背景与问题

用户在 Live 模式编辑长文档时，无法收起暂时不关心的章节：一个 H2 节动辄数十行，标题结构下的浏览与导航必须依赖大纲面板跳转，正文本身不可「折起来看骨架」。

[#403 research](../research/addon-fold-capability-probe.md) 已确认 vsidian **没有正文标题折叠功能本体**：三个既有折叠载体（frontmatter 卡折叠、代码块卡片折叠、大纲面板折叠状态机）分别属于局部装饰开合与面板 UI 状态，都不是编辑器折叠区间语义。本票补齐这个产品功能本体，同时为下游（折叠类附加组件 API，承接票 #410；easy-typing 的折叠标题 Enter，vsidian-easy-typing#18）提供前置。

## 目标

1. Live 模式获得**标题区间折叠**能力：点击 gutter 箭头或按快捷键收起标题节正文，再展开。
2. 折叠状态承载于编辑器状态（StateField），**跨外部同步、跨撤销/重做、跨双模式往返保持**；不写文档、不产生撤销历史。
3. 交互入口齐全：gutter 折叠箭头、折叠态省略号占位、五条可绑定操作进统一快捷键管理。
4. 本体设计为 #410 API（折叠区间查询、折叠/展开命令）留口，不堵死开放面。

## 用户故事

1. 作为笔记作者，我想点击标题行旁的折叠箭头收起该节正文，以便长文档里只看当前关心的章节。
2. 作为键盘用户，我想按 Ctrl+Shift+[ 折叠光标所在节、Ctrl+Shift+] 展开，以便不碰鼠标也能收放结构。
3. 作为键盘用户，我想要一个「折叠/展开切换」单键操作（Ctrl+K Ctrl+L），以便一个键位覆盖收与放两种意图。
4. 作为大纲型读者，我想一键折叠全部标题节（或全部展开），以便在「只有骨架」与「全文」之间快速切换。
5. 作为多章节作者，我想折叠 H1 的同时其内部 H2 保持已折叠状态，展开 H1 后 H2 仍是收起的，以便嵌套折叠互不干扰。
6. 作为协作者，我想折叠期间外部程序修改文件（另一编辑器改别处）后折叠原样保持，以便同步不打断我的阅读结构。
7. 作为谨慎的编辑者，我想折叠后 Ctrl+Z / Ctrl+Y 往返不丢折叠，以便撤销编辑不重置我的视图。
8. 作为编辑者，我想在折叠态下继续编辑标题行文字（含升降级标题），折叠保持且区间跟随新结构，以便折叠不阻碍编辑。
9. 作为编辑者，折叠包含光标的节时，我想让光标落到标题行行尾，以便折叠瞬间不出现「光标悬在隐藏区」的错乱。
10. 作为检索者，我想查找下一个命中落在折叠区内时该节自动展开并定位，以便查找不被折叠挡住。
11. 作为大纲面板用户，我想点击大纲条目跳转到正文折叠区内的标题时该节自动展开，以便面板跳转直达内容。
12. 作为双模式用户，我想 Live 折叠后切到阅读看全文、切回 Live 折叠原样，以便两模式各司其职互不干扰。
13. 作为嵌入编辑用户，我想在悬停/嵌入卡片内的 Live 编辑器里同样能折叠标题，以便引用编辑体验与主正文一致。
14. 作为附加组件开发者（下游 #410），我期望折叠本体可编程查询与驱动，以便未来暴露 `getFoldOffsets` 同类 API 时不需重构。

## 非目标

- **阅读模式折叠**：不开放（定案依据见「阅读模式语义与跨模式联动」节）。
- **通用代码折叠**：不装配 `@codemirror/language` 的 `codeFolding` / `foldGutter` / `foldState`（其 foldable 语义含列表、括号等非标题区间，超出本票票面；未来要通用折叠另开票评估）。
- **折叠持久化**：折叠是会话内存态，重开文档全展开（对齐代码卡折叠语义）；跨会话记忆不做。
- **折叠级别族键位**（VSCode 的 Ctrl+K Ctrl+1..7 折叠到 N 级）：不在本轮操作注册表（见「交互入口」节的登记清单与理由）。
- **右键菜单折叠项**：不进统一右键菜单（后续按用户反馈经 [context-menu.md](context-menu.md) 流程另行评估）。
- **折叠设置项**：不新增设置页条目（功能被动呈现——箭头悬停才显现、零布局足迹，无干扰面需要关闭）。
- **大纲面板折叠与正文折叠的状态打通**：不共享状态源（定案依据见「大纲面板关系」节）。

## 行为规格

### 一、折叠区间语义（本体）

**标题节（heading section）**：一个标题所辖的正文范围。设标题行级别为 n，其节 = 从该标题行（含）到下一个**级别 ≤ n** 的标题行（不含）之间的全部内容；其后没有更低层级（数字更大）标题之前若出现同级或更浅标题即终止；文档内再无此类标题则到文档末尾。跨级标题自然辖域化（H1 直接跟 H3 时，H3 节终止于下一个级别 ≤ 3 的标题，H1 节覆盖到下一个级别 ≤ 1 的标题——与大纲父子结构 `outlineCollapseFacts` 同构，但正文折叠不消费大纲索引，见「实施落档约定」）。

**折叠区间**：标题行（Setext 标题为整个标题块，含下划线行）**保持可见**，隐藏区间 = 标题行行尾到节末（下一符合条件标题行的行首，或文档末尾）之间的全部内容，含中间空行。

**可折叠判定**：隐藏区间内存在至少一个非空白字符。相邻标题（区间为空或仅空白）不可折叠——不显示箭头、命令对其 no-op，避免「折叠后两条标题行贴挤」的无观感收益操作。

**嵌套独立性**：每个标题节的折叠互相独立（折叠 H1 与折叠其内部 H2 同时成立）；展开外层后内层折叠态保留。折叠键集合是扁平的，嵌套语义由区间重叠自然表达。

**标题口径单一事实源**：标题识别复用 `headingLevelOf`（`src/shared/markdownDoc.ts`，ATX 1–6 与 Setext 1–2 双支持——Live 装饰、大纲、阅读切块三侧同源），并沿用 `extractOutline` 已钉住的排除语义：frontmatter 头块内伪标题不折叠、代码围栏内伪标题天然不产生标题节点。折叠区间派生须与大纲提取消费同一增量解析树（`liveDecorationsField` 维护的树传入复用，省略时全量解析——`extractOutline` 的既有双入口形态）。

**实现形态**：隐藏用 `Decoration.replace`（多行区间，折叠态带省略号占位 widget——代码卡折叠 `fenceHideDeco` 的同族机制，跨行块隐藏为 CM6 原生能力）。折叠被隐藏区间内的其他装饰（表格、代码卡、Mermaid 等）随 replace 覆盖一并不可见，Mermaid 懒加载因视口判定天然顺延，无需特判。

### 二、折叠本体与坐标生命周期

**StateField 承载**：新建 `headingFoldField`（建议落 `src/webview/headingFold.ts`，模块命名实施期可调，语义锚定此节），值为**折叠键集合**——已折叠标题的标题行行首位置集合（`ReadonlySet<number>`）。形态对齐 `codeCardFoldField`（`src/webview/codeCardState.ts`）：视图态、零写回、不 dirty、不进撤销栈、不跨会话持久化。

折叠的呈现与查询一律经**派生视图**：有效折叠 = 折叠键 ∩ 当前可折叠标题行行首集合，逐键 join 结构区间得有效折叠区间列表。原始键集不对外（含 #410 API），脱靶键（不在标题行首的残留）经此过滤天然无行为——「update 只做位置映射、不做修剪」的既有先例语义，且 API 面不自污。

**坐标生命周期**（对齐仓库 LF 坐标与 baseVersion 系约定）：

| 场景 | 行为 |
| --- | --- |
| 本地编辑 | 键随事务 ChangeSet 映射（`mapPos(pos, 1)`，assoc=1 对齐 codeCardFoldField）；标题节区间端不存键、每次按结构重派生 |
| 外部同步增量 | 外部增量经 `dispatchExternalChanges` 落为带 `externalSync` 注解的事务，docChanged 同上映射——折叠跨同步保持 |
| 宿主撤销/重做 | 撤销栈归宿主文本管线（架构既定），webview 侧收到的是回流的增量/全文，走上面两行同一路径；键存活的折叠保持 |
| 全文替换（init / doc.resync） | 折叠集**显式清空**（重开等价语义）。实现上识别「覆盖全文档的变更」即可，不依赖映射落点的隐式失效 |
| 编辑折叠边界文本 | 标题行内改字/升降级（Ctrl+1..6 或手改 `#`）：键保持在标题行行首，折叠保持、区间按新级别重派生；删除标题行或行首拆行：键脱靶，折叠消失（派生视图过滤）；「下一同级/更高级标题」前插入新标题：原节区间收缩到新标题前，折叠保持 |
| 撤销恢复被删标题 | 该节回到**未折叠**（键已在删除时丢失）。边界而非缺陷：撤销历史在宿主侧，webview 无 inverted-effect 可挂（StateField 历史映射需本地撤销栈，与「撤销栈归宿主」的架构决策冲突）。用户重新折叠即可，不做文本身份迁移 |

**不做内容身份迁移**：大纲面板的 Myers diff 键迁移（`migrateOutlineExpanded`）是面板索引态的会话机制，**不引入**正文折叠——正文折叠用 CM6 坐标映射即可，两套迁移机制并存只会制造口径分叉。

**标题表增量维护**：折叠区间派生需要全文档标题序列。按 `mermaidFencesField`（`src/webview/liveMermaid.ts`）的既有模式建增量维护的标题表（docChanged 时仅重扫受影响行区间 ± Setext 下划线行边界，未受影响区间沿用映射），选区/视口变化零成本；或按 `extractOutline` 形态在消费点经增量树直查——两条路线都符合仓库先例，实施票任选其一并补对应单测，**禁止**每次 docChanged 全文档重扫（10 万行档性能红线，对齐 perf 档位口径）。

### 三、折叠与光标/选区

**折叠瞬间**（惯例对照：VSCode 折叠含光标的区域时光标移到折叠起始行行尾；Obsidian 同向）：折叠事务内检查选区，任一 range 与被隐藏区间相交（标题行本身不算）时，该 range 迁移到标题行行尾（collapse 为空选区）；其余 range 保留。

**折叠后进入**：replace 隐藏区不可点击（零宽无 DOM），运行期进入隐藏区的路径收敛到「落点展开」机制（见第七节）；外部同步把光标映射进隐藏区时，钳制到辖域标题行行尾（`clampExternalCursor` 的同款防御思想，实施点在折叠侧提供判定函数）。

**折叠目标解析（辖域标题）**：光标所在行是标题行 → 该标题；否则 → 向上最近的标题（任意级别——最近上方标题的节必含光标）。操作语义：

- **折叠**：辖域标题可折叠且未折叠 → 折叠之；已折叠 → 上溯到最近的未折叠祖先标题折叠（VSCode 语义：连续折叠逐层外扩）。
- **展开**：光标所在/辖域标题已折叠 → 展开之；否则展开包含光标位置的最深已折叠区间；再无 → no-op（静默）。
- **非空选区 / 多光标**：逐 range 解析辖域并集去重后一次生效（行集合类命令的自然泛化，与 #120 Tab 缩进的多光标口径同族；区别于结构性格式操作退化主选区的口径——折叠无破坏性，无收敛必要）。
- 无可折叠目标：静默 no-op，不弹提示。

**IME 与组合**：折叠键位均为修饰键组合，经 keybindingRouter 的 document 捕获层路由，`keyStep` 对组合期（isComposing）不路由——既有门控天然覆盖，无需新增处理。

**实例边界**：StateField 随 EditorState 存在，主正文与嵌入/悬停内部 Live 实例**各自独立折叠态**；键位与命令面板按焦点实例解析目标（P2-10 既有焦点分派口径，实施为本地分支按 `focusedLiveEntry`/活动实例分发）。

### 四、交互入口

**gutter 折叠箭头（推荐定案）**：悬停编辑器左缘时，可折叠标题行的 gutter 位置显示向下箭头（折叠指示），点击折叠；已折叠标题的箭头**常显**且指向右侧，点击展开。悬停显现 + 折叠态常显是 VSCode 默认策略（`alwaysShowFoldControls` 关），兼顾无干扰与可发现性。

理由（对照票面给的三个候选）：

- **gutter 箭头 vs 标题行内标记**：VSCode 与 Obsidian 的主交互都是 gutter 箭头，肌肉记忆零迁移；行内标记会占用标题行内容区，与标题行级装饰（`vsidian-heading-line`）和可读行宽居中布局耦合更深。**推荐 gutter 箭头为唯一开合主入口**。
- **补充形态——省略号占位**：折叠态在标题行行尾呈现省略号（`⋯`）占位 widget（`Decoration.replace({widget})`），点击即展开，并作为「此处有被折叠内容」的常驻提示（VSCode 折叠区的 `...` 预览标记、Obsidian 折叠标题的 `⋯` 同款）。它与常显箭头分工：箭头在 gutter（结构操作心智），省略号在行内（内容提示心智）。

**硬约束（布局与样式）**：

- 箭头显现/消失**零布局位移**：不参与流内宽度分配（叠加呈现于既有左侧留白/gutter 边缘），不得因悬停显隐推动正文列——可读行宽档 `[.cm-gutters + 间距 + .cm-content]` 整组居中的既有契约（[viewport-width.md](viewport-width.md)「实施落档」节）不得被破坏。
- 行号列开/关两态下箭头均可呈现且定位正确（行号列是设置项，`liveLineNumbers` 经 Compartment 热重配）。
- 箭头与省略号的观感变量（颜色、尺寸、悬停区宽度等）走 **style-contract 公开变量**登记（实施时加载 style-contract 技能按其流程执行——固定旧契约、新变量登记、契约测试、样式指南再生；本规格只写约束指向，不定变量名与数值）。
- 可访问形态对齐代码卡折叠按钮先例（`buildFoldButton`）：aria-label + aria-expanded + `data-tooltip` 悬停词；带快捷键的操作提示走 `data-tooltip-keys` 结构化键位徽章（数据源为键位注册表，见 [tooltip.md](tooltip.md)「接管机制」节）。全部文案进 `src/shared/locales/` 双语言包。

**快捷键注册（五条操作，登记进 `src/shared/keybindings.ts` 的 UI_OPERATIONS 表）**：

| 操作 | 建议 id / command | 生效模式 | 写标记 | 默认绑定 |
| --- | --- | --- | --- | --- |
| 折叠（辖域标题，已折叠则逐层外扩） | `headingFold` / `onegayi.vsidian.heading.fold` | Live | 否 | Ctrl+Shift+[（mac Cmd+Alt+[） |
| 展开（辖域/包含光标的最深已折叠节） | `headingUnfold` / `onegayi.vsidian.heading.unfold` | Live | 否 | Ctrl+Shift+]（mac Cmd+Alt+]） |
| 折叠/展开切换（辖域标题两态取反） | `headingToggleFold` / `onegayi.vsidian.heading.toggleFold` | Live | 否 | Ctrl+K Ctrl+L |
| 全部折叠（全部可折叠标题） | `headingFoldAll` / `onegayi.vsidian.heading.foldAll` | Live | 否 | Ctrl+K Ctrl+0 |
| 全部展开（清空折叠集） | `headingUnfoldAll` / `onegayi.vsidian.heading.unfoldAll` | Live | 否 | Ctrl+K Ctrl+J |

登记口径逐项说明：

- **默认值对齐 VSCode 惯例**（editor.fold / editor.unfold / editor.toggleFold / editor.foldAll / editor.unfoldAll 的 Windows 与 mac 默认键位族；票面明确「对齐 VSCode 惯例」）。
- **生效模式 = Live**（`mode: 'live'`）：阅读只读不接管（按键冒泡宿主，无默认占用不产生意外行为）；源码编辑器不经 webview 键路由天然不涉及；设置页输入为独立 webview 无此路由。写操作快捷键仅覆盖 Live 编辑正文的 AGENTS.md 约定由此满足。
- **写标记 = 否**（`writes: false`）：折叠零写回、不改选区语义上的「文档写」，与 `outlineCollapseAll`（UI 态翻转）同口径而非与表格命令（写文档）同口径。执行域由目标解析自身保证——无 Live 正文实例/无目标即静默。
- **显式清空不因重启或升级恢复**：清空/改绑/恢复默认沿注册表既有全链路（`KeybindingOverrides`），无新机制。
- **键位所有权归注册表**：不经 CM6 keymap 装配（与词移动/选词族同款——router document 捕获层本地分支执行 + 命令面板经 UI_OPERATIONS 注册循环回发 `ui.command` 分发，两入口共用同一执行实现）。
- **级别折叠族（Ctrl+K Ctrl+1..6）不登记**：六级六条注册条目的膨胀收益低（全部折叠已覆盖「看骨架」主场景），级别折叠是全部折叠的参数化变体，#410 API 开放面不受影响（见该节）。用户反馈需要时按本表形态增量登记，不堵死。
- **冲突核对（起草期预核，实施票内按 #240 收口记录形态复核）**：Ctrl+Shift+[ / ] 与 Ctrl+K Ctrl+L / 0 / J 在当前操作注册表与 keybindingRouter 零占用（既有 Ctrl+K 弦仅 `ctrl+k ctrl+d`，首段重叠不冲突——弦匹配按整串精确）；CM6 defaultKeymap 无这些组合的内建绑定，无需接管吞键。
- **实施前提（本票新发现的键位模型缺口）**：keybindingRouter 的 `keyStep` 按 `event.key` 字符归一，美式布局下 Ctrl+Shift+[ 的实际事件字符是 `{`，当前 `validKey` 白名单不含 `{`——需在 `keyStep`/别名录补 **shift 产生的符号 → 物理键名**映射（`{`→bracketleft、`}`→bracketright 等白名单内符号键的 shift 变体），设置页键位捕获同源受益。非美式布局的物理等价键不做布局换算（与既有键位模型同口径的既有边界，不在本票扩）。此扩展有既有单测族（keyStep/router）钉住，浏览器套件以真实键盘验证。

### 五、大纲面板关系（定案：各自独立 + 单向跳转展开）

勘察现状：大纲折叠状态机（`outlineCollapse.ts`，#67）是**面板 UI 状态**——档位（全局持久化）+ 展开集合（**条目索引**集合，会话内存态，Myers 迁移存活），不含文档坐标映射。正文折叠是文档坐标键集合。两者状态模型（索引 vs 坐标）、生命周期（档位持久化 vs 会话内存）、语义域（面板条目可见性 vs 正文区间可见性）三侧不同构，共享状态源需要新建双向桥且互相污染生命周期。

**定案：各自独立、互不接管**（最小侵入；与 research 的「不建议把大纲展开集冒充折叠区间」一致）。唯一交叉是一条**单向导航语义**：大纲条目点击跳转的落点位于正文折叠隐藏区内时，跳转链路先派发展开（「落点展开」，见第七节），再定位滚动。大纲仍列出全部标题（正文折叠不改变大纲条目集合）——折叠态不影响大纲的完整性语义。

### 六、阅读模式语义与跨模式联动（定案）

**阅读模式不开放折叠，折叠态不带入阅读**。阅读视图渲染完整文档（纯呈现层），无折叠交互、无折叠呈现。依据：

1. research 既定边界：阅读折叠是呈现层概念，API 形态上应只读或不开放——「不开放」是给出的两候选之一且更稳。
2. **#410 API 下游语义一致性**：Live-only 使 API 只对「编辑器折叠状态」一个语义建模；若阅读也有折叠，API 要么分模式分语义（同一命令两套含义），要么引入跨模式状态桥——两者都在本体未稳时放大契约面。
3. 上游驱动方（easy-typing CollapsePersistentEnter）消费的是 Live 编辑器 API，阅读折叠无既有需求方。
4. 实现成本：阅读侧折叠需在块级虚拟化渲染器里另建一套呈现状态及其生命周期，无 StateField 可寄生。

**跨模式往返保持**（这不是联动，是存续）：双态切换不销毁 Live 实例（`setViewMode` 仅切换 DOM 呈现与刷新阅读渲染，CM6 实例与 StateField 内存驻留）——Live 折叠后切阅读看全文、切回 Live 折叠原样。模式回切时的滚动锚点（`modeAnchor`）若落在折叠隐藏区内，走「落点展开」（第七节）。

**与 Obsidian 的差异（明示）**：Obsidian 阅读视图呈现折叠且两模式联动；本定案反之。若用户预期 Obsidian 一致性，翻案路径是增量票（阅读呈现层折叠 + 可选状态桥），本体 StateField 设计不排斥该演进——折叠键与区间派生均不依赖「只有 Live 消费」的假设。此项列入「待用户定案」节供确认。

### 七、落点展开（reveal 族统一机制）

任何把选区/滚动定位到折叠隐藏区内的链路，先展开包含落点的全部已折叠区间（effect 派发），再执行定位——一个 helper（如 `unfoldAround(view, pos)` 语义），接线点枚举：

- 查找下一个/上一个命中与替换定位（`findLocate` 族）；
- 大纲条目点击跳转（`outlineLocate` → reveal 链路）；
- 锚点跳转（标题/块链接，anchorNavigation 族）与搜索结果定位（searchReveal `view.locate` 通道）；
- 双链/链接跳转回到正文折叠区内；
- 双模式回切（modeAnchor 落点）。

展开是**永久展开**（不做 VSCode 的临时折叠窥视——peek 需要折叠态快照与超时恢复机制，收益不抵复杂度，列为后续可选）。

### 八、附加组件开放面预留（#410 留口）

本节只约束本体设计不堵死 API，**不设计 API 细节**（那是 #410 的票面）。#410 需要的两类能力及本体侧保证：

1. **折叠区间查询**（上游 Obsidian 对标 `getFoldOffsets()` / `getAllFoldableLines()`）：
   - 有效折叠区间 = 派生视图（键集 ∩ 可折叠标题集 → join 结构区间），必须是 (field, doc) 的**纯函数**，不依赖控制器/ UI 在场——上表「StateField 承载」已按此设计；
   - 可折叠行集合同理纯派生（标题表 + 非空白判定）；
   - API 面暴露派生视图，不暴露原始键集（脱靶键不泄漏）。
2. **折叠/展开命令**（对标 `exec('toggleFold')`）：五操作与落点展开全部经 StateEffect + dispatch 驱动，**无 DOM-only 路径**——API 编程触发与用户触发同链路；按区间/按级别的参数化折叠是既有 effect 的批量组合，不需新机制。

约束落档：后续任何「让折叠操作绕过 effect 直改 DOM」的实现都是对本节的违背，评审拦。

## 实施落档约定

新增或修改标题折叠的区间语义、坐标生命周期、交互入口或 API 留口前，必读本规格对应节。硬边界与「不得顺手放宽」清单：

1. **折叠是视图态**：零写回、不 dirty、不进撤销栈、不跨会话持久化。任何让折叠产生文档写或撤销步的实现即违背。
2. **单一事实源**：标题口径 = `headingLevelOf`（`src/shared/markdownDoc.ts`，不另建标题识别）；折叠操作注册 = `src/shared/keybindings.ts` 注册表（不手写第二份命令表）；折叠观感变量 = `src/shared/styleContract.ts`；折叠区间派生 = headingFold 纯函数族（大纲/阅读/API 后续消费方引用它，不复制其逻辑）。
3. **不得顺手放宽**：不装配 `@codemirror/language` 的 codeFolding/foldGutter 全量折叠（票面是标题折叠）；不把大纲展开集映射为正文折叠或反之（research 明示的语义错位禁令）；不给阅读模式顺手加折叠呈现；不动 codeCard/frontmatter 折叠的既有语义；不新增右键菜单项与设置项（越过须按各自规格流程另行开票）。
4. **视觉层断言**：折叠呈现类变更的集成断言必须落在绘制层（`view.state.paint` 探针族 + `paintedWithVisibleBackground` 口径），CSS 关键规则由契约测试钉住。
5. **键位铁律沿既有**：折叠键位族不绑 Tab（#125 落档通则）；键位所有权归注册表，不经 CM6 keymap。
6. **API 留口纪律**：折叠操作一律 effect 驱动、查询一律纯函数派生——评审拦 DOM-only 路径。

## 边界与明确不包含

- 撤销恢复被删标题后该节回到未折叠（架构边界，见「坐标生命周期」表）。
- 折叠不跨会话持久化（重开全展开）；跨会话记忆与 Obsidian 式阅读联动同为潜在增量票，本体设计不排斥。
- 级别折叠键位族（Ctrl+K Ctrl+1..6）与 VSCode 式「临时折叠窥视」（peek）不在本轮。
- 非美式布局的物理键位换算不在本轮（与既有键位模型同口径的既有边界）。
- 折叠区间内不可点击（隐藏区零宽无 DOM）；进入隐藏区一律走落点展开或钳制。
- 性能：长文档折叠滚动为 CM6 原生视口能力（codeFolding 同款路径），perf 脚本补折叠档位为可选项，非本批门槛。
