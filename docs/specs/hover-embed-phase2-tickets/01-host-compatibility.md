## 问题与交付

A 面板内的编辑属于 B，当前全局 undo／redo 实现依赖活动编辑器。必须先证明公开宿主路线能满足目标归属，才能接入引用编辑。

给出最小可复现的 VSCode 1.82.3 真宿主探针、运行记录和技术结论，1.86.2 作为已有调研对照；本票不实现整套引用 UI。当前兼容下界按最新 AGENTS.md 对齐，不能用 1.86.2 的源码调研代替 1.82.3 下界验证。

## 实施范围

- 验证 A 活动、B 无独立标签时，保存 B、B 宿主历史撤销／重做与文档级丢弃的公开路线。候选需要切换活动标签或焦点时记录实际可见变化，不能默认获准该取舍。
- 验证宿主临时文档可否作为 vscode.diff 左侧、真实 B URI 作为右侧；记录保存、关闭、输入保留和资源释放的实际宿主行为，不设计自有 diff。
- 验证 onDidDispose 后 showTextDocument(existingB, preview:false) 的普通 A 关闭交接，含已有 B 标签和在途写回后才 dirty。
- 引用已核实的 1.86.2 API／源码事实，分开记录“API 存在”“探针通过”“Remote SSH 人工待验”。研究可提前，不关闭 #226 或 #227。

## 验收标准

- [x] 用真实 TextDocument 内容、isDirty、版本、tab／焦点和历史结果证明路由，不以 executeCommand mock 作为可行性证据。
- [x] A、B 各有独立修改，操作 B 的路由不错误落到 A；B 两视图交错修改后保持共享历史。宿主合法跨资源原子历史单独记录。
- [x] 保存失败和丢弃期间 B 再变化不会误关闭／误丢弃；丢弃能恢复整个 B 并清除目标 dirty。（丢弃后 undo 可翻回为宿主语义，单独记录）
- [x] 临时副本完整可读，打开对比失败不清除原输入；关闭与资源回收行为可复现，不能声称打开即已解决。
- [x] 普通 A 关闭后 dirty B 正确打开且去重；干净 B 不打开，窗口退出不误套用交接。
- [x] 任一关键路线无法满足产品契约时，结论标为阻塞并列出精确证据与所需取舍，不放行依赖实施票。（实测无阻塞路线；两项取舍列结论文档第 10 节，确认前不放行 P2-04／P2-05／P2-12／P2-13）
