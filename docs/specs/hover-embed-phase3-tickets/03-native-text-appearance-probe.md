## 问题与交付

语法／语义／主题／字体可达性探针及原生对照差异清单。

## 实施范围

- 以原生文字外观为目标：语言高亮、当前主题、字体字号和行号。先核实 TextDocument.languageId、资源／语言设置、已装插件 grammar 与主题文件能否公开读取。
- 验证 1.82.3 的 provideDocumentSemanticTokens／Legend 等公开命令；完整语法层候选为复用已装 TextMate grammar 的通用引擎，不内置各语言 grammar，不复制 VSCode 内部服务。
- 对照至少一种语法＋语义语言、一种仅 grammar 语言、一个受控第三方 grammar，以及原生本来无高亮的文件；覆盖明暗主题、主题 include、tokenColor／semanticToken 自定义与语言级字体设置。
- 分别验证 Windows 本地和 Remote SSH 下语言插件、主题位于不同宿主时的实际可达性、更新及成本；不能默认远端扩展进程能读取客户端所有 UI 扩展。

## 验收标准

- [ ] 输出可复现的原生截图／token／颜色／字体对照，分别记录数据可取得、预览确实绘制、与原生一致或差异；仅 API 存在不能算可行性通过。
- [ ] 所有高亮源可追溯到用户已装插件／当前主题；没有为样本语言硬编码配色或自行内置语言定义。
- [ ] 语义 provider 缺失、超时、扩展更新和目标未保存版本变化不产生错版 token；原生本来纯文本时，纯文本呈现不算降级。
- [ ] 本地／远程 grammar 和主题可达性有证据；若需新增客户端辅助扩展、改变产品形态或抬高下界，先报告取舍。
- [ ] 关键文字外观无法对齐时列出差异；用户尚未授权把原生有高亮的文件直接降成纯文本。P3-08 只有路线通过且必要差异获接受后放行。

## 复用入口与验证

VSCode 1.82.3 extHostApiCommands、官方 Syntax／Semantic Highlight Guide；src/host/hoverDocAccess.ts、test/integration/testHost.mjs；原生对照截图只作测试证据，生产不访问工作台 DOM。

## 明确排除

诊断波浪线、插件额外装饰、行内提示、完整原生编辑器 UI、文本编辑；本票不预先宣布 TextMate／主题方案已经选定。

## 共同完成条件

- 对可执行行为先补能暴露目标问题的契约测试，再实现；采用生产 browser／真实宿主等既有高层入口，不只检查消息调用次数或 DOM 存在。
- 呈现变更先加载项目 style-contract、固定旧契约，提供实际绘制和 CSS 契约证据。所有用户文字经 locales／t()，设置只进 Vsidian 自有页面。
- 每个新增操作登记可绑定入口、默认值和有效状态；只读内容不接管写操作，焦点和 Esc 沿用已有优先级。
- 来源验证、请求代次、目标版本、挂载释放及已存在预算都必须保持；自动化通过不等同用户验收。首次长命令即落盘日志和退出码，复核读取报告。
- 每票按一个新 agent 上下文安排；发现需要扩大接口／产品范围时报告增量并重切片，不将不完整行为标为完成。本票不授权推送、PR、合并或版本发布。
