## 问题与交付

PDF 在浮层与全部既有正文嵌入容器中按页浏览全文。

## 实施范围

- 在悬停、独占行、混排／列表／引用和表格格内 ![[文件.pdf]] 接入同一只读 PDF 内容视图；容器只负责尺寸、挂载和焦点。
- 目标全文可达，初始页码不变成读取范围；按可见页挂载 canvas，保留页面高度占位与本次 occurrence 滚动状态，离屏页取消并回收。
- 落实 P3-02 锁定的源字节、页像素、总 canvas、worker 和并发预算；同目标数据可共享，各引用位置的滚动与生命周期独立。
- 文件 changed／deleted／stale 与恢复分别处理，PDF 替换后重载并合法保留／钳制当前浏览位置；初次非法页码仍按 P3-05 报错。

## 验收标准

- [ ] 带大量页面的样本可从首到末浏览，绘制层证明中段／末段确实呈现，canvas 常驻与费用不随总页数线性增长。
- [ ] 所有既有容器下页码定位、内部滚动、父 Live 源码显隐均正确；PDF 操作不进入父编辑或表格导航。
- [ ] 同 PDF 两个 occurrence 可独立滚动、关闭一个不销毁另一个；父来源回收同时释放其子 PDF 的资格与资源。
- [ ] 删除撤下旧页，权限／断连给 stale 或读取失败，恢复可重试，不把旧快照宣称为已更新。
- [ ] 重复开关／滚动／切模式后 worker、Blob、canvas、任务和 watch 回到实际仍存活实例对应的水平。

## 复用入口与验证

src/webview/embedCard.ts、refContentInstance.ts、hoverPopup.ts、reading／Live 容器适配；P3-02 资源计量与 PDF 视口接口。

## 明确排除

全文搜索、PDF 标注、区域裁剪、页面编辑；不将 PDF 设为可写 Live，不打开额外编辑标签页。

## 共同完成条件

- 对可执行行为先补能暴露目标问题的契约测试，再实现；采用生产 browser／真实宿主等既有高层入口，不只检查消息调用次数或 DOM 存在。
- 呈现变更先加载项目 style-contract、固定旧契约，提供实际绘制和 CSS 契约证据。所有用户文字经 locales／t()，设置只进 Vsidian 自有页面。
- 每个新增操作登记可绑定入口、默认值和有效状态；只读内容不接管写操作，焦点和 Esc 沿用已有优先级。
- 来源验证、请求代次、目标版本、挂载释放及已存在预算都必须保持；自动化通过不等同用户验收。首次长命令即落盘日志和退出码，复核读取报告。
- 每票按一个新 agent 上下文安排；发现需要扩大接口／产品范围时报告增量并重切片，不将不完整行为标为完成。本票不授权推送、PR、合并或版本发布。
