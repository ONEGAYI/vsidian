## 问题与交付

原网页模式尽力显示网站，不可用时提供卡片和退回原因。

## 实施范围

- 自有设置页允许从默认卡片改为原网页，外链总开关仍默认关闭；保持同一浮层／来源／请求代次，不新建矛盾的关闭机制。
- 使用跨源沙箱 iframe，仅明确允许的网站内容能力；不泄露 acquireVsCodeApi／来源租约／本地资源，不给顶层导航、下载或宿主命令权限，不反向代理改写网站安全头。
- 元信息服务预检查已知 X-Frame-Options／frame-ancestors 限制，HTTP 页面无法安全内嵌、已知拒绝或网络失败时退回卡片并说明原因。
- 始终提供退回卡片和在浏览器打开入口。跨源 iframe 的 load 不证明加载成功、error 不可靠；无法观察的登录／脚本失败只给无法确认的真实状态，不编造检测结果。
- 原网页网络在客户端 webview 中发生，可能连到目标及其第三方站点；与宿主元信息抓取位置／防私网规则区分。设置说明如实告知，不承诺继承日常浏览器登录态。

## 验收标准

- [ ] 受控可嵌入站点在 VSCode 1.82.3 真宿主实际可见且可滚动，不能仅断言 iframe DOM／load 事件。
- [ ] DENY／SAMEORIGIN／禁止 frame-ancestors、HTTP 混合内容和超时样本有卡片、退回原因与打开入口。
- [ ] 无法可靠探测的空白／登录情况有可操作的退回入口和如实说明；自动／手动退回不偷偷更改用户形态设置。
- [ ] 恶意子页不能取得消息桥、工作区资源、顶层导航或任意宿主命令；父 webview 不扩大外网脚本与 connect-src 权限。
- [ ] 关闭、改目标、开关关闭和切模式后销毁 iframe、取消请求、释放监听；明暗／高对比下退回文字实际可见。

## 复用入口与验证

P3-10 卡片／元信息服务、src/host/editorCsp.ts、hoverPopup.ts、settings／locales；官方 iframe 与 Webview CSP 规则。

## 明确排除

绕过网站拒绝内嵌策略、网页登录代理、抓取完整正文重排、保证所有网站成功展示。

## 共同完成条件

- 对可执行行为先补能暴露目标问题的契约测试，再实现；采用生产 browser／真实宿主等既有高层入口，不只检查消息调用次数或 DOM 存在。
- 呈现变更先加载项目 style-contract、固定旧契约，提供实际绘制和 CSS 契约证据。所有用户文字经 locales／t()，设置只进 Vsidian 自有页面。
- 每个新增操作登记可绑定入口、默认值和有效状态；只读内容不接管写操作，焦点和 Esc 沿用已有优先级。
- 来源验证、请求代次、目标版本、挂载释放及已存在预算都必须保持；自动化通过不等同用户验收。首次长命令即落盘日志和退出码，复核读取报告。
