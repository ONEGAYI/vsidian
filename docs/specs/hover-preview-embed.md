## 目标与分期

在当前文档中查看引用目标，减少来回打开文件，同时为可编辑引用视图与其他文件类型保留架构空间。

| 阶段 | 交付范围 |
| --- | --- |
| 一期 | Markdown 悬停与嵌入，内部明确使用 Reading 视图且禁用写入；全文、标题章节、块引用 |
| 1.5 期 | 递归，以及表格单元格、文字混排、列表／引用容器内的嵌入 |
| 二期 | 悬停与嵌入内部的 Live 编辑，修改归属目标文档 |
| 三期 | PDF 预览与嵌入，具体渲染器与定位能力另行细化 |

父文档 Live／Reading 是展示环境，引用内容 Reading／Live 是内部视图模式，两者独立。一期父文档为 Live 时，嵌入内部仍是 Reading，不能称为“只读 Live”。

一期不包含：引用内容写入、递归展开、多层悬停浮窗、固定／拖动浮窗、PDF、其他附件新渲染器及混排嵌入。现有 Markdown 内容里的图片、公式、代码和图表仍复用既有阅读能力；不由本规格扩展它们的语法范围。

原生资源管理器文件悬停（2026-09-30 验收提问调研结论）：VSCode 公开 API 不支持——扩展进程无工作台 UI DOM 访问，原生 Explorer 文件树没有悬停扩展点；`TreeItem.tooltip` 只作用于扩展自建 TreeView，且是声明式 MarkdownString（宿主渲染、无悬停事件回调、无法感知 Ctrl/Cmd 修饰位），既做不到「必须 Ctrl」门控也承载不了完整 Reading 预览。后续若引入非 Markdown 类型（PDF/PNG）：目标装载链路的扩展点在 `hover.result` 回包加类型分派字段（缺省 markdown 向后兼容）+ webview 渲染侧按类型分派渲染器，`HoverPopupTargetSpec` 的目标身份抽象（target/linkHref/directFsPath）无需变动。

## 一期交互契约

### 悬停与键盘预览

- 正文双链、本地 Markdown 普通链接、反链／出链面板均支持预览；外部网页不接入本功能。
- 父文档 Live 默认 Ctrl+悬停，插件自有设置页可开启直接悬停；Reading 和反链／出链面板直接悬停，面板不随正文模式改变触发规则。
- Live 鼠标悬停按实际命中的链接装饰 DOM 起点解析源码目标，整段可见文字均为热区（含长路径、别名与相邻链接）；「先悬停再按 Ctrl/Cmd」同样采用该映射。不能用替换 widget 的 `posAtCoords` 结果直接判定：右半段会落在源码区间的结束位置。键盘预览仍按光标的精确源码位置判定，不扩展原有区间边界。（2026-09-30 验收跟进）
- 登记“预览当前链接”可绑定操作，默认未绑定。Live 以光标处的合法普通链接／双链为目标；Reading／面板以键盘聚焦链接为目标。原生源码编辑器不接管。
- 键盘命令是手动打开悬停浮层，不是光标进入链接就自动弹出。`![[…]]` 已有常驻嵌入内容，不再通过此命令生成重复浮层。
- 鼠标悬停不抢焦点；键盘打开时进入浮层，Esc 关闭后返回触发处。焦点在浮层内部时不能仅因鼠标离开而销毁键盘操作现场。
- 移入浮层后保活，可滚动和复制；鼠标离开链接与浮层后延迟关闭。面板销毁、切模式等使触发上下文失效时释放实例；异步迟到响应不得重开已关闭浮层。
- 窗口失焦（blur）或文档不可见即刻关闭浮层并取消待开计时（瞬态 UI 语义，与宿主 hover 一致）。成因：Chromium 对未聚焦窗口不派发 mouseout，切窗期间关闭计时永不启动，浮层滞留后台遮挡正文拦截 mouseover——切回后悬停完全失效，需点侧栏或切页才恢复（2026-09-30 验收反馈）。键盘模态不豁免：窗口失焦时键盘现场已断，关闭返还先前焦点无副作用。
- 一次显示一个浮层，内部链接可点击跳转，不再次叠加悬停窗口。
- 浮层顶部常驻标题条（#217 验收跟进，嵌入卡片同款）：左侧目标显示名（`spec.target`，不随回包换），右上角跳转按钮（同款外部跳转图标）。点击按目标形态分派——双链/普通链接直发既有激活消息（父文档身份解析，不带 sourceDocUri），反链/出链条目经调用方 `openAction` 闭包走条目点击同通道（反链定位引用处、出链带锚点）；点击即上下文切换关闭。
- 浮层内 Reading 容器采用 `10px 14px` 紧凑内边距；规则须在 `#app` 作用域内覆盖正文阅读容器的 `40vh` 底部留白，避免短文末尾出现随窗口高度变化的大截空白。正文自身的文末留白及引用内容的主题、别名桥与片段入口保持原有语义。（2026-09-30 验收跟进）
- 默认宽 480px、最大高度 400px；靠近边缘翻转，空间不足时收缩并约束在可用视口内。窗口缩放、内容变高后重新定位。

### 正文嵌入与源码显隐

- 一期支持独占正文一行的 `![[…]]`，沿用双链目标内部语法，可引用全文、标题或块。围栏／行内代码内的字面文本不作为嵌入。
- 混排、列表／引用容器及表格格内暂保留源文，1.5 期接入。首期限制只属于挂载适配，不得写死进目标解析和内容服务。
- 外观采用用户截图标注：左侧引用块样式边条，顶部文件名，右上角跳转目标文档入口。具体字体与颜色随主题，不逐像素复制截图。
- 短内容自然高度；长内容内部滚动，默认最大高度 480px，可在自有设置页调整。尺寸为实施初值，视觉验收可校准。
- 父文档 Live 中，光标／选区触及引用源码区间则显形，离开则隐藏，不设置“编辑引用”按钮。源码显形时下方 Reading 内容继续显示。
- 显隐采用已有 `selectionTouchesRange` 语义：折叠光标命中区间内部或两端；非空选区与区间严格重叠；任一 CM6 选区命中即显形。不扩大到任意相邻行。
- Reading 内部选字属于浏览器文本选区，不能被误当作父文档 CM6 源码选区；点击内容不能导致父文档错误编辑、菜单操作或写回。
- 源码未闭合时保留可编辑原文并撤下旧目标内容；完整但目标文件／锚点缺失时就地提示。修正或目标恢复后自动重新加载，不自动创建文档，不以全文代替缺失章节。
- 右上角入口与内部链接复用现有 Vsidian 打开和锚点定位行为；打开新目标不修改引用原文。

### Reading 内容、属性与刷新

- 任务框不可修改，frontmatter 无添加／删除／编辑入口。选字复制、滚动、属性折叠及跳转均不写文档。
- 全文引用保留“笔记属性”区。标题整行是悬停热区，悬停显示展开／折叠按钮，点击按钮切换；不是悬停自动展开。按钮键盘聚焦时也显示，Enter／Space 可操作。
- 属性区默认折叠，本次打开内保留展开状态，刷新不重置；重新打开恢复折叠。无 frontmatter 不显示标题行，章节／块引用不额外附带属性区。
- 属性支持类型与非法内容降级沿用现有 frontmatter 能力；截图中的更多类型及写操作不构成扩展要求，不静默丢弃不支持的原文。
- 跟随目标文档未保存修改：以宿主已收到的内容为准，短暂合并刷新，不等待保存。不承诺尚未送达宿主的前端输入已经可见。
- 刷新尽量保持滚动位置，目标范围变化时重新定位；内容缩短时合法钳制。目标引用改变视为新目标，不继续把旧内容显示成新目标。
- 引用内容沿用当前 Vsidian 主题及已启用 CSS 片段，增加悬停／嵌入专属样式入口；不为每份目标文档创建独立主题环境。

### 一层展开的含义

A 嵌入 B：显示 B；B 内的 `![[C]]` 只显示可打开的引用占位，不显示 C 正文。占位目标按 B 的目录解析。单独打开 B 后，C 相对新主文档 B 成为第一层，可正常显示。

嵌入深度和浮层叠加是两个维度。1.5 期分别设计递归预算与多层交互，不能用全局 visited 集合禁止合法重复引用。

## 通用架构与接口责任

### 分层

| 层 | 责任 | 不负责 |
| --- | --- | --- |
| 文档访问 | 目标解析、带版本正文、范围定位、资源上下文、更新订阅与释放 | 视图布局和编辑输入 |
| 内容视图 | Reading 渲染；未来按类型接入 Live、PDF；管理内部滚动与状态 | 判定自己放在浮层还是表格格内 |
| 展示容器 | 悬停定位／保活、嵌入挂载与高度；提供可用空间和生命周期 | 直接读取文件或写目标正文 |
| 编辑能力（二期） | 版本校验、范围映射、目标文档写回与同步 | 成为只读访问的依赖 |

只读视图不获得写入端口。未来 Live 可按可见实例创建独立 CM6 EditorView，共享目标文档内容服务，各自拥有选区和滚动状态；不创建独立 WebviewPanel 承载每个引用。

### 文档访问与消息约束

- 请求关联来源文档、父引用区间、引用原文、视图实例标识及请求代次；宿主按已绑定面板上下文校验，不信任前端任意 URI。
- 结果携带规范目标身份、目标版本、语义范围选择器、LF UTF-16 源范围和内容／解析上下文。不能只返回脱离来源的 HTML。
- 章节取目标标题至下一个同级或更高级标题之前，包含目标标题；匹配沿用现有 ATX、同名取首边界。块范围复用既有块 id 归属逻辑并扩展到完整块，不能拿块首行当完整正文。
- 保留全文解析上下文再选取目标范围，避免章节外的引用式链接定义丢失；不要孤立解析截取字符串。
- A 引用 B 时，B 内部链接和图片以 B 为来源；图片资源经宿主现有路径边界与 webview URI 机制加载。
- 使用 ADR-0008 的根内相对路径语义；不恢复 ADR-0002 的 basename 搜索或候选选择。索引不保存全文，不作为正文事实源。
- 订阅覆盖宿主文档修改与相关文件变化；版本变更使缓存失效。请求代次和内容版本分别校验，旧响应不能覆盖新目标或更新版本。
- 缓存有容量／内存限制，按规范目标、版本、范围、渲染选项区分；相同目标合并读取，实例订阅独立释放。DOM、文档解析和资源缓存分别计量。
- 错误至少区分文件缺失、锚点缺失、越界／不支持、读取失败与取消。就地 i18n 呈现，不连续弹宿主通知；确认删除后不无限保留旧内容。
- 更新共享消息协议及运行期校验；只读引用消息不进入父文档 edit.request 通道。二期再设计目标文档编辑路由。

### 后续阶段预留

1.5 期：引用识别保留父容器上下文，顶层块、混排、列表／引用容器、表格单元格各自适配挂载。父引用区间与目标源范围分开；表格转义、焦点和宽度不借用顶层块假设。递归沿展开路径记录目标与范围，独立限制深度、实例数及字节预算。

二期：必须另行细化现有文档会话多视图接入、带版本编辑、冲突、范围变化、撤销与保存归属、焦点与快捷键隔离。接口预留不等于这些问题已经实现。

三期：文件类型选择渲染器，PDF 不是先转 Markdown，也不要求复制一个已打开窗口的画面。引擎选型、页码与区域定位另议。

- **挂载边界**：`RefContentMount` 接收正文 DOM 与实际滚动壳，提供 render／clear／dispose、图片回包与失效、滚动恢复和监听器释放。图片资源、属性按钮监听器、内容块、延迟恢复帧与虚拟视图 observer 随挂载释放；浮层计时器、全局监听器和订阅经实例清理回调配对释放。外壳布局、可用空间与 CM6 `requestMeasure` 留在父适配器。本票保持卡片全量挂载与浮层原 VirtualReadingView 策略；实际内部滚动视口虚拟化由 #243 接入。

#### #242 来源租约交接（独立审查修复）

「刚送达」不能只保护本次回包：旧目标先退订再订阅新目标，或两个成功回包等待前端订阅，都可能发生容量回收。本票以显式来源租约固定这段生命周期，不使用延迟常数或提高容量规避。

1. 生产卡片／浮层的 `hover.request` 附 `retainSource: true`。宿主成功送达时单独生成 `sourceLeaseId` 并登记目标；失败不授予租约。旧请求不带此字段时维持旧协议兼容。
2. 前端接受回包后，首次／换目标的 `hover.watch` 附租约，宿主核对会话与目标后先登记 occurrence 持有，再消耗待订阅租约。重复 watch 幂等；已消耗租约不能交给另一个引用位置。
3. 同目标已订阅的刷新、陈旧版本或未被任何容器接纳的迟到成功回包，经 `hover.source.release` 放弃临时租约；退订只释放 occurrence 持有。释放重复或未知 token 无副作用，面板销毁整体释放。
4. `syncController` 先把结果交到实际消费者，浮层／卡片均不消费时才统一释放，未命中的容器不能提前撤销另一容器的租约。租约属于一次送达，宿主缓存的读取结果和 `RefLoadedContent` 不保存 token；同一缓存数据的两次送达有独立租约。

`DocumentSession.retainHoverSource` 是 provider 与会话消息入口共用的原子转交面；来源与目标、会话、occurrence 的校验在此闭合。未消费租约与已持有来源不计入可静默淘汰的缓存对象，未来 #244 须在请求／展开前执行预算及准入，而不能复用 token 或依赖 LRU 撤权。此扩展仍不启递归和全局预算。

### #243 引用长文内部视口挂载（2026-09-30）

卡片与浮层各自把外层滚动区作为 `VirtualReadingView.scrollEl`；内容容器只负责块 DOM 与实测。主文档仍缺省以自身同时承担两者。外层滚动、尺寸变化与块高回填驱动窗口差分；`RefContentMount` 配对监听、恢复滚动与释放资源。外壳尚未进入布局时，先用两个估计高度 spacer 撑开滚动区，等待真实视口出现后再挂首窗，不先创建全文节点。滚动到末尾后实测总高增长时保持末尾意图；用户主动滚动产生的首次估计校正不平移其位置，已测块的图片迟到增高仍按锚点补偿。

全文先解析为块，再按章节／块的 LF 范围求交；滚动只重排窗口。同目标且版本、正文相同的卡片／浮层实例可共用只读块模型，DOM、图片管理器、属性展开和滚动位置仍逐实例独立。语言包装配变化会清空解析缓存，因为块 HTML 可能包含 `t()` 文案。缓存最多四项、估算驻留总量 2 MiB、单项 512 KiB；超大目标不入该缓存，仍可由当前实例按视口挂载。估算按 UTF-16 正文和块 HTML 加每块 128 字节元数据计；这不是整树来源／订阅预算，后者仍由 #244 处理。

长文浏览器绘制、解析／DOM／回收和巨大单块边界的数据见 [性能记录](../perf/2026-09-hover-preview-embed-performance.md)。1000 段多块长文可按首／中／末挂载；1000 项同一列表仍是一个块，会一次生成 1000 个列表项，不能据多块结果宣称任意节点量恒定。卡片内嵌入继续只显示占位引用行，递归、混排、目标 Live 写回与 PDF 均未启用。没有新增用户操作或设置；复用既有预览、打开目标与 `embed.maxHeight`，快捷键登记不变。

公开样式入口对照已发布 v0.7.0（`c85d244578f41bb61654b5b9232f474fee6a4219`）和本票固定基点 `9f0c0d30fc5842c14b928b07e343b67c140e1ac4`：`.vsidian-hover-popup`、`.vsidian-hover-popup-scroll`、`.vsidian-embed-card`、`.vsidian-embed-card-scroll` 及其内部 `.vsidian-view-reading` 关系与变量保留；块的在场集合随视口变化，没有弃用或新增公开选择器。自动化通过与用户验收分开记录于 [人工验证清单](manual-verification.md)。

### #244 独占行卡片递归（2026-10-01）

父文档 Reading／Live 的独占行卡片现在沿 A→B→C→D 自动展开；A 是第 0 层，B/C/D 为第 1/2/3 层。目标内部仍是禁写 Reading。第四层显示深度说明与按直接父来源打开目标的入口，不发绕过限额的读取。`embed.maxDepth` 在插件自有设置页的「引用视图」组（2026-10 设置组批次自「显示」组迁入，见 [reference-view-group.md](reference-view-group.md)），默认 3、有效范围 1–6、步进 1；设为 1 恢复单层，保存立即撤下或重试后代，重开后按持久值回显。复用 `embed.maxHeight`：短卡自然高度，长卡各自限高、各自滚动和恢复；滚轮先由命中层消费，到边界时把剩余意图交给最近可滚动的外层。

**来源与路径**：`hover.request` 的根面板 `docUri` 始终是 A；子请求附父 occurrence 与宿主已送达的直接来源 fsPath。宿主只认本面板仍被 watch 固定的父实例；读取当前父 `TextDocument`，要求版本未变、子引用 LF 区间落在父语义范围内、整行独占嵌入原文精确匹配，且不在 frontmatter、注释或代码上下文。通过后才以 B 的目录和工作区根解析 C；`directTarget`／普通链接形态不能绕过这条子来源链。成功结果的租约按父 occurrence、目标版本、语义范围与当前路径交接；同 fsPath 未保存刷新仍发送新租约，先更新父关系再挂子块。父卸载、目标替换或迟到回包不能复活旧后代。读取缓存／在途键加规范父 fsPath 与版本，两个目录相同原文不串用。子卡原生右键止于只读卡片域，保留浏览器选字／复制，不触发父 Live 的写操作菜单。

循环节点是宿主平台规范化 fsPath 加 full／heading／block 语义范围；标题按既有标题匹配规则归一空白和大小写，块 id 保留大小写。根 A 的 full 节点进入路径；只查当前祖先，A→A、A→B→A 截断，兄弟重复 B、合法不同范围及两支共享 C 不因全局 visited 被误杀。循环、深度、预算、缺文件／锚点、来源过期各有就地语言包文案，卡片头部仍保留打开入口。

**容量与计量**：每棵根卡树最多 24 个 occurrence、宿主 LF 全文计费最多 2 MiB、webview 全文加生成 HTML／块元数据最多 2 MiB；每面板分别为 64 个 occurrence、8 MiB、8 MiB；宿主端每面板最多 8 个引用读取。并发按每次真实端口请求的 token 计数；occurrence 卸载或旧租约释放不归还尚未完成的读取许可，回报只结算自己的 token。文本按 UTF-16 code unit×2 加 128 字节记录；webview 在全文解析后按正文与全部块 HTML 的 UTF-16 长度×2、每块 128 字节近似元数据收费，超限在挂 DOM 前拒绝。每 occurrence 以及同 occurrence 双容器挂载保守重复收费，不把相同 fsPath/version 当作已共享的物理副本；实际解析块缓存另有四项／2 MiB／单项 512 KiB 的全局界限，宿主读取缓存另有 24 项／2 MiB 界限。块窗口、图片与 DOM 随挂载回收，离屏 root entry 保留正文与预算，子树离屏则退订、释放并在重挂时重读。provider 内 128 个规范目标 watch 槽跨文档和面板共用：满额拒绝新目标，保留既有订阅；拒绝经 `hover.watch.rejected` 到可见卡片／浮层撤下无刷新正文。每次送达租约关联拒绝回执，旧拒绝不撤新版本。

公开类名和 CSS 变量未改；嵌套复用 `.vsidian-embed-card`、`.vsidian-embed-card-scroll`、`.vsidian-view-reading`，卡片来源与绘制由真实 Chromium 验证。新增的只是原有卡片内再次挂载同一壳，不启用多层悬停浮窗（#245）、混排／列表／引用（#246）、表格格内（#248）、目标 Live 写回（#227）或 PDF（#228）。本票没有新增可绑定操作：仍用既有打开目标入口与「预览当前链接」操作，默认键位不变。自动化与人工待验见 [验证清单](manual-verification.md)。

预算单位、样本与关闭后的缓存边界见 [#244 驻留与滚动测量](../perf/2026-10-ref-expansion-244.md)。

### #245 悬停浮层内递归（2026-10-01）

### #246 Reading 混排、列表与引用容器（2026-10-01）

Reading 侧（主文档正文、卡片内容与悬停内容三处同一装配）的 `![[…]]` 不再要求独占正文一行：`前文 ![[B]] 后文` 渲染为「前文 → 块级卡片 → 后文」，无序/有序/任务列表、列表懒续行、blockquote 及二者的组合内嵌入升级为流内卡片，源文件不插入换行。渲染分段不改源文——全部变换发生在块 DOM 挂载阶段，块 HTML 重建即回到占位形态。

**识别与配对（三层同源）**：

- 渲染占位：markdown-it inline 规则（`shared/wikilink` 新增 `embedAtPosition`——与 `scanEmbedsInLine` 逐字节同源，命中集合由对拍测试钉住）在段落/列表/引用/表格的行内内容产出 `span.vsidian-embed-slot`（携带 `data-vsidian-embed-inner`）。占位是 span 而非 a：可处于链接文字域而不产生嵌套 a 的非法 DOM；代码字面量不产占位（backticks 先消费、围栏不进 inline——不通过删守卫把字面量升级为引用）。
- 区间回算：inline token 无全文坐标（列表缩进剥离与懒续行使换算不可靠），挂载时由 `webview/embedSlots` 的 `blockEmbedOccurrences` 按 lezer 树语法上下文（代码/注释/表格/frontmatter 排除，与 `validChildSource`、`vaultLinkExtract` 同边界）扫描块区间，与 DOM 占位按「inner 分组计数」顺序配对（第 k 个同 inner 占位 ↔ 第 k 个命中）。配对失败整块降级（占位保持文本形态）。**图片 alt 域排除**（终审 P1-1 修复）：markdown-it 把图片 alt 渲染为属性、占位不落 DOM，occurrence 侧同样排除**恰好图片 alt 内部**的字面量（`shared/wikilink` 的 `imageAltRangesInLine` 宁窄勿宽口径：行内式须目标 `(...)` 闭合、引用式须 ref 已定义——markdown-it 对未定义 ref 按字面文本渲染占位照落 DOM，不排除）——否则 alt 内字面量命中使序列不等、整块降级牵连同块合法嵌入。
- 挂载提升：`promoteEmbedSlot` 把占位提升为流内宿主 `div.vsidian-reading-embed.vsidian-reading-embed-mixed`（与独占行 embed 块同构 dataset——`EmbedCardManager.mountCardInto` / `mountChildFrom` 原样复用）。p 内拆段（前文 p + 宿主 + 后文 p，属性克隆、空半不产出——合法 DOM）；横跨嵌入的粗体/斜体/高亮经拆壳成为前后各完整的行内标签；列表项与引用内直接落位（编号、缩进、边条容器不拆）；宿主宽度跟随所属列/缩进区域。同段/行多个嵌入各按 occurrence 区间独立成卡、保持源顺序，不共享行首身份。

**宿主准入（`shared/refExpansion.validChildSource`）**：子请求区间不再要求独占整行，改为「该行内一个完整嵌入 occurrence 的精确边界且 inner 逐字节匹配」；列表/引用（含任务、嵌套、懒续行与组合）从语法排除中放行。守卫保留：代码（围栏/缩进/行内）、frontmatter、HTML 注释与表格（#248）仍拒绝——原注释检查的行级 `stripHtmlComments` 对拍被 lezer 节点判定取代（实测节点名 Comment/CommentBlock；原集合中的 `HTMLComment` 条目从未命中过，本次更正）。Live 侧混排（#247）与表格格内（#248）不在本票：Live 保持源文，表格格内为占位文本。

**索引与 rename 同源**：`vaultLinkExtract` 行扫描本就不设行独占（混排/容器位置照常产边，区间为嵌入原文精确边界——本票以集成用例与单测钉住）；随呈现接入补齐**注释排除**（lezer Comment/CommentBlock 加入 `INLINE_SCAN_CODE_CONTEXTS` 的宿主侧复制）——阅读呈现对注释整段剥离（#139），行扫描若在注释内产边即与「呈现不可见」分叉（反链出现不可见引用、rename 触达不可见位置）。vaultRename 沿嵌入边区间只改路径、别名与锚点保留，与位置无关，无平行扫描器。链接文字域内的嵌入（`[文字 ![[B]] 文字](url)`——行扫描形态学命中、索引照常产边）：渲染侧产占位（识别同源）但提升层以 a 祖先拒绝升级（块级卡片在行内链接内属非法 DOM），占位保持文本、点击走外层链接——该呈现差异在 `embed-slot` 条目与浏览器用例钉住。

### #247 Live 混排、列表与引用容器的精确源码显隐（2026-10-01）

Live 侧（父文档第 0 层）的 `![[…]]` 不再要求独占正文一行：段落混排、无序/有序/任务列表项、列表懒续行、blockquote 及其组合内的嵌入经 #246 同源识别（`scanEmbedsInLine` occurrence——Live 嵌入表 `liveEmbedSpansField` 从 `soleEmbedOfLine` 扩展为逐行全部 occurrence，`sole` 标记随行判定）挂载共用卡片；实际源文不插入换行。

**精确替换与前后文保真**：隐形态只对嵌入精确区间 `[from, to]`（`![[…]]` 本身，#223/#224 的整行替换退役）做 inline replace——前后文字、列表标记/编号、任务控件、引用前缀与既有缩进保留在行内；宿主为 CSS 块级化的 div（行内块级打断呈现「前文 → 卡片 → 后文」，与 Reading 混排拆段同观感），replace 前后的 cm-widgetBuffer 零高块级化沿用。保持 inline replace（而非块级 replace）仍是键盘垂直导航可进入嵌入行的前提（ArrowUp/Down 逐行落点不越过区间）。

**精确显隐**：显隐谓词沿用 selectionTouchesRange——折叠光标含区间两端、非空选区严格相交、任一 CM6 range 命中即显形；**不扩大到相邻文字或整行**：光标在前后文/相邻文字上不显形（反例钉住）。显形态为行下方 block widget（below 卡），源文可见可编辑，兄弟卡片独立显隐（同行双嵌入互不牵连）。未闭合引用撤下旧目标卡片、保留可编辑原文；恢复闭合按新引用重载（增量表在编辑/换行/合行/撤销/外部同步下按 occurrence 精确区间重建，窗口外条目以行内重扫精确对齐校验）。

**发射层排除（与 #246 同源集合）**：表构建层仍不排除（候选表含排除位——探针 `liveEmbedReveal` 含链接域/表格候选 7 枚即彼故）；发射层在围栏表/文末开放围栏/frontmatter 既有排除之外新增 lezer 语法上下文（行内代码/HTML 块/注释/表格——`embedSlots.OCCURRENCE_EXCLUDED` 同集合，表格 #248 前排除）与**行内链接/图片文字域**（`shared/wikilink` 新增 `linkLabelRangesInLine` 保守方括号配对形态学：`[`（前缀非 `\`）压栈、`]` 弹栈后紧邻 `(` 或 `[` 的配对域为链接文字域；lezer 把 `![[x]]` 解析为 Image 节点无法区分链接域，形态学误判方向为「保持源文」的安全降级——与 Reading 侧「链接域占位不升级」呈现对齐）。终审 P1-1 起 Reading 配对面（`embedSlots`）复用同一栈扫描核心的更窄出口 `imageAltRangesInLine`（仅图片 alt 域，且行内式目标须闭合、引用式须 ref 已定义）：两口径分工——发射排除（Live）宁宽（误判方向是少挂卡的安全侧），配对排除（Reading）宁窄（误排除即整块降级回归）。

**跨模式状态共享的 key 口径**：独占行嵌入宿主 key = 行区间（`lineFrom..lineTo`，Reading 独占行 embed 块同口径）；混排/容器 occurrence 宿主 key = 嵌入精确区间（`from..to`，Reading #246 混排提升宿主同口径）——同一嵌入在 Live↔Reading 切换时共享 fm 展开与滚动状态。Live 根请求的 `sourceStart/sourceEnd` 按同口径（宿主对根面板请求不设区间校验）。

**交互隔离与输入保真**：宿主 `ignoreEvent=true` 沿用——卡片内浏览器选区、滚动、复制、内部链接、任务控件（禁写 disabled）与右键不冒泡为父编辑器输入/选区/写操作；源码编辑走正常 edit.request。动态子卡/图片高度经 ResizeObserver → requestMeasure 回填（卡片滚动壳限高 480px 与 Reading 侧同源 EmbedCardManager）。引用内容内部始终禁写 Reading（目标 Live 编辑仍属 #227）。

### 内容、定位与实例身份

1. 成功打开后，Reading／Live 使用目标全文。标题／块选择器与初始 LF UTF-16 定位点单独记录，不再充当内容或编辑边界；删除标题或块 id 不限制已经打开的全文编辑。重新打开原引用时仍验证原锚点。
2. 打开时文件存在但锚点缺失，沿用 `anchor-missing` 和既有 i18n 错误；不能偷偷打开全文顶部。缺文件、读失败、取消、预算拒绝继续分别呈现。
3. 原引用文本不因浏览全文、切模式或编辑目标自动改写。目标或引用原文改变时重新验证身份；不把旧 B 内容当成新目标。
4. 根面板 A、直接来源文档、来源 occurrence、规范目标 B、初始定位点分别建模。相对资源属于直接目标；递归 C 的引用原文与目录由直接来源 B 解释。
5. 同一目标的不同 occurrence 共用权威内容与历史，模式、选区、光标、滚动和折叠状态各自独立；同一位置父模式切换或重新挂载恢复本次会话状态。关闭面板结束这份会话记忆。
6. 全文可达后，同一目标的不同锚点不再代表不同内容范围。递归祖先循环判定按规范目标文档身份，初始锚点不用于绕过循环；兄弟重复目标仍合法。这是 ADR-0011 对旧范围身份的配套调整，不能删除来源准入或预算守卫。
7. 数据预算按实际保留的全文及解析副本计费，不因导航选择器是标题／块而只收局部费用。

### 模式、可见性与能力

- 未手动选择的实例跟随直接父视图；父为引用视图时取它的内部模式。例如 A Live、B 手动 Reading，B 内的 C 默认 Reading。
- 用户手动选择后，本次面板会话内不再被父变化覆盖；不增加新默认模式设置或自动重置用户选择的入口。
- 只有可见且有效模式为 Live 的引用创建可写 EditorView。Reading 沿用只读渲染和按需块挂载，不取得编辑端口，任务、属性、菜单及快捷键均不能写入目标。
- 离屏可回收编辑器并保存实例状态；B dirty 文档由宿主管理，dirty 不要求每张嵌入卡的编辑器常驻。组合输入、提交或冲突输入未妥善处理前，不能按普通离屏流程销毁最后一份输入。
- 完整复用正文 Live 已有扩展和操作；引用内容不复制主面板的侧栏、顶栏、设置控制器或整个 WebviewSyncController。共享功能通过实例上下文运行，不能依赖唯一主编辑器的全局变量。
- 父正文源码显隐仍按原有 occurrence 与选区规则；B 的输入、选区、右键和格内导航不得触发 A 的编辑或表格操作。弹出的属性、菜单、图形／图片界面应保留其所属目标与调用实例。

### 编辑、保存与历史

- 宿主每个 B 只有一个权威 TextDocument 与 DocumentSession，引用实例以独立编辑端口接入；不创建每卡片的权威副本或独立 CM6 history 栈。
- 目标提交复用 LF／CRLF 协调、seq 去重、版本映射、串行写回、ack 与外部变更排序。宿主必须从已确认的来源租约绑定 B，拒绝前端自报任意 URI、过期实例、Reading 写请求和释放后的迟到消息。
- 根面板身份用于认证和生命周期；目标端口身份用于 B 的编辑与操作。消息路由和回包携带实例／挂载代次及目标版本，不能把 B 的 ack、dirty 或资源结果回到 A 或另一 occurrence。
- 焦点在 B 正文或其编辑控件时，保存只调用 B 的保存，撤销／重做作用于 B 宿主历史；返回 A 后恢复 A。两份 B 视图交错编辑仍是一份共享历史。
- 菜单在打开时捕获实际编辑目标，执行前重验端口；焦点切换或实例释放后不误向当前主编辑器分派。快捷键遵守弹窗、输入框和正文原有优先级，避免同一按键被父子同时消费。
- 撤销 B 必须经过 P2-01 的真宿主证明。向全局 undo／redo 追加 URI、调用未公开内部服务或悄悄为引用新增历史栈，都不能当作通过验证的实现。若候选路线改变用户可见活动标签／焦点，报告实际行为后再确认该取舍。
- “只操作 B”指路由归属 B；宿主合法的跨资源原子历史应保留宿主语义，不能误称每次撤销都必然只改一个文件。

### 浮窗标题、保活与关闭

浮窗 head 显示规范目标的文档名称标题，B 未保存时名称旁显示精确字符 `·`。别名和父 A dirty 不替代 B 名称或状态。引用头部提供保存 B 和切换内部模式的入口，嵌入也显示目标未保存状态。

| 当前情况 | 行为 |
| --- | --- |
| Reading 或目标干净的 Live | 沿用现有普通悬停规则，包括移出延迟关闭、失焦／不可见关闭和已有键盘焦点规则 |
| Live 且 B dirty | 移出、外点、失焦等普通关闭条件不销毁；保持可通过显式入口关闭 |
| IME 组合期或提交在途 | 暂缓销毁，完成后重新按模式与最新 dirty 判断 |
| 当前输入因冲突尚未写入 B | 按冲突选择处理；B 干净不等于该输入可丢弃 |
| 干净引用关闭后再打开 | 按同位置本次会话状态恢复，不要求原 EditorView 常驻 |

插件可控的关闭按钮、Esc 和删除正在编辑的引用等显式退出，在待提交处理完成后检查目标 dirty，使用宿主模态确认或同等可访问的插件模态界面，不调用 window.alert。

| 按钮 | 契约 |
| --- | --- |
| 保存并关闭 | 保存 B；只有保存成功并重新确认没有新增未保存输入／修改才关闭，失败保留现场 |
| 丢弃修改并关闭 | 恢复整个 B 到已保存内容，包含所有视图的未保存修改；提示 B 文件名与影响 |
| 取消 | 保留引用和当前输入；若退出意图是删除引用，不完成该删除 |

默认取消。确认期间 B 版本变化需重新确认丢弃；旧确认不能丢弃新修改。多个待关闭实例若指向同一 B，以文档为单位处理，不能重复回滚。模式切换和普通滚动离屏不弹关闭确认，也不自动保存／丢弃 B。

### 冲突、临时副本与原生对比

不能安全写入 B 时，按现有版本仲裁暂停该编辑端口，保留当次尚未提交的输入版本；其他 B 视图仍围绕宿主文档运行。冲突界面提供以下精确选项：

| 显示 | 行为 |
| --- | --- |
| 对比并解决 | 打开 VSCode 原生对比页：左侧为当前输入临时副本，右侧为当前 B 文档 |
| 放弃当前版本 | 丢弃本次未成功提交的输入，重新同步当前 B；不回滚整个 B |
| 取消 | 保持当前输入与暂停状态，不自动重载或覆盖 |

“对比并解决”的 hover 原文为：**在临时副本和冲突版本的对比视图中处理冲突**。

扩展提供临时资源与打开入口；对比页的编辑、保存和关闭由宿主管理，不新增自有差异编辑器、应用草稿按钮或完成解决界面。优先在 P2-01 验证宿主临时文档作为左侧资源，以减少自建文件存储和清理；如该路线不可用，先记录证据，不借机建设持久恢复库。

输入转交必须可验证：临时资源完整承载当前输入且对比打开成功前，原实例继续保持暂停与快照；打开失败不能清除输入或误报已解决。成功转交后，原引用可以重新同步 B，旧未提交队列不得再次自动写入；后续 B 的变化沿用普通同步。转交只改变输入的处理位置，不表示差异已合并或已保存。临时副本的生命周期沿用验证通过的宿主资源行为，不按历史档案管理。

宿主已收到的未提交输入与 B.isDirty 分开观测。插件可控关闭先处理当次输入；不可拦截的父面板关闭沿用现有通知路径提供上述当次选择。只承诺宿主已经收到的输入，不宣称尚在被销毁 webview 中的组合文字或窗口退出后的内存输入已经持久保存。

### 父标签关闭与目标交接

宿主直接关闭 A 标签没有公开可取消的前置事件。A disposed 后，扩展针对引用编辑涉及且仍 dirty 的 B，使用现有 TextDocument 打开普通文本标签，preview 为 false；同一 B 去重，已有 B 标签复用，干净目标不打开，不从磁盘创建副本。

交接中等待可继续完成的宿主在途提交，再检查最新 dirty；不能只检查 dispose 发生前的旧状态。B 的未提交冲突版本不能冒称已经在 B 标签内，仍按上一节的当次选择处理。关闭 B 后正常保存／丢弃沿用宿主，不将 A 伪造为 dirty 来诱导关闭确认。

### 架构责任与迁移

| 入口／层 | 二期责任 |
| --- | --- |
| host/hoverDocAccess、目标定位与读取 | 返回全文和独立初始定位；维持根边界、锚点校验、版本与来源身份 |
| shared/protocol、来源租约与 refExpansion | 区分根／来源／目标／端口；运行期校验、全文计费、文档级循环与释放 |
| host/documentSession、textEditorProvider | B 会话接入、编辑／保存／历史、dirty、关闭确认、临时对比与父关闭交接 |
| webview/refContentInstance | occurrence 的模式选择、选区／位置、Reading／Live 挂载、输入保护与释放 |
| webview/syncController 与 Live 复用入口 | 先提炼主编辑器已用的实例上下文，再复用同一 Live 能力；主面板 chrome 保持单份 |
| webview/embedCard、hoverPopup、各容器适配 | 提供空间、入口、焦点和关闭原因；不直接写 B 或自行维护目标历史 |
| keybindings、菜单、locales、styleContract | 实例目标分派、可绑定操作、两语言文字及公开呈现契约 |

实施采用“先增加可复用入口 → 主编辑器验证等价 → 分容器接入 → 全部迁移后移除旧单实例假设”。不把整个主控制器复制进每份引用。接入端口与 UI 生命周期分离，挂载回收不能释放其他 B 视图或撤销 B 的宿主 dirty 文档。

当前 1.5 期预算作为基线：每树 24、每面板 64 个引用实例，每树 2 MiB／每面板 8 MiB 内容预算，每面板 8 个在途读取，provider 128 个 watch 目标槽；这些是工程计费上界，不能直接当进程堆大小。新增 EditorView 及待处理输入资源须纳入统计，离屏不预建；测量前不虚构新的性能承诺或放宽现有上界。

### 操作、文字与样式交付

新增的内部模式切换、保存目标、显式关闭、对比并解决、放弃当前版本及取消操作，均登记可绑定入口与适用状态。模式切换、冲突选择默认未绑定；保存复用焦点内 Ctrl+S，浮窗关闭复用 Esc，并保持既有弹层／编辑器按键优先级。Reading 不覆盖写操作宿主绑定；挂载、滚动与自动释放不是新增操作。

标题、未保存状态的可访问说明、按钮、模态提示、错误和指定 hover 文字全部经两套 locales 与 t()；manifest 文字经既有生成流程。所有呈现变更实施前使用 style-contract 固定旧契约，补新入口和绘制层证据，不删除历史公开选择器或随意改变已有 CSS 片段作用域。新增设置如确有必要，必须走插件自有设置页，不另开宿主设置界面。

### 已核实的宿主 API 边界与实施前置验证

本次只读研究使用 VSCode 1.86.2 固定标签的官方源码。以下是已核实事实，不是已运行的真宿主验证结果。

- `undo/redo` 的 custom editor 实现取当前活动编辑器，不使用附加目标 URI；普通文本编辑器实现也按聚焦／活动代码编辑器执行。因此不能在 A 活动时直接追加 B URI，便宣称撤销归属 B。[custom editor 分派](https://github.com/microsoft/vscode/blob/1.86.2/src/vs/workbench/contrib/customEditor/browser/customEditors.ts#L84-L109)、[文本编辑器分派](https://github.com/microsoft/vscode/blob/1.86.2/src/vs/editor/browser/coreCommands.ts#L303-L336)
- `default:undo/redo` 只是同一命令的代理；内部 `IUndoRedoService` 虽能按 resource 操作，但不是已经核实可由普通扩展调用的公开路线。[命令代理](https://github.com/microsoft/vscode/blob/1.86.2/src/vs/editor/browser/editorExtensions.ts#L249-L260)、[内部服务](https://github.com/microsoft/vscode/blob/1.86.2/src/vs/platform/undoRedo/common/undoRedo.ts#L185-L189)
- **目前未找到保持 A 活动、按 B URI 撤销的公开稳定入口**。暂时激活 B 后撤销再返回 A 是候选，但会改变活动编辑器；未确认该备选符合交互要求，不将其当作既定实现。
- `WebviewPanel` 只有 `onDidDispose`，没有可取消的关闭前事件；`CustomTextEditorProvider` 也没有对应关闭 veto。A 的 custom text model dirty 只属于 A 的资源，B dirty 不自动成为 A 标签的关闭确认条件。[面板 API](https://github.com/microsoft/vscode/blob/1.86.2/src/vscode-dts/vscode.d.ts#L9398-L9426)、[provider API](https://github.com/microsoft/vscode/blob/1.86.2/src/vscode-dts/vscode.d.ts#L9623-L9645)、[dirty 判定](https://github.com/microsoft/vscode/blob/1.86.2/src/vs/workbench/contrib/customEditor/common/customTextEditorModel.ts#L63-L77)

目标撤销路由仍需技术验证，不能用关闭交接 API 的可用性代替撤销路由的证据。建议把目标历史与关闭交接的兼容性验证作为二期首票。验收至少覆盖 A 活动且 B 无独立标签、B 其他视图交错编辑、在途输入后立即撤销、连续撤销／重做、焦点变化、目标保存／丢弃与关闭。须区分错误路由造成的 A 修改，以及宿主合法的跨资源撤销元素；不能用单文档结果概括任意历史。[跨资源撤销元素](https://github.com/microsoft/vscode/blob/1.86.2/src/vs/workbench/contrib/bulkEdit/browser/bulkTextEdits.ts#L304-L322)

### 第五轮已确认共识

**Q13：文档级丢弃（已确认）**。用户选择丢弃整个 B 的未保存修改，并明确提示影响。丢弃恢复 B 到已保存内容，包含 B 其他视图的未保存修改；模态框显示 B 文件名及影响。对话框期间 B 再被修改时，重新确认后才能丢弃。

**Q14：父标签关闭后的目标交接（已确认）**。用户核对公开 API 后接受：普通关闭 A 文件标签后，将 A 内引用编辑涉及、仍有未保存修改的 B 打开为独立普通文本编辑标签。显示现有 B `TextDocument` 的当前内容，`preview: false`；不自动保存、不丢弃、不另从磁盘复制或生成 B 副本。关闭确认的 API 边界保持不变：插件自有浮窗／显式退出在关闭前确认，宿主直接关闭 A 标签后通过 B 标签承接后续编辑、保存或丢弃。

该决定只涵盖已成功写入 B 的未保存修改。内容属于 VSCode 的 dirty 文本模型；正常运行期间该模型不会因 dirty 而被一般回收，需保存或回滚后才可释放。退出后的恢复另受宿主 Hot Exit 设置与备份流程影响，不把普通标签关闭的交接扩大为退出／重载时自动重开窗口的保证。[1.86.2 模型生命周期](https://github.com/microsoft/vscode/blob/1.86.2/src/vs/workbench/services/textfile/common/textFileEditorModelManager.ts)、[Hot Exit 文档](https://code.visualstudio.com/docs/editing/codebasics#_hot-exit)

尚未成功写入目标的输入不能据此声称受到同样保护：当前 `DocumentSession.detachPanel` 只把已收到的输入快照／片段交给关闭通知，provider 提供复制取回；没有已实现的持久恢复档案，也没有已经确定的保留期限。二期应单独确定这部分的保护方案，不把「保留 dirty」与「保住未提交输入」合并承诺。

公开 API 依据：在 A 的 `WebviewPanel.onDidDispose` 通知后，可向 `window.showTextDocument` 传入仍打开的 B `TextDocument`，使用 `preview: false` 显示普通文本编辑标签。API 已存在于 VSCode 1.86.2；关闭期间的回流竞态、多个 dirty 目标、既有 B 标签及窗口退出／重载仍需真宿主验证，不能据此宣称关闭恢复已完成。该决定同步记录于 [ADR-0010](../adr/0010-reference-edit-target-session.md)。[1.86.2 API 声明](https://github.com/microsoft/vscode/blob/1.86.2/src/vscode-dts/vscode.d.ts)、[showTextDocument 文档](https://code.visualstudio.com/api/references/vscode-api#window.showTextDocument)

### Q15：写入冲突的三项选择（已确认）

用户指定写入冲突时使用以下三个选项，替换先前以「复制取回」作为主要冲突处理的建议：

| 实际显示文字 | 行为与说明 |
| --- | --- |
| 对比并解决 | 在临时副本与冲突版本的对比视图中处理冲突；hover 文案逐字为「在临时副本和冲突版本的对比视图中处理冲突」 |
| 放弃当前版本 | 放弃本次未成功写入 B 的当前输入版本，重新同步 B 的现有内容；与普通关闭时丢弃整个 B 的未保存修改分开建模 |
| 取消 | 取消本次选择，保持写回暂停与当前输入，不自动放弃或覆盖 |

临时副本承载本次尚未成功写入 B 的输入版本，冲突版本为 B 的当前权威内容。Q17 明确使用 VSCode 原生对比页：左侧提供临时副本，右侧打开 B；原生对比页的编辑、保存与交互由宿主管理，不新增自有差异编辑器、「应用草稿」或「完成解决」界面。扩展负责提供临时资源和打开入口，并通过既有目标文档同步接收 B 的变化。打开对比页本身不表示冲突已经解决；普通保存只保存已成功写入 B 的内容，不能误报临时副本已经写入 B。
