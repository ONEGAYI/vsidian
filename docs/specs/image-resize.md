# 规格：图片尺寸后缀与拖动手柄

> 状态：设计访谈完成（2026-10-22），未实施。本文是图片尺寸语法与拖动手柄的**单一事实源**；实施拆两票——尺寸语法与七渲染面 [#635](https://github.com/ONEGAYI/vsidian/issues/635)、拖动手柄与视觉 [#636](https://github.com/ONEGAYI/vsidian/issues/636)，验收以此为准。

## 1. 目标与范围

让用户在图片引用里声明显示尺寸，并且不写语法也能靠拖动调整。

**覆盖**：双链嵌入 `![[图.png|尺寸]]`、Markdown 直链 `![图注|尺寸](图.png)` 的尺寸后缀解析与全渲染面生效；Live 视图右下角拖动手柄。

**排除**：普通链接 `[[图.png|100]]`（见 §3.2）、只写高度 `|x200`（见 §3.4）、拖动的键盘可达性（见 §8）、图片弹窗内的缩放（既有能力，不改）。

## 2. Obsidian 语法基线

官方帮助（`obsidianmd/obsidian-help` 的 `Embed files.md` 与 `Basic formatting syntax.md`）明确两种形态：

| 写法 | 官方语义 |
| --- | --- |
| `![[图.png\|100]]` | 只写宽度，**按原纵横比**等比缩放 |
| `![[图.png\|640x480]]` | 固定宽 640、高 480，**不保持纵横比** |
| `![250](url)` | 直链形态同样支持上述后缀 |

三项经核实的边界，写入本规格的排除清单：

- **百分比不是官方语法**。Obsidian 论坛的百分比请求（t/16880、t/41974）自 2021 年至今 open，`![[图.png|50%]]` 在 Obsidian 里只是普通文本后缀。
- **只写高度未实现**。`|x200` 是功能请求（t/16225），不是语法。
- **多段竖线不是官方特性**。`![[图.png|right|300]]` 的对齐效果来自主题／插件 CSS，官方社区已确认「不是原生功能」（t/111600）。

## 3. 已确认决策

### 3.1 语法集合

支持四种形态，全部在**嵌入语境**内：

| 写法 | 语义 | 来源 |
| --- | --- | --- |
| `\|W` | 宽度 W 像素，等比 | 官方 |
| `\|WxH` | 宽 W、高 H 像素，**不保持比例** | 官方（保持拉伸语义） |
| `\|N%` | 图片固有宽度的 N%，等比 | 本项目扩展 |
| `\|N%` 之外的百分比形态 | **不支持**（`\|50%x30%` 判非法） | 排除 |

`WxH` 坚持官方会拉伸的语义，不做 contain-fit 改造：同一段源文在 Obsidian 与 Vsidian 里必须呈现同一尺寸，否则用户迁移笔记时无从判断谁对。要防变形由 Shift 交用户显式选择（§5.2）。

百分比基准是**图片固有宽度**（`naturalWidth × N%`），不是容器宽度、不是当前渲染宽度。理由：与 `|W` 同一坐标系（都落在一个绝对像素点），拖动改尺寸时不会因换了基准而漂移；用当前渲染宽度做基准会让结果依赖历史，必须排除。

### 3.2 作用域只限嵌入形态

`![[…]]` 与 `[[…]]` 共用 `parseWikilinkInner`。若不加区分，「最后一段是数字就当尺寸」会让**普通链接的别名「100」被误判**，而 Obsidian 里 `[[图.png]]` 是链接、不嵌入图片，`|100` 只是显示文字。

因此尺寸语义只在两条路径生效：`![[…]]` 扫描（`scanEmbedsInLine`）与 Markdown 图片 token。普通链接 `[[图.png|100]]`、`[[图.png|100|200]]` 维持现有别名语义，一个字符都不改。

### 3.3 别名与尺寸共存

跟随 Obsidian 的分段规则：**按 `|` 分段，最后一段匹配尺寸形态则判为尺寸，其余段拼回别名**。

```
![[图.png|说明文字|100]]   → 别名「说明文字」，尺寸 100
![[图.png|100]]            → 无别名，尺寸 100
![[图.png|说明文字]]        → 别名「说明文字」，无尺寸
```

尺寸形态的正则（单一事实源）：

```
宽度像素   ^\d+$
宽×高像素  ^\d+x\d+$
百分比     ^\d+(\.\d+)?%$
```

`^(\d+)x(\d+)$` 大小写不敏感（`x` 与 `X` 等价）。**副作用按既定行为接受**：用户本想写别名「100」时会被判为尺寸——这是 Obsidian 既定行为，跟随它比另立规则更可预期。

### 3.4 合法域

| 项 | 规则 |
| --- | --- |
| 像素下限 | 宽 ≥ 1，高 ≥ 1 |
| 像素上限 | 无显式上限 |
| 百分比域 | 1%–1000%，允许放大 |
| 非法值 | **原样降级为普通文本后缀**，不静默改写源文 |

`|0`、`|0x100`、`|0%`、`|2000%`、`|50%x30%`、`|x200` 一律按非法处理，整段留在别名里，图片按无尺寸渲染。降级而非纠正，沿用本项目「不静默修改用户内容」的一贯立场。

### 3.5 渲染生效范围

尺寸后缀是**源文语义**，影响所有呈现该图片的地方：

| 渲染面 | 生效 |
| --- | --- |
| Live 正文（独行／行内混排） | 是 |
| 阅读视图 | 是 |
| 表格格内图片 | 是（仅显示，无手柄） |
| 链接内图片 | 是（仅显示，无手柄） |
| 嵌入卡片内图片 | 是 |
| 悬停浮层图片 | 是 |
| PDF 导出 | 是 |

拖动手柄是**编辑入口**，只在 Live 的非排除区域出现（§5.1）。表格格内与链接内图片能正确显示尺寸，只是不能拖。

### 3.6 尺寸与行宽的钳制

手写的超大像素值由既有 `max-width: 100%` 兜底，不产生横向滚动。拖动的实时视觉另外钳到容器内容宽（§5.4），但**这层钳制不改变用户手写的值**。

## 4. 实施落点

### 4.1 解析：单一事实源

新建 `src/shared/imageSize.ts`，两端共用：

```ts
export interface ImageSize {
  width: number
  height: number | null   // null = 等比（只给宽）
  unit: 'px' | 'percent'
}

/** 解析尾缀段；非法返回 null（调用方按普通文本后缀降级） */
export function parseImageSizeSuffix(segment: string): ImageSize | null

/** 从 `a|b|100` 形态中剥离尾缀尺寸；返回别名与尺寸 */
export function splitAliasAndSize(parts: readonly string[]): {
  alias: string | null
  size: ImageSize | null
}
```

不建第二份解析：`wikilink.ts`、`readingMarkdown.ts`、`liveLinks.ts` 都引这一个模块。

### 4.2 双链嵌入路径

`parseWikilinkInner` 增加**可选的**尺寸提取，不改变既有字段语义——`alias` 仍是别名，新增 `size`：

```ts
export interface ParsedWikilink {
  // …既有字段不变
  /** 嵌入形态下的尺寸后缀（非嵌入或非法时为 null） */
  size: ImageSize | null
}
```

调用点分两类：

- **嵌入扫描**（`scanEmbedsInLine`、`embedAtPosition`）：传入标志位，允许提取 `size`。
- **链接扫描**（`scanWikilinksInLine`）：不提取，`size` 恒 `null`，别名语义原样。

### 4.3 Markdown 直链路径

markdown-it 把整个 `图注|100x80` 放进 `token.content` 与 `children`，`attrs` 里只有 `src` 与空 `alt`（实测确认）。所以尺寸剥离必须**在 alt 字符串层面做**，不能指望 token 有独立尺寸字段。

两个接入点：

- `vsidianEmbedInlineRule` 的 `vsidian_embed_image` token：`embedImageHtml` 增加尺寸属性输出。
- 标准 `image` token（含 `vsidianLooseLinkInlineRule` 产出的宽松形态）：在渲染规则里读 `token.content`，解析尾缀后写 `width`／`height` 属性，alt 取剥离后的别名。

### 4.4 属性写入

两种渲染面的载体不同：

| 形态 | 载体 | 写法 |
| --- | --- | --- |
| 阅读／直链 | `<img>` | `width`／`height` 属性（像素）或内联 `style.width`（百分比） |
| Live widget | `span.vsidian-image` 内的 `<img>` | 同上，由 `LiveImageWidget` 在 `render` 回调里写入 |

百分比必须走 `style.width = 'N%'`，因为 HTML `width` 属性不接受百分比。像素走属性更利于浏览器在加载前预留空间、减少布局跳动。

## 5. 拖动手柄

> 本节与 §6、§7 归 [#636](https://github.com/ONEGAYI/vsidian/issues/636)；§2–§4 归 [#635](https://github.com/ONEGAYI/vsidian/issues/635)。

### 5.1 出现范围

**仅 Live 视图，所有非排除图片**（含行内混排）。链接内与表格格内沿既有排除矩阵不出现——那里点击语义归链接跳转与单元格编辑，拖动会与之冲突（`src/webview/liveLinks.ts:511-515`、`src/webview/syncController.ts:11854-11856` 已钉住该矩阵）。

阅读视图不出现：阅读模式按契约只读（`CONTEXT.md:71`、`mvp.md:31`），拖动本质是改源文。

### 5.2 拖动轴行为

| 模式 | 触发 | 写回形态 |
| --- | --- | --- |
| 等比（默认） | 直接拖 | `\|W`；原写法是百分比则 `\|N%` |
| 自由双轴 | 拖动时按住 Shift | 一律写 `\|WxH` 像素 |

原写法是 `|100x80` 时，等比拖动**保留两轴等比缩放**（写 `|200x160`），不丢高度——`WxH` 是用户显式声明「我要固定这个框」。

写回遵循原有写法（Q11）：原为百分比写百分比，原为像素写像素，原本无后缀写像素。

### 5.3 提交时机与撤销

拖动期间**只改视觉**（内联 `style.width/height`，不碰文档）；松手时算最终尺寸、一次性改写尾缀。

一次拖动 = 一步撤销。Live 侧每笔 `edit.request` 在宿主聚合成一次 `WorkspaceEdit` 并只调用一次 `applyEdit`（`src/host/textEditorProvider.ts:1679-1692`），所以一笔请求天然是宿主撤销栈的一步。

拖动中按 Esc 恢复原状且不写文档。

### 5.4 尺寸界

- 最小：宽 **24px**，高按当前比例跟随、不低于 1px。24 与光晕保底值同档，再小抓不住。
- 最大：钳到容器内容宽（可读行宽或当前列宽），拖动中不产生横向滚动条。

### 5.5 手柄几何

- 视觉 **12×12**，热区 **20×20**（热区大于视觉，沿用侧栏拖宽句柄的既有做法）。
- 贴住相框右下角内侧，与相框圆角同心。
- 光标 `nwse-resize`。
- 12px 视觉尺寸与右上按钮 22px 方框、内部 15px 图标同档。

### 5.6 显现时机

悬停相框时显现，与现有右上角按钮组同一套 `frame:hover` 规则。不常驻——常驻会让每张图右下角都挂装饰。

### 5.7 尺寸读数

拖动中在手柄旁浮出实时读数（如 `320 × 180`），松手即消失。文案与数值形态经 i18n。

## 6. 视觉规格

### 6.1 手柄光晕

**沿圆角轮廓的描边发光**（outline／box-shadow 组合，不占布局），不是填充渐变。

光晕中心在图片右下角圆角处，沿 45° 向左上方放射并逐渐变淡。

延伸距离 = `max(24px, min(相框宽, 相框高) × 10%)`，即「10% 与保底 24px 取大」。

- **取 max 不取和**：相加会让大图的光晕边界难以预期。
- **基数用短边**：若用宽边，一张 982×169 的宽图会沿底边铺出 98px 的光，视觉上像「半条边在发光」而不是角落光斑。

### 6.2 拖动中相框态

按住时**整个相框外框异色描边**（1px 实线，`--vscode-focusBorder`），**角落光晕消失**——两者不叠加，避免一处出现两团亮区。

### 6.3 颜色与变量

全部走 style-contract 已登记的变量族，不新增硬编码色值。新增视觉参数（光晕半径、描边宽、手柄尺寸）如需公开，按 style-contract 流程登记后再实现。

## 7. Shift 提示

### 7.1 载体

复用既有 `ToastChannel`（`src/webview/toast.ts`），`show(text, severity, key?, action?)`。挂载在 `#app` 底部居中（`max-width: 480px`）。不新建浮层——再造一个跟随式提示条等于引入第二套轻提示形态，与「UI 元素形态先登记后实现」冲突。

### 7.2 触发与文案

- 每次拖动开始都提示，**但拖动开始时 Shift 已按下则跳过**（已按住的人不需要被告知）。
- `neutral` 档，不用 `warning`——这是能力说明，不是异常；用 warning 会带上警示色，语气不对。
- 文案：「按住 Shift 可自由调整宽高」，i18n 键 `imageResize.toast.shiftHint`。
- 用 `key` 去重，避免拖动连续触发时排队堆积。

### 7.3 与读数分工

尺寸读数在手柄旁报数值（§5.7），toast 在底部报能力。两者分工清晰，不重复。

## 8. 明确排除

| 项 | 理由 |
| --- | --- |
| 普通链接 `[[图.png\|100]]` 的尺寸语义 | 那是别名，改了会破坏既有链接（§3.2） |
| `\|x200` 只写高度 | Obsidian 未实现，不自造（§2） |
| `\|50%x30%` 双百分比 | 高度百分比无明确基准，会产生无法解释的组合 |
| `\|WxH` 的 contain-fit 改造 | 会与 Obsidian 呈现不同尺寸（§3.1） |
| 阅读视图的拖动手柄 | 破只读契约（§5.1） |
| 键盘调整尺寸（Tab 聚焦手柄、方向键微调） | 独立一票；步长、加速、焦点环、撤销语义需整体设计（§8 之后） |
| 表格格内与链接内图片的手柄 | 沿既有排除矩阵（§5.1） |
| 图片弹窗内的尺寸控制 | 既有缩放能力不改 |

键盘可达性本批不做，但手柄仍加 `aria-label` 供读屏识别。

## 9. 验收

### 9.1 单元

- `parseImageSizeSuffix` 矩阵：四种合法形态、全部非法值（`0`、`0%`、`2000%`、`50%x30%`、`x200`、`100X80` 大小写）。
- `splitAliasAndSize` 分段：无别名、单别名、多段别名、别名含数字但非尺寸。
- `parseWikilinkInner`：嵌入形态提取 size；链接形态 size 恒 null；既有别名断言全部不变。
- Markdown 直链 alt 串剥离：`![图注|100](a.png)` 的 alt 为「图注」、宽 100。

### 9.2 浏览器（真实 Chromium，断言绘制层几何）

- `|W` 等比：渲染宽 = W，高按比例。
- `|WxH` 拉伸：渲染宽高恰为 W×H。
- `|N%`：渲染宽 = 固有宽 × N%。
- 非法值降级：渲染宽 = 固有宽（或受 `max-width` 钳制），alt 含原后缀。
- 七个渲染面各自生效（Live／阅读／表格／链接／嵌入卡／悬停／导出）。
- 拖动：等比与 Shift 自由两种模式的最终渲染尺寸与写回源文形态。
- 一次拖动一步撤销（宿主撤销一次回到拖动前）。
- esc 中止不写文档。
- 光晕延伸距离与「光晕消失 + 异色描边」的互斥态（计算样式断言）。

### 9.3 集成

- 真实宿主下拖动 → 源文尾缀正确改写 → 宿主撤销一步回退。
- 嵌入卡片内图片拖动写回目标文档 B，不写 A。

## 10. 已知边界

- **存量文档的语义变更**：已有笔记里 `![[图.png|500]]` 今天被当作别名（渲染为 alt 与 tooltip），本票后变成宽度。属于可见行为变更，须在 CHANGELOG 明确。
- **表格内的管道转义**：单元格里的 `![[图.png\|500]]` 由 GFM 拆分解码为 `![[图.png|500]]`，尺寸识别作用在解码后的语义上，不碰原始区间。转义规则复用 `wikilinkField` 的 `pipeEscape`（`src/shared/wikilinkField.ts:30-42`）。
- **百分比与图片替换**：图片文件被换成不同固有尺寸后，同一 `|50%` 会呈现不同像素宽——这是百分比语义的必然结果，不是缺陷。
- **拖动不重算 sized 标记**：`markImageFrameSized` 的贴图判定在图装载时一次性计算（`docs/specs/image-popup.md:54` 已记录该边界），拖动改变尺寸后按钮贴图位置会随下一次装载事件收敛。
