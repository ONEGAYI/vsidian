**作用域**：写操作只在可编辑的 Live 正文获得焦点时拦截按键。阅读容器可执行只读视图操作；查找输入框仅允许只读操作；源码编辑器和设置页输入不装配正文按键路由。模式切换、失焦、超时（1.2 秒）或 Escape 会取消待输入的两段键。内部冲突包含完全相同的键位，以及重叠模式中的单段键与两段键首段；模式互斥时可复用键位。

**阅读查找源码浮层（2026-10-01 评估结论）**：这是当前隐藏命中的自动只读反馈，不提供独立按钮动作，不新增可绑定操作或默认键位。沿用「查找」「下一个/上一个查找结果」注册入口；面板输入中的 Enter/Shift+Enter 继续导航，Escape 关闭查找并清理浮层。仅阅读模式显示，不切换编辑模式，不抢输入焦点、不写入源码。

**未注册为通用快捷键的情境动作**：任务勾选、链接激活、图片点击、表格单元格/区域点击、大纲条目点击与折叠箭头、条目右键菜单（复制、重命名、调级、删除等）及拖拽依赖用户当时指向的具体元素。当前没有可由正文焦点唯一推导的目标；直接绑定会对错误条目执行写入。大纲当前控制域高亮是滚动/定位后的自动状态，不存在独立按钮动作。它们保留鼠标及原有键盘可达控件入口。后续若新增明确的目标选择语义，应逐项按 `AGENTS.md` 重新评估快捷键入口、默认值和生效模式。

**「打开样式参考」注册为全局命令、默认未绑定（#132 评估结论）**：只读视图操作（打开设置页「外观」分页并定位其中「样式参考」页签——离线查阅公开样式契约与 Obsidian 原名兼容等级；#231 起样式参考并入「外观」合并分页，定位随合并调整），双模式可用（`mode: both`、`writes: false`）；设置页分页入口常驻，命令面向命令面板/快捷键直达场景，默认不占键位，用户可按需绑定。与「打开设置」同形态登记于 extra 表。

**「导出样式参考 JSON」注册为全局命令、默认未绑定（#145 评估结论）**：只读操作（把随 VSIX 分发的机器可读契约清单 `media/style-reference/style-reference.json` 经另存为对话框导出到用户路径——不写文档、不依赖任何打开的编辑器面板），双模式可用（`mode: both`、`writes: false`）。设置页「样式参考」分页工具区的「导出 JSON」按钮经 `styleRef.export` 消息走同一实现；命令面向命令面板/脚本化场景（无需先打开设置页）。默认不占键位，用户可按需绑定。

**「打开 CSS 片段设置」未单列命令（#128 评估结论）**：片段管理页经「打开设置」（双模式、默认未绑定）进入设置页后由左侧导航直达，单独命令只为省一次导航、收益不抵命令面板与快捷键页的条目膨胀；「CSS 片段重新加载」已注册为全局命令（双模式、默认未绑定，只读视图操作——片段可能影响任一模式的界面，命令面板始终可达）。后续若设置页支持直达分页的深链，再评估单列入口。

**CSS 片段暂停/恢复（#131 评估结论）**：「暂停全部」与「恢复」注册为宿主侧全局命令（双模式、默认未绑定、只读视图操作——不写文档，仅翻转持久化的全局冻结标志）。命令在宿主注册，不依赖任何 webview 的健康度：正文工具栏被隐藏、编辑器面板或设置页异常时命令面板仍可救回被片段影响的界面。暂停与逐项停用语义正交：暂停不清逐片段开关，恢复按原配置立即生效。设置页 CSS 片段分页的「暂停全部」按钮与暂停状态条内的「恢复」入口与命令共用同一服务入口（`snippets.setPaused` 消息）。默认不占键位：高频用户可自行绑定。

**情境输入动作（Enter / Backspace，#119 评估结论）**：列表/引用行的 Enter 前缀延续与退格清层是对「光标所在行的结构前缀」的变换——目标由光标位置即时推导（列表项、嵌套层级、引用深度），不是可枚举的固定命令目标，故不注册进快捷键操作清单、不提供用户可改绑定；键位固定为 Enter 与 Backspace，仅 Live 编辑正文生效（表格上下文让位给单元格语义，块级公式内按源码字面编辑不接管；阅读只读、源码走原生编辑器）。处理器装配在 `src/webview/listEditing.ts`，keymap 顺序在 tableEditing 之后、defaultKeymap 之前。

**情境输入动作（Tab / Shift+Tab，#120 评估结论；#125 扩展）**：通用行缩进同属光标位置即时推导的情境变换（受影响行集合与列表行智能对齐宽度均由光标与选区现场决定），不注册进快捷键操作清单、不提供用户可改绑定。键位固定为 Tab（整行缩进一级）与 Shift+Tab（反向），仅 Live 编辑正文生效：列表行一级宽度对齐上方最近项的内容列（CommonMark 口径：父项「标记+一空格」，任务标记属内容不计——无序与任务父项下均 2 格、宽编号有序父项下 4 格；跨族取上方项内容列而非自身标记宽，防止缩进越界脱离列表结构），反向缩进升至树父项标记列（顶级删全部缩进）；普通行（含纯引用行、代码围栏、缩进代码块与块级公式内）固定 2 空格；多光标时各 range 覆盖行取并集缩进（与 Enter/Backspace 的「多光标不接管」口径不同：行集合命令的自然泛化，无破坏性）；表格内保持单元格导航语义优先（边界放行也不缩进表格行）；frontmatter 与 IME 组合中不接管；无可删空白时 Shift+Tab 仍吞键——Tab 族按键放行到默认路径会被宿主 webview 预加载脚本转发为工作台焦点导航（焦点逃逸），键盘焦点移出编辑器的出口相应改为 Esc / 鼠标。处理器装配在 `src/webview/indentEditing.ts`，keymap 顺序在 tableEditing 之后、defaultKeymap 之前；快速操作条等 UI 控件的 Tab 焦点管理不受影响（其 keydown 目标不是编辑器 contentDOM，不经过本 keymap）。

**情境输入动作（围栏内 Tab 越界，#125 评估结论，归 #120 情境输入键口径）**：光标在有效成对围栏内部且无选区时，Tab 先到闭合标记左边界、再按一次越过整个闭合标记（嵌套从最内层逐层退出）——目标由「光标位置 + 当前语法树/行内配对」即时推导，同属无固定命令目标的情境变换，**沿用 #120 结论**：不注册进快捷键操作清单、不提供用户可改绑定，键位即 Tab 本身。有效优先级为**围栏越界 → 表格导航 → 既有正文缩进**（输入法/只读门控先于一切；格内先越界、越出后切格，围栏外不向右搜索）：由 keymap 装配顺序实现——CM6 keymap 按扩展数组顺序**正序**拼接尝试（靠前者先匹配，与 transactionFilter 的逆序相反），`src/webview/fenceEscape.ts` 装配在 tableEditing **之前**，优先级已经 jsdom 真控制器与浏览器真实 Tab 键两层实测（`test/unit/tabEscapeInteraction.test.ts`、`test/browser/symbolInput.mjs`）。Shift+Tab 不新增反向越界（keymap 不绑 shift 槽，落穿保持反向切格/反向缩进）；Tab 命中时派发纯选区事务（零写回零 dirty）。关闭入口为扩展设置页「符号 Tab 越界」开关（`editor.symbolTabEscape`，默认开启，与 #123/#124 相互独立），关闭后 keymap 整组退出装配、Tab 回落既有行为。**后续工单不得把任何命令绑定到 Tab 键**（keybindingRouter 会先于 keymap 拦截并 stopPropagation，破坏上述三段优先级）。

**情境输入动作（符号字符键入与空对 Backspace，#123 评估结论）**：符号自动补全由**键入普通字符**触发（括号/引号起始符补闭合、Markdown 强调触发符在连续串首补对），闭合越过由键入同一闭合符号触发，自动空对删除由空对内 Backspace 触发——三者都是对「光标邻接字符与自动补出来源状态」的即时变换，没有可枚举的固定命令目标，故不注册进快捷键操作清单、不提供用户可改绑定。触发字符集合由符号注册表登记（`src/shared/symbols.ts`，英文尖括号默认不补全）；仅 Live 编辑正文无选区时生效（选区场景归 #124 包裹；表格格区替换语义不改写），阅读只读、源码与设置页输入不装配。关闭入口为扩展设置页「符号自动补全」开关（`editor.symbolAutocomplete`，默认开启），关闭后补全/越过/空对删除三条路径一并停用。Backspace 的空对删除仅认「自动补出且仍为空」的符号对（非自动来源交默认删除），处理器装配在 `src/webview/symbolAutocomplete.ts`，keymap 顺序在 tableEditing 之后、defaultKeymap 之前；补全/越过经 transactionFilter 改写输入事务（一次补全即一笔写回，宿主撤销一次整体恢复），不走独立按键命令。

**情境输入动作（选区包裹字符键入，#124 评估结论）**：选区包裹同样由**键入普通字符**触发（有非空选区时键入注册包裹符号，在选区两侧添加 open/close 并保持原文选中；连续键入叠加标记、跨段按空行拆段分别包裹）——目标由「当前选区 + 键入字符」即时推导，没有可枚举的固定命令目标，故不注册进快捷键操作清单、不提供用户可改绑定。包裹字符集合由符号注册表的 `selectionWrap` 字段逐项显式登记（与补全集合不同源：键入 close 字符不包裹、英文尖括号不包裹）；仅 Live 编辑正文有非空选区时生效（无选区归 #123 补全；代码上下文抑制 Markdown 强调、允许括号引号；表格格区替换语义不改写），粘贴/拖放与 IME 组合链路（选区已被组合替换）不包裹。与格式按钮（快速操作条粗体/斜体等命令）是**不同入口的两种操作**：按钮走两态切换（再次执行取消格式）且按行包裹，字符键入走叠加包裹且按空行拆段，语义不混用。关闭入口为扩展设置页「选区符号包裹」开关（`editor.symbolSelectionWrap`，默认开启，与 #123 相互独立）。处理器装配在 `src/webview/symbolWrap.ts`（transactionFilter 把选区替换事务改写为两侧插入，一次包裹含跨段多块即一笔写回，宿主撤销一次整体恢复），装配顺序在 symbolAutocomplete 之后；跨段包裹后选区为多 range（各段原文），依赖 `allowMultipleSelections`——#237 起该 facet 由多光标扩展组（`src/webview/multicursor.ts`，独立设置默认开）装配，包裹开关不再影响多选区存续；多光标关闭时跨段包裹的文本改写仍生效，产物选区被折回主 range（降级边界，见下方 #237 评估结论）。

**外部冲突边界**：VS Code 1.86 稳定扩展 API 无法枚举用户、工作台及其他扩展的全部有效按键规则与 `when` 条件。设置页只检查 Vsidian 内部冲突，不显示「外部无冲突」。如需排查工作台优先级，可使用 VS Code 的「记录键盘快捷方式故障排查」。

**依赖导入与资源拒绝无新增操作（#129 评估结论）**：本票全部为既有片段管理链路的自动行为（@import 依赖归因热更新、越界/符号链接逃逸拒绝与恢复），不引入新的用户可绑定操作——热更新由文件监听自动驱动（「CSS 片段重新加载」仍是手动兜底入口，语义不变）；拒绝与恢复以通知和设置页行内提示呈现，无需按键触发。

**HTTPS 导入与联网字体无新增操作（#130 评估结论）**：本票全部为既有片段链路的浏览器标准能力放开（CSP 放行 https: 样式/字体源、远程引用不进依赖图、字体晚到补测）——无新用户可绑定操作。远程资源的内容刷新沿用「CSS 片段重新加载」（#128，双模式、默认未绑定）手动驱动；断网、CORS 拒绝、HTTP 错误等失败面以既有装载失败提示与备用字体回退呈现，无需按键入口。

**工具栏双态视图切换按钮与快捷键（#141 评估结论，2026-09-27 用户增补定稿）**：编辑器顶栏右侧的双态按钮（live↔reading，不含源码）与快捷键「双态切换」是同一操作的两个入口，**单列为可绑定操作**（`onegayi.vsidian.mode.toggleDualView`，双模式生效、默认 Ctrl+Q）：目标由当前态取反推导（live→reading、reading→live），按钮经 webview→宿主 `view.switch.request` 消息、快捷键经 `keybindings.execute` 出站→宿主 executeCommand，两条入口汇到**同一宿主双态切换实现**（复用 `runViewSwitch` 全套编排：模式记忆、diff 防御、`view.mode.set` 回流驱动按钮态），不另造切换路径。源码模式入口仍只有右上角三态命令（`toggleViewMode` / `mode.toSource`）——双态操作在源码模式不经 webview 键路由天然不可达，命令面板在源码态调用时按当前态取反回到 Vsidian 面板。Ctrl+Q 冲突核对（2026-09-27）：操作表与 keybindingRouter 零占用，VSCode webview 键路由在宿主 workbench 默认绑定之外。

**工具栏刷新按钮与快捷键（#208 评估结论，2026-09-29）**：工具栏右端组的刷新按钮与快捷键「刷新嵌入资源」是同一操作的两个入口，**单列为可绑定操作**（`onegayi.vsidian.editor.refresh`，双模式生效、默认未绑定——手动触发场景低频，键位留给用户按需绑定）：作用范围为当前文档面板，点击/按键后清图片解析缓存、资源代次自增、活跃图片条目全量失效重挂（新 URI 带代次戳）并重置 Mermaid 懒加载失败终态；不触碰文档内容/撤销栈/视图状态。按钮经 webview→宿主 `refresh.request` 消息；快捷键经 `keybindings.execute` 出站→宿主 executeCommand（UI_OPERATIONS 注册循环）→回发 `ui.command`，webview 两条入口共用同一发送实现，宿主失效编排在 documentSession 的 `refresh.request` 处理唯一，不另造路径。

**复制块链接（2026-09-28 批次评估结论）**：目标由「光标所在块」即时推导（光标在标题行等价复制标题链接，其余块复制块链接；无块 id 时先在块尾自动补写——一笔可撤销编辑），属可枚举目标的写操作，**单列为可绑定操作**（默认 Ctrl+Shift+C，仅 Live 编辑正文生效——阅读只读不接管，源码与设置页输入不装配）。与正文右键菜单「复制块链接/复制标题链接」是同一命令的两个入口（规格 [anchor-navigation.md](anchor-navigation.md)）。Ctrl+Shift+C 冲突核对（2026-09-28）：操作表与 keybindingRouter 零占用；宿主侧该组合在集成终端有选区时为复制，编辑器正文无默认占用，Live 覆盖属既定「写操作仅 Live 正文覆盖宿主」语义。

**图片粘贴无快捷键（2026-09-28 批次评估结论）**：粘贴图片由**原生 Ctrl+V 通道**触发（webview paste 事件拦截剪贴板图片项），不是可枚举目标的命令、不占用键位（规格 [image-paste.md](image-paste.md)）；阅读模式不接管粘贴。

**「打开/切换反链面板」注册为 UI 操作、默认未绑定（#197 评估结论）**：目标固定明确（侧栏反链面板的显隐翻转，与大纲面板互斥），**单列为可绑定操作**（`onegayi.vsidian.ui.backlinksToggle`，双模式生效 `mode: both`、非写操作 `writes: false`）。反链查看为双模式需求（Live/阅读均显示当前笔记的反向链接，规格 [vault-index-backlinks.md](vault-index-backlinks.md)），面板切换是纯视图状态翻转（零写回、零出站编辑）；快捷键经 `keybindings.execute` 出站 → 宿主 `executeCommand` → `ui.command` 回流 webview，与侧栏按钮、命令面板三入口同链路（UI_OPERATIONS 登记即自动获得宿主命令注册）。默认不占键位：侧栏按钮常驻可见，快捷键留给高频用户按需绑定。索引维护类操作（重建/清理缓存）不在此列——属设置页/宿主域操作（#198 接线），不接管正文输入。

**「打开/切换出链面板」注册为 UI 操作、默认未绑定（出链面板批次评估结论）**：与反链面板同款镜像登记（`onegayi.vsidian.ui.outlinksToggle`，双模式生效 `mode: both`、非写操作 `writes: false`、默认 `[]`）——目标固定明确（侧栏出链面板的显隐翻转，与大纲/反链三面板互斥），纯视图状态翻转（零写回、零出站编辑），快捷键/侧栏按钮/命令面板三入口同链路。默认不占键位（侧栏按钮常驻可见）。**面板内局部控件不设全局键位**：排序下拉、搜索框、折叠全部、更多上下文四控件均为面板内部交互（面板未打开时无目标、焦点语义不成立），不注册 UI_OPERATIONS、不占键位——面板打开后控件自身可 Tab 聚合、Esc 关菜单/搜索框（键盘可达性由控件承担，规格见 [vault-index-backlinks.md](vault-index-backlinks.md) 的「反链面板形态改版」节）。

**索引维护命令注册为宿主命令、默认未绑定（#198 评估结论）**：「完整重建」（`onegayi.vsidian.index.rebuild`）与「清理当前工作区缓存」（`onegayi.vsidian.index.cleanup`）登记于 extra 操作表（双模式生效 `mode: both`、非写操作 `writes: false`——语义为命令在两模式下均可用；操作本体不写正文，只维护索引缓存）。索引维护属**设置页/宿主域操作**：入口常驻设置页「索引维护」分页（按钮与命令共用同一 wiring），不接管正文输入、不进 webview 键路由；宿主侧注册保证设置页或面板异常时命令面板仍可达（cssSnippets.pause 同模式）。低频操作默认不占键位，用户可按需绑定。

**单文件更名/移动的引用自动更新无快捷键（#199 评估结论）**：引用改写由 `onWillRenameFiles`/`onDidRenameFiles` 事件自动驱动（用户在资源管理器/命令面板发起 rename 或 move 即触发，任何 VSCode 原生改名入口都覆盖），不是可枚举目标的用户命令、不注册操作、不占键位（通道语义与实测边界见 [vault-index-backlinks.md](vault-index-backlinks.md) 的「#199 实施落档」节）。外部工具改名不触发 VSCode rename 事件，只刷新索引不改写（「不猜测旧新身份」）。

**目录/批量移动的引用更新无新增键位入口（#200 评估结论）**：与 #199 同一事件通道的批量化扩展——目录 rename/move 与多文件同批移动由同一 `onWillRenameFiles`/`onDidRenameFiles` 驱动（事件内的 files 数组即批量输入），无新的用户主动命令面、不注册操作、不占键位（展开与批量规划语义见 [vault-index-backlinks.md](vault-index-backlinks.md) 的「#200 实施落档」节）。

**图片定期刷新与删除态无快捷键（#201 评估结论）**：本票全部为自动行为——文件事件即时核验（宿主图片扩展 watcher + 索引 onTargetChange 订阅）、周期核验（webview 调度器约 30 秒合并上报，常量集中可调）、失效重载（image.invalidate 广播 + `?v=` 代次击穿）与失败态呈现（找不到/不可访问细分），无任何用户主动触发的可绑定操作；失败槽位的既有「点击重试」语义不变（保留鼠标点击入口，与 #10 相同）。不占用键位。

**代码折行开关无快捷键（#191 评估结论）**：阅读视图代码块头部的折行开关（[折行] [复制] [折叠]，点击全文联动开/关自动折行）为**纯指针操作**，不提供快捷键入口、默认不绑定——目标虽是全文级（无歧义），但开关已常驻每张卡片头部、一键直达，键位收益不抵命令面板与快捷键页的条目膨胀；且仅阅读视图可切换（Live 恒折行，CM6 折行是编辑器级 facet 无法按块关），正文焦点路由难以覆盖「阅读视图专属」的操作域。后续若用户提出键盘直达需求，按 `AGENTS.md` 重新评估（语义为只读视图操作、双模式中仅阅读生效）。

**「预览当前链接」注册为 UI 操作、默认未绑定（#221 评估结论）**：悬停浮层的键盘入口（命令面板与快捷键共用 id）——手动打开浮层且焦点进入（Esc 关闭后返还触发处焦点；焦点在浮层内时不因鼠标离开或父容器滚动销毁键盘现场）。目标由「光标位置或键盘焦点」即时推导：Live 以主光标处合法双链/普通 Markdown 链接为目标（判定族与点击同一口径——双链 → 树驱动链接 → 宽松链接；嵌入 `![[…]]` 因扫描守卫不命中，不重复弹窗），Reading/反链/出链面板以键盘聚焦的链接/条目为目标；无目标静默不误开。**单列为可绑定操作**（`onegayi.vsidian.ui.hoverPreviewLink`，双模式生效 `mode: both`、非写操作 `writes: false`——`mode: both` 只表示两模式下命令均可用，目标判定各入口独立实现；源码编辑器不经 webview 键路由天然不接管，设置页输入为独立 webview 无此路由）。快捷键经 keybindingRouter 本地分支执行（纯 webview 域，无宿主往返），命令面板经 UI_OPERATIONS 注册循环回发 `ui.command`——两条入口共用 webview 同一实现。默认不占键位：目标判定依赖光标/聚焦上下文，键位留给用户按需绑定；显式清空后保持禁用（清空不因重启或升级恢复）。**单修饰键限制的评估事实（2026-10-02 补记）**：单 Ctrl 等单修饰键不可绑定为键位——VSCode 原生与本插件键路由均为「修饰键只作 chord 前缀、不作键本体」，修饰键按下本身不构成可注册的按键事件；「按住 Ctrl 悬停」与「悬停中补按 Ctrl」两条触发路径由悬停行为设置（`hover.liveDirect` 关闭态）与事件特判承载，不依赖键位绑定——「预览当前链接」的理想键位（单修饰键）不存在是键位模型的通则而非本操作缺口，命令定位为命令面板与光标/聚焦上下文入口。

**Reading 正文嵌入的卡片内交互无快捷键（#222 评估结论）**：嵌入卡片（独占行 `![[…]]` 在阅读视图升级为引用卡片）的全部交互——右上角「打开目标笔记」入口、内部 Reading 的链接与一层展开占位点击、笔记属性区折叠按钮、内容滚动——均为**卡片容器局部交互**（目标由点击位置即时推导，无卡片时无目标，与出链面板局部控件同判定口径），不注册 `UI_OPERATIONS`、不占键位。键盘可达性由元素自身承担（打开入口与 fm 折叠按钮为真实 `<button>`，Tab 可达、Enter/Space 原生激活；嵌入内容为只读 Reading，选字复制走浏览器原生选区）。目标打开复用正文双链跳转的既有命令族（`wikilink.activate`，无新命令面）；嵌入限高为设置项（`embed.maxHeight`，设置页可调）而非操作。Live 侧嵌入（#223）的源码显隐属光标位置驱动的自动行为，届时另行评估。

**Live 正文嵌入的源码显隐无快捷键（#223 评估结论）**：实时预览中独占行嵌入的**源码显/隐不是操作**——由光标/选区是否触及引用源码区间（`![[` 到 `]]`，含两端）自动驱动（复用 `selectionTouchesRange` 语义，与 Mermaid 图、代码块卡片的编辑态切换同一交互族，均无键位），方向键、鼠标点击与选区移动的既有键位即全部入口；卡片本身无「编辑引用」按钮（规格明确不设）。卡片内交互（打开入口、链接、属性折叠、滚动）沿用 #222 评估结论（容器局部交互、真实 button 键盘可达）。零新增操作注册与键位。

**Reading 混排/列表/引用容器内嵌入无新增快捷键（#246 评估结论）**：混排嵌入的全部交互沿用既有入口——卡片本体（打开目标入口、内容链接、属性折叠、滚动）为容器局部交互（#222 评估口径），卡片与悬停内容内的递归展开为自动行为（#244/#245 既有键位与预算规则），未升级占位（链接文字域、表格格内）的点击走外层链接或保留到 #248 接入。零新增操作注册与键位；「预览当前链接」与打开目标入口继续覆盖本票场景。

**Live 混排/容器嵌入的精确源码显隐无新增快捷键（#247 评估结论）**：#223 的评估口径原样延伸到混排/列表/任务/引用/懒续行容器内的嵌入 occurrence——源码显隐仍由光标/选区是否触及嵌入精确区间（`![[` 到 `]]`，含两端）自动驱动（selectionTouchesRange 语义不变，不扩大到相邻文字/整行），方向键、鼠标点击与选区移动的既有键位即全部入口；源码编辑（含 IME）走正常编辑链路。卡片内交互（打开入口、内容链接、属性折叠、滚动、禁写任务框）沿用 #222 评估口径（容器局部交互、真实 button 键盘可达）。表格格内嵌入保留到 #248 接入。零新增操作注册与键位；「预览当前链接」与打开目标入口继续覆盖本票场景。

**多光标「在上方/下方添加光标」注册为 UI 操作、默认 Ctrl+Alt+Up/Down（#237 评估结论）**：多光标三入口中的两条命令（`onegayi.vsidian.editor.addCursorAbove` / `addCursorBelow`，@codemirror/commands 内置实现，webview 本地消化）**单列为可绑定操作**（仅 Live 编辑正文生效 `mode: live`、写操作 `writes: true`——本表首个 live+writes 的 UI 操作；阅读只读不接管，源码与设置页输入不装配）。默认绑定对齐 VSCode（Ctrl+Alt+Up / Ctrl+Alt+Down）；键位所有权归注册表——defaultKeymap 的内建同键位绑定由多光标扩展组的接管 keymap 退役（吞键不执行），用户清空/改绑后内建绑定不得复活，实际执行经 keybindingRouter 本地分支按注册表当前生效绑定分发；命令面板经 UI_OPERATIONS 注册循环回发 `ui.command`，两入口共用 `runCursorAdd` 同一实现（`src/webview/syncController.ts`）。边界：多光标设置（`editor.multicursor`，默认开）关闭时不接管（键位仍由注册表持有）；表格格区 region 存在时不接管（region 状态机维持单选区语义，批次 §3 已定边界）；frontmatter 成型头区由 frontmatterEditing 选区引导兜底。**第三入口 Alt+点击是指针手势不是命令**（`EditorView.clickAddsSelectionRange.of(e => e.altKey)`，CM6 默认 Ctrl/Cmd 显式改 Alt——Ctrl+点击已被 Live 链接跳转占用，CONTEXT.md 产品边界钉死，恒为 Alt 无切换空间）：不注册操作、不占键位、不可改绑，与表格格内拖选（altKey 让路先例）同属指针路径。Esc 收敛多选区由 defaultKeymap 的 `simplifySelection` 既有绑定承担（排全部浮层 Esc 之后，浮窗打开期间键位被浮窗消费不达 CM6，天然不插队）。Ctrl+Alt+Up/Down 冲突核对（#237）：操作表与 keybindingRouter 零占用（表内既有方向键绑定均为单修饰或无 Alt 组合）。

**「选下一处相同词」族注册为四个可绑定操作、默认 Ctrl+D / Ctrl+K Ctrl+D / Ctrl+Shift+L（#238 评估结论）**：多光标三入口的第三条命令族（`onegayi.vsidian.find.selectNext` / `selectPrevious` / `skipCurrent` / `allOccurrences`，选区计划在 webview 本地消化，`src/webview/nextOccurrence.ts` 纯函数 + `runOccurrenceSelect` 适配层）**单列为可绑定操作**（Live 编辑正文生效 `mode: live`、写类 `writes: true`——选区操作与 #237 addCursor 同口径，router 的 allowWrites 门控据此在查找输入框等非正文焦点不劫持；阅读只读不接管）。默认绑定对齐 VSCode：Ctrl+D（选下一处——连按逐次追加、文档尾回绕）、Ctrl+K Ctrl+D（跳过链，**两段弦**——router 的整串 chord 匹配与 1.2 秒前缀超时/Escape 取消为既有基建，键位冲突检测含弦首段前缀重叠）、Ctrl+Shift+L（全选相同词转多光标）；「选上一处」对齐 VSCode 无默认键位（命令面板入口可达，不做不视为缺口——批次文档 §4 钉住）。匹配选项与查找面板三开关**同源消费**（`shared/findOptions` 单一事实源，workspace 级记忆）：面板开且搜索词非空沿用面板档；面板未开 + 空选区以「敏感+全字」override 档种子选词（会话级、不写回记忆档）；面板未开 + 有选区沿用面板记忆档、选区文本为搜索词——会话档在创建时决定、存续期间不漂移。**无内建绑定需接管**：defaultKeymap 不绑定这三键，searchKeymap 的 Mod-d（selectNextOccurrence）随官方面板一并不装配，故无需吞键 keymap；用户清空/改绑后按键自然落穿（浏览器无对应默认行为）。原生 `selectNextOccurrence`（恒敏感、无选项联动）由本票计划函数 + 控制器 dispatch 取代。配套「查找选项条」（Ctrl+D 会话期的迷你三按钮）非模态——不抢编辑器焦点、不占弹窗互斥槽位、Esc 在查找面板之后消费一次（只关条不收敛选区，收敛由下一次 Esc 经 CM6 `simplifySelection`），详见 `docs/specs/batch-2026-10-vscode-ops.md` §3「查找选项条细节」。Ctrl+D / Ctrl+K Ctrl+D / Ctrl+Shift+L 冲突核对（#238）：操作表与 keybindingRouter 零占用（表内无 ctrl+d、无 ctrl+k 起始弦、无 ctrl+shift+l）。

**中文分词词级移动注册为四个可绑定操作（#239 评估结论）**：Ctrl+Left/Right 及 Shift 变体对连续中文段按分词结果逐词切分（引擎可切换：预设 Intl.Segmenter，可选 jieba-wasm 按需下载——设置页「中文分词」分页管理），拉丁与数字段**逐字节沿用 CM6 既有 group 语义**（无 CJK 细化时整笔委托原生命令，回归断言钉住）。四个操作**单列注册**（`wordMotion.cursorLeft/Right`、`wordMotion.selectLeft/Right`，Live 编辑正文生效 `mode: live`、写类 `writes: true`——router 的 allowWrites 门控据此在 find 输入框等非正文焦点不劫持；Shift 变体独立注册——router 按整串 chord 精确匹配，ctrl+left 不隐含 shift 扩选）。默认绑定 ctrl+方向（Windows/Linux）与 alt+方向（mac 词移动惯例；Cmd+方向不注册——mac 行首/行尾惯例不被覆盖）。执行装配在 **keybindingRouter 的 document 捕获层本地分支**（词移动高频按键，同步直达不出站宿主往返）；命令面板经 UI_OPERATIONS 注册循环 → `ui.command` 回流。不选 CM6 keymap 派生替换 defaultKeymap 的 Mod-Arrow：路由层已有注册表改绑/清空/恢复默认全链路，且「注册表只登记带修饰键方向键」天然保证与表格裸方向键格导航共存（tableEditing 只绑裸 ArrowLeft/Right，browser 测试钉住 Tab 格导航与格内词移动并存）。

**2026-10 编辑器操作批次键位冲突核对（#240 收口记录，AGENTS.md 快捷键约定的评估记录）**：本批次新增键位逐键核对操作注册表与 keybindingRouter 占用，结论如下——`Ctrl+H`（替换，#236）：注册表内此前无占用（粗体 Ctrl+B / HTML 注释 Ctrl+/ 均不同键），CM6 defaultKeymap 无内建绑定；`Ctrl+Alt+Up/Down`（添加光标，#237）：表内既有方向键绑定均为单修饰或无 Alt 组合，defaultKeymap 内建同键位绑定由多光标扩展组的接管 keymap 退役（吞键不执行，键位所有权归注册表）；`Ctrl+D` / `Ctrl+K Ctrl+D` / `Ctrl+Shift+L`（选词族，#238，合并后键位与票面一致）：注册表与 CM6 内建均无占用，`Ctrl+K` 两段键首段与既有两段键（待输入超时 1.2 秒取消）无首段重叠冲突；`Ctrl+Left/Right` 与 Shift 变体（词级移动，#239）：注册表此前无占用，defaultKeymap 的 Mod-Arrow group 移动由路由层本地分支接管（注册表只登记带修饰键方向键，与表格裸方向键格导航共存，browser 测试钉住）；`Alt+Left/Right`（mac 词移动惯例默认）：与浏览器后退/前进手势在同一 webview 上下文由编辑器消费，不透传。批次内互检：六族键位两两无重叠（Ctrl+D 与 Ctrl+Alt+方向、Ctrl+Shift+L 与 Ctrl+Shift+Left/Right 修饰组合不同）；与批次外既有绑定的唯一交叉面是 Ctrl+方向键从「CM6 内建 group 移动」转为「注册表命令」（行为超集：拉丁语义不变，CJK 段分词细化）。

**多光标下格式操作的键位语义（#240 评估结论）**：格式操作（粗体/斜体/标题等注册表操作）在多光标形态下的作用域由操作类别决定，不改键位注册——**行内包裹类**（粗体/斜体/删除线/行内代码/高亮/清除行内格式/链接/行内公式/双链）逐 range 应用（每条选区独立两态判定，一笔撤销整批回退）；**结构性操作**（标题/列表/引用/代码块/块级公式/分割线/HTML 注释）退化主选区（其余选区原样保留，多光标形态不收敛）。表格格区（矩形多格选区）与多 range 互斥（region 状态机维持单选区，批次实施树 §3 已定边界），表格增删行列命令按既有契约在选区中不执行。Tab/Shift+Tab 行缩进取各 range 覆盖行并集（#120 既有口径，与 Enter/Backspace 的「多光标不接管」不同：行集合命令的自然泛化），Tab 越界对多 range 显式不接管（#125 既有决策）。

**表格格内嵌入无新增快捷键（#248 评估结论）**：表格单元格内 `![[…]]` 嵌入（表头/数据格、含 `\|` 别名等转义形态）的全部交互沿用既有入口——卡片本体（打开目标入口、内容链接、属性折叠、滚动、禁写任务框）为容器局部交互（#222/#246 评估口径，真实 button 键盘可达）；源码显隐由光标/选区是否触及嵌入精确区间自动驱动（#223/#247 的 selectionTouchesRange 语义原样延伸到格内 occurrence，不扩大到相邻文字或整格）；格内导航与输入（Tab 切格、Enter 格内换行、方向键、IME、填充空白契约）全部沿用表格既有键位（`table-interaction-rework.md` 契约，无新键）。卡内浏览器选字/复制不启动父矩形格区选取（`tableRegionSelection` 的起点锚定排除嵌入卡域——指针路径修补，非键位面）。零新增操作注册与键位；「预览当前链接」与打开目标入口继续覆盖本票场景。

**替换操作生效模式收窄到 Live（2026-10 用户决策评估记录）**：`findReplace`（Ctrl+H）自 #236 起注册为 `mode: both`，阅读侧收窄为「只开面板不展开」；用户决策改为**阅读模式整体禁用替换**——注册表生效模式改 `live`（Ctrl+H 在阅读不消费，冒泡宿主无该键绑定，不产生意外行为；保留消费反而需要「按键吞掉但不响应」的哑注册，语义更混），webview 侧同步三守卫：带 `replace` 的 `view.find.open` 指令不开面板（与命令面板入口同口径静默忽略）、替换栏 toggle 阅读态 disabled 灰化（点击链路加模式守卫，live 侧展开记忆不被阅读侧触碰——修除「阅读点击 toggle 钳空 live 记忆」的既有缺陷）、替换执行命令本就仅 Live（#236 既有）。快捷键设置页「生效模式」列与 manifest 文案随注册表自动同步；默认键位 Ctrl+H 不变，冲突面无变化（注册表内仍无 ctrl+h 占用，#240 收口记录结论不受影响）。

**引用内部视图模式切换注册为 UI 操作、默认未绑定；保存目标复用焦点内 Ctrl+S（P2-04/#281 评估结论）**：嵌入卡片头部新增「内部模式切换」按钮（Reading ↔ Live，图标与悬停词指向另一态）与「保存目标」入口（目标未保存时可见），键盘面评估如下——**内部模式切换单列为可绑定操作**（`onegayi.vsidian.ui.embedToggleMode`，双模式生效 `mode: both`、非写操作 `writes: false`——切换只建/拆目标编辑端口、不写权威文本；焦点不在嵌入编辑器内零操作），命令面板经 UI_OPERATIONS 注册循环回发 `ui.command`，与头部按钮共用 `EmbedCardManager.toggleMode` 同一实现；默认不占键位（规格「模式切换、冲突选择默认未绑定」），显式清空后保持禁用。**保存目标不设独立操作**：复用焦点内 Ctrl+S 路由（syncController docKeydown 捕获层——焦点在嵌入内部 Live 编辑器内时拦截 Ctrl/Cmd+S 出站 `refEdit.save` 只保存目标 B，焦点回 A 正文后不拦截、宿主默认保存 A 不变），头部保存按钮与该路由共用同一出站；Ctrl+S 的键位所有权属宿主（本插件不注册该键，只在焦点路由层条件拦截），无注册表占用。**嵌入内撤销/重做不设键位**：嵌入实例的 CM6 keymap 转发 `history.request` 经 `refEdit.message` 走 B 会话（宿主 P2-01 验证的临时激活路由），Mod-Z/Shift-Mod-Z/Mod-Y 键位由实例自身 keymap 消费（焦点在嵌入内时命中，焦点在 A 时命中 A 的转发——父子不同时消费同一按键）。
