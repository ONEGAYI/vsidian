# 规格：Live 表格列宽内容比例分配

状态：已实施（工单 [#142](https://github.com/ONEGAYI/vsidian/issues/142)；[#371](https://github.com/ONEGAYI/vsidian/issues/371)/[#372](https://github.com/ONEGAYI/vsidian/issues/372)/[#373](https://github.com/ONEGAYI/vsidian/issues/373) 于 2026-10-05 三票合一实施——短列可读下限与整表高度优化见下方专节）。本文是 Live 表格列宽机制的单一事实源，工单验收以此为准。

## 范围

- **覆盖**：Live 表格网格列宽由强制等分改为按内容比例分配，对齐阅读模式观感（小列小宽、大列大宽）。
- **排除**：列宽拖拽调整（CONTEXT.md 明确不含）；阅读侧表格（维持浏览器 auto 现状）；表格交互行为（[#72 规格](table-interaction-rework.md)不变）。

## 现状要点（勘察证实 2026-09-27）

- Live 每行为独立 CSS grid：`repeat(var(--vsidian-table-columns), minmax(0,1fr))` 等分、总宽 `min(100%,880px)`、格内 `pre-wrap`（`src/webview/main.css:1503-1520`）；列数由行装饰内联写入（`src/webview/liveDecorations.ts:377-383`）。
- 阅读侧为真 `<table>`，浏览器 auto 按内容自适应（`src/webview/main.css:1877-1883`，无 table-layout 声明）。
- 全仓无 colgroup / col、无列宽 resize（`tableControls.ts` 的拖动是行列**重排移动**）。

## 已确认决策（2026-09-27 澄清答复）

1. **算法：内容比例分配**——逐列度量各单元格与表头的内容宽度，设最小列宽下限，剩余宽度按内容占比分配。
2. **总宽与折行维持**：`min(100%,880px)` 总宽与格内折行不变，不做横向滚动。

## 计算契约

1. **度量**：按列取各单元格与表头的最大显示宽度（按渲染字体度量或等价字符宽度启发式；GFM 对齐标记剔除后计）。实现选型（离屏 canvas / 字符宽度估算 / DOM 探针）在工单记录；度量函数可注入以便测试。
2. **分配**：每列先保底最小列宽，剩余宽度按内容宽度占比分配，总和恰为网格总宽；**同表各行必须共享同一列宽计划**（行是独立 grid，逐行内联相同 `grid-template-columns`）。
3. **重算时机**：表格内容变更、列数变更、容器宽度变更时重算；编辑中沿用表格网格的防抖策略，输入时列宽不跳动。
4. **GFM 列对齐（`:-:`）**：阅读侧有 text-align 内联样式；Live 侧本票核对并对齐（应用到该列全部单元格）。
5. **极端形态**：单列超长内容按折行处理不撑破总宽；空列 / 空表头取最小列宽。

## 用户故事

1. 作为编辑者，我希望窄内容的列不被等分拉宽、长内容的列不被挤压成细条，表格像阅读模式一样按内容取宽。
2. 作为编辑者，我希望输入时列宽稳定，不会每敲一个字就跳。

## 实施决策

- **纯函数**：列宽计算独立为纯函数（输入：各列宽度样本 + 总宽 + 列数；输出：逐列宽度），脱离 DOM 单测。
- **装饰层**：`tableGridPlan` 旁新增共享列宽计划；行装饰从内联 `--vsidian-table-columns` 迁移为内联 `grid-template-columns`（已实施形态：逐行内联相同计划）。**等分规则不退场，降为 CSS 缺省回退**——无列宽计划（计划缺失的行）时由等分 `repeat(var(--vsidian-table-columns), minmax(0,1fr))` 兜底；契约钉住等分不再是列宽的唯一来源。
- **CSS 契约**：更新契约测试钉住新机制，防等分规则回潮为唯一来源。

## #248 格内嵌入兼容边界（2026-10-01 落档）

表格单元格内的 `![[…]]` 嵌入卡片（#248，规格见 [hover-preview-embed.md](hover-preview-embed.md)）与列宽机制的职责分界：

- **列宽计划不受格内卡影响**：格内卡是网格格 mark span 内部的挂载（CM6 inline replace widget 不切开 mark），含卡格仍是单 grid item——采样、分配与重算时机（计算契约 1–3）不变；卡被限高滚动约束在格盒内（`max-width:100%` + 卡壳 overflow:hidden + 内层横向滚动），不因内层最小宽度（长文件名/长代码块）撑破列宽或挤掉邻格（浏览器 tableEmbed 场景断言卡不越格）。
- **格内宿主的内边距收窄**：格内 `vsidian-live-embed` 宿主 padding 收紧为 `3px 0`（行级宿主的 `7px 0` 是行语义间距，格内由格自身 padding 承担）——CSS 契约由 `embedCardCssContract` 钉住，列宽计算不感知该 padding（采样按字符宽度，不含卡）。

## #371–#373 短列可读下限与整表高度优化（2026-10-05 落档）

三票合一实施（PR #383）：[#371](https://github.com/ONEGAYI/vsidian/issues/371) 把 #142 的静态 48px 最小列宽改造为随字号/盒模型变化的**短列可读下限**并把采样口径对齐「可见文字」语义；[#372](https://github.com/ONEGAYI/vsidian/issues/372)/[#373](https://github.com/ONEGAYI/vsidian/issues/373) 在此之上叠加**整表高度优化**——光标在表内时保持轻量计划，离开整表后做一次有界搜索，选择预计整表高度较低的布局。本节是这三层机制的落档事实源；下述既有各节在未被本节显式修订处继续有效。2026-10-05 人工验收反馈补充「结构操作后立即重算」（见下节末条目）。

### 短列可读下限与可见文字采样（#371）

- **纯数据输入**：`tableColumnWidth.ts` 的 `options` 新增普通数据输入 `readability`——`contentPx`（三汉字内容宽）、`cellBoxPx`（格左右 padding + border）、可选 `availablePx`。缺省不传时保持 #142 静态 48px 行为（不变式测试钉住），StateField/装饰构建内零 DOM 测量的红线不破——度量由视图层测量后注入。
- **下限计算**：下限 = `contentPx + cellBoxPx`，随字号单调变化。各列下限之和超过 `availablePx` 时按比例收缩（非负、总宽不超网格）；容器恢复宽度后自动回到常规下限。生产轨道仍写 `minmax(min(px, share%), …fr)` 双保险——CSS 份额（等分百分比）兜底承接容器宽变化，px 下限随字号。
- **可见文字采样口径**：上节「计算契约 1」的「最大显示宽度」自 #371 起细化为**可见文字**口径——双链别名与 markdown 链接只计链接文字域（隐藏目标不计入）、成对格式标记（`**`/`__`/`*`/`==`/`~~`/`_`）与行内代码反引号剥离（对齐 CodeMark/EmphasisMark 的隐藏呈现）；图片/公式/嵌入卡按有界回退 `TABLE_WIDGET_FALLBACK_UNITS = 6` 计，格内卡不主导父列宽（#248「不测量目标全文」边界保持）。形态学复用 `shared/wikilink`、`shared/math`、`shared/tableCells` 单一事实源，不新增语法。
- **视图层度量注入**（`tableMetrics.ts`）：`tableMetricsFacet` + `metricsCompartment` 热重配通道（`tableContainerRenderFacet` 同款先例）；探针 span 挂 `.cm-scroller` 继承正文字号、叠 `vsidian-table-line` 拿表格字体族，实测三汉字宽。字号/字体变化经字体签名比较感知（update 驱动），`fonts.ready` 补一轮；IME 组合期零 dispatch（pending 于 compositionend 宏任务补测）。`availablePx` 实测注入：首个网格行 border-box 宽扣除左右 padding/border（引用缩进随行盒 padding 扣除，净宽口径——与引用块内表格规格的「格区外占位不进列宽」一致）；几何变化与文档变更延后一拍补测，值未变不 dispatch。

### 整表高度优化（#372/#373）

- **评分模型**：整表高度 = 逐行「各格估算高度最大值」之和（含表头）——不是格行数相加，也不是只压最高一行；统一行高时等价逐行最大折行数之和。折行估算：中文任意字符间可断、拉丁按词（空格随前词换行丢弃）、行内代码按词且超长无空格串按宽硬断、裸 `br` 显式行（连续 `br` 空行计行）；可见文字口径与 #371 采样同源（`cellVisibleLines` 单一实现共享）。
- **安全系数**：`TABLE_OPT_WRAP_SAFETY = 0.98`——字符启发式与真实字体 advance 有 1–2% 偏差，恰在「N 字整」刀口宽度上模型判 2 行而真实折 3 行（README 24px 样例实证）；评分按收缩宽悲观化，优化器自然避开刀口。
- **两列搜索（#372）**：9 粗搜点 + 内容锚点 + 轻量基线 + 8 细搜点（候选上限 24）。**轻量基线必在候选集内，同模型评分不劣于基线**；赢家与基线重合（±0.5px）时不发布（行装饰键不变零重绘）。
- **多列搜索（#373）**：统一入口 `optimizeTableHeight`——两列走粗搜+细搜、3..12 列走多列通道（候选族 = 基线 + 等分 + 逐列内容锚点 + 阈值贪心转移层：把列拓宽到「最高格少折一行」的跨阈值最小宽，贪心对宽单调、二分 40 轮收敛，差额按各列下限以上余量比例分摊，列宽和守恒、不破下限），超 `TABLE_OPT_MAX_COLUMNS = 12` 或缺度量稳定降级为轻量计划。不穷举列宽组合。
- **同分决胜**：总折行 → 表头折行 + 短标签超行 → 距基线变化（两列）/ Σ|列宽−基线| 与逐列宽字典序（多列）——层级序与两列同源，逐字节确定。
- **活动定义与触发**：以**整表**为单位——任一光标在表内（端点两侧解析，分隔行算表内）、任一非空选区与网格段相交、矩形格区属于该表，任一成立则完整搜索为零；表内切格仅局部处理。仅焦点短暂进入工具栏/菜单/浮层而选区未离表不触发；格内引用编辑（嵌入卡持焦）期间父表暂停。离开最后一个表内选区后 0ms 冲量执行一次；初次挂载的非活动可见表允许一次，离屏表延至可见（viewportChanged 非 doc 变更触发，键入不扫描）。
- **结构操作后立即重算（2026-10-05 验收反馈）**：把手拖拽重排（行/列）、删除整行、删除整列三个离散结构操作的编辑事务自带 `requestTableReworkOptimize` 效果（`tableHeightScheduler` 导出；载荷 = 事务前表格 from，调度层经 `u.transactions` 逐笔读取并随事务变更映射）——落定后 0ms 冲量内立即一次完整重算，与「离开触发」的唯一差别是**豁免活动态检查**（三个操作离散且落定即结构终态，不与「连续键入活动表零搜索」契约冲突）；IME 组合期/嵌入编辑期/视图隐藏守卫、四元组复核与指纹仲裁同流程，同版本去重兜底与离开任务对同表的重复入队。补的两条实证缺口：活动态删行后光标跟随留在表内（无离开事件，此前永不重算）；把手拖拽是纯指针操作不要求光标进表，非活动表结构变更后 docChanged 不请求扫描（此前模板与列序错位一直挂到下次滚动/进离表）。**不携带效果的操作**：插入行/列（操作后通常继续填内容，立即重算会在空结构上定格）、退格删空行（空行不携带列宽样本）、矩形格区删除（行列保留）——仍走离开/滚动/度量触发。测试钉在 tableCaret `height-optimize-rework` 场景：活动态删行、表外把手拖列/拖行、进表删列四步各自 searches 等值等待（`===` 天然防超额）+ 结构编辑恰好一笔 edit.request 出站（布局重算零写回）+ computed 轨道数随列数。
- **取消与验证**：回表、删表、表前编辑（docChanged 清空待执行）、视图隐藏（display:none 两级判定）、实例销毁均取消待执行任务；发布载荷带表格身份/文档引用/列数/度量签名**四元组**，应用前逐载荷复核（含组合冻结），旧任务不能覆盖新表或已销毁视图；销毁清空冲量定时器、待执行映射、签名登记、折行缓存并注销 compositionend 监听。
- **缓存仲裁键**：同版本去重的仲裁键 = 列数 + 度量签名 + **逐行内容指纹**——任一行换行分布变化即失效，不依赖列最大样本（修正 #142 IME 定稿只比较最大样本的盲区）；IME 组合期零搜索零发布（compositionend 重排），定稿快路径在模板未变时同样回写定稿行样本。缓存随视图释放，无持久列宽存储。
- **预算与降级**：预算集中定义——候选 24（多列 32）、单轮格评估 20000、行缓存 4096、登记 256。超预算降级保留轻量计划（不跑搜索），签名登记防反复重试，条件变化后才重试。常量依据与实测记录见 [2026-10-table-height-opt.md](../perf/2026-10-table-height-opt.md)：百行三/六列表纯计算冷 0.8–1.7ms、千行表确定降级（0 候选 0 评估）、键入中位 0.4–0.6ms 与表规模无关、挂载格数视口量级。
- **发布效果**：优化模板套进同表共享计划并整表重发射（模板变化 → 行装饰键变 → CM6 重绘）；零写回、零宿主消息、零撤销记录。`tableGridPlan` 的结构判定抽出为 `tableGridRowsInfo` 单一事实源（调度层同源消费）；rowsScanned 记账只在 `tableGridPlan`（调度路径零增量，千行表纯光标扫描 <20 行契约不破）。

### 断言口径与跨字体边界

- 浏览器真实布局断言分两类：**冻结样例（blockquoteTablePaint 的 README #372 与引用三列 #373 场景）用「不劣于轻量基线 +1px」契约**——CI Linux 字体度量量子化下，冻结内容里模型改进可能未跨过折行阈值（两场景分别实证 184=184 / 490=490，本地六种 CJK 字体均实测 -42/-63px，机制对字体不敏感、边缘在阈值，见提交 d9349f74 与后续同型加固）；**tableCaret 顶层三/六列设计样例（周期性全短行杠杆）保留严格高度下降断言**——CI 实证绿。
- 表内键入/Tab/矩形拖选/真实 IME 组合期间搜索为零、退出后恰好一次且零写回（edit.request 出站与源文不变）、短标签列宽不破下限、轨道总宽不超行区净宽（引用缩进口径）、同版本再进出不重复搜索——以上由 tableCaret/blockquoteTablePaint 套件断言钉住。
- 样式契约：`live-table-grid-row` 条目双语描述更新（48px 静态下限 → #371 字号感知下限），属既有公开入口措辞对齐，无新增公开 CSS 变量；探针隐藏规则（`.cm-scroller` 内测量 span）非公开契约入口，探针载荷「汉汉汉」登记 i18n CJK 白名单（测量输入非用户文案）。
