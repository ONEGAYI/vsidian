# 规格：Live 表格列宽内容比例分配

状态：待实施（工单 [#142](https://github.com/ONEGAYI/vsidian/issues/142)）。本文是 Live 表格列宽机制的单一事实源，工单验收以此为准。

## 范围

- **覆盖**：Live 表格网格列宽由强制等分改为按内容比例分配，对齐阅读模式观感（小列小宽、大列大宽）。
- **排除**：列宽拖拽调整（CONTEXT.md 明确不含）；阅读侧表格（维持浏览器 auto 现状）；表格交互行为（[#72 规格](table-interaction-rework.md)不变）。

## 现状要点（勘察证实 2026-09-27）

- Live 每行为独立 CSS grid：`repeat(var(--vsidian-table-columns), minmax(0,1fr))` 等分、总宽 `min(100%,880px)`、格内 `pre-wrap`（`src/webview/main.css:1503-1520`）；列数由行装饰内联写入（`src/webview/liveDecorations.ts:377-383`）。
- 阅读侧为真 `<table>`，浏览器 auto 按内容自适应（`src/webview/main.css:1877-1883`，无 table-layout 声明）。
- 全仓无 colgroup / col、无列宽 resize（`tableControls.ts` 的拖动是行列**重排移动**）。

## 已确认决策（2026-09-27 澄清答复）

1. **算法：内容比例分配**——逐列度量各单元格与表头的内容宽度，设最小列宽下限，剩余宽度按内容占比分配。
2. **总宽与折行维持**：`min(100%,880px)` 总宽与格内折行不变，不做横向滚动。

## 计算契约

1. **度量**：按列取各单元格与表头的最大显示宽度（按渲染字体度量或等价字符宽度启发式；GFM 对齐标记剔除后计）。实现选型（离屏 canvas / 字符宽度估算 / DOM 探针）在工单记录；度量函数可注入以便测试。
2. **分配**：每列先保底最小列宽，剩余宽度按内容宽度占比分配，总和恰为网格总宽；**同表各行必须共享同一列宽计划**（行是独立 grid，逐行内联相同 `grid-template-columns`）。
3. **重算时机**：表格内容变更、列数变更、容器宽度变更时重算；编辑中沿用表格网格的防抖策略，输入时列宽不跳动。
4. **GFM 列对齐（`:-:`）**：阅读侧有 text-align 内联样式；Live 侧本票核对并对齐（应用到该列全部单元格）。
5. **极端形态**：单列超长内容按折行处理不撑破总宽；空列 / 空表头取最小列宽。

## 用户故事

1. 作为编辑者，我希望窄内容的列不被等分拉宽、长内容的列不被挤压成细条，表格像阅读模式一样按内容取宽。
2. 作为编辑者，我希望输入时列宽稳定，不会每敲一个字就跳。

## 实施决策

- **纯函数**：列宽计算独立为纯函数（输入：各列宽度样本 + 总宽 + 列数；输出：逐列宽度），脱离 DOM 单测。
- **装饰层**：`tableGridPlan` 旁新增共享列宽计划；行装饰从内联 `--vsidian-table-columns` 迁移为内联 `grid-template-columns`（或过渡期并存，最终等分规则退场）。
- **CSS 契约**：更新契约测试钉住新机制，防等分规则回潮。

## 验证与完成条件

- **测试**：列宽纯函数单测（占比分配、最小下限、极端列、总和恒等、跨行一致）；表格输入 / 光标行为变更，合并前必跑 `npm run test:browser`。
- **视觉层断言**：绘制层可观测列宽差异（宽内容列宽于窄内容列）。
- **用户人工验收**：以用户样例表核对「小列小宽、大列大宽」及与阅读模式的一致性。
- **回归与文档**：compile / test:unit / test:browser / test:integration；更新 README 双语、人工验证清单、文件树。
