## 通用准备

- 安装 VSIX（`vsidian-0.1.0.vsix`）到 VSCode 1.86+：命令面板 →「Extensions: Install from VSIX…」。
- 打开方式：安装后打开 `.md` 文件默认进入 Vsidian（#38 起注册为默认编辑器）；改回原生用右键「打开方式…」选文本编辑器，或「Reopen With… → Configure default editor for '*.md'…」修改关联设置。
- 切换视图：编辑器标题栏三态按钮（实时预览 → 阅读 → 源码编辑器循环，只显示下一步的图标与提示），或命令面板 →「Vsidian: 切换到下一视图模式」及三个显式目标命令。

## 一、输入与组合（#3 / #12 / #13）

### A1. 中文 IME 真实组合输入（#3）

先在刚打开且未编辑的普通段落及空白表头中输入中文，经历多次候选更新后确认，再保存并重开。确认没有「检测到无法安全同步的外部修改」横幅，磁盘保留中文；随后再执行以下 Esc 与真实外部冲突场景。

1. Windows VSCode 1.86.2 的 live 视图先选中一个已有汉字，切换中文拼音 IME，输入拼音使候选窗出现，再按 Esc 取消候选；确认英文字母留在原选区。
2. 不作外部编辑，连续重复数轮；保存、关闭并重新打开文档，比对编辑器、TextDocument 与磁盘文本，确认无重复字母、丢字或暂停横幅。
3. 另开同一文件，在一轮组合期间由另一编辑器修改本地选区，确认真实重叠修改会保留本地输入并暂停。
4. 组合期间观察候选窗位置跟随光标、无闪烁跳动。

预期：候选词上屏文本正确写入并保存后回读一致；组合中途外部修改该文件（另一编辑器改同一行），上屏不被打断且冲突按「保留输入」语义处理（顶部出现冲突横幅，本地输入保留）。

复验边界（#44）：自动化能验证删除后补入拼音的 CM6 事务顺序、宿主确认与回流，以及真实 1.86.2 宿主的重叠修改保护；测试钩子无法打开 Windows 输入法候选窗或发出物理 Esc。此项保持待真实 IME 验证，执行后补充输入法名称、VSCode 启动方式、实际加载产物、复现次数与保存回读结果。

### A3. 表格内真实键盘/IME 输入（#12）

1. 打开含表格的文档（如 `| a | b |` 一行起始两列表）。

### A4. 表格 Tab 物理按键手感（#13）

1. 光标置于表格单元格内，按 Tab / Shift+Tab 在单元格间移动。
2. 在行末单元格按 Tab（环绕到下一表格行首格）、行首单元格按 Shift+Tab（回退到上一表格行末格）；在表格最后一行的行末按 Tab、表格首行的首格按 Shift+Tab（表格行不被缩进，按键交工作台焦点导航）。
3. 命令面板执行六个「表格：…」命令确认可见性与快捷入口。

> **行号布局修订（2026-09-25，用户决策，取代上述 P0 记录中的留白带叠加方案）**：行号列改为**流内布局**——`行号列 + 固定间距（--vsidian-ln-gap = 2 × VSCode UI 字号，响应界面元素大小）+ 主体文字` 的总宽 = 行号关闭时的正文宽度；列不外扩、正文向右内缩，关闭行号（或阅读模式）时正文回到 24px 页面留白基线。此修订正式取代 #32 验收中"行号栏不得右移正文基线"的旧口径（该口径源于留白带叠加设计，带宽 24px 无法容纳宽编号与合理间距，用户已决策改为内缩式）。scaleX 宽编号压缩机制随带宽约束一并移除：CM6 按文档最大行号预留列宽，真宿主实测 10 万行文档开启行号正文内缩 89.6px 全程恒定（滚动无回流），关闭行号回到 24px 基线。旧 P0 记录中 `position: relative !important` 压制内联 sticky 的做法随之退役（流内静态位与 sticky 钳制一致，无需干预）。

> **光标明暗主题自适应（2026-09-25，用户验收发现两轮）**：深色主题下光标黑底黑色不可见。第一轮诊断有误：`.cm-cursor`/`.cm-selectionBackground` 是 CM6 `drawSelection()` 扩展的产物，本扩展未启用该扩展——光标实为**原生 caret**，颜色由 baseTheme 的 `caret-color` 决定（light 变体写死 black），故第一轮引 `--vscode-editorCursor-foreground` 覆盖 `.cm-cursor` 的规则不命中任何元素（无效修复），运行时探针实证 `cursorBorderColor=null` 后推翻。最终方案（用户指示：**自适应明暗，不硬编码 dark 也不硬编码颜色**）：`syncController` 以 `darkCompartment` 声明 `EditorView.darkTheme`——初始按 webview body 主题 class 判定（`vscode-dark`/`vscode-high-contrast` 为暗，`vscode-light`/`vscode-high-contrast-light` 为亮），MutationObserver 监听 body class 热跟随宿主主题切换；caret 颜色完全交给 baseTheme 内建变体（light: black / dark: white），main.css 零颜色代码。真宿主 Dark+ 实测 `darkTheme=true`、`caret-color=rgb(255,255,255)`。契约由 test/unit/editorChromeCssContract.test.ts 钉住（facet 热跟随行为 + main.css 不得出现 caret/cursor 硬编码规则）；浅色/高对比主题下的观感属目视项，随 A23 人工复核。

## 十一、标题栏三态切换与全局模式记忆（#38）

### A24. 三态按钮循环、多标签独立、重启恢复与未保存保留

1. **三态循环与图标/提示**：打开一个 `.md`（默认进入 Vsidian 实时预览），观察编辑器标题栏按钮——实时预览态显示「切换到阅读模式」（书本图标），点击进入阅读；阅读态显示「切换到源码编辑器」（代码图标），点击切到原生源码编辑器；源码态显示「切换到实时预览」（铅笔图标），点击回到实时预览。命令面板执行「Vsidian: 切换到下一视图模式」应走同一循环。
2. **多标签各态独立**：开两个 `.md` 标签，A 切到阅读、B 保持实时预览；点击标题栏按钮时只作用于当前活动标签，另一标签状态不变。
3. **重启恢复与全局记忆**：切到阅读模式后关闭面板，打开另一个 `.md` 应直接进入阅读；切到源码编辑器后新开 `.md` 应落在原生编辑器。重启 VSCode 后该记忆仍生效；若窗口重开时恢复的 Vsidian 标签在源码记忆下被弹回原生，点铅笔按钮一步切回即属预期。
4. **未保存内容跨切换保留**：实时预览输入若干文字不保存，依次切到源码编辑器再切回——未保存内容全程可见、文件仍为 dirty、磁盘未被写入（纯视图切换不隐式保存）。
5. **diff 视图无按钮**：对两个 `.md` 执行「比较选中」（或在 SCM 更改列表点开 `.md`），对比视图的标题栏不出现三态按钮；此时执行命令面板切换命令应提示「对比视图不支持视图切换」且不改变对比视图。
6. **IME 组合未上屏时切换（#38 评审补充）**：在实时预览用中文输入法输入到组合态（拼音未上屏），直接点击标题栏三态按钮切到源码编辑器，再切回实时预览——组合文本应不丢失，或按项目冲突保留约定处理（出现「未确认输入已保留」类提示可取回）。自动化覆盖说明：组合中收到 `view.mode.set` 不打断组合缓冲链路（提交与 flush 照常、切回后输入保留）已有 jsdom 单测钉死；真实浏览器在容器切换时对未上屏拼音的处置无法无头模拟，须在此人工验证。
7. **双 Vsidian 标签的按钮随焦点切换（#38 评审补充）**：开两个 Vsidian 标签，A 处于实时预览、B 切到阅读模式；在两个标签间切换焦点——标题栏按钮应随活动标签变化（A 显示书本、B 显示代码图标）。此构型在 1.86 无头测试宿主下第二个 webview 面板创建偶发不就绪（约 5/7 轮复现，环境 flaky），集成用例已降级为「Vsidian 面板 + 原生 .md 标签」构型，双面板各自模式独立与按钮联动依赖本人工项。

预期：三态循环方向恒为 实时预览 → 阅读 → 源码 → 实时预览；按钮只显示下一步的目标；模式记忆为最近一次成功切换（跨窗口、重启保留）；已知代价——记忆停留在源码态时显式「Reopen With → Vsidian」会被弹回原生，铅笔按钮可一步切回。

## 十二、大纲面板呈现（#65）

### A25. 行内样式透传、字重语义与主题色同源的目视复核

准备一个含各类标记的文档（或参照测试样例）：

```markdown
# **重点** 结论
## *斜体* 与 `代码`
### ~~删除线~~ 与 [[目标笔记|显示别名]]
#### [链接文字](https://example.com) 尾注
##### ***粗斜*** 与普通
```

1. **标记透传**：展开右侧栏大纲，各条目按标记渲染——`**重点**` 显示加粗的「重点」（无星号）、`*斜体*` 斜体、`` `代码` `` 等宽字体带浅底、`~~删除线~~` 删除线、`***粗斜***` 同时加粗斜体；标记字符（`*`、`` ` ``、`~~`）不得以原文透出。
2. **字重语义**：无标记的条目（「结论」「尾注」等）与各级标题条目一律常规字重——与正文标题的加粗观感明显不同；仅显式粗体段加重。
3. **主题色同源**：大纲各层级条目颜色与正文同层级标题颜色一致（当前主题无分级着色，两侧同前景色）；切换明暗主题后两侧同步变化。
4. **双链/链接纯文本**：`[[目标笔记|显示别名]]` 显示「显示别名」、`[链接文字](…)` 显示「链接文字」，无 URL 透出；鼠标悬停/点击不出现链接指针与跳转。
5. **编辑跟随**：把某个标题从 `# 甲` 改为 `# *甲*`，停顿约 250ms 后大纲对应条目变为斜体「甲」；改回后恢复。

预期：标记渲染、字重、颜色均与上文一致；自动化覆盖（plainText/spans 数据对拍 + computed 字重/颜色绘制证据）见集成用例「大纲条目行内样式透传与主题色同源：标记渲染、字重与颜色绘制证据（#65）」（上列名称的前缀可检索到该用例，完整标题含副标题）；本项复核真实视觉效果（字体渲染观感、主题切换跟随）与鼠标交互。

## 十三、大纲点击跳转与常驻高亮（#66）

### A26. 大纲跳转定位、高亮跟随与滚动观感

1. **点击跳转（双模式）**：打开多级标题的长文档，展开右侧栏大纲；在实时预览点击中部某章节条目——光标应落标题行首、正文滚动到目标居中可见；切到阅读模式点击另一条目——阅读视图滚动到该标题块。两模式点击后文件不得变 dirty（零写回、Ctrl+Z 无可撤销项）。
2. **常驻高亮跟随**：滚动正文，观察大纲面板的半透明横条随视口顶部所在章节实时移动；跳转后横条停在目标条目上（不因程序性滚动的中间态抖动回上一章）；继续手动滚动后横条恢复跟随视口顶部。
3. **悬停视效（#99）**：鼠标悬停在大纲条目上——条目整行（含缩进空白区）光标变手指；悬停行出现比常驻横条更浅一档的同色背景；悬停行恰为常驻高亮行时保持常驻底色不叠加（最多两条高亮、最少一条）；悬停移开后浅色背景立即消失、常驻横条不受影响。
4. **模式切换重算**：带高亮状态下实时预览 ↔ 阅读来回切换——横条位置即时重算到当前视口对应章节，无长时间滞留旧值。
5. **快速滚动观感**：用滚轮快速长距离滚动长文档——横条更新无闪烁、无长时间错位（100ms 去抖内的短暂滞后属预期）；文档首标题之前（如 frontmatter/序言区）无高亮条目属预期。

预期：跳转与高亮均为纯视图操作（零写回、零出站编辑、不入撤销栈）；高亮以视口顶部行向上最近标题为准。悬停浅档与 located 不叠加由 CSS `:not(.located)` 承载（Chromium computed 断言已覆盖三态），浅档色阶与主题跟随的观感须由人工验收。真实滚轮手感与半透明横条观感须由人工验收（自动化只断终态与绘制层证据）。

### A26a. 层级对齐引导线（#99 视效）

准备多级标题的长文档（至少 H1–H3 三层、含跨级标题如 H1 直接跟 H3），展开右侧栏大纲。

1. **逐级多线**：深层条目左侧的竖线数量 = 其真实祖先数（H3 条目在 H1→H2 下有两条；参考 Obsidian 大纲的文件树式引导线）。每条线与对应**祖先级折叠三角的水平中心**垂直对齐。
2. **跨级无线**：H1 直接跟 H3 时，H3 行只有一条线（对齐 H1 的三角）——不为不存在的 H2 层级槽位画悬空的幽灵线。
3. **包住子树**：线从父条目行的底缘一路延伸到最末一个子孙条目的行底，把整棵子树框在内；穿过 located/悬停高亮行时线仍可见（线绘制于高亮背景之上）。
4. **折叠断线**：折叠任一父条目（三角朝右）后，其子孙行连同行内引导线一并消失；展开恢复。滚动动态展开（only-expand）后引导线与可见行一致。
5. **线观感**：1px 宽浅色竖线（亮色主题下浅灰、暗色主题跟随 VSCode 缩进引导变量自动适配）；线不拦截鼠标——点击线所在位置仍触发条目跳转或折叠箭头。

预期：引导线为纯装饰（aria-hidden、pointer-events:none、零写回）；线段渲染于每个子孙行内、相邻行视觉连成整条，折叠 display:none 时随行断开。自动化已覆盖纯函数祖先链（跨级/兄弟重置）、DOM 结构（span 数量与 left 对齐）、CSS 契约与 Chromium 绘制层（computed 背景非透明、折叠后 offsetParent 为 null）；线的颜色深浅与主题适配观感须由人工验收。

## 十四、大纲折叠滑块与手动折叠（#67）

### A27. 六档滑块、箭头折叠与滚动动态展开的人工复核

准备一个多级标题的长文档（至少 H1–H3 三层、若干跨级标题），展开右侧栏大纲。

1. **滑块六档语义**：侧栏顶栏下方应有一行结绳记事样式的滑块（六圆点 + 横线串联），默认第 6 点（H5 全展开）档；点击第 2 点（H1 档）——H2 直接子级全部出现、H3 起折叠；点击第 1 点（No-Expand）——只露各顶层标题；跨级标题（H1 直接跟 H3）应自然挂靠（H3 出现在其 H1 之下）。**口径：第 N 点 = 档 N−1**（即第 1 点 = 档 0/No-Expand、第 6 点 = 档 5/H5 全展开），与本清单他处「档 0」「档位」的写法同义。
2. **能量条填充（#99）**：滑块横线上应有从左端铺到当前档珠的填充色段（与实心珠同色，呈「充了一部分能量条」的量感）；左端到当前档之间的沿途珠全部实心、其右的珠保持空心描边；当前档由最右实心珠表达；点击/拖拽换档时填充段与珠态实时跟随；0 档（No-Expand）时填充归零、仅首珠实心。
3. **点击与拖拽选档**：单击任一圆点即选档；按住鼠标从一端圆点拖到另一端——拖动过程中档位跟随指针实时切换，松手落在最近的圆点档。
4. **箭头折叠与手动叠加**：有子项的条目左侧有箭头（展开朝下、折叠朝右），无子项条目无箭头但文字对齐；点箭头折叠/展开单条（折叠的子级整体隐藏，再点恢复）；折叠态与档位叠加正确（如 H3 档下手动折叠某个 H1，其整个子树隐藏）。
5. **滑块切换重置手动折叠**：手动折叠若干条目后切换滑块档位——手动微调被丢弃，展开集精确等于新档位语义。
6. **滚动动态展开与高亮回退**：切到 No-Expand 档，滚动正文进入某深层章节——大纲自动展开该章节的祖先链（该路径可见），其余章节保持折叠；高亮横条落在当前标题上并自动滚进大纲面板可视区；手动折叠当前高亮标题的父级——高亮回退到第一个可见祖先（父条目），不自动展开。
7. **编辑存活**：手动折叠某章节后，修改正文其他标题的文字（重命名）——折叠视图不扰动；在文档尾部新增深层标题——新标题可见（其祖先链自动展开）；删除折叠章节的子标题使其降格为叶——箭头消失。
8. **档位记忆**：切到某非默认档后关闭该文档，打开另一个 `.md`——档位应保持（全局记忆）；重启 VSCode 后仍保持。
9. **大幅重排后的熔断回退（已知取舍）**：对含大量标题的文档一次性改动超过迁移上限时，折叠状态**不再逐条迁移**，而是整体回退为**当前档位**的展开集（此前的手动折叠微调被丢弃），并在面板控制台留 `[vsidian]` 诊断（**同一次刷新最多两行——主展开集与搜索快照各调一次迁移，两边都超限则各留一行**）。判定量是标题序列的**编辑距离**（一次改名 = 一删一插 = 2，一次搬移同量级），超过 256 即触发——约等于一次改动 129 个以上标题，或整篇全选粘贴。观察方式：命令面板「Developer: Open Webview Developer Tools」看控制台，诊断形如「`[vsidian]` 大纲标题序列变化超过迁移上限（编辑距离 > 256）：折叠状态回退到当前档位集」。取舍理由：迁移用 Myers diff，超限时 trace 快照内存与循环开销在数千标题下会卡死 webview——视图状态重置优于面板卡死。常态编辑（个位数标题变动）不触发；本项验收按「可见重置 + 控制台诊断（至多两行）」的预期判断，不记为缺陷。

预期：折叠均为纯视图状态（零写回、Ctrl+Z 无可撤销项、文件不 dirty）；空文档与无子项文档下滑块仍可操作、条目恒可见。第 9 项的熔断只在超限时发生，触发后档位与滑块指示一致（回退到当前档，不出现滑块与视图不符）。圆点串珠视觉（空心/实心、横线贯穿与 #99 能量条填充段）、拖拽手感与滚动展开的观感须由人工验收（自动化断终态、computed 证据与几何关系）。

## 十五、大纲工具条与标题搜索（#68）

### A28. 工具条三控件、搜索过滤高亮与重置/跳末的人工复核

准备一个多级标题的长文档（含行内标记标题，如 `## **重点** 章节`），展开右侧栏大纲。

1. **工具条装配**：侧栏顶栏与滑块行之间应有一行工具条——左起「跳转到笔记末尾」按钮、「重置」按钮、搜索输入框（占位文案「输入以搜索」）；按钮悬停有高亮，搜索框为 VSCode 输入配色；面板收起（大纲关闭）时整行随之消失。

## 十六、大纲右键菜单（#69）

### A29. 右键菜单、结构命令、复制五项、调级、重命名与删除的人工复核

准备一个多级标题文档（含跨级标题、行内标记标题（如 `## **加粗** 标题`）、Setext 标题与文末标题段），展开右侧栏大纲。

1. **菜单开合**：右键任一条目弹出菜单（浏览器原生右键菜单被接管）；菜单出现在点击处附近且不遮挡被右键的条目（目标条目保持可见）；Esc 与点击菜单外任意处关闭；侧栏收起时菜单随之消失。
2. **结构命令**：档 0（No-Expand）下右键某深层父条目执行「递归展开」——整棵子树展开；「折叠同级」/「展开同级」作用于同父的全部兄弟（含自身）。
3. **复制五项**：逐项执行后在任意编辑器粘贴核对——「标题」为剥标记可见文本（`**加粗**` 复制出「加粗」）；「标题和兄弟标题」为同父全部标题逐行；「标题和子标题」含全部后代（这两项与「标题」同取**剥标记可见文本**逐行拼接，与保留源文标记的「该段内容」相对）；「该段内容」为整段源文（含标题行与正文，标记原样）；「标题链接」为 `[[笔记名#标题片段]]`（笔记名 = 当前文档文件名去扩展名），其中**标题片段是标题原文、含行内标记**，不是剥标记可见文本——与宿主定位函数 `findHeadingOffset` 的按标题行原文（**字面**）比较同源，宿主匹配前的规范化仅为 trim + 空白折叠 + 大小写不敏感。核对样例：对 `## **加粗** 标题` 执行「标题链接」→ 粘贴得到 `[[笔记名#**加粗** 标题]]` → 单击应打开目标笔记并定位到该标题（目标以 Vsidian 面板打开并定位到标题行）；把片段手工改成剥标记的 `加粗 标题` 再单击 → 命中失败：文件仍会打开，并弹出未找到标题的警告——警告里回显目标文档与待找标题 `加粗 标题`，并附匹配规则说明（trim + 空白折叠 + 大小写不敏感的 ATX 标题）；这两次单击的可见差异正是本项的判据。**已知限制**（wikilink 形态学与一期标题匹配规则的既定口径，复制动作不做也无从做事后改写）：标题自身含 `]`/`[`、`#` 时整条 `[[…]]` 不构成合法双链（按原文显示、单击不跳转）；`^` 已分口径——`#^` 开头的块引用形态（`[[笔记#^块ID]]`，块 ID 仅拉丁字母/数字/连字符）构成合法双链（渲染为链接、单击打开目标文件并定位到块首行——#159/#160 块级定位已交付：目标以 Vsidian 面板打开并定位到块首行；块 ID 在目标文档不存在时打开文件并弹块缺失警告，与标题未找到的警告分词条），标题文本含 `^`（非 `#^` 开头）与路径裸含 `^` 仍整条降级；**空标题**（`#` 单行时的 `[[笔记#]]`）同属此列——它也不是「找不到」，而是整条链接不成立、按原文显示；含 `|` 时首个 `|` 被当作别名分隔，标题截断到 `|` 之前（落到截断后的标题；**若文档内另有能匹配该截断串的标题（匹配为 trim + 空白折叠 + 大小写不敏感）会静默定位到它**——宿主 `findHeadingOffset` 恒取**首个**匹配行，找不到才同样提示未找到）；**容器内标题**（引用块/列表内的标题，如 `> ## T`、`- ## T`）链接形态合法，但匹配规则只认行首 ≤3 空格的 ATX 行，故只打开文件、不定位（并提示未找到标题）；**Setext 标题**（下划线式）同理只打开文件、不定位。同名标题的链接只命中首个匹配行——后续同名标题没有可分辨的链接形态。
4. **调整层级四项**：增加/减少一级只动自身 `#` 数量；递归变体作用于整棵子树；H1 上「减少」与 H6 上「增加」无可写变更（菜单点击后文档不 dirty）；Setext 标题（下划线式）调级后变为 `#` 式单行；控制域外内容逐字节不变（Ctrl+Z 一次完整回滚）。
5. **重命名**：右键「重命名」进入条目行内编辑（初值含 `**` 等标记原文）；Enter 提交整行替换（层级 `#` 数保持、标记保留）；Esc 取消零写回；**失焦（focusout）也会提交**——票面只承诺 Enter/Esc，实现补录了与 Obsidian 一致的失焦提交直觉，误提交靠 undo 兜底；编辑期间点击输入框不触发跳转；提交后大纲条目、实时预览装饰与阅读渲染一致更新；折叠视图不扰动。
6. **删除**：右键「删除」直接生效（无确认弹窗）——标题行与其内容直到下一同级/更浅标题整段消失，相邻段直接相接无空行残留；Ctrl+Z 一次回滚。

预期：全部写操作单事务可一次撤销；结构命令与复制零写回（文件不 dirty）；菜单项键盘可达（Tab 聚焦、Enter 激活、聚焦含子菜单的父项时子菜单展开）。

## 十七、大纲拖拽排序（#70）

### A30. 拖拽三态落点、子树调级、无效落点拒绝与取消的人工复核

准备一个多级标题文档（建议含跨级标题（如 H2 下直接 H4）、行内标记标题、frontmatter 与代码围栏内以 `#` 开头的行），展开右侧栏大纲。

1. **拖拽启动与源提示**：按住任一条目拖动超过几像素——源条目整体半透明弱化（提示「这段正在被搬走」），其余条目无变化；未移动超阈值的按住-释放等同普通点击（触发跳转，不进入拖拽）。
2. **三态落点**：拖到目标条目**上缘四分之一**——目标上缘出现水平插入线（之前）；**下缘四分之一**——下缘插入线（之后）；**中部**——目标整条包裹高亮（内部 = 成为其子标题）；三种指示随拖动实时切换，同一时间只出现一处。
3. **写回语义**：松手后整段（标题 + 内容直到下一同级/更浅标题）搬到目标位置——之前/之后对齐目标层级（`#` 数量随目标），内部比目标深一级；被拖子树内全部标题递归同步调级；跨级挂靠的子孙随段搬移；控制域外内容（frontmatter、围栏内 `#` 行、相邻段）逐字节不变；Ctrl+Z 一次完整回滚整次拖拽（正文与大纲同步还原）。**已知视图态边界**：把子标题拖出父域后撤销——文本完整回滚，但该父降格期间被丢弃的展开键不恢复（子标题呈折叠遮蔽，点箭头或重设档位即恢复）——属折叠迁移策略的既定口径，集成用例已按此断言。
4. **无效落点**：把某父条目拖到自己任何后代（含直接子级）上——任何位置（上缘/中部/下缘）都不出现落点指示，松手无写回；拖到自己身上同样拒绝。
5. **取消**：拖动途中按 Esc——指示消失、无写回；拖出面板（在侧栏空白处松手）同样无写回。
6. **视图状态存活**：折叠若干区域后拖动可见条目——写回后折叠视图合理保持（搬走的条目随新位置、档位不变）；搜索过滤下拖动可见条目——词条保持、过滤对新大纲重算；写回后常驻高亮落位正确。
7. **点击不受扰动（补发 click 只吞一次）**：拖拽写回后浏览器会补发一次 click，该 click 被吞掉（不触发跳转、不触发折叠）；**紧随其后的第一次真实单击必须立即生效**——拖拽完成后马上单击另一条目，应立即跳转并高亮该条，不得出现「第一击无反应、第二击才生效」。实现口径（本轮实测修正）：吞噬标志在任何 pointerdown 时先复位，而补发 click 恒在本次按下之后，故「只吞一次」成立；背景是写回会在 pointerup 处理内同步重建条目 DOM，补发 click 若未送达则标志残留、会吞掉下一次真实点击。按住-释放未超阈值（未进入拖拽态）等同普通点击，不吞 click；折叠箭头点击照常。
8. **拖拽中按下右键（和弦按键）**：拖拽进行中按下右键（左键仍按住）——**手势立即结束**：源条目弱化与落点指示同时清空，此后任意释放顺序（先松右键，或先松左键、右键最后抬起）都**零写回**（文件不 dirty、Ctrl+Z 无可撤销项）；右键落在条目上时**照常弹出右键菜单**（目标即右键处条目），落在面板空白处则只结束手势、不弹条目菜单。机制（本轮实测）：浏览器只在首个按键按下时报 `pointerdown`，和弦的第二个按键只报 `pointermove`（其释放也不是 `pointerup`），故「非主键按下即结束」的判据落在移动路径上——否则先松左键时，右键抬起是最后一个按键、会投递真实 `pointerup` 并按残留落点搬移一次。**不变式：仅左键（主键）释放执行落点写回**。

预期：每次成功拖拽恰好一笔写回（单事务，一次 Ctrl+Z 回滚）；取消与无效落点零写回（文件不 dirty）；三态指示的视觉观感（插入线粗细、包裹高亮辨识度）与真实鼠标拖动手感（阈值、跟手感）须由人工验收。**触屏不在支持面**——按住移动会被浏览器接管为面板滚动、会话按取消处理（零写回）；该机制已由 Chromium 触屏管线（CDP 触摸仿真）实测并由浏览器回归场景 K 钉住：触摸实测取值 `pointerdown` `ptr=touch` `button=0`/`buttons=1`、`pointermove` `ptr=touch` `button=-1`/`buttons=1`，浏览器随后投递 `pointercancel`（`buttons=0`）——拖拽态始终为 null、无拖拽/落点指示类、`edit.request` 不增、文档逐字不变；真机触屏手感与不同设备、触控板及浏览器接管滚动的时机差异仍待用户验收，见「已知限制」的触屏条目；本项按鼠标链路验收。

## 已知限制（如实记录）


- **全局记忆停留在源码态时的显式打开被弹回**（#38）：Vsidian 默认接管 `.md` 打开后，记忆为源码态时新开（含显式「Reopen With → Vsidian」与窗口恢复的 Vsidian 标签）会被弹回原生编辑器——扩展无法区分默认关联与显式指定。可点标题栏铅笔按钮一步切回；经「Reopen With… → Configure default editor for '*.md'…」改回原生关联不受影响。
- **diff 对比视图不支持三态切换**（#38）：对比视图（SCM 更改、比较选中）的标题栏不显示三态按钮，命令面板切换命令在 diff 语境为 no-op 加提示，对比完整性优先。
- **超长行与图片密集场景已有单机专项**（#23）：结构、实测结果及边界见[性能档位汇总](../perf/2026-09-mvp-performance-summary.md)。大型位图解码内存和图片加载瞬时峰值仍未覆盖。
- **双链目标面板含未确认输入时的标题定位基准**（#11）：目标文档在另一编辑器面板打开且该面板含未确认（未保存）输入时，标题定位以 `TextDocument` 权威文本为基准，可能与面板可见内容错位；窗口过小等极端场景下定位 clamp 保证不越界。
- **歧义双链并发触发时 QuickPick 单例替换行为**（#11）：两个歧义双链几乎同时触发跳转时，后发的候选 QuickPick 会替换先发者（VSCode QuickPick 为单例），先发跳转被放弃——该并发路径的自动化覆盖有限，行为以人工使用观察为准。
- **快速关闭与远端断连仍需真实操作复核**（#21/#27）：暂停和暂缓态的输入现已即时上报宿主快照；#49 起 IME 组合期间的暂缓输入例外——延后到组合结束后经 `edit.request` 出站进入宿主权威文档（组合中逐笔全文快照在大文档下开销放大），组合外的暂缓输入与暂停态仍逐笔快照。单测与 1.86.2 宿主集成用例验证关闭通知含最后一笔。真实 Ctrl+W 操作与 CentOS 7 Remote SSH 断连后恢复尚未由人工执行，不据此宣称跨环境通过。
- **紧凑格式表格格尾首键产生两笔写回，撤销可能两步**（#49）：光标位于格尾无空格的紧凑格式格（如 `|ab|`）首次键入时，webview 在 beforeinput 先派发填充空格事务再接收用户输入，两笔 CM6 事务经宿主逐笔 applyEdit，VSCode 撤销栈可能需按两次 Ctrl+Z 才能整体恢复。触发面窄（常规 `| ab |` 格式格尾已有空格，不触发）、无数据正确性风险（行为正确性已由浏览器回归覆盖）。已决策接受现状：宿主侧把队列中相邻快速多笔合并为单次 applyEdit 需重构 `documentSession` 的 pending/ack/回流匹配核心链路（该链路经历 #42–#45 打磨与 #48 竞态修复），风险收益比差；webview 侧填充与浏览器原生输入是两笔独立事务，无自然合并点。
- **触屏不支持大纲拖拽**（#70）：大纲面板是可滚动容器，实现刻意未加 `touch-action: none`——加上它虽能让触屏拖拽成立，代价是触屏无法滚动面板，故取滚动优先。触屏按住条目再移动会被浏览器接管为面板滚动，并随后发出 `pointercancel`；实现按「取消」收尾——指示清空、零写回（文件不 dirty、无可撤销项），不会产生错位搬移。因此拖拽排序只按鼠标链路验收；该机制已由 Chromium 触屏管线（CDP 触摸仿真）实测并由浏览器回归场景 K 钉住（触摸按下/移动的 `button`/`buttons` 实测取值、随后 `pointercancel` 收尾；拖拽态始终为 null、无拖拽与落点指示类、`edit.request` 不增、文档逐字不变）；**真机触屏手感与不同设备、触控板及浏览器接管滚动的时机差异仍待用户验收**，不作为已通过结论。
- **普通链接锚点定位的边界**（#160，2026-09-28 落地）：`[t](./文件.md#标题)` 打开后定位标题、`[t](#标题)` 页内定位已支持（此前 fragment 被宿主剥掉丢弃、`#` 开头被拦为空目标）。已知边界：路径与锚点按 **CommonMark 语义取首个 `#`** 拆分——路径本身含 `#` 时（如 `[t](./a#b.md)`）拆为路径 `./a` + 锚点 `b.md`，链接无法表达「文件名带 `#`」的目标（文件系统层面 `#` 极少用于文件名，行为文档化接受）；外部 scheme（`http(s)`/`mailto`/`vscode` 等）的 `#` 是网页锚点语义**不接管**，照旧外开；`#^块id` 形态的普通链接 fragment 复用双链块引用语义，经 #159 同源块定位器定位到块首行（批次合并时接通，缺失块 id 弹块引用提示）。
