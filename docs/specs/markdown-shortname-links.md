## 目标与语法范围

1. **语法范围**：Markdown 双链 `[[笔记]]`、`[[笔记.md]]`、普通 Markdown 链接以及现有 Markdown 嵌入均覆盖。跳转、悬停、出链与反链采用一致解析。
2. **解析优先级**：先按现有相对路径规则；未命中且仅含文件名时，再查来源所属根内唯一同名 Markdown。
3. **联想生成设置**：作为设置项提供；默认仍使用当前笔记相对路径。

普通 Markdown 链接包含现有引用式定义；明确的相对目录路径，如 `资料/目标.md`、`./目标.md` 与 `../目标.md`，继续按来源目录解析，不增加全根唯一目录后缀搜索。相对路径仍受来源根边界约束。

## 设置与引用更新

### 设置标题、描述与三档选项

用户指定的中文文案：

| 项目 | 文案 |
| --- | --- |
| 标题 | 内部链接类型 |
| 描述 | 设置在笔记中链接其他文件时插入“[[ ]]”中的文件路径类型。 |
| 选项一 | 尽可能简短的形式 |
| 选项二 | 基于当前笔记的相对路径 |
| 选项三 | 基于文件系统的绝对路径 |

默认选项为第二档。设置覆盖全部文件候选的后续双链联想插入，沿现有内置设置的用户 profile 级持久化、跨窗口通知及即时生效机制；不批量转换现有正文。联想候选范围仍沿现有文件清单，不因绝对路径档位扫描其他根或外部目录。

### 同名歧义

同目录未命中且根内存在多个候选时，提示补充路径并保持未解析。索引不归到任意候选，不按目录距离、字典序或历史选择猜测；重复目标移除后重新解析并恢复。

### 改名与移动

保留更名前已确定的目标。原短名在新状态仍能准确命中时不改，改名后新短名唯一则更新短名，否则改有效的明确相对路径。移动使目标越出来源根或变为外部目标时，使用明确绝对路径，不生成越界相对引用。

已有路径链接按原形式更新：相对路径仍有效时保持相对，绝对路径随目标更名。来源与目标同批移动时按新位置统一规划，保留别名、锚点、编码和无关正文，不覆盖并发输入。外部工具改名不猜测旧新身份。

### 相对优先的可见结果

若 `项目/来源.md` 中的 `[[目标]]` 原先补查到 `资料/目标.md`，后来新增 `项目/目标.md`，链接会按已确认的相对优先规则转向 `项目/目标.md`。出链、反链、悬停与嵌入应一起重新判定。

这与 VSCode 内改名时保留原目标的自动更新是不同触发：新建同名文件不会被解释成替用户改写已有链接的授权。

## 路径生成与外部引用

### 最短形式与三档路径

- **尽可能简短的形式**：在文件名、来源相对路径和文件系统绝对路径中，选择生成后经统一解析器能返回所选目标身份的最短形式；能正确解析时可省略 Markdown 的 `.md`。同长时依次优先文件名、相对路径、绝对路径，结果保持稳定。
- **基于当前笔记的相对路径**：保留现有生成风格和显式扩展名，以实际编辑文档目录为基准。明确跨根或外部目标无法以合法根内相对路径表达时，使用绝对路径保留身份。
- **基于文件系统的绝对路径**：写入当前宿主的完整文件路径，Windows 生成含盘符的 `/` 分隔形式，POSIX 保留绝对路径；不写库根相对路径。

短名补查限来源所属根内未被索引排除的 Markdown，其他根、排除目录和非 Markdown 不参与；嵌套根沿最具体归属划分。非 Markdown 在最短档只选其现有规则能正确解析的路径，来源目录直接命中的文件名仍可作为有效相对形式。

路径生成保持既有写回语法校验和所选目标身份核对，不使用联想模糊匹配猜目标。已有别名、标题／块锚点及默认显示文字保持原规则。

### 显式绝对路径

绝对路径允许跨根及工作区外目标，按当前扩展宿主的文件系统解释。例如：

```md
[[D:/笔记库/资料/目标.md]]
[[/home/user/notes/资料/目标.md]]
```

两例分别表示 Windows 与 POSIX 宿主路径；Remote SSH 使用服务器路径，不使用本地客户端路径。POSIX `/` 表示服务器文件系统根，不能改释为工作区根。绝对路径无需短名补查；保留各入口既有的 scheme、编码与语法约束，不新增 `file://` 格式。

目标使用各文件类型已有的点击、悬停、嵌入和引用编辑能力，按目标实际可读、可写状态及现有只读规则执行。明确不存在、权限失败和 Remote 不可达不得混报。

### 外部引用关系

已索引来源对外部目标的出链、反链及 VSCode 内明确更名更新均覆盖。外部仅登记被明确引用的目标，不扫描其目录，不递归追踪外部文档建库；反链完整性只针对已索引来源。

索引与打开视图使用规范完整文件身份，不能把不同根相同相对路径合并。跨根及外部目标的快照、恢复、失效和更名计划由统一身份承接；缓存仍是派生数据，不复制附件内容。

### 状态变化

| 场景 | 必须结果 |
| --- | --- |
| 来源目录已有相对候选 | 沿现有优先级命中，不受其他目录同名文件干扰 |
| 来源目录未命中、补查范围只有一个同名 Markdown | 命中该文件 |
| 来源目录未命中、补查存在多个同名 Markdown | 歧义，提示补路径，不归到任一候选 |
| 完整清单没有候选 | 找不到，保留来源原文 |
| 清单未完整、只发现一个候选 | 不声明唯一，显示未就绪／更新中状态 |
| 无可靠来源根 | 不作短名补查，不猜其他根；明确绝对路径独立解析 |

文件增删改名、根与排除变化、扫描完成均可能改变没有修改正文的来源。需同时处理已解析边失效和未解析边恢复；唯一变歧义、歧义恢复唯一、相对候选新增和删除后重现都应覆盖。

已挂载预览和嵌入按目标身份变化失效，复用现有目标会话、未保存状态与迟到结果守卫，不能把旧目标响应交给新目标。旧快照不能直接把旧规则下的解析结果当成新规则有效结果。

## 实施验收条件

以下是实施设计与验证的检查项，不代表已经执行或通过：

- [ ] 所有消费入口对同一目标解析一致；A 引用的 B 内部，以 B 的目录与所属根为来源。
- [ ] 唯一、缺失、多候选、相对路径优先、明确目录与根边界均符合状态表；中文、空格、URL 编码及既有标题／块锚点保持可用。
- [ ] Windows 与 POSIX 沿现有宿主大小写、分隔符和真实文件身份口径；不使用联想模糊评分选择实际目标。
- [ ] 文件增删改名、根与排除变化、清单不完整、异步迟到与旧快照恢复有验证，同时处理未解析边恢复与已解析边失效。
- [ ] 来源与目标同时变化、批量目录移动、未保存正文与并发版本的更新符合已确定目标身份，不误改链接目标或覆盖新输入。
- [ ] 三档设置在自有设置页持久化、重开回显并即时生效，默认相对路径；现有别名与锚点不被路径类型覆盖。
- [ ] 外部绝对路径各文件类型的现有预览与嵌入、已索引来源关系及更名更新可用；外部目标不触发目录扫描，不同根的同名路径不串反链。
- [ ] 最短档结果正确且稳定，非 Markdown 不新增跨目录短名补查，联想接受时核对当前清单，旧快照恢复与重建结果一致。
- [ ] 可执行变更有 TDD 证据；呈现变更执行 style-contract 与 ui-patterns，用户文案经 i18n，至少一条集成断言落在绘制层。

验收时至少记录纯逻辑单测、生产浏览器与真宿主的对应证据。长耗时验证首次落日志与退出码，后续读报告；容量验证关注清单与关系维护，不以每次点击全库扫描实现补查。自动化结果不等于人工验收。
