# Live 富文本粘贴

状态：2026-10-02 用户确认产品行为及四票拆分；#305–#308 本地实现完成，2026-10-03 对齐最新 main 后完整回归通过，分基线证据见下文。真实 Word/Google Docs、物理键盘与具体观感仍待人工验收；toast 数值为初始视觉方案。

## 问题与目标

阅读模式复制已可携带 HTML，Live 粘贴尚未将其中的格式转换为 Markdown。普通粘贴应利用可转换格式，同时提供明确的纯文本入口、选择提示和可分步撤销的编辑结果。

## 用户故事

1. 作为 Live 编辑用户，我希望普通粘贴保留可表达的格式，以继续编辑 Markdown。
2. 作为 Live 编辑用户，我希望用 Ctrl+Shift+V 或右键粘贴纯文本，以明确绕过格式与图片导入。
3. 作为用户，我希望选择本次是否保留格式，并能记住选择或恢复询问，以控制粘贴行为。
4. 作为用户，我希望先撤销粘贴格式、再撤销文本，以保留内容而去除格式。
5. 作为用户，我希望撤销替换粘贴后恢复原选区内容，重做按原顺序恢复，以保持编辑历史可信。
6. 作为用户，我希望代码、表格和图片已有粘贴规则继续生效，以避免损坏结构或改变资产流程。
7. 作为用户，我希望在图片无法以纯文本粘贴、格式保留成功及转换失败时获得 toast，以理解结果。

## 入口与设置

仅 Live 正文可编辑时接管写操作，不覆盖源码模式、阅读模式或设置页输入。

| 入口 | 默认键位 | 行为 |
| --- | --- | --- |
| 粘贴 | Ctrl+V | 普通粘贴，遵循上下文和设置 |
| 粘贴纯文本 | Ctrl+Shift+V | 明确使用纯文本，不弹格式询问，不导入图片 |

两操作均纳入快捷键管理，支持改绑、清空、单项及全部恢复默认；提示中的键位取有效注册值，改绑后不继续硬编码默认键。右键提供两操作；普通粘贴菜单与键盘入口语义一致。

| 设置 | 默认 | 语义 |
| --- | --- | --- |
| 粘贴保留富文本 | 开 | 普通文本粘贴允许 HTML 转 Markdown；关时直接纯文本且不询问 |
| 分步撤销富文本粘贴 | 开 | 成功转换分为文本与格式两个撤销阶段；依赖总开关灰化，值不清除 |
| 粘贴前询问 | 开 | 总开关开启且有可转换格式时询问；可在设置页重新开启 |

设置统一纳入扩展自己的设置页并持久化、回显、生效；实现沿用既有设置存储范围，不新增一套偏好存储。

## 询问与结果

检测到可转换格式且询问开启时，在修改文档前显示模态框：

> 是否保留粘贴内容中的格式？

按钮「保留格式」「仅粘贴文本」「取消」，复选框「不再提示该信息」。不勾选时仅作用本次；勾选并选择保留/仅文本时，同步富文本总开关并关闭询问。取消或 Esc 不粘贴，也不保存此次复选框选择。HTML 仅有普通文字包装时不询问。

模态期间保留本次剪贴板快照与目标身份；文档关闭、模式改变、只读/暂停或目标失效时，不将迟到结果插入其他文档。不得重复粘贴或在取消时产生空撤销记录。

## 上下文和转换边界

- 显式纯文本操作绕过图片导入。有文字仅插入文字，无文字不修改文档。纯文本优先剪贴板 text/plain，缺失时从 HTML 提取。
- 普通粘贴继续遵循现有独立图片项优先规则与资产落盘流程；关闭富文本总开关不等于关闭图片粘贴。
- 代码块内文本粘贴优先纯文本；表格内粘贴保留既有规则，不扩大成 Excel 区域粘贴。代码上下文不做 HTML 格式转换。
- 支持标题、段落与换行、粗体、斜体、删除线、链接、有序/无序列表、任务列表、引用、行内代码、代码块及普通表格。
- 字体、字号、任意颜色、复杂布局不保留。不支持合并单元格等复杂表格布局的等价转换。
- HTML 内图片仅完整 HTTP(S) 地址转换为 Markdown 图片引用，不下载；相对、本地、临时等地址只保留替代文字。这不改变独立图片项粘贴规则。
- 公式仅保留可提取文本，不承诺恢复 LaTeX，不截图。
- 只解析剪贴板内容，不执行 HTML 脚本或通过渲染副作用加载资源；输出链接遵循项目已有危险 URL 过滤规则。不把不支持的 HTML 原样塞回正文。
- 转换失败时回退纯文本并提示，仅一次撤销；无可提取文本则不修改文档并提示失败。转换结果等于纯文本时不制造格式阶段。

## 撤销与重做契约

宿主 TextDocument 继续作为唯一权威文本及撤销历史来源，不新增 webview 私有历史替代宿主历史。

设粘贴前文档为 A，替换选区后的纯文本结果为 B，保留格式后的 Markdown 结果为 C。分步撤销开启且 B 与 C 不同时：最终展示 C；第一次撤销 C → B，第二次 B → A。重做 A → B → C。关闭分步撤销时只有 A ↔ C。

例如选中「旧内容」并粘贴粗体文字：`**新内容** → 新内容 → 旧内容`。纯文本与格式阶段不得和前后用户输入合并；连续两次粘贴保持各自历史。后续编辑优先正常撤销，不跳历史定向寻找粘贴。

选区原文、光标恢复与多个打开面板的回流须随宿主历史一致。快速连按撤销、等待编辑确认、切换源码模式后的撤销均不得出现丢字、重复插入或撤销其他文档。只有真正完成格式阶段撤销时触发对应 toast。

## Toast 反馈

以下为中文文案基线，全部经中英语言包；键位从快捷键注册表派生，无绑定时以操作名称引导。

| 时点 | 提示 | 约束 |
| --- | --- | --- |
| 纯文本操作遇到图片项，无文本 | 无法将图片粘贴为纯文本，请使用“粘贴”（默认 Ctrl+V）粘贴图片 | 不修改文档 |
| 纯文本操作遇到图片项，同时有文本 | 已粘贴文本，未粘贴图片；如需图片，请使用“粘贴”（默认 Ctrl+V） | 只插入文本 |
| 富文本实际成功保留格式 | 已保留粘贴内容中的格式 | 不在取消、纯文本回退或无格式差异时提示成功 |
| 分步撤销第一步完成 | 已撤销粘贴格式，再撤销一次可撤回粘贴的文本 | 只针对格式阶段，不响应普通撤销或第二步 |
| 转换失败但已回退 | 无法保留格式，已粘贴为纯文本 | 单次撤销 |
| 失败且没有可提取文本 | 无法粘贴：未能提取可用文本 | 文档及历史不变 |

Toast 非模态、不抢输入焦点，不新增编辑或历史。动作成功反馈以实际编辑成功为准。

### 自带 toast 通道与语义（用户已确认）

自带 toast 是 webview 内更轻、更不扰人的即时反馈，位于当前编辑器视口底部水平居中，从下方轻微上移并淡入；不以整个 VSCode 窗口为定位基准，不随正文滚动。

它与通过 VSCode API 进入右下角通知区的宿主通知是独立通道。两者不共用队列、不互相清除或抑制；一次本批次反馈只投递到自带 toast，不同时弹宿主通知，不因自带 toast 不可见而自动转发右下角。既有其他宿主通知不在本票全局迁移。

| 本批次反馈 | 严重性 | 呈现 |
| --- | --- | --- |
| 纯文本粘贴遇图片（有/无文字） | warning | 淡黄底、适配明暗主题的可读文字和轻边框 |
| 已成功保留格式 | neutral | 跟随当前主题，不使用成功绿 |
| 第一次撤销格式成功 | neutral | 跟随当前主题 |
| 转换失败并回退，或完全无法提取 | error | 淡红底、适配明暗主题的可读文字和轻边框 |

颜色不能作为唯一语义线索；文案明确说明结果和下一步。warning/error 也不抢焦点，不升级为模态框。

### Toast token 方案（拟定默认值，待视觉验收）

公开 CSS 变量统一以 `--vsidian-toast-` 为前缀，定义在 `#app`，toast 容器必须处于其继承链内；不得将容器挂到作用域之外导致片段覆盖失效。下表名字均为完整公开名称。

| Token | 建议默认值/语义 |
| --- | --- |
| `--vsidian-toast-background` | 跟随 VSCode editorWidget.background，缺失回退 editor.background |
| `--vsidian-toast-foreground` | 跟随 editorWidget.foreground，缺失回退 editor.foreground |
| `--vsidian-toast-border` | 跟随 widget.border，无值采用低对比主题边框 |
| `--vsidian-toast-warning-background` | 浅色 #FFF7DB；深色 #393321 |
| `--vsidian-toast-warning-foreground` | 浅色 #70530B；深色 #F1D990 |
| `--vsidian-toast-warning-border` | 浅色 #E7D49A；深色 #6B5930 |
| `--vsidian-toast-error-background` | 浅色 #FDEBEC；深色 #3C292D |
| `--vsidian-toast-error-foreground` | 浅色 #922F3C；深色 #F3B6BF |
| `--vsidian-toast-error-border` | 浅色 #E9BBC1；深色 #74414A |
| `--vsidian-toast-radius` | 8px |
| `--vsidian-toast-font-size` | 12px |
| `--vsidian-toast-padding-inline` | 14px |
| `--vsidian-toast-padding-block` | 9px |
| `--vsidian-toast-max-width` | 480px，同时受视口两侧安全留白钳制 |
| `--vsidian-toast-viewport-margin` | 16px，窄视口最小留白 |
| `--vsidian-toast-bottom-offset` | 24px，另计安全区 |
| `--vsidian-toast-shadow` | 0 4px 16px rgb(0 0 0 / 0.12)，深色适度增强 |
| `--vsidian-toast-enter-distance` | 8px，自下向上浮现距离 |
| `--vsidian-toast-enter-duration` | 160ms |
| `--vsidian-toast-exit-duration` | 120ms |
| `--vsidian-toast-duration` | 2600，单位毫秒、无单位数值；neutral 停留时间 |
| `--vsidian-toast-warning-duration` | 4000，单位毫秒、无单位数值 |
| `--vsidian-toast-error-duration` | 5000，单位毫秒、无单位数值 |

颜色具体数值属于初始视觉方案；淡黄/淡红及普通提示跟随主题是已确认约束。高对比主题优先采用主题高对比前景/边框，保证文字可读。减少动态效果偏好开启时移除位移动画；内容应折行，不裁掉操作指引。

默认生命周期方案：同一 webview 同时最多一条，后续消息顺序显示，相同连续消息合并，待显示消息设上限避免堆积；不遮住整个编辑器，不产生可点击操作或拦截下层编辑，保持输入焦点。容器随 webview 销毁清理计时器，模式切换不产生历史。辅助技术通过 polite live region 获得结果，不以强制焦点或反复播报制造干扰。层级须高于正文、低于模态交互层，并验证提示不会被编辑区 overflow 裁切。

公开选择器拟为 `.vsidian-toast-container`、`.vsidian-toast` 与 `[data-severity="neutral|warning|error"]`（属性值分别为三种，不是字面管道字符串）；内部动画状态不承诺公开。实现时在 styleContract 单一事实源登记 toast 类目、用途、视图、状态、作用域及中英文说明，生成样式指南，补片段覆盖与绘制层验证，不将本节设计表代替已发布的契约清单。

只读核查基线：当前 HEAD `cf983d1f181020b745287ce65339f032e3138998`；现有 styleContract 清单未检出 toast 入口，本方案为新增，tooltip 变量与机制保持原义。实施前另固定届时已发布 tag/SHA 并执行 style-contract 门禁。本轮仅规格修改，未登记运行时 token，不宣称 CSS 变量已可用。

## 实现接入与验证

已核查入口：`src/webview/imagePaste.ts` 处理独立图片项；`syncController.ts` 的右键粘贴通过 clipboard.read 读取文本；`src/host/documentSession.ts` 串行处理宿主撤销。实现需让键盘与菜单获得一致的格式数据能力，不能仅给键盘 paste 事件加转换而保留菜单纯文本路径。

转换逻辑与剪贴板获取、询问状态、编辑应用分离；先固定输入输出契约，再选实现库。库如有新增须锁精确版本并核对打包影响。无需在规格阶段锁定尚未经宿主验证的剪贴板 API 或两阶段提交方法。

按 TDD 先验证目标行为失败，再实现。验证层次：

- 设置测试：默认值、持久化与回显、灰化保值、恢复询问；快捷键冲突、清空和恢复；中英 i18n 与公开样式契约。

## #305 实施落档（2026-10-02）

- 可绑定操作 `paste` / `pastePlain` 登记于 UI_OPERATIONS，写操作仅 Live 正文可编辑时执行；菜单提示和图片提醒读取有效键位。默认普通 Ctrl+V 保留原生 paste 事件（保留文件原名及表格已有规则）；改绑普通粘贴、纯文本操作与菜单通过 `readClipboardSnapshot` 读取完整快照，`dispatchClipboardPaste` 进入既有 CM6/table/image 处理链。纯文本缺失才从脱离活动文档的 HTML template 提取文本，空串不视为缺失。

## #306 实施落档（2026-10-02）

- 普通原生 paste 与菜单/改绑快照共用 `processRichPaste`。独立图片文件项先走原有资产管线；代码（含行内代码）与表格上下文优先纯文本，不扩大区域粘贴。`htmlToMarkdown` 只解析脱离活动文档的 HTML，不执行脚本、样式表或加载资源；支持语义标签及内联 font-weight/font-style/line-through 声明，按继承后的行内语义片段组合，避免嵌套同标记变成其他格式。Markdown 字面符号会转义；普通包装不会仅因转义差异而触发询问。

## #307 实施落档（2026-10-02）

- `editor.pasteSplitUndo` 默认开启，进入扩展设置页「编辑」小节；关闭富文本总开关时灰化且保留值，重新打开回显。`planRichPaste` 使用同一 CM6 选区替换模型计划 B/C，本地同步显示 C；`deferredSegments` 按明确阶段边界及 ACK 顺序分别提交，每次宿主 WorkspaceEdit 为独立历史。前后输入和连续粘贴不合并；A=B、B=C 及最终无变化跳过空步骤，关闭分步为单笔。
- 已同步接纳的 C 属于未确认输入，切模式后继续按既有保护流程落宿主；尚未应用的剪贴板读取、转换或模态结果仍按目标身份取消。B 成功而 C 写失败时保留本地 C 及后续输入、进入既有暂停，不虚报格式成功，不另设私有撤销栈。
- 宿主 `onDidChangeTextDocument.reason` 透传真实 Undo/Redo。`PasteHistoryTracker` 只解释实际增量的阶段归属，并为普通输入、连续组及原生编辑器合并输入保留次序；未知或无法精确对账的历史不猜测。阶段带 session/group、前后选区，真正格式撤销才显示引导；原选区在发起面板按真实回流恢复。Undo/Redo 三条 CM6 绑定阻止已处理按键继续冒泡，修复真宿主中一次按键同时走两条撤销通道的问题。
- `ToastChannel.show` 可携业务 key，`dismiss` 仅清除对应组。新的撤销阶段替换旧的成功反馈；第二次撤销、重做和后续输入使相关引导立即失效，不清除无关 warning/error 或宿主通知。A=B 的仅格式记录不诱导再撤一次无关历史。公开 toast 选择器、token 与配色契约保持不变。
- 多选区遇到纯文本行数与 Markdown 行数分发策略不一致时，本次回退原 CM6 纯文本分发并显示 error，只有一次撤销。例如两个选区收到 `甲\n乙`，HTML 的段落空行使格式文本变为三行，此时不将整块内容重复到两个选区。该保守边界不扩大为任意多光标 HTML 重排；分发一致的多选区仍可分步保留格式。
- 自动证据包含阶段出站、失败/迟到 ACK、协议校验、真实原因与普通格式编辑的区分、快速双撤及 toast 队列清理。浏览器验证首次撤格式的 `paint.toast.visible`、淡红回退、设置灰化/持久化及多选区；VSCode 1.82.3 真宿主验证 A/B/C、替换选区、连续粘贴、前后输入、快速 Undo/Redo、关闭/等价无空阶段、两个真实面板与切源码后合并输入撤销。物理键盘、真实外部软件复制和具体视觉观感仍待用户验收。
