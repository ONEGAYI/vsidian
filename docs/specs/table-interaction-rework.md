# 表格交互重做

规格：[GitHub #72](https://github.com/ONEGAYI/vsidian/issues/72)。实施顺序：[#73 矩形选择与复制](https://github.com/ONEGAYI/vsidian/issues/73) → [#74 结构删除](https://github.com/ONEGAYI/vsidian/issues/74) → [#75 悬停控件与拖排](https://github.com/ONEGAYI/vsidian/issues/75)。本规格已获用户确认；实现与人工验收状态另记。

## 问题与目标
preview-5760 的表格跨格拖选、删除和控件交互未通过用户验收。本规格取代 #57 中不明确的“可见内容选择”解释，关联 #42/#43；不关闭或改写原票。用户已逐项确认并授权开票、实施。

## 已确认交互契约
1. 单格内保留普通文本编辑/选择；拖出单元格形成矩形单元格选区，统一淡色背景、外围主题色圆角边框，内部网格线可见。反向拖选同样有效。选区是高亮、复制、删除的共同依据。
2. 删除独立“选择第 x 列”按钮；行/列点阵把手紧贴表格左/上边沿，对准对应行/列，悬停显示。单击把手选择整行/列；拖动把手插入式移动整行/列，显示插入线，不做两位置交换，不是单格内容搬移。
3. 靠近底边显示新增行窄条，靠近右边显示新增列窄条，居中加号与相应提示；移入操作带保持显示，离开隐藏。平时操作带及边框不可见，不常驻占位。
4. Ctrl/Cmd+C 复制单元格区域时输出完整 Markdown 表格，选区第一行作为新表头，紧接正确分隔行；不附带未选中的原表头。格内局部文字保持普通复制。转义、空格、中文、内联格式不得被破坏。
5. Delete/Backspace：局部矩形清内容；覆盖完整行则删行；覆盖完整列则删列；覆盖整表（同时满行满列）优先删表。部分选区不得删掉未选内容或破坏语法。
6. 整行内容为空时，在最左格内容起点 Backspace 删除该行。删除表头后下一存活行晋升；删尽最后行/列时删除整表与分隔行，保护前后正文。（2026-09-28 验收反馈澄清：「最左格内容起点」指首格区间内任意透明空白位——真实点击锚定格首同样触发删行，不要求恰好压在内容首。）
7. 表头可拖入数据区，数据行可拖到顶部；移动后首行就是表头，原表头进入数据区时成为普通行；分隔行永远在新表头后。列移动同步移动对应对齐信息。
8. 结构编辑经过既有宿主增量写回；一次撤销恢复整次操作；模式切换、失焦、外部文档同步不能留下错位/过期选区。保留 IME、普通格内输入、现有文本与表外选区行为。
9. （2026-09-28 验收反馈补充）矩形拖选**进行中**（未松手）不得同时显示原生线性文字选区（蓝色逐字高亮）——矩形蒙版与边框是唯一选区反馈；首格内拖选与拖出表格后恢复 CM6 原生文本选区不变。拖选全程蒙版不得断档：蒙版类由表格网格装饰的 class 托管（`liveDecorations` 把 region 类并入网格格 mark/widget 装饰，`regionSpans` 增量种子随区域增删重刷受影响行），外部贴类曾与列把手高亮、CM6 mark 重写竞态互抹——满列/整表扩张拖选中第一列整列消失直到松手，已按此修复钉住（`region-drag-fulltable-mask` 场景）。
10. （2026-09-28 验收反馈补充）**填充空白对用户透明**（取代 #12 时代「空格是可编辑文本」的旧语义）：空内容格的源码填充不可被 Backspace/Delete 删除（守恒）、左右方向键不得逐位经过空白位（直接切格）、空内容格不接受纯空白键入/粘贴（含非空白的输入照常进入）。
11. （2026-09-28 用户决策）**格对格粘贴**：格区选区活跃时粘贴「构成合法 GFM 表格」的剪贴板文本（如格区复制产物），以选区左上为锚逐格铺开替换——复制产物自动补的表头包装被剥掉（首行也是数据）；源越过选区继续覆盖表内已有格；源小于选区时选区内未覆盖格清空；源越出表格时向表格末尾扩行/扩列容纳（扩列的分隔格用默认左对齐，原列对齐保真）；**粘贴永不删行列**（结构只增不减，与 Delete 键的结构删除语义无关）。普通文本（非法表格）粘贴维持「清空所选格、文本落左上格」的现状；单格光标与表外正文粘贴不受影响。事件层截获直发单事务（`tableEditing` 的 paste handler），抢在事务层格内粘贴转义之前完成表格判定（`region-paste-grid` 场景钉住）。

输入一致性实现决策：格区仍有效时直接键入、粘贴或开始 IME 替换，应先清空所选格内容，再在区域起始格接收输入；不能悄悄取消高亮后变成前插。此路径保留行列结构，即使覆盖整行／整列也不复用 Delete 键的结构删除语义。区域粘贴的形态升级见契约 11（2026-09-28 决策，取代早前「不扩展区域粘贴」的暂缓口径）。

## 用户故事
1. 作为编辑者，我希望跨格拖动形成矩形高亮，从而直接看到下一步操作的准确范围。
2. 作为编辑者，我希望复制任意格区得到独立 Markdown 表格，从而在其他文本编辑器中使用。
3. 作为编辑者，我希望局部清空与完整行列删除符合选择范围，从而保留未选数据。
4. 作为编辑者，我希望空行退格、表头晋升与最后行列删除自然衔接，从而把表格删干净。
5. 作为编辑者，我希望新增入口按边缘悬停显现，从而保持正文整洁。
6. 作为编辑者，我希望紧贴边沿的把手可点击选择、拖动重排，从而稳定操作行列。
7. 作为编辑者，我希望拖排表头仍产生有效表格，并可一次撤销，从而放心调整顺序。

## 实施决策
- 延续 CM6 全文模型/视口渲染与宿主权威文本路线；不另起富文本编辑器、不引入 Advanced Tables 运行依赖。
- 以 tableEditing/liveDecorations/tableControls/tableStructure/tableCells 现有边界为基础；可提取专门格区状态与纯结构规划模块，不复制多套选区状态。
- 纯函数负责结构变更与剪贴板序列化；统一选区由鼠标、把手和键盘消费；普通文本输入保持原语义。
- 拖排按真实坐标与稳定行列标识计算落点，必须支持沿把手栏拖动、重绘/滚动、取消和失焦。不要依赖直接派事件给目标行的假命中。
- 新行为覆盖已有错误断言，不能保留“同列拖选删除邻列”契约。保持已有同步、CRLF/LF、撤销及主题规则。

## #248 格内嵌入兼容边界（2026-10-01 落档）

表格单元格内的 `![[…]]` 嵌入升级为格内卡片（双模式，规格见 [hover-preview-embed.md](hover-preview-embed.md) 的 #248 节），本规格的交互契约**全部保持**，本节钉住与格编辑的职责分界：

- **格区选取起点隔离**：从嵌入卡内部（`vsidian-embed-card` 卡壳 / `vsidian-live-embed` 宿主）开始的 pointerdown 不建立矩形格区锚（`tableRegionSelection.hit` 的 `excludeCardDomain`）——卡内选字/复制/滚动不启动父格区选取或父写操作；从格/把手开始的拖选**路径经过**卡片时仍按所在格扩展（onMove 不排除）。契约 1 的矩形语义与其余九条不变。
- **格输入语义不变**：Tab/Enter/方向键/IME/填充空白契约照旧——嵌入格是普通格内容（`![[…]]` 是格内文本），Tab 定位格内容首、Enter 写 `<br>`、Delete/Backspace 按格内容清空语义；编辑引用走正常格内编辑（光标触及嵌入区间时源码显形），**不复用整格替换**。
- **区域复制序列化源文**：契约 4 的复制对嵌入格输出**引用源码原文**（含 `\|` 转义，`escapeCopiedPipes` 不双重转义），不把目标正文灌入表格；格对格粘贴（契约 11）对含嵌入的源文本按既有转义规则铺开（`escapeCellText` 对已转义管道保持原样）。
- **列宽与网格**：格内卡嵌在网格格 mark span 内（CM6 inline replace widget 不切开 mark），网格行仍是单 grid item——列宽计划（[live-table-column-width.md](live-table-column-width.md)）与列对齐不受影响；紧邻嵌入宿主的 cm-widgetBuffer 零高块级化（其余格内 widget 的 buffer 是 posAtCoords 坐标锚，**不得**一并零高——tableCaret cell-widget 场景曾因误伤回归，回归用例钉住）。
- **转义映射单一事实源**：格内嵌入的「源码—表格转义—渲染文字」三套区间映射在 `src/webview/tableCellEmbed.ts`（`\|` 按格内语义解码、inner 为解码语义、区间恒为源文），切列判定复用 `tableCells` 不另起一套。
