## 实施落档（接入点与迁移范围，2026-10-07）

**不是已发布 SDK**：本节登记的全部形状都是待 T06 消费的接入面；组件侧 `applyEdits` 公开入口、历史协调器本体、持久化快照均不在本票。

### 可选来源元数据：形状与贯通

- 形状单一事实源在 `src/shared/editOrigin.ts`：`EditOriginMeta = { addonId, opId, undo: 'atomic' | 'joinPrevious' }`——addonId 沿用 T01 身份体系（Extension.id 形态，非空无空白），opId 为一次修饰提交的操作身份；不用文本显示名充当身份。校验器 `isEditOriginMeta` 与净变更判定 `hasNetTextChange` 同文件。
- 协议：`edit.request` 增加可选 `origin` 字段（`src/shared/protocol.ts`），在场即须形状合法，非法整条消息拒绝；旧调用缺省不携带，`isWebviewToHost` 行为不变。
- 写回层：`HostDocumentPort.applyChanges(changes, origin?)` 第二可选参数（vscode 层按需记账，当前生产实现不消费）。
- 确认管线（`src/host/documentSession.ts`）：`PendingEdit` 携带 origin；确认的单一汇合点 `confirmPending` 在回流匹配与兜底确认两条路径上都恰好触发一次 `onEditAttributed(record)`——record.version 与该笔 `edit.ack(ok)` 同源，changes 为 LF 形态（与 `doc.changed` 广播同款）。归属登记另有查询面 `editOriginAtVersion(version)`（有界，外来版本返回 undefined）。
- 旧调用契约等价由 `test/unit/documentSessionEditOrigin.test.ts` 钉住：无 origin 的输入不触发回调、ack/广播行为不变；CRLF 文档归属为 LF 坐标；重定位成功后归属落定 version。

### 失败、重放与纯选区

- 失败不留下成功来源记录：写回失败（applyChanges false）、不可安全重定位（版本超前/日志缺口）、暂停面板拒绝三条路径都不经过 `confirmPending`，不产生归属（单测钉住；集成侧以 t03Attributions 断言）。
- 重放不重复计入：ackCache 命中的重传直接重发原 ack，不重复入队；每笔 pending 确认恰一次。
- 纯选区事务不造文本撤销项：origin 在场且无净文本变更（空数组或全部 no-op 段）的请求直接以当前版本 ack 成功——不调用 applyChanges、不产生宿主历史项、不留来源记录。无 origin 的空请求保持既有路径（契约等价）。
- 跨目标元数据不合并到父文档历史：归属按 DocumentSession 划分（每 docUri 一个会话），B 会话的归属只触发 B 的回调与登记；单测与集成（t03Attributions 隔离断言）双钉。

### 组历史窄适配点（同目标历史协调的承接面）

- `DocumentSession.runHistorySteps(op, steps, origin?)`：挂在会话 queue 串行链上（排在在途 edit.request 之后，V01「单一路由点」要求——组请求不另建并行串行链），调用权威端口可选组入口 `undoGroup/redoGroup`；端口未实现时明确 `route-unavailable`，不降级为逐次单步、不改变 `history.request` 单步语义。
- provider 实现（`src/host/textEditorProvider.ts`）：活动 custom editor 场景 `runHistoryStepsCore` 直接整组执行；引用 B 场景 `historyGroupViaTempActivation` 一次临时激活执行整组、结束后恢复来源 A。每步执行前快照版本、执行后核对版本恰 +1（F2/F4 生产形态——核对口径为版本推进，不依赖文本全等），命令失败或失配即中止剩余步骤（超量请求在空栈步失配中止）。
- F1 修复（V01 实测发现）：1.82.3 的 `tabGroups.close` 关闭脏文本标签会静默丢弃未保存修改。收口收敛为 `closeTempTextTabsIfClean`——目标 dirty 时跳过关闭（标签留给用户，激活态已恢复来源 A），单步 `historyViaTempActivation` 与组路由共用该收口。clean 收口行为不变（既有 P2-04 撤销路由用例回归覆盖）。

### 迁移范围（扩展后迁移）

- 生产迁移：V01 探针 `runSteps` 的批量临时激活路由迁移为生产 `historyGroupViaTempActivation` + `runHistoryStepsCore`（核对口径从「版本 + 文本全等」收敛为「版本推进」——文本对账是验证工件语义，生产以来源元数据管线替代）；F1 脏态收口从探针实现固化为生产共用函数。
- 探针保持验证工件身份不动：其文本全等对账与分组状态机继续服务 V01 用例回归（`_test.addonHistory.*` 全族仍在）；生产语义另经 `_test.addonHistory.t03Submit / t03Attributions / t03GroupHistory` 三个钩子验证（直通生产管线，不经探针状态机）。
- 未迁移（留 T06）：同组未提交合并为一笔 WorkspaceEdit、非原子归属判定（HistoryBoundaryUnavailable）、外部回流补完（F3 前置检查）、分组撤回/重做计划、`joinPrevious` 语义执行——这些是历史协调器本体，消费本票的归属与组入口。
