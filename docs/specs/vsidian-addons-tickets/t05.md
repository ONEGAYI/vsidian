## 目标

用户在统一的 Vsidian 设置页按官方/第三方管理组件，停用后仍能配置自己的页面，开启时已开文档随之更新。

## 范围与已确认规则

- 侧栏三个有分隔的大组：选项（现有内置）、核心组件、第三方组件；后两组各有已启用/已停用。核心来自官方 ID 清单，不信任自称官方。
- 按用户开关分组；开关开启但故障暂停者仍在已启用组标故障。整体安装/卸载/VSCode 禁用由 VSCode 管理。
- 实现自己的自定义设置页；平台掌握框架、导航、作用范围和开关，拒绝覆写内置或其他组件页面。
- 普通停用只释放运行功能，自己的设置页重启后仍可配置；故障时撤下自定义页代码，已有定义使用平台基础控件，无定义仅排障。
- 切换作用于已开文档，IME 或提交未完成时安全收尾，保留原文、历史和用户偏好。

## 验收标准

- [ ] 三个大组及启用/停用子组按约定呈现，官方/第三方来源准确，内置设置操作不回退。
- [ ] 自定义设置页、普通关闭后的配置与重启回显、故障后的基础配置分别真实可用。
- [ ] 开关与作用范围持久化，热切换不丢组合输入、不清历史、不留旧功能。
- [ ] 状态、导航和自定义页面边界有绘制层/交互证据，并同步 API 与样式契约。

## 验证与留证

- 侧栏与设置页面浏览器交互
- 开关、热切换、重启宿主
- 故障页撤下和平台基础配置

## 范围外

- 不将开关描述成杀死整扩展
- 行为冲突管理由 T08 完成

## 实施与交付约定

- 接口名称与字段仍是待冻结技术提议；实现可据通过的验证收敛形状，已确认的用户行为不能自行弱化。通过公开消费路径验证，不引用内部控制器当 SDK。
- 可执行变更按仓库 TDD 约定先立预期再实现；输入/光标变更必跑浏览器原生路径，装载/历史/安装需真宿主。长命令首次执行留完整日志和退出码，复核读报告。
