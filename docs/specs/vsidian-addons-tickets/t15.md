## 目标

开发者有三套只使用公开 SDK 的可独立构建样例，共同检验 API 不只为 Easy Typing 一项需求服务。

## 范围与已确认规则

- 输入样例借鉴 Easy Typing 的一个明确场景，如自动空格或括号处理，展示默认原子及声明非原子、顺序与逐项关闭；不承诺完整移植。
- 渲染样例支持替换一个内置语言及一个普通语言，展示安装后自动接管、按需调整、正常停用/全组件故障及自身 bug 的区别。
- 界面样例新增自己的命令/菜单、按钮或面板及复杂设置，展示用户默认/工作区覆盖、停用后配置和手动恢复。
- 每个样例为独立 VSCode 扩展工程，声明依赖、同宿主偏好、身份/API兼容与各自宿主/页面产物；不得导入内部代码或重复 CM6。
- 维护于主仓库可打包的示例/测试位置，使用同一公开 SDK 开发包与生成指南，准备后续独立仓库复制路径。

## 实施发现的已知边界与未决事项（如实记录）

1. **esbuild CJS 入口导出消除**：`export function activate` 经 esbuild CJS bundle 后被消除为死代码（`0&&module.exports=...`）——宿主拿不到 activate。样例宿主改用显式 `module.exports = { activate, deactivate }` 赋值（VSCode 扩展 CJS 契约的可靠形态）。后续 SDK 文档可补此注意事项。
2. **扩展 ID = publisher.name**：样例 name 初版带 `vsidian-example-` 前缀导致实际 ID（`vsidian-example.vsidian-example-input-behavior`）与代码 SELF_ID 不符，registerAddon 拒绝 `extension-not-in-host`。已修正 name 字段；命名惯例可补进开发指南。
3. **符号字符不进行为链**：`(` 经内核符号输入情境（beforeinput 拦截）的事务无 input.type userEvent，行为链按平台门控不驱动——paren-close 在集成通道（execCommand 注入）无法端到端验证键入效果；真键盘路径归浏览器套件（本票豁免浏览器全量，无 src/ 运行时变更）。用例以「键入落盘 + 无自动补全」如实断言门控语义，并以行为目录声明断言非原子注册形态。
4. **独立键入场景的 joinPrevious 修饰被拒**：非原子的并组目标须是同链前序的 SDK 原子修饰（T07 夹具模式：atomic 段在前、joinPrevious 并入）；行为独立处理单次键入（无前序原子修饰）时声明 joinPrevious 被 history-boundary 拒绝。样例的 joinPrevious 展示由此调整为注册声明形态。
5. **键入后紧邻 atomic 修饰的撤销粒度差异（未定根因）**：输入样例场景（'a' 键入 + 前插空格 atomic 修饰）实测一次撤销回退键入+修饰整体（撤销栈一笔），与 T07 夹具场景（'^' 键入 + 尾部追加修饰）的两笔行为存在未解释差异（时间窗假说已实验否定：undo 前延迟 1.2s 仍一笔）。atomic 修饰的独立撤回粒度不在 T15 用例断言，平台粒度语义由 T07 用例与单元测试承载；根因排查留待后续平台票。
6. **autoOpenPanel 路径的面板绘制层断言**：页面装载注册回调内立即 open() 的路径上，`paint.addonUi.panelBodyVisible`（内容根几何命中）未收敛（openPanelIds 开态与 mount 事件均确认面板已开）；用户手动打开路径的绘制层断言由 T11 夹具用例承载。用例以开态 + mount 完成事件双证据断言，几何断言的时序根因留待排查。
