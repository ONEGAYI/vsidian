## 实施发现的已知边界与未决事项（如实记录）

1. **1.82.3 工作台会为缺失依赖自动从 marketplace 补装**：阶段 A 初版「主扩展缺席」被自动补装破坏（extensions.json 出现带 uuid/publisherId 的 onegayi.vsidian 0.11.0 安装记录）。处置：`--disable-extension=onegayi.vsidian` 钉住依赖不可用态（实测阻断自动补装）；阶段 B 主 VSIX 以 `--force` 安装防占位。对真实用户是正面行为（装组件即自动装宿主），「纯缺失」态在完整工作台不可复现——依赖缺失语义以禁用态承载，票面口径如实记录。
2. **测试模式宿主 storage 完全 in-memory，「重启/升级不重置」的跨会话读取面不可自动化**：三途径实证——(a) 写入后 `workbench.action.quit` 优雅退出（driver 源码确认走 `quit()`），state.vscdb 恒 0 字节；(b) 75s 周期等待无效；(c) sqlite 直写预置（ItemTable + 双 storage marker + 三键）宿主读不到。对照实验：同参数正常窗口模式 22 秒内 state.vscdb 完整落盘（147KB，含扩展 memento 键）——正常用户路径不受影响。处置：跨会话保留拆为写入链路（B6 真实 globalState.update + ok 回执）+ 启动装配读取面（平台单测承载：服务构造从持久层装配）+ D/E 会话内持久语义闭环（写入→读回→行为级效果→面板重开不重置）。**未决**：真实重启/升级后保留的用户侧验收归人工验证待办；如需自动化闭环需换通道（如正常窗口模式驱动，超出本票范围）。
3. **已开文档热接入的同面板事件断言**：enable 后 wiring 经 `pushEditorDirectives` 推装载指令 diff（平台链路真实支持），但 paint.addonUi 几何探针在该路径受 1.82.3 资源根扩展触发的整页重载时序影响（textEditorProvider 注释记录的同族现象）；用例以「装载指令 + loaded 事件（宿主权威事件流，事件基线清零防前序冒充）+ 兜底重开按钮挂载」承载，两条路径至少其一必达。
4. **依赖不可用时依赖者被扩展服务整体排除**：样例 `getExtension` 为 undefined（不可见即不可用）——用例对「排除」与「在场不激活」两种时序都稳健（未来宿主行为变化不破坏断言语义）。
5. **1.82.3 CLI 升级的旧版目录清理不确定**：三样例 0.1.0→0.2.0 升级中两枚旧目录被 CLI 即时删除、ui-command 的旧目录残留（磁盘孤儿）——但 extensions.json 权威清单与运行态均唯一注册新版本（孤儿目录不加载）。E 阶段以权威清单 + 运行态双断言承载「无重复注册」，目录级清理差异不作违规。
