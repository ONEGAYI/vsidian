## 目标

在真实 Remote SSH 工作区中，Vsidian 与组件在同一远端宿主接入，页面资源和双端 API 可用，安装侧缺失提示不做错误归因。

## 范围与已确认规则

- 使用 T16 的实际包，记录安装侧、运行扩展宿主、API 导出与页面 URI。宿主代码同远端，页面仍在相应 Webview。
- 重复三类样例的关键公开接入、复杂设置保存、输入/渲染结果、关闭释放及故障重试；验证组件自己的宿主文件/网络逻辑按原生扩展模型运行。
- 覆盖组件未在当前宿主可见、不兼容、原生依赖失败等情况；不能仅查不到就写未安装或装错侧，提供 VSCode 管理/运行扩展排查入口。
- 本地和 SSH 之间不建透明跨宿主导出 API，不绕开原生资源 URI 授权。无真实 SSH 环境时记录外部阻塞，不能用本机 mock 宣布通过。

## 验收标准

- [ ] 真实 SSH 环境中有双 VSIX 安装、实际同宿主和页面资源成功的版本/位置证据。
- [ ] 三类功能、设置/开关、释放及手动恢复在远端目标工作区有可重放结果。
- [ ] 不可见与其他失败的诊断有负向对照，没有把宿主可见性冒充全局安装清单。
- [ ] 环境、命令、日志、退出码与未验项如实落档，环境受限时保持未验状态。

## 验证与留证

- 真实 Remote SSH 同宿主和安装
- Remote Webview URI/资源及三类 SDK
- 失败侧诊断与恢复

## 范围外

- 不设计首版跨本机/远端透明调用
- 不修改用户 SSH 配置、凭据或另建服务
