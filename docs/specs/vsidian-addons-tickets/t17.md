### 通道边界与架构事实（如实记录，未绕过）

- **extension tests runner 挂在本地 ext host**（1.82.3 实测：remote window 下 `--extensionTestsPath` 在本地执行；workspace 类扩展分流到远端 ext host，dev path 亦按 extensionKind 分流）——runner 不能直接断言远端清单，断言面经命令路由（本地 runner 调远端注册的命令——VSCode 原生通道）+ 样例 stats 宿主观测自报（样例代码在远端执行，读远端清单）双通道构成。
- **远端 ext host 不继承本地 env**：`VSIDIAN_TEST_HOOKS`/`VSIDIAN_TEST_CASES`/`WORKSPACE_DIR` 一概传不进 SSH 会话（server 进程 env 来自远端登录 shell；`server-env-setup` 仅支持 Linux/macOS 远端，Windows 不适用；`SendEnv` 需改 sshd 配置——范围外）。由此 SSH 会话天然是**发行态语义**（`_test.*` 缺席本身是用例断言面，T16 阶段 C 同构）；阶段变量与用例筛选经工作区标记文件 `.vsidian-t17-ssh.json` 传递（suite 入口 `sshMarkerCaseFilter` 兜底、`WORKSPACE_DIR` 从 workspaceFolders 推导——本地会话 env 优先，行为不变）。
- **远端安装链的通道形态**：远端 server CLI（`~/.vscode-server/code-<commit>.exe`）的 `ext install` 是桌面版语义（找不到本地安装的 VSCode 即失败），不提供「给已连接 server 装 VSIX」的无头通道——远端装载采用权威清单镜像（见上），装载与运行仍走远端扩展服务全链路。
- **未验项（通道限制，非实现缺失）**：输入行为的真实键入（`table.test.domType` 注入）、绘制层探针（`requestViewState` paint）、经 `_test` 的设置写入与 T12 故障链查询——发行态无对应公开命令，远端会话不可达；本地 hooks 会话的同面由 T16 矩阵覆盖。

### 资源与 URI 模型审计（代码级证据，#366）

- manifest 铸造唯一入口 `buildManifest`（`src/host/addons/addonWiring.ts:472-484`）：scriptUri/cssUris/resourceBase 全经 `webview.asWebviewUri(vscode.Uri.file(fsPath))`——remote 场景自动产出带 authority 映射的 `vscode-webview-resource:` URI。
- CSP 参数化（`src/host/editorCsp.ts:56-78`）：只认传入 `cspSource`（webview 私有随机 origin），无硬编码源。
- webview 消费（`src/webview/addonPageLoader.ts:409-418`）：原样消费 manifest URI + 相对拼接（词法拒绝绝对路径/协议形态/`..`）。
- 资源许可面（`src/host/textEditorProvider.ts:3854-3856` 初始、`408-425` 动态只增不减）：`localResourceRoots` 聚合含 addon 装载根。
- 协议 `fsPath` 字段为身份戳记非资源地址（`src/shared/protocol.ts:85-93` 注释明确 webview 无法从 fsPath 自行构造）；HTML 装配无手工 `file://`/盘符拼接（grep 审计零命中）。
- 运行态证据：R1 用例断言 `extensionUri.scheme === 'file'`（远端盘面）+ 页面装载 + 命令落盘。

### 跨宿主边界声明审计（ADR-0001 口径）

- 发现面 = `vscode.extensions.all`（当前扩展宿主快照，`addonWiring.ts:331`）；「曾发现本轮查不到」→ `host-unavailable`，不归因未安装/装错侧（`addonCoordinator.ts:202-213`）。
- 公开 API 唯一发布通道 = `activate()` 返回值 exports（`addonWiring.ts:346-357、1289`）——VSCode 同宿主语义：本地与远端 ext host 互不可达对方 exports，**无透明跨宿主导出 API**。
- 注册入口 `registerAddon(owner, ...)` 的 owner 身份来自调用者扩展（`extension-not-in-host` 拒绝路径，`addonIdentity.ts:150-155`）——不可伪造跨宿主身份。
- 资源装载三层防线（词法包含 `addonPageRegistry.ts`、realpath 守卫 `addonRealpathGuard.ts`、资源服务 `localResourceRoots`）无绕开原生资源 URI 授权的路径。
- 远端实证：R1/R2 对照——同一本地安装（profile 不变），R2 装配面少 input-behavior 即「当前宿主查不到」，协调器不产生任何安装侧归因。

### VSCode 管理/运行扩展排查入口指引（安装侧诊断）

- **两侧各查一遍**：SSH 会话的扩展视图按「本地 — 已安装」与「SSH: <主机名> — 已安装」分组（workspace 类扩展如 Vsidian 装远端组；ui 类装本地组）；命令面板 `Extensions: Show Installed Extensions`。
- **远端安装目录**：`~/.vscode-server/extensions`（真实 SSH 安装链的落盘位置；本地 `--extensions-dir` 只影响 UI 扩展）。
- **禁用态注意**：`--disable-extension` 或扩展视图禁用开关会让扩展从当前宿主清单消失（`vscode.extensions.all` 查不到）——排查时先确认未禁用。
- **Vsidian 组件列表语义**：`host-unavailable` = 当前宿主查不到（原因不可判），**不等于**未安装或装错侧；激活失败/不兼容各有独立状态与原因原文。
- 排障块与诊断链（T05/T12）在远端会话语义同本地：状态经同一协调器产出，仅可见面随宿主变化。
