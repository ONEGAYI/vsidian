## 1. 目标与边界

**先建立接入机制与公开契约，再制作组件验证它们**。提供 Vsidian 自己的 API，覆盖输入处理、内容渲染和界面操作。Easy Typing 移植作为输入类样本，与另外两类样例共同验证。

附加组件经 VSCode 发现和安装。核心组件是官方提供的附加组件，也作为独立 VSCode 扩展分发，与第三方共用公开 API、兼容和生命周期约定。整体 VSCode 扩展的安装、卸载、启用与禁用仍由 VSCode 管理。

首版采用同扩展宿主接入：本机项目两者的宿主代码在本机，Remote SSH 项目两者的宿主代码在远端。页面代码在相应 Webview 中执行。

首批稳定 API 包含六组：视图与编辑、内容渲染、操作与界面、设置、生命周期与通信、诊断。CodeMirror 6 等底层接口经显式实验入口提供，另行声明兼容要求。

## 2. 用户故事

1. 作为使用者，我希望在 VSCode 中寻找并安装附加组件，以便沿用已有的扩展管理方式。
2. 作为使用者，我希望 Vsidian 只列出声明了附加组件身份的扩展，以便不用从全部扩展中挑选。
3. 作为使用者，我希望看到组件的名称、来源、扩展 ID 和实际状态，以便判断自己安装了什么。
4. 作为使用者，我希望官方组件与第三方组件分组展示，以便区分来源。
5. 作为使用者，我希望新安装的兼容组件默认启用，以便安装后可以使用其功能。
6. 作为使用者，我希望关闭选择在重启与普通升级后保留，以便不会被自动重新开启。
7. 作为使用者，我希望切换组件开关时已打开文档随之更新，以便不用重开文档。
8. 作为输入法使用者，我希望切换功能时保留正在输入的文字与正常撤销，以便配置调整不会破坏输入。
9. 作为使用者，我希望同一操作的行为可以按顺序共同执行，以便组合多个组件的功能。
10. 作为使用者，我希望在组件管理的「行为冲突管理」中调序或关闭某项行为，以便调整功能组合而不必停用整个组件。
11. 作为使用者，我希望行为有清楚的名称并标明所属组件，以便知道自己正在调整什么。
12. 作为使用者，我希望新安装的渲染组件自动替换其支持语言的现有显示，包括内置渲染，以便安装后直接使用；有需要时仍可主动调整。
13. 作为使用者，我希望组件设置支持用户默认与当前工作区覆盖，以便在不同项目中采用不同配置。
14. 作为使用者，我希望「使用用户默认」清除工作区覆盖，以便恢复继承而不丢掉个人默认。
15. 作为使用者，我希望设置能保存列表与对象，以便配置替换规则等复杂内容。
16. 作为使用者，我希望手动停用后仍能配置组件，以便再次开启前先调整参数。
17. 作为使用者，我希望组件故障后看到原因和重试入口，以便恢复功能，同时保留原来的启用偏好。
18. 作为使用者，我希望在组件自定义设置页故障时仍能获得平台提供的排障界面，以便不被坏页面挡住。
19. 作为引用视图使用者，我希望组件操作归实际目标文档，以便编辑引用 B 时不会误改父文档 A。
20. 作为 Remote SSH 使用者，我希望获得有依据的运行位置提示，以便排查组件接入问题。
21. 作为组件作者，我希望注册自己的命令、菜单、按钮、面板与设置内容，以便扩展 Vsidian。
22. 作为组件作者，我希望宿主与页面通过公开接口通信，以便分别使用文档能力和页面交互能力。
23. 作为组件作者，我希望注册与资源有统一的释放机制，以便热切换、关闭视图和故障恢复后不会留下旧功能。
24. 作为组件作者，我希望稳定 API 有版本文档、兼容检查与弃用期限，以便组件可以持续维护。
25. 作为组件作者，我希望复用 VSCode 的调试工具并看到带来源的日志，以便定位问题。
26. 作为使用者，我希望文本修饰默认具有独立撤回边界，以便逐步撤回自动改动。
27. 作为组件作者，我希望明确声明某次修饰不建立独立撤销项，以便让辅助改动随同一目标文档的上次原子操作撤回。
28. 作为使用者，我希望组件正常关闭或整组件故障停用后交回内置显示，以便继续阅读内容。
29. 作为组件作者，我希望仍在运行的组件负责自身渲染输出，以便问题不会被平台自动切换所掩盖。

## 3. 接入与模块职责

### 3.1 已确认的顺序

```text
Vsidian 自身激活完成，公开 API 可访问
  → 扫描当前扩展宿主中的附加组件声明
  → 校验身份声明与 API 兼容要求
  → 协调唤醒合格的 VSCode 扩展
  → 组件代码调用公开 API 注册
  → 设置接入与运行功能分别按生命周期装配
```

Vsidian 不在自己的激活流程中等待依赖它的组件完成激活。VSCode 原生机制也可能先于主动唤醒步骤激活组件，注册入口仍须校验并避免重复接入。具体调度必须通过 1.82.3 真宿主验证。

没有身份声明的普通扩展不进入组件列表。声明合法但不兼容或加载失败者保留状态与原因。当前宿主查不到某个扩展时，不将原因直接写成「未安装」或「装错侧」。

### 3.2 内部模块边界

以下是实现职责划分，文件位置在实施时确定。组件只访问公开接口，不引用这些内部模块。

| 模块职责 | 输入与输出 | 主要约束 |
| --- | --- | --- |
| 发现与兼容检查 | VSCode 扩展清单、私有身份声明 → 可接入记录与状态 | 当前宿主范围；关键词只用于搜索 |
| 接入协调 | 合格记录、原生激活结果 → 组件注册上下文 | API 先就绪；处理重复注册与失效实例 |
| 组件生命周期 | 启用偏好、故障状态、视图变化 → 有效注册与资源 | 设置能力与运行功能分开；故障暂停整个组件的注册功能 |
| 行为调度 | 当前操作、适用行为、顺序与逐项开关 → 顺序执行过程 | 默认不假定互斥；独占操作的表达待定 |
| 渲染提供者管理 | 语言、模式、新安装候选与持久首选 → 生效提供者 | 新安装的组件自动接管，用户可主动调整；正常停用或整组件故障停用后可交回内置，仍运行的渲染 bug 不自动接管 |
| 设置存储与界面 | 组件设置定义、两层覆盖 → 值、来源与配置页面 | 组件隔离；保存失败不通知成功 |
| 页面装载与通信 | 组件页面入口、视图上下文 → 页面注册与消息路由 | 入口归所属组件；失效消息不得继续产生写操作 |
| 契约与文档维护 | 公开声明、版本与语义清单 → 指南、检查报告 | 与实现一起维护；历史证据独立保存 |

### 3.3 身份与分发数据

**身份声明仅描述接入元数据**。能力、适用模式、业务条件及昂贵资源初始化由代码注册和回调表达，不增加 Vsidian 激活事件 DSL。

| 数据 | 草案要求 |
| --- | --- |
| 扩展身份 | 使用 VSCode 扩展身份定位安装包；组件注册不得任意占用另一个组件的命名空间 |
| 私有身份标记 | 顶层私有清单字段由 Vsidian 校验，不能作为 VSCode 正式 contributes 贡献点使用 |
| 稳定 API 范围 | 必须声明支持范围；具体字段名与首个 API 版本尚未冻结 |
| 实验兼容要求 | 使用实验入口时另行声明，不用普通本体版本代替稳定 API 版本 |
| 必要展示信息 | 沿用扩展身份与作者信息；避免重复维护能力及激活条件 |
| 页面入口 | 由组件代码注册，按编辑器页面和设置页面的实际需要提供 |

建议组件声明对 `onegayi.vsidian` 的原生扩展依赖及 workspace 运行偏好。这两个字段与模块格式须在装载验证后定稿，不把本草案示意当作已发布的 SDK 模板。

官方归属由 Vsidian 管理。具体识别方案需要随接入实现明确，不能仅因组件自己写了「官方」就据此分入核心组件。

## 4. 公共上下文与数据契约

**公开上下文提供操作接口与归属信息，内部控制器留在内核中**。宿主注册上下文与页面上下文由平台分别构造；函数、DOM 对象及编辑器实例不作为跨消息桥载荷。

| 数据或句柄 | 语义 |
| --- | --- |
| 组件上下文 | 组件身份、API 版本、有效生命周期与所属注册范围 |
| 视图句柄 | 主正文、悬停引用、正文嵌入共用；标明目标文档、模式、可编辑状态与有效实例 |
| 文本与选区快照 | 位置沿用全文 UTF-16 code unit 偏移；页面侧采用 LF 坐标；保留多选区信息 |
| 编辑请求 | 明确目标实例及版本，经过原有宿主文本管线写回；拒绝向只读或已释放实例写入 |
| 文本修饰操作 | 一次相关变更的提交单位；默认原子跟踪及独立撤回，作者可声明非原子、随同一目标文档的上次原子操作撤回 |
| 行为描述 | 可稳定识别的管理单位、用户可读名称、所属组件；说明和例子可选 |
| 渲染提供者 | 独立于语言的候选身份、支持语言与模式、装载及释放能力 |
| 设置值与来源 | 用户默认与工作区覆盖、当前生效值及来源；支持适合 JSON 协议的普通值、数组与对象 |
| 注册释放句柄 | 取消自己的注册；组件或视图释放时平台统一回收 |
| 消息与结果 | 可传输的数据、请求关联、组件和实例归属、成功或拒绝原因 |

行为的显示名不应直接作为持久化身份。否则重命名或切换语言会丢失逐项开关和顺序选择。稳定标识的具体格式随接口声明冻结。

调用被合理拒绝与组件运行异常应区分。例如只读写入、旧实例调用或无效设置补丁需要明确拒绝结果；可捕获且可归因的注册、初始化或回调异常仍按已确认规则暂停组件。错误码与结果类型在接口定稿时统一。

## 5. 六组稳定 API 的接口草案

本节的参考名称用于讨论接口职责，不是已存在或已经发布的函数。实现前将名称、参数和结果收敛到公开声明，并以该声明生成参考文档。

### 5.1 视图与编辑

| 参考接口 | 对外能力 | 执行与边界 |
| --- | --- | --- |
| `views.list` / `views.onCreated` / `views.onDisposed` | 枚举或订阅有效视图实例 | 区分实例与目标文档，不把父视图作为引用编辑目标 |
| `editor.getSnapshot` | 读取文本、选区、模式和版本 | 快照有效性与 LF 坐标要写入契约 |
| `editor.setSelection` / `editor.reveal` | 移动选区或定位内容 | 操作当前目标实例；保留只读视图的定位能力 |
| `editor.applyEdits` | 提交文本修饰操作 | 只作用于合法可编辑 Live 目标；默认原子跟踪和独立撤回，可明确声明非原子，保存与撤销归宿主 |
| `behaviors.register` | 注册参与输入操作的行为 | 名称必填；顺序与逐项开关由平台管理；一次行为执行与一次修饰操作不是必然同一粒度 |
| `editor.onChanged` | 观察文档或视图变化 | 不把通知监听自动等同于同一输入的写入行为链 |

稳定输入接口应让作者表达业务处理，而不依赖原始 CodeMirror 控制器。组合输入、表格、选区与 Tab 等既有边界继续遵守 [符号输入约定](symbol-input.md)。输入处理与首次挂载、热接入的就绪状态要明确，不能假定首次按键才装载代码仍能无损接管。

**修饰跟踪与撤销边界**（Q29）：一次公开编辑接口提交的文本修饰默认作为原子操作，记录来源和变更，具有独立撤回边界。一个修饰操作可以包含多个相关范围的变更，不按字符或每条底层变更拆分；也不自动把同次输入中的所有组件修饰合成一次撤销。

组件作者可明确声明某项操作非原子，含义是不建立独立撤销项，与同一目标文档的上次原子操作一起撤回。连续非原子修饰均归入该原子操作，各次变更与来源仍须独立跟踪；作者不需要另行选择要合并到哪一次触发操作。合并归属已经确认，声明方式、宿主撤销和重做协议仍须设计并通过真实宿主验证。原始输入分组和纯选区导航保留各自已有契约，不因新 API 给无文本变化的定位操作强造文本撤销项。

### 5.2 内容渲染

| 参考接口 | 对外能力 | 执行与边界 |
| --- | --- | --- |
| `renderers.register` | 为一个或多个代码块语言提供渲染候选 | 新安装的兼容且已启用组件成功接入后自动替换现有显示；同一语言可有多个候选，用户可主动调整；可替代内置语言渲染 |
| 渲染挂载上下文 | 获取代码、语言、目标视图与所属内容容器 | 页面端执行；挂载资源归本次渲染和组件 |
| 渲染刷新与释放 | 源码、选择、视图及组件状态变化后更新或卸载 | 不把旧异步结果装到新实例中 |
| `reading.registerPostProcessor` | 处理阅读模式生成的内容 | 保持目标文档归属；不是接管整个编辑器或设置界面 |
| 可选图形导出能力 | 接入现有图形按钮、弹窗与导出链路 | 能力登记与降级遵守现有图形代码块约定，不要求所有渲染器具备图形导出 |

**安装后直接生效**（Q28）：新安装、兼容且已启用的渲染组件成功接入后，自动成为其支持语言的生效提供者，替换当前内置或其他组件的渲染。该规则适用于所有代码块语言，不要求用户先打开设置选择渲染器。仍保留主动调整候选及改回内置的能力，选择入口不是安装后的必经步骤。

自动接管结果与用户调整均须持久保存。重启、重复注册与普通升级不当作新安装，不重新覆盖已有首选。多个新候选同时接入的自动顺序在接口设计中明确，不要求用户逐语言完成初始配置。

内置渲染器保留为候选，组件注册自己的提供者。某种模式不受候选支持时，不调用其不支持的入口；模式资格、尚未接入等状态的呈现须在接口中明确，不能假装成用户正常停用或整组件已经崩溃。

**显示接管条件**（Q30）：接管依据组件或提供者是否实际被停用，不以任意渲染异常或错误输出为自动切换依据。

| 状态 | 显示责任 |
| --- | --- |
| 用户正常停用该渲染器或组件 | 交回内置显示管线 |
| 整组件因故障已被平台降级停用 | 内置可以接管，标明故障原因，保留组件启用偏好与渲染首选 |
| 组件仍运行，渲染逻辑有 bug 或自行处理了局部失败 | 不自动接管；不承诺识别、修复或替作者重渲染错误输出 |

框架捕获可归因的注册、初始化或回调异常时，仍按既定规则暂停组件全部注册功能；实际停用后，属于整组件降级停用一档。不能仅因组件记录了错误日志或输出看起来不正确，就认定它已进入停用状态。

保留自动接管或用户调整所确定的首选；重新启用或手动重试成功、首选提供者恢复可用后，按原选择显示。不自动重试故障组件。内置没有相应图形能力时，沿用普通代码块显示。切换前回收所属挂载和注册，旧异步结果不得覆盖内置或恢复后的新内容。

落地必须适配 [图形代码块约定](graphic-code-block-interaction.md) 的两表同步与降级口径。已有单一语言注册表不是附加组件多提供者管理接口。

### 5.3 操作与界面

| 参考接口 | 对外能力 | 执行与边界 |
| --- | --- | --- |
| `commands.register` | 新增自己的命令与可绑定操作 | 所属组件命名空间；适用 Live、阅读或双模式由代码注册 |
| `menus.registerItem` | 向公开挂载位置新增自己的菜单项 | 校验归属及内置标识冲突；同名注册不能间接覆写内置项 |
| `ui.registerButton` | 新增自己的按钮 | 绑定公开命令，生命周期结束后撤下 |
| `ui.registerPanel` | 新增自己的面板内容 | 平台管理挂载与释放，组件管理自身内容 |
| 快捷键接入 | 纳入统一绑定、清空、恢复默认与冲突检查 | 写操作不接管源码模式或设置页输入；不得绕过已有 Tab 约定 |

命令注册时记录执行端和目标上下文。宿主与页面回调分别在所在端执行，不能通过 JSON 消息直接传送回调函数。确切挂载槽位与面板形式在界面接入时确定。

### 5.4 设置

| 参考接口 | 对外能力 | 执行与边界 |
| --- | --- | --- |
| `settings.registerDefinitions` | 定义组件的用户设置 | 支持普通值、数组与对象；定义归组件隔离范围 |
| `settings.get` / `settings.getSource` | 获取生效值及来源 | 区分出厂默认、用户默认与工作区覆盖 |
| `settings.update` | 写入指定作用范围的设置补丁 | 平台校验和持久化；失败不得报告保存成功 |
| `settings.clearWorkspaceOverride` | 清除工作区对某项的覆盖 | 恢复继承用户默认，不是恢复出厂默认 |
| `settings.onChanged` | 订阅成功保存后的配置变化 | 所属设置和组件生命周期明确 |
| `settings.registerPage` | 自定义自己的设置内容 | 平台掌握框架、导航、作用范围与功能开关 |

组件私有缓存与业务数据不并入用户设置定义。现有内置标量模型不能仅用类型断言就当作已支持复杂值；结构校验、序列化、存储失败、读取与升级必须有行为验证。

自定义页面不得成为配置的唯一存取通道。平台要保留可以独立校验和持久化的定义，支撑组件手动停用后的配置，以及故障暂停后的基础配置界面。已有定义时的基础控件应由平台执行，不重新运行故障组件的页面代码。

### 5.5 生命周期与通信

| 参考接口 | 对外能力 | 执行与边界 |
| --- | --- | --- |
| `registerAddon` | 在宿主 API 就绪后接入组件 | 校验身份、兼容及重复注册，返回所属组件上下文 |
| 页面入口注册 | 声明实际需要的编辑器或设置页面入口 | 与组件自己的 VSIX 同包；资源位置、模块格式及装载方式待技术验证 |
| `lifecycle.onEnable` / `lifecycle.onDisable` | 装配或释放运行功能 | 普通停用保留设置能力；热切换等待输入安全收尾 |
| 所属注册与资源管理 | 回收回调、页面内容、监听与异步任务的有效引用 | 组件、行为或视图结束时释放相应资源；取消应可重复调用 |
| `channel.request` / `channel.onMessage` | 组件宿主与自身页面之间传递请求和结果 | 使用可传输数据；请求归属与超时、取消需要明确 |

消息路由要识别组件、页面实例与生命周期是否仍有效。组件停用、故障或实例释放后，旧消息及异步完成不能继续产生编辑写回或重新挂载功能。

在原生 VSCode 信任模型中，这些能力控制平台管理的注册和资源，不等同于停止整个扩展的任意代码。

### 5.6 诊断

| 参考接口 | 对外能力 | 执行与边界 |
| --- | --- | --- |
| `logger` | 记录带来源的调试、信息、警告和错误日志 | 包含组件身份，必要时包含行为、视图及阶段 |
| `diagnostics.reportFault` | 报告需要平台处理的组件故障 | 与普通错误日志区分；故障处理按全组件暂停规则执行 |
| 管理状态查询 | 展示启用偏好、兼容、装载和故障状态 | 启用偏好与实际故障分别记录 |
| 手动重试 | 重新接入故障组件 | 失败继续保留故障状态，不自动改写启用偏好 |

页面调试使用 VSCode Webview 开发者工具，宿主调试使用 F5、断点与 Debug Console，安装态日志写入 VSCode 输出通道。设置页提供状态、原因与重试，不另建开发者控制台。

## 6. 组件管理与配置界面

### 6.1 导航与状态

设置侧栏保持已确认的三个大分组，并有视觉分隔：

| 大分组 | 内容与子组 |
| --- | --- |
| 选项 | 现有内置选项 |
| 核心组件 | 官方组件设置，分「已启用」「已停用」 |
| 第三方组件 | 第三方组件设置，分「已启用」「已停用」 |

分组按用户功能开关归类。开关开启但因故障暂停的组件仍放在「已启用」，另外标注「故障暂停」。

组件管理设置页提供「行为冲突管理」入口。其调序单位是注册行为，显示名称和所属组件；说明和例子存在时可按需查看，缺少它们不能成为拒绝接入的理由。同一操作下的适用行为默认依次触发，用户可调序及逐项关闭。

分组、搜索、调序控件和过程记录的具体布局仍是 UI 设计项。此前「最近一次输入」的排查视图是候选方案，不作为已经确认的必做界面。

### 6.2 设置作用范围

附加组件设置页顶部由 Vsidian 提供「用户默认」「当前工作区」标签。修改用户默认影响未覆盖的工作区；当前工作区修改只作用于当前项目。每项「使用用户默认」清除工作区覆盖。

功能开关同样支持两层作用范围。行为顺序、逐项开关和渲染首选（安装后的自动接管及用户主动调整）的保存格式需要与组件管理状态共同设计，保留稳定身份及恢复关系；不以显示名作为存储键。

无工作区时的布局、跨窗口写入协调与具体存储位置在实现前明确，不借此变更已有内置选项的作用范围。

### 6.3 停用与故障

| 状态 | 运行功能 | 设置内容 |
| --- | --- | --- |
| 启用且正常 | 根据视图、模式与逐项开关装配 | 组件自己的设置页 |
| 单项行为关闭 | 该行为停止，组件其他适用功能继续 | 行为配置保留 |
| 组件手动停用 | 停止运行贡献并释放对应资源 | 自己的设置页仍能打开；重启后仍能配置 |
| 组件故障暂停 | 暂停组件在 Vsidian 中的全部注册功能 | 平台状态、日志与重试；已有定义时提供基础配置控件 |

可捕获且可归因的异常是故障暂停的范围。普通 API 拒绝结果、业务自行处理的失败与未捕获异常在错误模型中区分，不把所有日志消息都当作故障。

## 7. API 文档与兼容检查

**文档维护与 CSS 样式契约同等地位**。主仓库保存公开声明、兼容契约、版本文档与检查证据。独立示例仓库展示如何消费公开 API；Wiki 可作为展示入口，不能取代主仓库事实源。

### 7.1 事实源与文档分工

| 内容 | 拟定维护方式 |
| --- | --- |
| 类型和可调用接口 | 公开 TypeScript 声明为形状事实源；不把内部类整体导出 |
| 语义契约 | 结构化清单记录归属、模式、坐标、生命周期、错误与兼容阶段，链接到公开接入测试 |
| API 参考 | 从声明与结构化清单生成，检查生成结果是否新鲜 |
| 开发指南 | 解释接入流程、三类样例、设置与行为管理、调试及迁移；引用参考条目 |
| 历史基线 | 绑定实际发行版本及 Git 证据，独立于待检查的当前声明 |
| 发布台账 | 记录独立 API 版本、适用本体与实际发布日期、弃用与替代方案 |

公开 API 的初始版本与 SDK 载体尚未冻结。API 编号独立于 Vsidian 本体；实验能力另行声明兼容要求。稳定 API 确需移除时，先发布弃用与替代方案，从实际发布日计算，至少两个后续 API 次版本且满 30 天，两项同时满足。

### 7.2 检查入口（2026-10-08 已实施）

以下命令已在 package.json scripts 落地（另有 `check:addoncompat` 契约门禁与 CI job `addon-api-contract`，见 [addons-api-gate.md](addons-api-gate.md)）。

| 入口 | 检查责任 |
| --- | --- |
| `gen:addonapi` | 生成版本对应的接口参考与索引 |
| `check:addonapi:baseline` | 核对历史锚点和基线证据，先确认基线可信 |
| `check:addonapi` | 类型兼容、语义清单、文档新鲜度、版本及弃用期限检查 |
| 接入样例检查 | 验证输入、渲染、界面三类消费方式；不依赖内部模块 |
| 打包清单检查 | 沿用开发文档不随 Vsidian VSIX 分发的安排，并验证所需运行入口随组件包完整 |

门禁应覆盖独立证据和负向演示：删除公开接口、收窄参数或结果、改变只读与目标归属、修改基线、遗漏指南及提前移除弃用条目等变更必须被对应检查发现。类型兼容不能代替行为兼容。

AGENTS 保留单一触发入口。新增或变更 API 时同时更新声明、语义清单、指南、样例和相关验证。落地触及 DOM、样式、渲染依赖或页面资源加载时，同时执行项目 style-contract 技能，API 门禁不代替样式门禁。

CI job `addon-api-contract` 与 bootstrap 首版基线已随 #363 交付（本地与 CI 先基线复验后契约检查）；**仅剩远端必需检查配置属待授权项**，未配置前其失败不阻塞合并（见 [addons-api-gate.md](addons-api-gate.md)）。

## 8. 验证与完成条件

**以公开接入样例和真实用户路径验证**。内核内部纯逻辑可沿用单测，验收依据优先放在 SDK 接入、浏览器输入和真实宿主的外部行为上。

| 验证层 | 必须覆盖的路径 |
| --- | --- |
| 公开类型与消费样例 | 六组接口、稳定与实验入口区别、三类样例编译消费；无内部控制器引用 |
| 纯逻辑和设置服务 | 身份声明校验、兼容与重复注册、归属、默认序与逐项覆盖、复杂值校验、保存失败及数据恢复 |
| 生产控制器浏览器测试 | 原生输入与 IME、多行为调序和部分关闭、默认原子修饰与非原子归属、热切换、异步失效、视图释放 |
| 开发态真宿主 | API 就绪与依赖顺序、已开文档热切换、原子修饰独立撤回及非原子随上次原子操作撤回和重做、A/B 目标隔离、只读拒绝、设置范围与回显、故障全组件暂停及手动重试 |
| 安装态真宿主 | Vsidian 与样例组件均从 VSIX 装载；无需选择的新渲染器自动替换、内置语言替代、页面资源完整、重启和普通升级保留首选、声明不兼容与装载失败状态 |
| Remote SSH | 同宿主安装、实际运行位置、接入与资源装载；不可见原因提示不做错误归因 |
| 绘制与样式 | 安装后自动替代渲染的实际内容与按钮、用户主动调整；正常停用和整组件故障停用可交回内置；仍运行的错误渲染不自动接管；迟到结果及手动恢复；不只断言 DOM 存在 |
| 契约门禁 | 可信历史基线、参考生成结果、版本与弃用期、负向变更被拦截的证据 |

使用已有 `test/integration/suite/cases.ts` 的设置回读、视图状态与绘制探针，沿用浏览器测试和安装态宿主报告。需要增加测试样例扩展，但不为每个内部模块另造 mocking 接缝。测试注入继续遵循现有门控约定，发布态不得开放测试命令。

实施完成还须提供：公开声明与版本参考、三个消费样例、AGENTS 入口与检查命令、生命周期及故障验证记录、VSIX 内容证据，以及待人工验证清单。自动化通过不表述为用户已验收。

## 9. 已确认修订与技术验证

### 9.1 已确认的用户结果

| 编号 | 已确认修订 | 对接口和测试的影响 |
| --- | --- | --- |
| Q28 | 新安装的兼容且已启用渲染组件成功接入后，自动替换其支持语言的现有显示，包括内置渲染；用户可按需调整，无需逐语言初始配置 | 区分新安装与重启、重复注册、普通升级；自动接管、首选保存与恢复、多候选及模式适配 |
| Q29 | 每次文本修饰默认原子跟踪并具有独立撤回边界；作者声明非原子时，随同一目标文档的上次原子操作一起撤回，变更与来源仍须跟踪 | 编辑操作粒度、已确认合并归属的接入、宿主撤销与重做协议及跟踪证据 |
| Q30 | 正常停用或整组件故障降级停用后可交回内置；仍运行的渲染 bug 不自动接管、不承诺识别或修复 | 区分实际运行状态、停用原因与首选；回收、接管和手动恢复的呈现与验证 |

以上规则排除将渲染器选择作为安装后必需配置的方案；非原子修饰的归属采用上次原子操作，不采用另行指定因果触发操作的建议。此前「整次输入合为一次撤销」及「渲染器遇到任意故障就自动回退」的建议也不采用。产品规则已经确认，具体协议和装载实现仍待验证。

### 9.2 接口定稿前的技术验证

- 原生依赖、API 返回后主动唤醒和重复激活已在最小宿主探针验证；仍须验证生产注册入口、组件先被 VSCode 激活、清单变化与并发接入，证明不互等且不会重复注册。
- 独立 IIFE、授权后的本地资源和注入共享 EditorState 已在最小宿主探针验证；仍须验证实际 CM6 扩展、资源拒绝对照、完整卸载及 Remote。输入模块就绪与首个按键不能只靠桌面以外的模拟推断。
- 明确可组合行为与确需独占操作的接口区别，保留内置输入安全边界，不把顺序规则直接当作原始 CM6 装配顺序。
- 来源分组协调与宿主撤销、重做的基本路线已在最小原生编辑器和 Custom Editor 中验证；仍须接入生产版本与确认管线，验证原子独立撤回、非原子随同目标上次原子操作撤回、重做、来源跟踪、原生并发入口与跨目标隔离。历史为空、分支截断和重载恢复也须验证，撤销继续归宿主，不另建并行文本历史。
- 验证新安装的渲染组件自动替换内置或其他组件提供者，不要求初始选择；明确多候选同时接入的自动顺序，验证重启、重复注册与普通升级保留既有首选。
- 验证正常停用、仍运行的渲染失败与整组件故障降级停用的区分；证明故障后的内置接管只在允许状态发生，旧异步结果不回潮，手动重试按首选恢复。
- 明确行为默认序算法、稳定身份、显示信息本地化、顺序和开关的存储与恢复。
- 明确复杂设置定义、数组与对象的基础控件、迁移，以及用户默认和工作区覆盖的存储协调。
- 冻结公开接口签名、错误结果、消息载荷、SDK 载体、首个 API 版本与实验兼容清单。
- 明确官方归属识别、组件管理页布局、行为筛选与排查展示，并落地文档生成和 CI 检查。

## 10. 明确不包含

- 未经修改的 Obsidian 插件包直接运行。
- 独立于 VSCode 的 Vsidian 内部安装器、市场或整个扩展启停控制器。
- 首版跨扩展宿主的透明 API 调用。
- 附加组件接管整体设置页面、覆写内置设置页或内置菜单项。
- 把普通 VSCode 扩展或页面代码变成具有完整隔离保证的沙箱。
- 文件与外部服务的专门 Vsidian API，尚未单独讨论的能力不混入首批六组范围。
- 当前创建或发布外部示例仓库、Wiki、SDK 包、VSIX 或远端门禁配置。
