## 目标

主正文新建双链后，从现有根内 Markdown 文件表取得候选，按 VSCode 查询／评分逻辑选择并插入可靠相对路径，完成最小生产闭环。

## 交付范围

- 固定 VSCode 查询准备／评分源码基线和许可信息，适配依赖；以官方测试例验证顺序模糊、文件名／前缀及路径／多词分支，保持同分 mtime。
- 新增内部查询协议与主正文接线，携带实际来源、会话和查询代次；复用已有索引 Markdown 文件，不等待全文件清单或附加组件 API。
- 识别新建闭合空双链与文件前缀，支持 `[[]]` 和 `![[]]`；未成型状态的识别不放宽既有完整渲染解析器。
- 候选显示文件名／目录，空查询不高亮、有查询高亮首项；箭头选择，Enter／Tab 接受，Esc 关闭。
- 确认后生成来源相对路径与文件名别名，无可用根／索引未就绪时显示真实状态、允许手写。
- 创建候选绘制探针、i18n 和公开样式条目，兼容旧契约；复杂目标区重编辑及转阶段在 T03 补齐。

## 验收标准

- [ ] 从生产编辑器连续输入两个 [ 后出现实际可见候选，选择同目录和其他目录 Markdown 都能按相对路径插入。
- [ ] 空查询与非空查询高亮符合共识，方向键不移动正文光标；Enter／Tab 确认后无额外换行／缩进。
- [ ] 插入 [[../资料/方案.md|方案]] 等结果经现有解析器往返核对为所选目标，不作 basename 或跨根补查。
- [ ] 缓存未就绪、无可靠来源、取消及迟到响应不改正文，不伪装为空结果。
- [ ] 至少一条绘制层集成断言验证候选可见性；新增文案双语，旧样式契约独立证据通过。
- [ ] 源码与 Reading 不接管，IME 组合期间和非空／多 range 不确认候选。

## 验证

- TDD 单测：查询适配、消息守卫、相对路径与会话；生产 browser：新建双链、方向键、Enter／Tab／Esc。
- 真宿主：实际写回、dirty／撤销、绘制；npm run check:stylecontract:baseline 与 check:stylecontract。
