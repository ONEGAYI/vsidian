## 目标

把 T01 的候选扩展为所有未排除文件，使未被引用的附件和未知类型可搜索，并在生命周期变化中保持正确。

## 交付范围

- 扩展文件登记为所有未排除普通文件，多数仅记名；常用资源取真实 mtime，元数据未知显式建模。
- 清单就绪与引用关系就绪分别处理，不能因名称枚举完成提前放行更名；保留既有索引／rename／资源权限边界。
- 空查询仅常用 Markdown、图片、PDF、音视频、已声明可读文本，按 mtime；有查询允许未知／编译类型，匹配同分再比 mtime。
- 复用工作区私有快照、根分区和原子写入；决定格式兼容与重建，维护排除、事件、改名、根变化、周期核验和 Remote 重连。
- 查询分页／限量和扫描／评分可取消、分批让出；结果包含清单代次，旧枚举／stat 不复活删除项。
- 通过 T01 的实际候选 UI 与现有索引维护入口验证全文件计数、持久化、排除回显和恢复。

## 验收标准

- [ ] 未曾被引用的 png／pdf／音视频／代码文件可在空查询或搜索中出现；.pyc 等不进空查询但能按查询找到。
- [ ] .git／node_modules 和用户排除仍生效，排除持久化、重开回显与恢复默认保持原语义。
- [ ] mtime 由文件信息取得，未知沉底；同分稳定排序，未保存编辑不冒充磁盘修改时间。
- [ ] 增删改名、排除／根变化后 UI 失效或更新；乱序请求、旧扫描、旧 stat 无法恢复陈旧条目。
- [ ] 新清单不复制附件全文，冷恢复与损坏重建有证据；引用关系就绪／更名失败边界没有被顺手放宽。
- [ ] 生产候选实际展示新资源，访问失败与删除、部分就绪与完整空结果可区分。

## 验证

- 文件清单／快照／调度／排除和消息单测；生产 browser 验证候选过滤、排序、变化。
- 真宿主：真实文件事件、缓存重开、排除和更名回归；容量原始采样留给 T07 汇总。

## 不包含与失败口径

不增加全文／附件内容索引、SQLite 或跨根补查；不新增一套用户排除设置。
