## 目标

在 1.82.3 真宿主中验证现有文档与历史管线能协调“目标补 ID＋来源接受”，给 T05 提供可实施的尽力撤回路径。

## 交付范围

- 仅做有范围的探针与证据，不实现完整候选 UI，不依赖附加组件 API／SDK 或 #348／#349。
- 覆盖 A 引 B、同文档引用、B 未保存、已有 ID 复用；核对 TextDocumentChangeReason、版本变化、来源接受的一笔撤销与重做。
- 尝试只撤回本次新增 ID。B 被修改、标记变化、只读／失败时保留 ID，并有可观测的警示路径；不得撤销 B 的无关输入。
- 验证来源接受失败、来源／目标关闭、后台引用端口与迟到结果的收尾；不要求严格原子回滚或零副作用。
- 以现有 test hooks、便携宿主及报告机制验证，给出成功／风险跳过／不可执行的明确结论。

## 验收标准

- [ ] 普通可写、版本未变的跨文档案例，能够尝试撤回新增 ID，来源链接按现有历史撤销。
- [ ] 同文档与已有 ID 的路径分别有记录；已有 ID 永不被清理。
- [ ] 目标版本／标记变化、读取或写入失败有保留 ID 的安全分支及 toast 所需的明确结果，来源撤销继续完成。
- [ ] 重做、初次接受失败及释放后迟到案例有可审阅证据，不把关闭验证票当作自动通过。
- [ ] 报告包含源码／宿主版本、输入输出、日志与退出码，并给 T05 写出放行结论。

## 验证

- 1.82.3 真宿主探针；使用生产 DocumentSession 和 WorkspaceEdit／既有历史路由。
- 本轮不要求运行全部 browser；涉及新控件时执行相应 style-contract 和绘制检查。

## 不包含与失败口径

本票不是附加组件原子历史实现；允许无法安全撤回 ID 时保留并提示，不以严格分组或 SDK 完成作为门槛。

## 公共约束

- 现有 #194／#196／#197–#202 与引用内部 Live 为已落地基础，不作为未完成依赖；#16 仅背景，附加组件 API／SDK 不作为前置。
- 可执行行为 TDD；输入／光标变更跑生产 browser，呈现先执行 style-contract 并给绘制层证据；测试优先真实生产控制器／宿主，不新造镜像 mock 管线。
- 用户文案 i18n；新增设置走自有设置页，操作按统一键位规则评估；保存和权威正文归 VSCode，缓存不扩大权限。
- 长命令首轮日志与退出码落盘；file-tree 维护新增文件；不推送、合并或发布，用户验收另行记录。
