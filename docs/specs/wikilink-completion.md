## 已确认的交互

### 触发、关闭与再次触发

触发依据是双链围栏及光标所在的编辑区域，不是把 `[[` 或 `![[` 这个按键序列本身定义为唯一入口。新建围栏与已有引用的二次触发分别定义。

连续输入两个 `[` 时，既有成对符号补全形成完整的 `[[]]` 并把光标留在中间，因此触发联想。`!` 前缀不改变围栏内部的候选交互。

- Esc 关闭当前联想。
- 关闭后，仅把光标移动回双链内部，不重新打开联想。
- 已有 `[[Aa|B]]` 中，只有光标位于目标区 `Aa`，且用户输入或删除改变了目标区内容，才再次触发候选。
- 仅移动光标、修改显示文字 `B`，不再次触发文件／锚点候选。
- 再次触发时自动用光标左侧的目标输入填入查询，而非把光标右侧的文字并入搜索。

以下以 `¦` 表示光标，`¦` 不是链接源码；真正的 `|` 仍是显示文字分隔符：

| 用户输入／删除后的位置 | 自动查询 |
| --- | --- |
| `[[A¦a\|B]]` | `A` |
| `[[Aa¦\|B]]` | `Aa` |
| `[[Aa\|B¦]]` | 不触发候选 |

以上位置变化本身不构成再次触发，须伴随用户输入／删除。未闭合围栏、IME、用户以外的正文变更和各锚点字段的处理，按下文技术设计与各票输入矩阵验证。

### 高亮与确认

候选显示文件名及所在目录，以目录区分同名文件。方向键移动候选高亮，不必输入完整文件名。

空查询先不高亮候选；有搜索文字且有真实结果时，自动高亮首项，用户仍可用方向键改选。空双链内没有高亮时直接输入 `#`／`^`，不补文件名，进入对应占位状态；已经高亮文件时按 `#`／`^` 则补全该文件并转阶段。

| 输入 | 已确认行为 |
| --- | --- |
| `↑`／`↓` | 移动候选高亮 |
| Enter／Tab | 确认当前高亮候选 |
| `#` | 补全高亮 Markdown 的文件部分，进入标题联想 |
| `^` | 补全高亮 Markdown 的文件部分，进入块联想 |
| `\|` | 有高亮时补全前面的目标，无高亮时保留原输入；关闭候选，手动编辑显示文字 |
| Esc | 关闭当前联想 |

Enter／Tab 仅在候选会话中有可确认项时接管。候选关闭或没有可确认项时，保留既有围栏越界、表格切格和段落缩进。

块联想的触发键为 `^`；选定块后，最终引用使用现有语法中的 `#^块ID`。不能要求用户先输入 `#^` 才打开块候选。

### 没有目标或候选时的占位

没有明确联想目标时，不默认指定当前文档为标题／块联想文档。没有可确认高亮时，也不擅自拿文件列表首项替换原输入。

标题／块联想为空时，显示“小标题”／“块 ID”等占位提示，保留用户原文。用户提供的 `[[#]]` 界面图用于说明这一空态；占位只作提示，不可接受并写入正文，不把示例词视为真实标题或块 ID。

占位不是可确认的候选，Enter／Tab 继续按“没有可确认项”的规则处理。

### 路径与显示文字

选定文件后生成直接来源文档相对路径，默认自动加文件名作为显示文字。例如，来源为 `项目/记录.md`，目标为 `资料/方案.md`，文件确认结果是：

```md
[[../资料/方案.md|方案]]
```

按 `#`、`^` 或 `|` 可以直接确认高亮文件并进入对应阶段，无需先按 Enter。按 `|` 时，没有高亮就保持前面的原输入，然后关闭候选、手动填写显示文字。

显示文字区域不触发文件／锚点候选；回到目标区后，也只有用户输入／删除改变目标内容才再次触发。

文件段中间确认候选时，替换整个文件字段，保留用户已有的显示文字。例如，`[[A¦a|B]]` 查询 `A`，确认同目录的“目标.md”后成为 `[[目标.md|B]]`，不留下光标右侧原来的 `a`。

新链接主动按 `|` 时，显示文字留空，等待手动输入。例如，高亮同目录“方案.md”后按 `|` 得到 `[[方案.md|¦]]`。已有别名则保留，不用自动文件名覆盖。

Enter／Tab 完成新链接的文件选择时，自动加文件名别名；标题／块选择完成后，没有用户手写别名时也仍用文件名作为默认显示文字。例如，选“方案.md”的“预算”标题后，结果为 `[[方案.md#预算|方案]]`。用户已有别名始终保留。

### 首期编辑位置

首期同时覆盖主正文、表格单元格、悬停浮窗及正文嵌入内部 Live。阅读模式仍只读，源码模式保持宿主已有输入链路。

内部编辑 B 时，候选范围、插入的相对路径以及当前内容均以 B 为来源；外层 A 不参与替代来源判断。表格格内继续沿用既有别名竖线的转义与原始源码坐标口径。

### 文件与锚点范围

- 文件级联想覆盖 Markdown、图片、PDF 等各种可链接文件，具体候选规则见下节。
- 标题和块的细则联想仅用于 Markdown，其他文件保持文件级候选。
- 首期先确定文件，再对明确的 Markdown 目标使用 `#`／`^`；不提供 `##`／`^^` 全根标题／块搜索。
- Markdown 的块联想包括无 ID 的可引用块；选定后，为没有 ID 的目标块自动补写 `^id`，已有 ID 则复用。
- 首期沿用 `src/shared/blockId.ts` 的块边界：代码围栏整体一块，围栏外按空行与围栏行分界；没有空行分隔的连续列表整体一块，不新增逐列表项定位。
- 可引用块包括上述边界下没有 ID 的块，不能偷换为仅列已有 ID。具体容器的枚举与插入验证矩阵由 V01／T05 依据现有块边界落实。

### 重复标题的呈现与提示

同一文档的重复标题全部展示，保留各候选的独立位置，不合并为一项。选择时检测该标题是否有同名项；检测到重复则以 toast 提示潜在的跳转定位风险，继续接受本次选择。

候选呈现与引用后的跳转分别负责。首期不为区分重复候选而更改现有跳转语义，也不因为现有跳转会取首处而隐藏其他标题。风险检测须参考现有标题定位的规范化口径，避免原文略有差异但实际定位到同名项时漏报。

### 新增块 ID 的保存与撤销

补 ID 和插入链接均不自动保存。

用户撤销本次链接插入时，尝试一并撤回目标文档中本次自动新增的 ID。撤销无需严格保证跨文档无副作用：如果有潜在风险或无法撤回 ID，保留该 ID，并用 toast 明确提示未撤回。不要求为了严格联动而阻塞本功能。

只尝试撤回本次自动新增的 ID，不删除原本存在的 ID。安全判据、失败收尾、重做，以及来源与目标是同一文档时的历史行为，按下文设计并经 V01 真宿主验证；不把现有宿主历史能力当作已验证的跨文档保证。

## 已确认的文件登记、过滤与排序

### 清单与排除

索引扩大到所有文件类型；多数文件只登记名称、路径等信息以加速搜索。沿用现有索引排除规则，包括默认排除 `.git` 和 `node_modules`，不因此全量读取全部文件的内容。

### 空查询

没有搜索文字时，只列 Markdown、图片、PDF、音视频、可读文本等常用资源，按 mtime 从新到旧。这里的 mtime 是文件修改时间，不是首次被索引、首次被引用或候选进入列表的时间。

常用资源的扩展名／可读文本判定、同 mtime 的稳定次序、候选数量和分页方式，按下文技术设计落实。

### 有查询

有搜索文字时，根据匹配内容显示相关文件，允许 `.pyc` 等其他类型进入候选。排序先比较匹配程度，同等匹配再按 mtime 从新到旧。

用户确认直接以 VSCode 的查询处理和匹配逻辑为候选联想基线，仅按 Vsidian 的实际需要少量适配，决定见 [ADR-0014](../adr/0014-vscode-query-matching-for-wikilinks.md)。已完成[官方源码核查](../research/vscode-quick-open-matching.md)：支持按顺序模糊匹配、文件名／前缀加权及路径分支；不是“准确／前缀／包含／模糊”四段固定排序。

Vsidian 继续沿用本节已确认的匹配优先、同分按 mtime 的规则。具体复用代码与依赖适配、查询准备和评分的接口在技术规格中说明；不把采用源码基线等同于照搬 Ctrl+P 的全部候选来源或排序。

路径片段、查询规范化、缺少 mtime 的处理按下文技术设计，匹配性能经 T07 测量；此决定不授权全文或附件内容搜索。

## 沿用的现行边界与源码依据

- **路径解析**：沿用 [ADR-0008](../adr/0008-workspace-reference-index.md) 与[引用索引规格](vault-index-backlinks.md)的直接来源相对路径、根内边界、多根互不补查。联想中显式选择文件，不等于恢复点击链接时按 basename 自动搜索目标。
- **当前内容**：Markdown 当前正文仍是事实来源；未保存输入不能被旧索引或缓存覆盖。标题／块枚举参考既有语法与块边界；重复标题全部展示，候选不借此扩展跳转能力，已知定位风险在选择时提示。
- **输入协调**：按[符号输入约定](symbol-input.md)和[快捷键约定](keybindings.md)协调候选确认、成对符号、闭合越过、Tab 越界、表格切格、缩进与 Esc。不得接管输入法选词，或扩大多光标、源码模式的既有输入契约。
- **引用内部 Live**：首期已确认覆盖悬停／嵌入内部编辑；正在编辑 B 时，候选范围与插入路径均以 B 为直接来源，不能误用外层 A。
- **既有文件表**：`src/host/vaultIndexService.ts` 当前从 Markdown 的出链中发现附件并登记；`indexedFilesUnder` 返回已登记文件，不保证含尚未被引用的附件。全文件清单需要真实扩展。
- **现有复用点**：`src/webview/liveInstance.ts` 为主正文与内部 Live 共用装配入口；`src/shared/vaultLink.ts` 是相对路径解析核心；`src/shared/blockId.ts` 提供 ID 查重、生成与插入计划；`src/host/wikilinkTarget.ts` 提供标题／块定位口径。
- **专项前置**：本功能不等待尚未实施的附加组件 API／SDK。

Obsidian 是交互参考，Vsidian 的已确认规则由本文和现行仓库契约定义。[官方内部链接说明](https://obsidian.md/help/Linking%2Bnotes%2Band%2Bfiles/Internal%2Blinks)支持 `^` 触发块建议、最终以 `#^id` 引用的区别；不据此引入 Obsidian 的其他全库搜索或路径规则。

## 技术设计与实施边界

以下把已确认交互转为可实施约束。代码、消息字段的具体命名由实施决定；这里规定职责、守卫和可观测行为，不把未实现的接口写成公开 API。

### 文件清单、元数据与生命周期

- 每根独立维护文件登记，嵌套根取最具体归属；使用规范 URI／真实路径作为身份，搜索用的大小写折叠不改变文件身份。
- 所有未排除的普通文件均登记名称、根内路径和类型提示。多数文件只记名，不读取全文；mtime／size 等为带有“已取得／未知”状态的元数据，未知不能伪装为当前时间。
- 常用资源分类复用现有资源及文本语言分类的声明和后缀，集中维护；不为判断空查询是否显示而打开全部未知文件。未知类型仍可被非空查询找到。
- 空查询的已知 mtime 下降排序，未知沉底，再以稳定路径破同分；非空查询按匹配分数、已知 mtime 下降、稳定路径排序。
- 文件清单与引用关系分别标记就绪状态。名称已枚举不代表 Markdown 出链核验已完成，不能因此放行尚未准备好的引用更名操作。
- 复用现有工作区私有缓存、根级分区与原子提交机制；按实际格式变化决定版本升级和旧缓存重建，维持索引可重建、不含附件全文的边界。
- 创建、删除、改名／移动、排除修改、根增删、重连和周期核验更新清单代次。旧目录枚举、旧 stat 与旧查询不得复活已删除身份或覆盖较新结果。

### VSCode 查询与评分适配

以研究记录固定的 VSCode 源码为起点，记录复用片段、版本、来源与许可；参考现有查询准备和匹配评分，不重新发明四档评分。

首期采用按字符顺序的模糊匹配、文件名／前缀加权、路径分支，以及空格拆片后全部命中的规则。片段首尾引号按源实现表示连续匹配，不扩展为完整短语解析。候选的 label 为真实文件名，目录与可搜索路径由来源上下文提供，匹配高亮区间对应原始文字的 UTF-16 位置。

直接来源所属根和排除规则先筛候选，评分不能通过其他工作区根或搜索排除外的路径直达补齐结果。完整比较器中会先区分名称／路径长度的部分按 mtime 契约适配，匹配分数相同后先比 mtime。

候选响应按页／限量传递，首屏默认最多 50 项，可继续加载；总体排序在宿主侧有界维护，不将整库逐次传到 webview。长扫描和评分分批让出，可取消；具体切片、缓存和限流经容量验证调整，不承诺尚未测得的延迟。

### 输入识别、选区与确认

- 新增局部输入识别器可认识闭合但未成型的双链，如空文件段、空锚点和空显示文字；完整呈现／跳转解析器继续保持现有严格语义。占位仅存在于 UI，不能写进正文。
- 首期只处理同一行中可识别的闭合双链围栏，覆盖普通与嵌入前缀；未闭合、嵌套残缺等保留普通输入。代码、行内代码、HTML 块和 frontmatter 上下文不启用候选。
- 只有单个折叠光标的可编辑 Live 正文进入会话；多 range／非空选区、暂停和 IME 组合期不接管。纯光标移动不发起新查询；移出目标字段、进入显示文字、切模式或释放实例关闭候选。
- 文本确认替换当前完整文件字段，不残留光标右侧旧名称，保留已有锚点／显示文字的范围在各阶段显式规划。已有竖线后的文字，包括空值，均按用户显式内容保留；只在没有显示文字分隔符时补默认别名。
- 新链接文件确认默认别名：Markdown 去掉末尾 .md，其余资源保留完整文件名。标题／块确认默认也用该文件名；主动键入竖线进入手动显示文字时留空。
- 文件 Enter／Tab 确认后关闭会话，光标留在目标区末端、已有别名分隔符之前或闭围栏之前，便于随后添加锚点；#／^ 转对应查询，竖线进入显示文字。已有分隔符按阶段跳转或复用，不重复插入竖线。
- 同一查询的异步列表更新按候选身份保留手动高亮；身份消失时，非空查询取首项、空查询回到无高亮。用户改变查询则执行已确认的初始高亮规则。
- 空目标 #／^ 不指定联想文档，仅显示占位。文件目标明确且能按现有来源相对语义解析时，才读取该 Markdown 的标题／块；不按部分文件名猜一个目标。
- 文件阶段的 ^ 将块标记形成现有 #^ 语法；已经有 # 时不重复补 #。无目标时也只形成可继续手写的空块字段，不写占位词。
- 竖线在文件／标题／块阶段都接受该阶段的真实高亮候选，再进入手动显示文字；无高亮保留当前目标。无 ID 块的接受先按目标写入守卫执行，失败保留输入并提示，不能先写一个虚构 ID。
- 路径生成使用现有来源根与平台语义。文件名含空格、Unicode、点号和保留符号做解析往返核对；无法生成与所选文件身份一致的路径时保留原输入并 toast，不扩展链接解析语义。
- 标题按现有 ATX 口径枚举，围栏内伪标题排除；重复标题保留独立候选身份与位置，按定位规范化口径检测风险。候选不负责升级标题跳转能力。

### 候选 UI、按键与可访问性

候选锚定实际 EditorView 的目标位置，文件列表显示文件名／目录，标题显示标题和层级／位置，块显示文本片段并可搜索已有 ID；空态、加载、部分就绪和读取失败分别表达。菜单滚动和定位限于可见视口，覆盖嵌入内部滚动、缩放、主题和字号变化。

有真实高亮候选时 Enter／Tab 确认；箭头选择不移动正文光标；候选中的 Esc 先关闭候选，再由后续 Esc 进入原选区／引用关闭链路。既有模态优先级保留。无可确认项时原编辑按键落穿，不能把占位当成候选。

导航、确认和关闭是候选会话操作，须评估并记录可绑定入口、默认绑定和生效模式；可绑定项沿用统一注册模型，不能通过全局 keybindingRouter 绑定 Tab 破坏围栏／切格／缩进。固定的候选控件按键只在会话内消费。本批不新增“手动重开”或总开关需求；若实现需要新增设置，必须走 Vsidian 自有设置页并在票中明确理由。

UI 文案全部 i18n；新增 DOM、类、属性和变量按 style-contract 固定旧契约并保留兼容，指南／双语说明和独立绘制证据同步。无原生 title 回潮；必要悬停说明走 data-tooltip。候选行与键盘高亮使用列表语义和可观测焦点状态，不夺走正文输入焦点。

### 文档查询、块 ID 与撤销

文件查询只使用派生清单；标题／块内容以宿主当前 TextDocument 为依据，自己正在编辑的未落定输入先协调到最新有效版本。缓存只可加速，不替代版本核对。只读或不可访问目标可以保留文件候选；需要给无 ID 块写入时，先核对可写、目标版本、块身份和来源会话。

无 ID 块选定后先在目标文档按现有块边界、ID 查重与插入计划补写，再接受来源链接；已有 ID 复用。源与目标为同一文档时合为该文档内一笔受控操作，不自动保存。跨文档不宣称 VSCode 天然提供严格原子历史，V01 先验证协调路径。

只记录本次新增 ID 与来源接受操作之间的因果关系。来源撤销时，尝试仅撤回这段新增标记；目标版本／标记内容改变、已观测到新使用、权限或版本核验失败等风险时跳过并 toast。不能借撤销 B 的最近一笔来撤掉 B 的无关输入。失败后的 ID 留存允许，不能阻塞来源撤销，也不删除原本存在的 ID。

重做需要重新核对目标；目标标记仍在则复用，已安全移除时按探针结论恢复或重建映射，不能复活被他人改写的标记。来源接受失败后的补 ID 收尾同样尽力处理并说明结果。完整方案依据 V01 的真实宿主证据放行，附加组件 API／SDK 和其验证票不作为依赖。

### 消息、归属与迟到守卫

查询职责包含文件候选、明确目标的 Markdown 锚点、接受无 ID 块三类。请求携带实际来源文档／会话、实例与查询代次、当前字段范围和所需目标版本；结果携带匹配身份、分数／高亮、已取得元数据与真实状态。具体 kind／字段命名在现有 protocol 中落地，并保持双向校验和 refEdit 白名单一致。

主正文经原会话，内部 B 经 B 的 refEdit 信封和身份守卫；候选 UI 仅操作当前实例。查询取消、来源版本／范围变化、根变化、端口释放、切 Reading 后，旧响应和旧确认一律拒收；禁止借外层 A 或旧 B 端口继续提交。引用内部最深焦点路由、LF／CRLF 坐标与表格竖线解码均复用既有管线。

## 失败、容量与交付口径

| 场景 | 必须表现 |
| --- | --- |
| 清单正在构建／部分可用 | 明确标出状态，可用项继续候选；不把部分结果说成完整空列表 |
| 无工作区／来源尚无可靠路径 | 不猜根或插入跨根路径，显示可用性说明，继续允许手写 |
| 明确目标已删除或改名 | 失效对应候选；确认前核对，失败保留原输入并提示 |
| 权限失败／Remote 断连 | 显示不可访问／失败状态，不冒充文件删除或无结果 |
| 目标正文在请求中改动 | 淘汰旧标题／块候选或重新查询，不能按陈旧范围写 ID |
| IME、非空选区／多光标 | 保持现行输入行为，候选不消费选词确认或改写其他 range |
| 重复标题选择 | 接受选择并 toast 提示，不合并、不扩展既有跳转 |
| 新增 ID 撤回风险／失败 | 来源继续撤销，ID 留存并 toast；不动既有 ID |

测量 1千／1万／10万文件的首建、恢复、空查询、短／长／多词查询、单文件变动与并发取消，记录墙钟、事件循环最长停顿、内存、磁盘和传输量。区分 Markdown 与仅登记文件，报告逐字输入的候选响应费用；不以源码阅读或小样本冒充大库／Remote 通过。

验证优先走生产 LiveEditorInstance／WebviewSyncController、既有浏览器运行器和真实宿主。单测覆盖纯查询／字段计划／目录边界／版本淘汰；浏览器验证真实键盘、IME、表格、绘制可见性；宿主验证权威正文、保存状态、块 ID 与撤销、B 归属、缓存及更名。最终至少一条候选绘制层集成断言，并运行 style-contract 门禁。

长命令首次落盘输出和退出码，后续复核读报告。人工清单记录物理键盘／输入法、鼠标、观感和 Remote 的实际状态；自动化不代替用户验收。

## 明确不包含

- 全根 ##／^^ 标题和块搜索、跨根补查或 basename 自动目标解析。
- 新的重复标题定位语法、逐列表项块定位、完整 Markdown 解析规则扩展。
- 全文／附件内容索引、独立目录候选、未保存无路径文档的目标猜测。
- 对输入法选词、多光标、源码模式或 Reading 写入行为的接管。
- 严格无副作用的跨文档回滚保证、自动保存目标或删除既有 ID。
- Ctrl+P 编辑历史／符号／行号功能、附加组件 API／SDK 的实施或依赖。
- 未授权的推送、合并和产品发布。
